# EDA 项目中 Floorplan（布局规划）的用途

Floorplanning 是数字/混合信号芯片物理设计流程中**最早期、也最具决定性的阶段**之一。它介于逻辑综合（Synthesis）与布局（Placement）之间，主要任务是**在还没有做精确布局布线之前，先确定芯片的"宏观骨架"**。可以说，floorplan 做得好坏，直接决定了后续 P&R 能否收敛。

下面是它的核心用途：

## 一、核心用途

### 1. 确定芯片整体尺寸与形状
- 决定 **die size（芯片面积）** 与 **core size（内核面积）**。
- 确定 **core-to-IO 间距**、**aspect ratio（长宽比）**。
- 直接影响成本：面积越大，晶圆上能切的 die 越少，成本越高。因此 floorplan 是控制 **PPA（Power/Performance/Area）** 中 A 的关键环节。

### 2. 宏单元 / IP 的摆放（Macro Placement）
- 决定 RAM、ROM、PLL、模拟 IP、SerDes 等**硬核位置与朝向**。
- 约束条件通常包括：
 - 靠近相关逻辑以减少线长（如 memory 靠近数据通路）
 - 避免遮挡布线通道（routing blockage）
 - 满足模拟/数字隔离、噪声与衬底噪声要求
- 宏单元摆放不当会导致后续布局布线**严重拥塞或无法布线**。

### 3. I/O Pad 与引脚规划
- 确定 pad ring 上各信号/电源 pad 的位置。
- 需满足 ESD、封装、bondwire/flip-chip bump 的物理约束。

### 4. 电源规划（Power Planning）
- 这是 floorplan 阶段极其重要的一环：
 - **Power Ring**（电源环）
 - **Power Stripe / Strap**（电源条带）
 - **Power Grid / Mesh**（电源网格）
- 保证 IR-drop 与 EM（电迁移）满足可靠性要求，并合理分配电源网络资源。

## 二、对后续流程的价值

<details>
<summary><b>点击展开：Floorplan 如何支撑后续阶段</b></summary>

- **为 Placement 提供边界与约束**：确定 core 区域后，标准单元才有合法的摆放空间。
- **为 CTS / Routing 预留资源**：提前规划通道与拥塞热点，减少后期绕线困难。
- **早期时序与拥塞预估**：好的 floorplan 能让工具在早期就得到较可信的 timing / congestion 估计（即 "virtual" 评估），避免后期返工。
- **支持层次化设计（Hierarchical Design）**：在大型 SoC 中划分 partition，floorplan 决定各 block 的物理边界与接口位置。

</details>

## 三、常用目标与优化指标

Floorplan 本质上是一个**多目标优化问题**，通常要同时权衡：

| 指标 | 说明 |
|------|------|
| Area | 面积最小化 |
| Wirelength | 总线长最小化 |
| Congestion | 布线拥塞最小化 |
| Timing | 关键路径时延 |
| Power | 功耗与 IR-drop |
| Thermal | 热点分布（先进工艺尤为重要） |

## 四、一句话总结

> **Floorplan 的用途是：在芯片物理实现的"第一步"就搭好宏观结构——定尺寸、摆宏单元、排引脚、布电源、划通道，从而为后续布局布线奠定一个面积、时序、拥塞、功耗都可收敛的基础。**

它的质量往往是整个物理设计能否按期签核（sign-off）的**决定性因素**，业界常说 "**A good floorplan is half the battle**"（好的 floorplan 等于成功了一半）。

# 一、总览：这个方向的研究脉络

floorplanning 本质是一个 **NP-hard 组合优化**问题（模块摆放 + 朝向 + 布线/时序/拥塞多目标）。ML 介入的核心动机是：

1. **摊销（amortize）搜索成本**：用模型学一个策略/生成器，替代每张图都重新跑一次 SA/BO；
2. **跨设计泛化（transfer）**：一次训练，多个设计复用；
3. **端到端优化代理（surrogate）**：用学习模型快速预测 HPWL / 拥塞 / IR-drop，摆脱昂贵的真实 P&R 评估。

研究路线大致分四派：**RL 直接摆**、**生成式（diffusion / decision transformer）**、**GNN 表示**、**ML 辅助经典优化器（BO / Q-learning）**。

# 二、经典（非 ML）基线——必须先理解它们

> ML 论文几乎全部以这些为 baseline，不理解它们就看不懂"效果不怎么样"的争论。

- **模拟/版图**：**ALIGN**、**MAGICAL**（DARPA 资助的 analog layout 自动化）。

# 五、为什么"很慢、效果又不怎么样"——这就是研究难点

这些正是当前论文想解决的 open problems：

1. **搜索空间爆炸 + 序贯决策**：动作空间巨大（3D/不规则形状更甚），稀疏奖励，收敛慢（见 `2406.10538`）。
2. **评估昂贵**：真实 P&R 评估一次几分钟~几小时，RL 训练需要成千上万次 rollout，**训练成本远超 SA 一次求解**。
3. **代理目标不可靠**：多用 HPWL 做 reward，但 HPWL 低 ≠ 拥塞/时序/IR-drop 好，reward hacking 严重。
4. **泛化差**：换个网表/工艺就失效 → 催生了 transfer（ChiPFormer）、offline（decision transformer）等工作。
5. **可复现性与公平 baseline 争议**：多篇论文（`2302.11014` 等）指出 RL 没稳定打赢 SA/BO，且对比时 baseline 调参不公。这是整个方向的"信任危机"。
6. **约束难处理**：fixed-outline、时序、热、电源、设计规则（`2601.22476`）等硬约束很难塞进 RL。

# 六、如果要切入研究，可考虑的方向

- **代理模型 / differentiable proxy**：用可微或 GNN 预测拥塞/时序，替代昂贵评估（配合 DALI-PD 类合成数据）。
- **混合/两阶段**：ML 出初始 floorplan → 解析式/AutoDMP 精修（PARSAC、CSF 是典型）。
- **迁移与 few-shot**：一设计训练、多设计部署（ChiPFormer 路线仍open）。
- **多目标 / 约束**：thermal（RLPlanner）、IR-drop、EM、封装协同（`2607.15005`）。
- **LLM/agent + 物理约束**：2025–2026 热点，但水分多，注意评测。
- **统一 benchmark 与复现**：BBOPlace-Bench、FloorSet 提供了标准化土壤，是刷榜+打假的好机会。

**一句话总结**：这个领域的真实图景是——**RL/生成式方法做"端到端 floorplanning"尚不稳定（常打不过 SA/BO），但"ML 做代理模型 + 混合优化 + 迁移"才是更有落地前景的方向**；而数据基础设施已由 CircuitNet、FloorSet、OpenROAD 生态基本补齐，争议核心仍是**公平评测与可复现性**。
