# 缓解 LLM 流式 Markdown + LaTeX 渲染卡顿

**一句话结论**：卡顿的本质是 **每个 token 都触发「整篇重新解析 + 整棵 DOM 重新 diff + 所有公式重新排版」**，把总复杂度从 $O(n)$ 推到了 $O(n^2)$。优化的核心就一句：**只重解析和重渲染「正在变化的那一小段」，其余部分冻结并 memo 掉**。

---

<details>
<summary><b>一、根因分析（为什么越到后面越卡）</b></summary>

Assuming a document of length $n$ streaming in $k$ chunks, naive implementation cost:

$$\sum_{i=1}^{k} O\!\left(\frac{i\,n}{k}\right) = O(n^2)$$

具体慢在这几层：

| 层级 | 现象 | 代价 |
|------|------|------|
| Markdown 解析 | 每个 chunk 重新 parse 全文 | $O(n)$ / 次，累计 $O(n^2)$ |
| KaTeX 渲染 | 所有公式重建 DOM + 重新排版 | 每个公式含大量 inline 元素 + 字体度量 |
| React reconcile | 大子树 diff、组件重跑 | 组件数 × 次数 |
| 语法高亮 | Shiki/Prism 重跑 | 极重，单次可达几十 ms |
| 浏览器 Layout | `innerHTML` 全量重设 → 整页 reflow | 触发 forced synchronous layout |
| 字体 | KaTeX woff2 未命中 → FOUT / 重排 | 抖动、闪烁 |

</details>

<details>
<summary><b>二、方案速览（按性价比排序）</b></summary>

| # | 方案 | 收益 | 成本 |
|---|------|------|------|
| 1 | rAF/定时批处理 token | ⭐⭐⭐⭐⭐ | 极低 |
| 2 | 分块 + `React.memo`（核心） | ⭐⭐⭐⭐⭐ | 低 |
| 3 | KaTeX 结果缓存 + 只渲染完整公式 | ⭐⭐⭐⭐ | 低 |
| 4 | `useDeferredValue` / `startTransition` | ⭐⭐⭐⭐ | 极低 |
| 5 | 代码高亮延迟到块闭合 | ⭐⭐⭐⭐ | 低 |
| 6 | 虚拟化 / `content-visibility` | ⭐⭐⭐⭐ | 中 |
| 7 | Web Worker 解析 | ⭐⭐⭐ | 高 |

</details>

## 三、逐项实现

### 1. 用 rAF 批量刷新，别 per-token setState

SSE/流式回调通常是每收到一个 token 就 `setState`，一帧内可能触发几十次。改为**缓冲 + 每帧 flush 一次**：

```ts
function useStreamText() {
  const buffer = useRef('');
  const rafId = useRef(0);
  const [text, setText] = useState('');

  const push = useCallback((chunk: string) => {
    buffer.current += chunk;
    if (rafId.current) return;
    rafId.current = requestAnimationFrame(() => {
      rafId.current = 0;
      setText(buffer.current);      // 每帧最多一次更新
    });
  }, []);

  return { text, push };
}
```

> 想更粗糙可以节流到 30fps（~33ms），肉眼几乎无感，CPU 直接砍半。React 18 的 automatic batching 只合并同一 tick 的更新，**跨 macrotask 的流式回调不会被合并**，所以必须手动批。

### 2. 分块 + memo：真正消灭 $O(n^2)$ 的关键

把 Markdown 按**块级边界**切分，每块是一个独立的 memo 组件。新 chunk 通常只影响最后一块，前面的块因为 `source` 字符串不变，`React.memo` 直接跳过。

**难点**：不能用简单的 `\n\n` 切，因为会切断代码围栏和 `$$` 公式。需要一个「fence-aware」切分器：

```ts
/** 按块级边界切分，且不切断 ``` 代码围栏 与 $$ 公式块 */
export function splitBlocks(md: string): string[] {
  const lines = md.split('\n');
  const blocks: string[] = [];
  let buf: string[] = [];
  let inFence = false;
  let fenceMark = '';
  let inMath = false;

  const flush = () => {
    if (buf.length) { blocks.push(buf.join('\n')); buf = []; }
  };

  for (const line of lines) {
    const fence = line.match(/^(\s*)(`{3,}|~{3,})/);
    if (fence && !inMath) {
      const mark = fence[2][0];
      if (!inFence) { inFence = true; fenceMark = mark; }
      else if (mark === fenceMark) { inFence = false; }
    }
    // 只统计块级 $$（行内不做切换，交给行内解析）
    if (!inFence) {
      const hits = (line.match(/\$\$/g) || []).length;
      if (hits % 2 === 1) inMath = !inMath;
    }

    buf.push(line);

    const atSafeBoundary = !inFence && !inMath && line.trim() === '';
    if (atSafeBoundary) flush();
  }
  flush();
  return blocks;
}
```

渲染：

```tsx
const Block = React.memo(function Block({ source }: { source: string }) {
  return (
    <div className="md-block">
      <ReactMarkdown
        remarkPlugins={[remarkMath, remarkGfm]}
        rehypePlugins={[rehypeKatex]}
      >
        {source}
      </ReactMarkdown>
    </div>
  );
});

function StreamingMarkdown({ text }: { text: string }) {
  const blocks = useMemo(() => splitBlocks(text), [text]);
  return (
    <>
      {blocks.map((b, i) => (
        // 稳定 key：前缀块用下标（只增不改），最后一块用内容
        <Block key={i} source={b} />
      ))}
    </>
  );
}
```

**要点**：
- 下标作 key 在这里是安全的，因为块列表**只会追加**。
- `remarkPlugins` / `rehypePlugins` 数组提到组件外，否则每次 render 都是新引用，React 会当新 props。
- 最后一块（未闭合的尾巴）仍会重渲染，但代价是 $O(\text{tail})$ 而不是 $O(n)$。

### 3. KaTeX：缓存 + 拒绝渲染「半截公式」

**a) 结果缓存**（同一公式在光标移动/重渲染时复用）：

```ts
const katexCache = new LRU<string, string>(500);

function renderTex(tex: string, displayMode: boolean): string {
  const key = (displayMode ? 'D:' : 'I:') + tex;
  let html = katexCache.get(key);
  if (html == null) {
    html = katex.renderToString(tex, {
      displayMode,
      throwOnError: false,
      output: 'htmlAndMathml',
    });
    katexCache.set(key, html);
  }
  return html;
}
```

**b) 未闭合公式处理**：流式过程中 `$$ ... ` 还没结束时，不要去喂 KaTeX（会渲染出错误内容并反复重排）。检测未闭合的 `$$` / `$`，把尾部当作**纯文本**占位，等闭合后再交给公式渲染器。这也是上面 `splitBlocks` 里 `inMath` 标记的作用。

**c) KaTeX 本身可跑在 Worker**：`katex.renderToString` 是纯函数（不碰 DOM），可以在 Worker 里算好 HTML 字符串传回，主线程只负责插入。

**d) 字体预加载**，避免 FOUT 引发的重排：

```html
<link rel="preload" as="font" type="font/woff2"
      href="/katex/fonts/KaTeX_Main-Regular.woff2" crossorigin>
```

### 4. 代码高亮：延迟到围栏闭合再执行

Shiki / Prism 是全场最重的操作。策略：

- **未闭合的代码块**：只做 `<pre><code>` + 等宽字体，不高亮。
- **闭合后**：才调用高亮（最好放 Worker，或 Shiki 的 `codeToHtml` 异步版）。
- 已高亮的块用 memo 冻住。

```tsx
const CodeBlock = React.memo(function CodeBlock({ code, lang, closed }) {
  const html = useMemo(
    () => (closed ? highlightSync(code, lang) : escapeHtml(code)),
    [code, lang, closed]
  );
  return <pre dangerouslySetInnerHTML={{ __html: html }} />;
});
```

### 5. 用并发特性降优先级

让「流式文字上屏」保持高优先，Markdown 解析降级：

```tsx
function Message({ fullText }: { fullText: string }) {
  // 输入/滚动保持流畅，md 渲染在后台
  const deferred = useDeferredValue(fullText);
  const isStale = deferred !== fullText;

  return (
    <div style={{ opacity: isStale ? 0.6 : 1 }}>
      <StreamingMarkdown text={deferred} />
    </div>
  );
}
```

也可以把块渲染包在 `startTransition` 里：

```ts
startTransition(() => setText(next));
```

### 6. 虚拟化 + CSS containment

即使做了 memo，**DOM 总量**仍然是 $O(n)$，长对话一多就会整体变卡。

```css
.md-block {
  content-visibility: auto;                    /* 离屏跳过渲染 */
  contain-intrinsic-size: auto 400px;          /* 占位，防滚动条跳动 */
  contain: content;                            /* 限制 layout/paint 范围 */
}
```

整条消息级别再上虚拟列表（`react-virtuoso` 的 `VirtuosoMessageList`、`react-window`），只挂载视口附近的若干条消息。

---

### 7. Worker 卸载解析（进阶）

把 `micromark → mdast → hast`（含 `rehype-katex`、高亮）整条管线放进 Worker，主线程只收 HTML/AST 并挂载。

- 注意：`react-markdown` 依赖 React 运行时，**不能**直接在 Worker 里用；需在 Worker 产出 `hast`/HTML，主线程用 `hast-util-to-jsx-runtime` 或直接挂 HTML。
- 用 `@lezer/markdown` 这类**增量语法树**可以进一步做到「只重解析变化的部分」。

<details>
<summary><b>四、常见坑（踩了白优化）</b></summary>

1. **`dangerouslySetInnerHTML` 全量替换**：用 `marked + katex` 拼 HTML 再整段塞进去，等于每次都重建整棵树 + 全页 reflow。要么分块，要么改用组件渲染。
2. **插件数组/回调每次新建**：`remarkPlugins={[remarkMath]}` 写在 JSX 里 → 每帧新引用 → memo 失效。
3. **把流式文本放进 Context / 顶层 state**：导致整个消息列表全部重渲染。应把 state 关在单条消息组件内。
4. **对每帧文本做 `JSON.stringify`/深比较**：本身就成了瓶颈。
5. **scroll 跟随用 `scrollIntoView` 每帧调用**：强制同步布局，改用 `scrollTop = scrollHeight` 或 `scrollTo({ behavior:'auto' })` 并节流。
6. **动画给了整棵树**：光标闪烁等动画只放在叶子节点，别触发父级 repaint。

</details>

<details>
<summary><b>五、推荐组合 & 度量</b></summary>

**推荐落地顺序（ROI 从高到低）：**

```
rAF 批处理  →  分块 + memo  →  公式缓存/半截处理  →  useDeferredValue
→  高亮延迟  →  content-visibility  →  （必要时）Worker / 虚拟化
```

**度量方法：**

- Chrome Performance 面板看 **Long Tasks（>50ms）**，定位是 parse 还是 layout。
- React DevTools Profiler 开 **Highlight updates**，卡顿时满屏闪 = memo 失效。
- 打点：

```ts
const t = performance.now();
// ...render
performance.mark('md'); performance.measure('md', ...);
```

- 关注 **Layout / Recalculate Style** 与 **Parse HTML** 在火焰图中的占比，这两处通常就是 KaTeX 与 innerHTML 的锅。

</details>

如果只做一件事：**实现 fence-aware 分块 + 每块 `React.memo`**，多数场景的卡顿会直接消失；再叠加 **rAF 批处理**与 **KaTeX 缓存**，基本可以做到长文（几万字含大量公式）流畅输出。
