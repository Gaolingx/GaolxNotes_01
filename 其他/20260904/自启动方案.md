# Windows 实现开机自启动的几种方式

Linux 的 `systemd` 本质是一个**服务管理器 + 依赖编排 + 日志系统**。Windows 上没有完全对等的单一组件，但有多个机制可以组合出类似效果。按“最接近 systemd 服务”到“最轻量”排序：

## 1. Windows 服务 (Service) —— 最接近 systemd service

这是最标准的“后台常驻服务”方案，开机即启动、无需用户登录、可设置失败自动重启。

```powershell
# 用 sc 创建服务（需管理员权限）
sc.exe create MyService binPath= "C:\app\myapp.exe" start= auto
sc.exe start MyService
```

```powershell
# PowerShell 原生方式
New-Service -Name "MyService" -BinaryPathName "C:\app\myapp.exe" -StartupType Automatic
```

关键参数对照 systemd：

| systemd | Windows 服务 |
|---|---|
| `WantedBy=multi-user.target` | `start= auto`（Automatic） |
| `Restart=always` | 服务恢复策略（Failure actions） |
| `systemctl enable` | `sc config ... start= auto` |
| `systemctl start` | `sc start` |
| `journalctl -u` | 事件查看器 / `Get-WinEvent` |

设置自动重启（对应 `Restart=always`）：

```powershell
sc.exe failure MyService reset= 86400 actions= restart/5000/restart/5000/restart/5000
```

> 注意：服务进程必须响应 SCM 的 Service Control 消息。如果是普通控制台程序，需要用 [NSSM](https://nssm.cc/)、[WinSW](https://github.com/winsw/winsw) 或 `sc.exe` 包装成服务。

**用 WinSW 把任意 exe 包成服务（最推荐的懒人方案）：**

```xml
<!-- myapp.xml -->
<service>
  <id>myapp</id>
  <name>My App</name>
  <executable>C:\app\myapp.exe</executable>
  <startmode>Automatic</startmode>
  <onfailure action="restart" delay="5 sec"/>
  <logpath>C:\app\logs</logpath>
</service>
```

```powershell
winsw.exe install myapp.xml
winsw.exe start myapp.xml
```

## 2. 任务计划程序 (Task Scheduler) —— 最灵活，可对标 timer + oneshot

可以用“开机时”或“用户登录时”作为触发器，还能设置延迟、重复、依赖条件。

```powershell
$action  = New-ScheduledTaskAction -Execute "C:\app\myapp.exe"
$trigger = New-ScheduledTaskTrigger -AtStartup      # 开机（无需登录）
# 或 -AtLogOn 登录时触发
$settings = New-ScheduledTaskSettingsSet -RestartCount 3 -RestartInterval (New-TimeSpan -Minutes 1)
Register-ScheduledTask -TaskName "MyTask" -Action $action -Trigger $trigger `
  -Settings $settings -User "SYSTEM" -RunLevel Highest
```

命令行也可以用 `schtasks`：

```cmd
schtasks /create /tn "MyTask" /tr "C:\app\myapp.exe" /sc onstart /ru SYSTEM
```

- `-AtStartup` + 以 `SYSTEM` 运行 ≈ systemd 的系统级服务
- `-AtLogOn` ≈ systemd user service
- 触发器可加 `-RandomDelay` / 延迟，对标 systemd `ExecStartPre=sleep`

## 3. 注册表 Run 键 —— 最轻量（对标 ~/.config/autostart）

仅当前用户，**登录后**才执行：

```powershell
Set-ItemProperty -Path "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" `
  -Name "MyApp" -Value "C:\app\myapp.exe"
```

机器级（所有用户，需管理员）：

```powershell
Set-ItemProperty -Path "HKLM:\Software\Microsoft\Windows\CurrentVersion\Run" ...
```

启动文件夹图形化等价物：

```
C:\Users\<user>\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup
```

## 4. 启动文件夹 / Winlogon Shell

- **启动文件夹**：最直观，等价于桌面环境的 autostart。
- **`Winlogon\Userinit`**、**`Image File Execution Options`** 等属于较底层的持久化位置（也常被恶意软件利用，慎用）。

## 各方案对比

| 方案 | 需登录? | 权限 | 自动重启 | 适合场景 |
|---|---|---|---|---|
| Windows 服务 | 否 | 管理员 | ✅ | 后台常驻守护进程（最像 systemd） |
| 任务计划程序 | 可选 | 可 SYSTEM | ✅（设置） | 定时/开机脚本、复杂触发条件 |
| 注册表 Run | 是 | 用户 | ❌ | 用户级自启小程序 |
| 启动文件夹 | 是 | 用户 | ❌ | 简单 GUI 自启 |

## 有没有真正“像 systemd”的一体化工具？

Windows 没有官方对标品，但可考虑：

- **NSSM / WinSW** —— 把普通程序变成带重启策略的服务。
- **Supervisor 类工具**（如通过 MSYS2/Cygwin 跑）—— 不推荐，管理混乱。
- **WSL2 内的 systemd** —— 如果你只是想要 systemd 语义，可以在 WSL2 里启用 systemd（`/etc/wsl.conf` 中 `[boot] systemd=true`），再用 Windows 任务计划开机拉起 `wsl.exe`。
- **PowerShell DSC / Ansible** —— 对标声明式配置管理（而非运行时服务管理）。

## 小结

- 想要**系统服务语义**（开机、免登录、自动重启）→ 用 **Windows 服务**，配合 **WinSW/NSSM** 包装普通程序。
- 想要**定时/复杂触发** → 用 **任务计划程序**。
- 想要**用户登录自启** → **注册表 Run** 或 **启动文件夹**。

# frpc 用 `sc` 做开机自启的正确姿势

先说结论：**不能直接把 `sc create` 指向 `frpc.exe`。** `frpc` 是普通控制台程序，不会调用 `StartServiceCtrlDispatcher` 与 SCM（服务控制管理器）通信，所以这样注册后启动会报：

```
错误 1053：服务没有及时响应启动或控制请求。
```

想用 `sc`，必须配一个**服务包装器**（会替 frpc 响应 SCM）。下面给出几种可用方案。

## 方案 A：NSSM（最省事，推荐）

NSSM 自带服务安装，无需手写 sc：

```powershell
nssm install frpc "C:\frp\frpc.exe" -c "C:\frp\frpc.toml"

# 工作目录（重要：相对路径配置/log 依赖它）
nssm set frpc AppDirectory "C:\frp"

# 开机自启
nssm set frpc Start SERVICE_AUTO_START

# 崩溃自动重启（对标 systemd Restart=always）
nssm set frpc AppExit Default Restart
nssm set frpc AppRestartDelay 5000

# 日志
nssm set frpc AppStdout "C:\frp\logs\frpc.log"
nssm set frpc AppStderr "C:\frp\logs\frpc.err.log"
nssm set frpc AppRotateFiles 1
nssm set frpc AppRotateBytes 1048576

nssm start frpc
```

卸载：`nssm stop frpc && nssm remove frpc confirm`

## 方案 B：WinSW 包装器 + `sc`（最贴近你问的“sc 命令”）

WinSW 是一个自带 SCM 逻辑的包装 exe。你可以让服务直接指向 WinSW。

**1. 准备 `frpc.xml`（与 `winsw.exe` 放同目录，且改名对齐）：**

```xml
<service>
  <id>frpc</id>
  <name>frp client</name>
  <description>frp 内网穿透客户端</description>
  <executable>C:\frp\frpc.exe</executable>
  <arguments>-c "C:\frp\frpc.toml"</arguments>
  <workingdirectory>C:\frp</workingdirectory>
  <startmode>Automatic</startmode>
  <onfailure action="restart" delay="5 sec"/>
  <logpath>C:\frp\logs</logpath>
  <log mode="roll-by-size">
    <sizeThreshold>1048576</sizeThreshold>
    <keepFiles>4</keepFiles>
  </log>
</service>
```

把 `WinSW-x64.exe` 重命名为 `frpc.exe` 与 `frpc.xml` 放在同目录（WinSW 靠 exe 同名 xml 识别配置）。

**2. 安装并启动（WinSW 自己会调 SCM，等价于 sc create）：**

```powershell
C:\frp\frpc.exe install
C:\frp\frpc.exe start
```

**3. 如果你想看到等价的 sc 结果，WinSW install 后执行的实际上就是：**

```powershell
sc.exe create frpc binPath= "C:\frp\frpc.exe" start= auto DisplayName= "frp client"
sc.exe description frpc "frp 内网穿透客户端"
sc.exe failure frpc reset= 86400 actions= restart/5000/restart/5000/restart/5000
sc.exe start frpc
```

> 这里的 `C:\frp\frpc.exe` 是 **WinSW 包装器**，不是真正的 frp 客户端，别搞混。

## 方案 C：`srvany` + `sc`（老式做法，不推荐但确实纯 sc）

Windows 2003 Resource Kit 的 `srvany.exe` 能把任意程序挂成服务。

```powershell
# 1) 用 srvany 注册服务
sc.exe create frpc binPath= "C:\frp\srvany.exe" start= auto DisplayName= "frp client"

# 2) 告诉 srvany 该拉起谁（改注册表）
$p = "HKLM:\SYSTEM\CurrentControlSet\Services\frpc\Parameters"
New-Item -Path $p -Force | Out-Null
Set-ItemProperty $p -Name Application   -Value "C:\frp\frpc.exe"
Set-ItemProperty $p -Name AppParameters -Value '-c "C:\frp\frpc.toml"'
Set-ItemProperty $p -Name AppDirectory  -Value "C:\frp"

# 3) 启动
sc.exe start frpc
```

卸载：

```powershell
sc.exe stop frpc
sc.exe delete frpc
```

`srvany` 已很老（不支持优雅停止、日志弱），仅作了解。

## 方案 D：不用 sc，直接任务计划程序（对 frpc 其实最合适）

frpc 是单进程长连接程序，用计划程序反而更简单、免第三方工具：

```powershell
$action  = New-ScheduledTaskAction -Execute "C:\frp\frpc.exe" `
             -Argument '-c "C:\frp\frpc.toml"' -WorkingDirectory "C:\frp"
$trigger = New-ScheduledTaskTrigger -AtStartup
$settings = New-ScheduledTaskSettingsSet -RestartCount 999 `
             -RestartInterval (New-TimeSpan -Minutes 1) -ExecutionTimeLimit 0
$principal = New-ScheduledTaskPrincipal -UserId "SYSTEM" -RunLevel Highest

Register-ScheduledTask -TaskName "frpc" -Action $action -Trigger $trigger `
  -Settings $settings -Principal $principal
```

或命令行：

```cmd
schtasks /create /tn frpc /tr "C:\frp\frpc.exe -c C:\frp\frpc.toml" /sc onstart /ru SYSTEM /rl highest /f
```

## 常见坑

| 问题 | 原因 | 处理 |
|---|---|---|
| 错误 1053 | 直接 sc 指向 frpc.exe | 用 NSSM / WinSW / srvany 包装 |
| 服务起来了但连不上 | 工作目录不对，找不到配置或证书 | 设置 `AppDirectory` / `workingdirectory` |
| 路径带空格 | `binPath=` 引号问题 | sc 里写 `binPath= "\"C:\my frp\frpc.exe\" ..."` |
| 想改配置要重启服务 | 正常 | 改完 `sc stop frpc && sc start frpc` |
| 想开机立刻起 | `start= auto` 默认有延迟 | 用 `start= auto` + `SERVICE_DELAYED_AUTO_START` 或计划程序 `-AtStartup` |

## 一句话选择建议

- **想少折腾** → `nssm install frpc`。
- **必须是 sc 命令** → 用 **WinSW** 包装后 `install/start`（底层就是 sc create）。
- **不想装第三方** → 用 **计划任务** `-AtStartup /ru SYSTEM`。
