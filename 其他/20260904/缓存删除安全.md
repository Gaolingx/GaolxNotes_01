# 缓存删除安全

## 🧑‍💻 User

linux ~/.cache下的文件可用直接删吗

---
## 🤖 Assistant

**可以直接删，但建议"删内容、留目录"，并且最好在相关程序没运行时删。**

`~/.cache`（或 `$XDG_CACHE_HOME`）按 XDG 规范就是用来放**可再生的缓存数据**的：缩略图、浏览器缓存、包管理器下载的 tarball、编译/着色器缓存等。程序发现缓存没了会自己重建，所以清空它通常是安全的。

## 核心结论

- ✅ 删掉里面的**文件/子目录** → 安全
- ✅ 删掉 `~/.cache` 目录本身 → 一般也行，但**记得用正确权限重建**
- ⚠️ 少数程序把不该放的东西（登录 token、应用状态）塞进缓存 → 可能被登出或丢状态
- ❌ 不要用 `rm -rf ~/.cache/*` 时忘了点号/路径写错（经典事故来源）

## 推荐做法

先看清楚各目录占用：

```bash
du -sh ~/.cache/* 2>/dev/null | sort -h
```

清空内容（保留目录本身，最稳妥）：

```bash
rm -rf ~/.cache/*
```

注意 `*` **不匹配隐藏文件**，要连隐藏项一起清：

```bash
find ~/.cache -mindepth 1 -maxdepth 1 -exec rm -rf -- {} +
```

如果连目录也想重建：

```bash
rm -rf ~/.cache && mkdir -m 700 ~/.cache
```

<details>
<summary><b>常见子目录说明（哪些删了完全无感）</b></summary>

| 路径 | 内容 | 删了会怎样 |
|------|------|-----------|
| `~/.cache/thumbnails` | 文件管理器缩略图 | 重新生成，无感 |
| `~/.cache/pip`、`~/.cache/uv` | Python 包下载缓存 | 下次装包重新下载 |
| `~/.cache/npm`、`~/.cache/yarn` | JS 包缓存 | 重新下载 |
| `~/.cache/mozilla`、`~/.cache/google-chrome` | 浏览器缓存 | 只是缓存，书签/密码在别处 |
| `~/.cache/fontconfig` | 字体缓存 | 重建，稍慢一下 |
| `~/.cache/JetBrains`、编辑器索引 | 索引缓存 | 首次打开项目重新索引 |
| `~/.cache/…/shader`、游戏着色器 | 着色器缓存 | 重进游戏时重建 |

</details>

<details>
<summary><b>需要注意的坑</b></summary>

1. **有些程序滥用缓存目录**
个别 Electron 应用、CLI 工具会把 OAuth token、会话状态写到 `~/.cache`。删了可能导致重新登录、设置丢失。删前不认识就先只删明确是缓存的大目录。

2. **程序运行中删除**
通常不会崩，但可能导致该程序写出不一致状态，或缓存马上又长回来。建议先退出相关程序（尤其浏览器、IDE）。

3. **权限问题**
别习惯性加 `sudo` 去删用户自己的 `~/.cache`，可能残留 root 属主文件。除非确认就是要清理 root 的缓存。

4. **`~/.cache` 是符号链接或挂载点**
比如指向 tmpfs。删除前先确认，避免误删到别处：
```bash
readlink -f ~/.cache
findmnt -T ~/.cache
```

5. **不可替代数据**
极少数程序（某些设计糟糕的工具）把唯一数据放这里。**不确定就先备份**，或只删除你认得的那几个大目录。

</details>

## 一句话总结

> 缓存本来就是"丢了能重建"的东西，清 `~/.cache` 基本等于给程序来个"记忆重置"。删之前先 `du -sh` 看一眼，退出相关程序，删内容别乱删路径，就能安心回收空间。
