# Linux 查看磁盘读写速率与平均响应时间

核心工具是 **`iostat`**（来自 `sysstat` 包），先用包管理器安装：

```bash
# RHEL/CentOS
yum install -y sysstat
# Debian/Ubuntu
apt install -y sysstat
```

## 一、最常用：`iostat -x`

```bash
iostat -x 1 5          # 每 1 秒刷新，共 5 次
iostat -dxm 1          # -d 只看设备，-m 以 MB 为单位
```

关键列含义：

| 列 | 含义 |
|----|------|
| `r/s`、`w/s` | 每秒读、写请求次数（IOPS） |
| `rkB/s`、`wkB/s` | 每秒读、写数据量（**读写速率**） |
| `r_await`、`w_await` | 读/写请求的**平均响应时间**（ms） |
| `await` | 所有请求的平均响应时间（含排队时间，ms） |
| `aqu-sz`（旧版 `avgqu-sz`） | 平均等待队列长度 |
| `%util` | 设备忙碌百分比（接近 100% 说明已饱和） |

> **关于“平均响应时间”**：
> - `await` = 从请求进入队列到完成的总时间（排队 + 处理）。
> - 若 `await` 远大于 `svctm`（旧版字段）/设备处理能力，说明存在排队。
> - 一般经验：机械盘 `await > 20ms`、SSD `await > 3~5ms` 就需关注。

## 二、历史与采样：`sar -d`

```bash
sar -d 1 3             # 实时采样
sar -d -f /var/log/sa/sa20   # 查看历史某天
```

输出含 `await`、`r_await`、`w_await`、`%util` 等，适合回溯分析。

## 三、原始数据：`/proc/diskstats`

`iostat`、`sar` 底层都读取这个文件。字段较多，可用脚本按需计算：

```bash
cat /proc/diskstats
# 字段依次大致为：
# major minor name reads_completed reads_merged sectors_read ms_reading \
# writes_completed writes_merged sectors_written ms_writing io_in_progress ms_io time_io
```

计算平均响应时间示例（两次采样差值）：

```bash
awk '{print $1,$2,$3,$4,$8,$12,$13}' /proc/diskstats
# $4=读完成次数 $8=读耗时(ms) → 读平均响应 = $8/$4
# $8... 注意按实际字段核对
```

## 四、按进程查看：`iotop` / `pidstat`

<details>
<summary>展开查看进程级工具</summary>

```bash
iotop -oPa            # 只显示真正有 I/O 的进程，累计模式
pidstat -d 1          # 按进程统计读写速率
```

- `iotop` 显示每个进程的 **磁盘读/写速率**，适合定位“谁在狂写盘”。
- `pidstat -d` 列出进程级 `kB_rd/s`、`kB_wr/s` 与 `iodelay`。
</details>

## 五、实时综合监控：`dstat` / `nmon`

<details>
<summary>展开查看综合工具</summary>

```bash
dstat -d --disk-util --disk-tps   # 读写量、util、TPS
dstat -D sda -d -t                # 指定磁盘
nmon                              # 交互式，按 d 看磁盘
```
</details>

## 六、一句话速查

| 想看什么 | 命令 |
|---------|------|
| 读写速率 + 响应时间 | `iostat -dxm 1` |
| 历史数据 | `sar -d` |
| 哪个进程在读写 | `iotop -oPa` 或 `pidstat -d 1` |
| 原始计数 | `cat /proc/diskstats` |

**判读要点**：重点看 `%util`（是否饱和）、`await`（是否变慢）、`aqu-sz`（是否排队）。三者同时飙升，基本可判定磁盘 I/O 瓶颈。
