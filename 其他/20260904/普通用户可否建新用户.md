# 普通用户能否用 `sudo` 新建用户？

**结论：取决于该普通用户是否被授予了 `sudo` 权限，而不是取决于"普通用户"这个身份本身。**

---

## 核心机制

`sudo` 的授权规则由 `/etc/sudoers`（及 `/etc/sudoers.d/` 下的文件）决定。判断流程如下：

| 情况 | 能否用 `sudo useradd` |
|------|----------------------|
| 用户**不在** sudoers 中 | ❌ 不能。会提示 `xxx is not in the sudoers file` |
| 用户在 sudoers 中 | ✅ 可以（前提是命令规则允许） |
| 用户被授予 `ALL=(ALL) ALL`（典型管理员） | ✅ 可以执行任意命令，包括建用户 |
| 用户被授予**受限命令白名单** | ⚠️ 只有当 `useradd`/`adduser` 在白名单里才行 |

> 简单说：**"普通用户"能不能越权，看的不是身份标签，而是它在 sudoers 里的授权。**

---

## 常见场景举例

**1. Ubuntu 桌面版普通用户**

初次安装时创建的用户默认在 `sudo` 组里：

```bash
groups alice
# alice : alice sudo
```

因此这类"普通用户"是可以 `sudo` 建用户的：

```bash
sudo adduser bob
# 或者更底层
sudo useradd -m -s /bin/bash bob
```

**2. 被刻意限制的用户**

```bash
# /etc/sudoers.d/limited
limited_user ALL=(ALL) /usr/bin/apt update, /usr/bin/systemctl restart nginx
```

这个用户只能跑白名单命令，执行 `sudo useradd` 会被拒绝。

**3. 完全无 sudo 权限的用户**

```bash
sudo useradd bob
# alice is not in the sudoers file. This incident will be reported.
```

---

## 如何查看自己是否有权限

```bash
# 列出当前用户可执行的 sudo 命令
sudo -l
```

输出示例：

```
User alice may run the following commands on host:
    (ALL : ALL) ALL
```

如果这里出现 `ALL` 或 `useradd`/`adduser`，说明可以建用户；若命令被列为需密码的特定项，则按规则执行。

---

## 补充要点

- **`sudo` 组 ≠ sudoers 文件里写了组**。很多发行版（如 Ubuntu）在 `/etc/sudoers` 中预置了 `%sudo ALL=(ALL:ALL) ALL`，把用户加进 `sudo` 组即可获得权限。
- 建用户后若要设密码，还需 `sudo passwd bob`（同样受 sudoers 限制）。
- 即使有 sudo 权限，**审计日志**仍会记录该操作（`/var/log/auth.log` 或 `journalctl`），"This incident will be reported" 并非虚言。
- 想授权但不给全权，可用 `visudo` 精确添加：
```bash
# 允许 alice 仅创建用户
alice ALL=(root) /usr/sbin/useradd, /usr/sbin/adduser
```

---

**一句话总结：** 普通用户本身不能建用户；但一旦它被管理员写进 sudoers（或加入 `sudo`/`wheel` 组并配有相应规则），它就获得了"像 root 一样"建用户的能力。授权范围完全由 `/etc/sudoers` 说了算。
