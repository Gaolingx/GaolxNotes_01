# 抢占实例比预留便宜 代价是什么

## 🧑‍💻 User

preemption实例为什么比reserve便宜点，代价是什么？

---
## 😀 默认助手 (7)

这个问题要先把两者的**本质**分清楚，因为它们省钱的逻辑根本不是一回事。

## 一句话结论

**Reserve（预留/包年包月）省的是"你用承诺换折扣"；Preemptible/Spot（抢占式）省的是"你用不确定性换折扣"。** 后者便宜，是因为云厂商把**本来会闲置的库存**按边际成本甩卖，而代价是**随时可能被收回**。

## 为什么抢占式更便宜

| 维度 | Reserve（RI / 承诺折扣） | Preemptible / Spot |
|---|---|---|
| 资源性质 | **保证有货**的专属容量 | 厂商的**空闲/剩余产能** |
| 定价逻辑 | 你承诺 1–3 年，换 on-demand 的 30–70% 折扣 | 边际成本接近 0 的库存，直接甩卖，折扣可达 60–90% 甚至更高 |
| 可用性保证 | 有 SLA，容量锁定 | **无 SLA**，需求上来就被回收 |
| 生命周期 | 长期可用 | GCP 最长 24h；AWS Spot 无固定上限但会被中断 |
| 中断/回收 | 不会 | 会被"抢占"，AWS 提前 2 分钟通知，GCP 30 秒 |
| 适合负载 | 稳定的常态业务、生产核心 | 可续跑、可重试的任务 |

核心原因：**预留卖的是"确定性"，抢占卖的是"剩余库存"。** 前者你为"随时能拿到、且长期有"付溢价；后者厂商反正闲着也闲着，卖掉就是纯增量收入，所以愿意用极低价出清。价格里因此几乎不含"可用性溢价"。

## 代价是什么（这才是重点）

省下来的钱，本质是拿下面这些去换的：

1. **随时被中断**
   - 负载必须是**可中断、可重启、可幂等**的。跑一半被 kill，未 checkpoint 的计算全白费——这部分"返工成本"要算进去。

2. **没有 SLA / 容量不保证**
   - 高峰期可能**申请不到**实例（尤其单机型），价格也可能飙升（AWS Spot 市场价会波动，虽然现在封顶在 on-demand 价）。
   - 出故障厂商不赔。

3. **有使用限制**
   - 通常**不能挂到需要高可用的托管服务**上（如 GCP 抢占式不能用于某些 GKE 场景、不能自动重启/热迁移）。
   - 机型、配额受限；GCP 抢占式**最长 24 小时后强制重启**。

4. **架构复杂度上升**
   - 你得自己做：多机型/多可用区**打散**、Spot Fleet / 自动补货、检查点（checkpoint）、重试队列、优雅退出处理。
   - 这套工程成本，往往才是真正的隐性代价。

5. **不适合的负载**
   - 数据库主节点、长事务、有状态且难恢复的服务、对延迟/连续运行敏感的任务——硬上抢占式，省的钱可能还不够赔故障。

## 怎么选

- **稳定、7×24、核心生产** → 用 Reserve 打底（省得稳、无风险）。
- **批处理、可重跑、渲染、CI、大数据离线任务** → 用 Preemptible/Spot（做好容错后性价比最高）。
- **最佳实践**：**混合**——用预留覆盖基线负载，用抢占式扛峰值和弹性部分，兼顾成本与稳定。

> 补一句：AWS 的 Savings Plans、GCP 的 Committed Use Discounts 属于 Reserve 类；AWS Spot、GCP Preemptible/Spot VM 属于抢占类。别把"Spot 比"预留"便宜"当成同一产品线的不同档位——它们卖的是两种完全不同的东西。
