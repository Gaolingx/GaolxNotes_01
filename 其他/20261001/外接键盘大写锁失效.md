# macOS 12 外接键盘 Caps Lock 没反应 — 排查思路

Caps Lock 失灵通常不是键盘坏了，而是**输入法占用**或**修饰键映射**被改掉了。按下面顺序走，多数人第 1、2 步就能解决。

## 第一步：先判断"信号是否到达 macOS"

打开 **键盘显示程序**：`系统偏好设置 → 键盘 → 输入法 → 勾选"在菜单栏中显示输入法菜单"`，然后点菜单栏输入法图标 → **显示键盘显示程序**。

按下 Caps Lock 观察虚拟键盘上的 `⇪`：

| 现象 | 结论 | 去看 |
|---|---|---|
| `⇪` 会高亮/亮起 | 键盘信号正常，是 macOS 层面被改写或占用 | 第 2、3、4 节 |
| `⇪` 完全无反应 | 键盘根本没发出该键，固件/连接问题 | 第 5 节 |

> 也可以装 **Karabiner-EventViewer**（免费，Karabiner 自带），它能直接显示收到的按键事件，比虚拟键盘更可靠。
>
> ⚠️ 不要只看键盘上的 Caps Lock LED 灯——不少外接键盘在 Mac 下 LED 本来就不亮，灯不亮 ≠ 键没用。

## 第二步：输入法占用了 Caps Lock（中文用户命中率最高）

如果你装了中文/日文等输入法，macOS 会把 Caps Lock 变成"中英切换键"，此时它**不会**触发大写锁定，看起来就像失灵。

- 关闭：`系统偏好设置 → 键盘 → 输入法`，取消勾选 **"使用大写锁定键切换'ABC'输入法"**（英文版：*Use the Caps Lock key to switch to and from ABC*）。
- 想保留中英切换又想要大写：改用 `Control + 空格` 切换输入法，在 `键盘 → 快捷键 → 输入法` 里设置。

## 第三步：修饰键映射（外接键盘要单独设一次）

这里最容易踩坑：设置是**按键盘分别保存**的，很多人只改了内置键盘那一项。

`系统偏好设置 → 键盘 → 快捷键 → 右下角"修饰键…"`

- 顶部下拉菜单里**选中你的外接键盘**（不是"内置键盘"）；
- 确认 **Caps Lock 键** 设为 `⇪ 大写锁定`，**不要**是"无操作 / No Action"；
- 改完点"好"，然后拔插一次键盘。

## 第四步：第三方改键软件

按常见程度排序：**Karabiner-Elements** > BetterTouchTool > Keyboard Maestro > Hammerspoon > Logi Options+ / 厂商驱动。

- Karabiner：检查 `Simple Modifications` 里是否把 `caps_lock` 改成了 `escape` / `control`；`Devices` 里该键盘是否启用；`Complex Modifications` 的规则；配置文件在 `~/.config/karabiner/`。
- 最快验证：**完全退出（或卸载）这些软件后重启**再测。Karabiner 还装了系统扩展，要在 `安全性与隐私 → 隐私 → 辅助功能` 里看是否残留。

## 第五步：键盘本身与连接

<details>
<summary>按键盘类型逐项检查（点开）</summary>

**所有键盘**
- 键盘上的 **Mac / Windows(PC) 模式开关**：切到 Mac。
- 换一台电脑（另一台 Mac 或 Windows）测试该键盘：
  - 那边也不行 → 键盘硬件/固件问题；
  - 那边正常 → 回到 macOS 层面继续查。
- 很多机械键盘（Keychron、客制化等）的改键存在**键盘固件里**（VIA/QMK）。可能之前把 Caps Lock 换成了 Ctrl 或 Escape。用 VIA 恢复默认，或按住 `Esc` 插线进入恢复模式重刷（因键盘而异）。
- 廉价/游戏键盘可能需要在厂商软件里重新绑定 Caps Lock。

**有线**
- 直插机身 USB 口，**不要**经过无源 Hub、KVM 或扩展坞。
- 换一根数据线（有些线只供电不传数据）。

**蓝牙**
- 删除设备后重新配对；换电池/充满电；靠近 Mac；
- 远离 USB 3.0 设备和 2.4G 接收器（干扰）。

</details>

## 第六步：系统层面修复

<details>
<summary>前面都没解决时（点开）</summary>

1. **不要只看灯**：macOS 对 Caps Lock 有约 100–200ms 的防误触判定，**短按一下、稍等一下**再输入文字看是否变大写。某些键盘发送的按键时长短，会被 macOS 丢弃（Karabiner 有专门的 caps lock delay 补丁）。
2. **键盘类型识别**：如果不止 Caps Lock 有问题（比如按键错乱），运行 `系统偏好设置 → 键盘 → 键盘 → 更改键盘类型…`，按提示重新识别（区分 ANSI / ISO / JIS）。识别时按错键会导致整张键盘被错误映射。
3. **安全模式启动**测试（Intel：开机按住 `Shift`；Apple Silicon：长按电源键进入启动选项后按住 `Shift`），可排除第三方驱动/扩展。
4. **重置**：
   - Intel 机型：重置 NVRAM（开机按 `Option+Command+P+R`）和 SMC；
   - Apple Silicon：关机等 30 秒再开机即可。
5. **检查是否有自定义 HID 映射**，终端执行：
   ```bash
   hidutil property --get "UserKeyMapping"
   ```
   非空且包含 Caps Lock 相关项，就是你（或某个软件）改过，可清除：
   ```bash
   hidutil property --set '{"UserKeyMapping":[]}'
   ```
6. 检查 `辅助功能 → 键盘` 里的"粘滞键 / 慢速键"是否被意外开启。
7. 确认键盘已被系统识别：
   ```bash
   system_profiler SPUSBDataType | grep -i -A 3 keyboard
   system_profiler SPBluetoothDataType | grep -i -A 3 keyboard
   ```

</details>

## 😀 默认助手 (7)

问题拆成两个完全独立的事情来看——一个来自 macOS 的设计，一个来自键盘硬件本身。

## 问题 1：必须长按 Caps Lock 才生效

这是 **macOS 对 Caps Lock 特有的"防误触延迟"**：短于某个时长（约 0.1 秒量级）的轻点会被系统直接丢弃，只有按住一会儿才判定为"真的想切换大写"。

- 系统没有开关可以调，`修饰键`里也没有。
- Karabiner 这类改键工具也管不到它——延迟发生的层级比按键映射更靠底层。
- 反过来：**只要这个键在 macOS 眼里还是 `caps_lock`，延迟就一直在。**

### 先花 30 秒排除干扰项

| 检查 | 位置 / 做法 |
|---|---|
| 慢速键（会让所有键都需长按） | `辅助功能 → 键盘 → 慢速键`，确认关闭 |
| 粘滞键、按住延迟 | `辅助功能 → 键盘` 里一并对一遍 |
| 蓝牙/固件去抖 | 改用**有线**接一次，如果延迟明显变小 → 是键盘固件或蓝牙延迟，不是 macOS |
| 键盘的 Mac/PC 开关 | 有开关就切到 **Mac** 模式（有些键盘在 Mac 模式下自行接管这个键，体感会好很多） |

### 彻底去掉延迟的几种办法

| 方案 | 效果 | 代价 |
|---|---|---|
| **不把 Caps Lock 当 Caps Lock 用**（改成 `Control` / `Escape`，用 Karabiner 或 `修饰键`） | 延迟**立刻消失** | 失去大写锁定功能 |
| 用键盘固件（VIA / QMK）把 Caps Lock 改成别的键 | 同上，且不依赖任何 Mac 软件 | 同上 |
| macOS 下重新定义大写锁定的触发方式 | 延迟仍在（还是 `caps_lock` 用法码） | — |
| 第三方去延迟工具（GitHub 上搜 `caps lock delay fix macOS`，靠注入 dylib 修改 IOHIDSystem 行为） | 能去掉延迟 | 通常要**关闭 SIP**、随系统升级失效、macOS 12 上不一定还能用，有稳定性风险 |
| 干脆接受它 | — | 需要养成"按住一下"的习惯 |

> 如果你其实很少用大写锁定，**把 Caps Lock 映射成 `Control` 或 `Escape` 是收益最高的一步**：延迟没了，还白得一个顺手的修饰键。大写临时用 `Shift` 打就行。

## 问题 2：外接键盘的灯不跟内置的同步

首先纠正一个前提：**macOS 并不"同步"两把键盘的灯**，它只是向每把键盘分别发送标准的 HID LED 输出报告（Caps Lock LED 那一位）。内置键盘的灯亮，是因为 Apple 自己的固件配合；外接键盘亮不亮，取决于**该键盘的固件是否接受、是否遵循**这个报告。

所以"不同步"其实是"外接键盘那一侧没点亮"。

### 先分清是灯的问题还是键的问题

在内置键盘和外接键盘上分别按 Caps Lock，然后在文本里敲字母：

- **字母确实变大写、只是灯不亮** → 纯 LED 报告问题，功能没坏。
- **灯不亮且字母也不变大写** → 回到问题 1（延迟/映射），不是灯的事。

### 外接键盘 LED 不亮的 4 个常见原因

<details>
<summary>展开：原因与对策</summary>

**① 键盘处于 Windows 模式 / 固件接管了 LED 逻辑**
切到 Mac 模式（很多键盘有 DIP 开关或 `Fn + 某键` 组合）。部分键盘在 PC 模式下自己点灯，在 Mac 模式下才跟随主机报告。

**② 键盘忽略主机的 LED 报告，需要厂商软件**
Logitech 系（Logi Options+）、雷蛇、Keychron（VIA/Launchpad）、罗技 G 系（G HUB）等，装官方软件后指示灯行为经常就正常了。若是 QMK 键盘，固件里指示灯默认跟随主机报告，可检查 `led_update_*` / `host_keyboard_led_state()` 的实现。

**③ 用了 Karabiner 等虚拟键盘设备**
这是**已知副作用**：按键被 Karabiner 的虚拟设备接管后，macOS 的 LED 输出报告可能发给了虚拟设备，物理键盘收不到，灯就永远不亮。如果介意灯，就不要用 Karabiner 改 Caps Lock。

**④ 蓝牙连接的偶发问题 / 键盘就没打算让你看**
蓝牙键盘删除设备后重新配对试试（LED 报告与连接状态有关）；顺带一提，不少外接键盘的 Caps Lock 灯在本机就是不定亮，别只凭灯判断。

</details>

### 一条最有用的验证

**把这把外接键盘接到 Windows 电脑上按 Caps Lock：**

- Windows 下灯正常亮 → 键盘硬件和固件都没问题，是 macOS 与它之间的 LED 报告没有被支持/忽略 → 优先试①和②。
- Windows 下灯也不亮 → 键盘固件/硬件层面的问题（比如 Caps Lock 被 VIA 改过、LED 坏了）→ 在 VIA 里恢复默认或重新刷固件。

### 进阶：手动发一次 LED 报告来确认（可选）

<details>
<summary>展开：用 hidapitester 验证键盘是否响应 LED 报告</summary>

先确认键盘被识别为 HID 设备：

```bash
hidutil list | grep -i -A2 keyboard
system_profiler SPBluetoothDataType | head -40
```

然后用 `hidapitester`（hidapi 自带的小工具）手动发一次输出报告：

```bash
hidapitester --list
hidapitester --vidpid <你的VID:PID> --open --send-output 0x02,0x02
```

⚠️ 具体用哪个 **report ID** 和哪个字节，取决于该键盘的 HID 描述符，**不能照抄**——发错报告最坏情况只是无效或让灯闪一下。目的是判断"键盘到底响不响应主机的 LED 报告"。嫌麻烦可以跳过这步。

</details>

## 一句话结论

- **长按才生效**：macOS 的 Caps Lock 防误触延迟，没有官方开关。要么接受，要么把这个键改成 `Control`/`Escape`（延迟立即消失），要么用有风险的注入式工具去补丁。
- **灯不同步**：不存在"同步"这回事，是外接键盘没点亮。先确认打字时大写功能是否正常；再依次试 **切 Mac 模式 → 装厂商软件 → 蓝牙重配 → 接 Windows 验证**；如果用了 Karabiner，灯不亮属于它已知的副作用。
