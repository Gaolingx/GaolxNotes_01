# 恢复误删远程仓库 本地提交推送

## 🧑‍💻 User

git如果不小心删除了远端仓库的某个分支，但本地分支还在，如何将本地仓库的所有提交到远程仓库？

---
## 😀 默认助手 (7)

## 核心结论

删除远端分支只会删掉远端那一个**引用（ref）**，并不会删掉提交对象本身。你的本地分支是完整的，最直接的做法就是把本地分支重新推上去即可：

```bash
git push origin <分支名>
```

如果希望重新建立上游跟踪关系，可以加上 `-u`：

```bash
git push -u origin <分支名>
```

推完后远端分支就“复活”了，提交历史、作者信息、时间戳全部保留。

---

## 标准操作流程（推荐按顺序执行）

```bash
# 1. 确认本地分支状态和跟踪关系
git branch -vv

# 2. 切换到该分支（如果不在上面）
git switch <分支名>

# 3. 清掉已失效的远端跟踪引用（可选，见下方警告）
git fetch --prune

# 4. 重新推送
git push -u origin <分支名>
```

<details>
<summary>⚠️ 关于 <code>git fetch --prune</code> 的重要警告</summary>

`--prune` 会删掉本地的 `origin/<分支名>` 跟踪引用。如果远端那个分支上存在**你本地没有的提交**（比如别人推过东西而你还没拉），你就失去了通过 `origin/<分支名>` 找回它的最后机会。

**在执行 prune 之前，先做一次对比：**

```bash
# 本地领先远端的提交（这些是你不会丢的）
git log --oneline origin/<分支名>..<分支名>

# 远端有、本地没有的提交（这些会被丢掉！）
git log --oneline <分支名>..origin/<分支名>
```

如果第二条命令有输出，先备份：

```bash
git branch backup-<分支名> origin/<分支名>
```

然后再进行 merge / cherry-pick / rebase。
</details>

## 其他常见情况

<details>
<summary>情况一：远端已经有同名分支了（被人重建过），push 被拒绝</summary>

说明远端分支存在但与本地分叉。先看清楚差异：

```bash
git fetch origin
git log --oneline --graph --all -20
```

确认要**用本地覆盖远端**后，用 `--force-with-lease` 而不是 `--force`：

```bash
git push --force-with-lease origin <分支名>
```

`--force-with-lease` 会在远端被别人更新过时拒绝推送，比 `--force` 安全。如果远端确实有别人的新提交，正确做法是 `git pull --rebase` 后再普通 push。
</details>

<details>
<summary>情况二：一次性恢复多个分支 / 所有标签</summary>

```bash
git push origin --all      # 推送所有本地分支
git push origin --tags     # 推送所有标签
```

**不要**随手使用 `git push --mirror`：它会把远端多余的分支删掉，等于在远端“强制执行”本地状态，破坏力很大。
</details>

<details>
<summary>情况三：远端分支上有本地没有的提交，需要从服务端找回</summary>

删除分支后，Git 对象在服务端还会存活一段时间（直到 `git gc --prune` 或平台回收），所以通常还能救回来：

- **知道提交 SHA**：直接用它重建分支
  ```bash
  git push origin <commit-sha>:refs/heads/<分支名>
  ```
- **GitHub**：打开仓库 → `Activity` / `Insights → Network`，或用 `Branches` 页面里最近的 deleted branch 恢复入口；也可以在 `https://github.com/<owner>/<repo>/commits/<sha>` 直接访问到游离提交。
- **GitLab**：`Repository → Commits` 里通常还能看到，或通过 `Settings → Repository → Deleted branches` 恢复。
- **自建服务器**：登录服务器到仓库目录执行 `git fsck --lost-found` 或 `git reflog --all` 找 SHA。
</details>

<details>
<summary>情况四：推送被拒（权限 / 保护分支）</summary>

- 报 `protected branch`：需要仓库管理员临时关闭保护规则，或走 MR 而不是直推。
- 报 `403 / permission denied`：确认 SSH key 或 token 有 `write` 权限，以及你是否还是该仓库成员。
</details>

## 预防建议

| 措施 | 说明 |
| --- | --- |
| 删除前先打标签 | `git tag archive/<分支名> origin/<分支名>` 再推送标签，成本极低 |
| 保护关键分支 | 在平台设置 protected branch，禁止误删 |
| 用 `--force-with-lease` 取代 `--force` | 防止覆盖别人提交 |
| 定期备份 | `git push --mirror` 到备份仓库（注意这是"全量镜像"，适合备份库） |

**一句话总结**：本地分支还在就绝对不算丢数据，`git push origin <分支名>` 就能原样恢复；唯一的风险是远端曾有本地没有的提交，那种情况要先别 `--prune`，从 `origin/<分支名>` 或服务端抢救。
