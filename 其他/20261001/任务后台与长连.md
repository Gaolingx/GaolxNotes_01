# 任务后台与长连

## 🧑‍💻 User

linux vscode ssh如何将前台任务转移到后台，或者延迟ssh断联销毁注销时间？

---
## 😀 默认助手 (7)

这是纯 Linux/SSH 使用问题，不涉及工具调用，我直接给你完整方案。

## 一、把前台任务转移到后台

### 1. Shell 作业控制（针对当前 SSH 会话）

```bash
# 1. 按 Ctrl+Z 挂起当前前台任务（进程进入 Stopped 状态）
# 2. 查看作业编号
jobs -l
# 3. 让作业在后台继续运行
bg %1
# 4. 需要时再调回前台
fg %1
```

### 2. 让任务彻底脱离 Shell（防 `SIGHUP`）

`Ctrl+Z` + `bg` 只是放进当前 shell 的作业表，**SSH 断开时 shell 退出仍会发 `SIGHUP` 杀掉它们**。要真正存活，需要 `disown`：

```bash
Ctrl+Z
bg %1
disown -h %1     # 从作业表移除并忽略 HUP
# 或一次性：disown -a
```

### 3. 启动时就以后台/持久方式运行

```bash
command &                 # 后台运行，但断线仍可能被杀
nohup command &           # 忽略 SIGHUP，输出默认到 nohup.out
nohup command >out.log 2>&1 &
setsid command            # 新会话，彻底脱离控制终端
```

### 4. 最佳实践：用 `tmux` / `screen`（强烈推荐）

VSCode Remote-SSH 场景下这是最可靠的方式：

```bash
tmux new -s work          # 新建名为 work 的会话
# 在里面跑任务，然后 Ctrl+b 再按 d 分离
tmux ls                   # 列出会话
tmux attach -t work       # 重新接入
```

<details>
<summary>把「已经在跑」的进程搬进 tmux（reptyr）</summary>

```bash
sudo apt install reptyr        # Debian/Ubuntu
echo 0 | sudo tee /proc/sys/kernel/yama/ptrace_scope

# 找到目标 PID，然后
reptyr <PID>
```
注意：对已经 daemon 化或复杂进程不一定成功，且部分系统需关闭 `ptrace_scope`。
</details>

## 二、延长 / 防止 SSH 断连

SSH 断连通常有两个原因：**网络中间设备回收空闲连接**，或 **服务端主动踢掉空闲会话**。要双向配置。

### 1. 客户端配置（推荐，VSCode 会读取）

编辑 `~/.ssh/config`：

```sshconfig
Host *
    ServerAliveInterval 60     # 每 60 秒发一次心跳
    ServerAliveCountMax 3      # 连续 3 次无响应才断开
    TCPKeepAlive yes
```

- `ServerAliveInterval`：客户端主动发 keepalive，防止 NAT/防火墙回收连接。
- `ServerAliveCountMax`：实际容错时间 ≈ 两者乘积（示例 ≈ 180 秒）。

### 2. 服务端配置

编辑 `/etc/ssh/sshd_config`（需 root）：

```sshconfig
ClientAliveInterval 60
ClientAliveCountMax 3
TCPKeepAlive yes
```

然后重启服务：

```bash
sudo systemctl restart sshd     # 或 ssh
```

- `ClientAliveInterval`：服务端每隔多少秒向客户端发探测，**为 0 表示不发送（会话永不因空闲断开）**。
- `ClientAliveCountMax`：多少次无响应后断开。

> 若只想「永不因空闲断连」，可把服务端 `ClientAliveInterval 0`；但网络层的中断仍需靠客户端 `ServerAliveInterval` 解决，所以两端都配最好。

### 3. VSCode Remote-SSH 专属设置

在 `settings.json` 中：

```json
{
  "remote.SSH.connectTimeout": 120,
  "remote.SSH.useLocalServer": true,
  "remote.SSH.remoteServerListenOnSocket": true
}
```

其中：
- `connectTimeout`：单次连接超时（秒），网络慢可调大。
- `remoteServerListenOnSocket`：用 socket 转发替代端口转发，某些网络环境下更稳定。

<details>
<summary>排查「自动断开」的常见坑</summary>

- **服务器有 TMOUT**：`/etc/profile` 或 `~/.bashrc` 中若有 `TMOUT=300`，空闲会直接踢出会话，需注释掉或调大。
- **公司防火墙/云厂商 NAT 空闲回收**：通常 5～30 分钟，靠客户端 `ServerAliveInterval` 解决最有效。
- **VSCode 自身重连**：Remote-SSH 断线后窗口会尝试重连；只要进程用 `tmux` 承载，重连后 `tmux attach` 即可恢复。
</details>

---

**一句话总结**：任务持久化交给 `tmux`（或 `nohup/setsid/disown`），连接存活交给两端 `AliveInterval/CountMax` 配置。两者配合即可实现「断线不中断任务、长时间挂机不掉线」。
