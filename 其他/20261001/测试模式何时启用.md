# 测试模式何时启用

## 🧑‍💻 User

windows什么情况下要开测试模式

---
## 😀 默认助手 (7)

## 一句话结论

Windows 的「测试模式」（Test Mode，就是 `bcdedit /set testsigning on`）**只有一个作用：关掉 64 位 Windows 内核对驱动程序数字签名的强制校验**，让没有微软（WHQL/认证）签名的内核驱动也能加载。

所以判断标准很简单：**你是否需要长期、反复地加载未签名的内核驱动？** 不是这个需求，就没必要开。

---

## 真正需要开测试模式的场景

<details>
<summary><strong>1. 驱动开发与调试（最正当的用途）</strong></summary>

- 用 WDK / Visual Studio 写内核驱动，在**测试机**上用测试证书（test certificate）签名驱动。
- 测试签名的驱动**只有在测试模式开启时才会被加载**，否则报错 `0xC0000428` / 代码 52。
- 正确做法：用专门的测试虚拟机，别在你日常主力机上开。
</details>

<details>
<summary><strong>2. 老硬件 / 停产设备没有正规签名驱动</strong></summary>

- 老式打印机、扫描仪、采集卡、USB 转串口、并口卡。
- 工业设备、医疗仪器、POS 机、机床控制卡。
- 软件加密狗 / 保护锁（尤其是国产老软件）。
- 一些二手洋垃圾网卡、阵列卡。
</details>

<details>
<summary><strong>3. 特定工具链本身就带未签名驱动</strong></summary>

- 显卡 vBIOS 刷写工具（部分 nvflash / amdvbflash 改版）。
- 光驱固件破解、某些手机刷机 / 写号 / 解锁工具。
- SSD 主控量产工具、CH341A 之类编程器的改版驱动。
- OBD 汽车诊断、部分仿真器（J-Link 克隆版等）。
</details>

<details>
<summary><strong>4. ⚠️ 灰色 / 高风险场景（常见但强烈不推荐）</strong></summary>

- **游戏外挂、作弊器、"过检测" 工具**——这类工具需要加载未签名的内核驱动来读写游戏内存、绕过反作弊。它们**几乎一定会要求你开测试模式**，这本身就是危险信号。
- 内核级 DRM 破解、私服 / 模拟器辅助工具。
- 来路不明的"优化大师""驱动精灵改版""系统精简工具"。
</details>

## 不建议开的情况

日常办公和游戏机器上，**基本都不该开**：

- 玩游戏（VAC、Vanguard/无畏契约、EAC、BattlEye 等会检测甚至拒绝启动）。
- 装了 BitLocker 的机器（改启动配置可能触发恢复密钥）。
- Windows 11 想用内存完整性（HVCI）、VBS、Credential Guard。
- 企业统一管理的电脑（组策略 / EDR 通常会直接告警或拦截）。

---

## 代价与风险

| 风险 | 说明 |
|---|---|
| 安全边界失效 | 任意（包括恶意）未签名驱动都能进内核，rootkit / 勒索软件可直接加载 |
| BYOVD 攻击面 | 攻击者利用有漏洞的合法驱动做内核攻击，测试模式让门槛更低 |
| 桌面水印 | 右下角常驻 `Test Mode` 字样 |
| Secure Boot 冲突 | 必须先在 UEFI 里**关闭安全启动**，否则设了也加载不了或直接启动失败 |
| 兼容性问题 | 部分游戏、反作弊、Windows 功能更新可能受影响 |
| 企业环境 | 被组策略禁用或安全软件告警 |

## 开关方法

<details>
<summary>永久开启 / 关闭</summary>

管理员打开 CMD/PowerShell：

```cmd
:: 开启
bcdedit /set testsigning on

:: 关闭
bcdedit /set testsigning off
```

前提：先在 BIOS/UEFI 里关闭 Secure Boot，然后重启。

查看当前状态：

```cmd
bcdedit /enum {current}
```

或运行 `msinfo32`，看「测试签名 / Test Signing」和「安全启动状态」。
</details>

<details>
<summary>临时一次性方案（更推荐）</summary>

只想跑一次某个未签名驱动，不必永久改系统：

```cmd
shutdown /r /o /t 0
```

重启进「疑难解答 → 高级选项 → 启动设置 → 重启」，然后按 **7**（或 F7）= **禁用驱动程序强制签名**。这只对本次启动生效，重启后自动恢复。
</details>

还有一个更强（也更危险）的开关 `bcdedit /set nointegritychecks on`，它会跳过内核完整性检查，和内存完整性（HVCI）直接冲突，非必要不要用。

## 两个常见误区

- **32 位 Windows 不强制驱动签名**，所以 x86 系统根本用不到测试模式；这是 x64 / ARM64 才有的机制。
- **内核调试模式**（`bcdedit /debug on`）和测试模式是两回事，那个用来接 WinDbg 调内核，不会自动放行未签名驱动。

如果只是偶尔要用某个驱动，优先考虑：装进虚拟机测试 → 或者让驱动作者走微软的 **attestation / WHQL 签名**（EV 代码签名证书 + 合作伙伴中心）。这比在自己主力机上常驻测试模式安全得多。
