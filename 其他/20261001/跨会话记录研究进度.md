## 😀 默认助手 (7)

# Vibe Research 的"记忆架构"：把对话当工作台，把文件当硬盘

先说结论：**跨对话断片，几乎从来不是模型记性问题，而是你没有给研究留一个"对话之外的持久载体"。** 聊天窗口是 RAM，随时断电清零；你要做的是给它接一块 SSD。下面是我实际用下来最有效的几条经验。

---

## 一、先认清到底丢的是什么

大家以为丢的是"结论"，其实结论最好补。真正致命的是这三样：

| 丢失物 | 后果 |
|---|---|
| **决策依据**（为什么选 A 不选 B） | 下个对话重新争论一遍，甚至推翻既有结论 |
| **被否决的路径**（试过但不行的） | 重复踩坑，浪费大量 token |
| **未决问题**（当时挂着没查的） | 研究永远收不了口，或漏掉关键分支 |

所以台账必须显式记录 **"否决了什么、为什么"**——这条最反直觉，也最省命。

---

## 二、核心心法：双轨制

不要写一份"完整记录"，那既没人读也维护不动。拆成两层：

- **过程日志（append-only，只增不改）** —— 时间顺序的流水账，负责可追溯。类比 `git log`。
- **状态快照（可覆盖，随时重写）** —— "当前最佳理解"，负责快速交接。类比 `README`。

**关键原则：新对话默认只读"状态快照"，需要追溯时才去翻日志。** 让模型每次吞全部历史，是最常见的自毁操作。

<details>
<summary><b>建议的台账目录结构（点开）</b></summary>

```text
research/
├─ 00_索引.md          # 当前状态快照 + 指向各文件的链接
├─ 01_问题定义.md       # 研究问题 / 边界 / 成功标准
├─ 02_假设.md          # H1, H2... 含状态：待验证/成立/证伪
├─ 03_证据库.md         # E1, E2... 每条：来源/日期/摘录/可信度
├─ 04_决策日志.md       # D1... 选了什么、为什么、否决了什么、为什么
├─ 05_开放问题.md       # Q1... 负责人/阻塞点/下一步
├─ 06_结论.md          # 带置信度的当前结论（可覆盖）
├─ 90_过程日志/         # 按日期，流水账，只增不改
└─ 99_交接简报.md       # 每次会话结束生成，喂给下一次
```

</details>

## 三、两个最重要的仪式

### 收官仪式：生成「交接简报」

**每次结束对话前，让模型输出一段结构化简报，存进 `99_交接简报.md`。** 这是最值钱的一个习惯。

```markdown
## 交接简报 · 2025-XX-XX
**当前状态**：一句话说清研究到哪了
**本轮新增**：做了/发现了什么
**已决决策**：D12 采用X方案 —— 因为Y
**已否决**：Z方案 —— 因为成本/证据不足（勿再提）
**开放问题**：Q7 仍缺数据源；Q9 待验证
**下一步**：给下一个对话的 3 条明确动作
**置信度**：结论A 高 / 结论B 中(缺反例) / 结论C 低
```

### 开场仪式：接续卡 + 状态复述

新对话第一轮这样开场：

```text
以下是本研究的唯一真源，请先读。
然后在动手前，用你自己的话复述一遍：当前状态、已否决路径、下一步。
如果我后续说的和真源冲突，以真源为准并提醒我。

[粘贴 99_交接简报.md]
```

**"先复述再动手"这一步能拦住 80% 的漂移**——模型会主动暴露它理解错的地方，而不是直接闷头往下跑。

## 四、防漂移的几个硬技巧

1. **ID 化一切**：来源叫 `E1/E2`，假设叫 `H1`，问题叫 `Q1`。这样"根据 E3 支持 H2"永远指代明确，跨对话不会串味。
2. **置信度三档标签**：高 / 中 / 低，并强制写"低/中的原因"。没有置信度的结论等于没有结论。
3. **覆盖而非删除**：结论变了就写"~~旧结论~~ → 新结论（因 E12）"。历史链条断掉后，你会想不通自己当初为什么转弯。
4. **矛盾专区**：证据打架时不要急着调和，单开一节列出冲突双方。很多研究价值就藏在这里。
5. **定期"合并整理"会话**：专门开一轮，只做三件事——合并重复、清理过期、把日志里的洞见提升进快照。研究越久，这一步越不可省。

<details>
<summary><b>反模式清单（我踩过的坑）</b></summary>

- ❌ 结论只留在聊天记录里，靠"往上翻"续命 → 一定丢
- ❌ 每次新对话塞入全部历史 → 又贵又乱，重点被稀释
- ❌ 只用自然语言指代，不起 ID → 越聊越糊
- ❌ 记录写太细、要求太高 → 三天后就懒得维护，不如不记
- ❌ 只记成功路径 → 下一篇对话重复踩坑
- ❌ 让模型"帮我记住" → 它记不住，只有文件和知识库能记

</details>

## 五、工具层怎么落地（Cherry Studio 场景）

**客户端内置能力优先用：**

- **知识库（RAG）**：把 `research/` 整个目录丢进去。这样**任意新对话都能自动检索到台账**，不用手动粘贴——这是最省事的跨对话衔接方式。
- **助手 + 预设提示词**：建一个"研究员"助手，把上面的开场仪式、简报模板写进系统提示词，每次自动生效，不用重复解释。
- **话题（Topics）**：同一研究的不同分支放在同助手的不同话题下，天然共享提示词和知识库。
- **导出**：阶段性把话题导出归档，作为过程日志的一部分。

**MCP 补齐"可写 + 跨对话记忆"两块短板：**

你现在这个环境已经能看到 MCP 注册表。针对你的需求，我建议装两类：

| 需求 | 推荐方向 | 注册表里的候选 |
|---|---|---|
| 让模型直接**读写本地台账文件** | filesystem MCP | `io.github.domdomegg/filesystem-mcp`（读写文件，轻量）、`io.github.Digital-Defiance/mcp-filesystem`（安全边界强） |
| **跨对话持久记忆**（不用手动粘） | memory MCP | `ai.brainmemory/brain`、`ai.memoryrouter/memoryrouter`（多客户端共享）、`ai.korely/memory`（双时序、知道"什么还成立"） |

> 我的偏好：**filesystem MCP 是刚需**（让台账真正"活"在磁盘上，模型能自己写交接简报），**memory MCP 是锦上添花**（适合结论多、跨工具的场景，但要接受它不如自己维护的 Markdown 可控）。

需要的话我可以直接帮你查这几个 server 的 README 并 `dryRun` 出一个安装方案，你确认后再落地。

## 六、一句话版本

> **对话 = 工作台（用完就走），文件/知识库 = 唯一真源（永不丢失）；每次开场先复述、每轮结束留简报、所有东西起 ID、被否决的路径一定要记。**

做到这四条，你的 vibe research 就能真正"接得上"，而不是每次从零开始猜自己上次想到哪了。
