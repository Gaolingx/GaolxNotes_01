# 路由器密码重启

## 🧑‍💻 User

路由器固件 输入wifi密码 填reboot字符串会导致路由器重启吗（甚至循环重启）

---
## 😀 默认助手 (7)

# 结论先行

**单纯在 WiFi 密码框里填一个字符串 `reboot`,绝大多数情况下不会让路由器重启。** 路由器重启通常需要满足"命令注入（Command Injection）"条件 —— 也就是固件把你的输入直接拼进 shell 命令里执行。

但**如果该固件存在命令注入漏洞**,那确实可能重启,甚至进入**循环重启（boot loop）**。这属于典型的嵌入式 Web 固件安全缺陷。

---

## 一、为什么"填 reboot"本身一般没用

WiFi 密码框在正常情况下只是一个普通参数,后端一般是:

```c
// 正常写法(安全)
snprintf(buf, sizeof(buf), "iwconfig wlan0 key %s", password);
system(buf);
```

此时输入 `reboot` 会被当成**密码内容**,不是命令,不会执行。

只有当代码是下面这种"危险写法"时才会出问题:

```c
// 危险写法:直接把整个输入当命令
system(password);                 // 输入 reboot → 直接执行
system(user_input);               // 或拼接时未过滤
```

---

## 二、什么情况下会导致重启

### 1. 命令注入(Command Injection)

如果固件把密码拼进 shell,**光填 `reboot` 通常还是不够的**,需要借助 shell 元字符:

| 注入方式 | 说明 |
|---|---|
| `;reboot;` | 命令分隔符 |
| `` `reboot` `` | 反引号命令替换 |
| `$(reboot)` | 命令替换 |
| `&& reboot` / `\|\| reboot` | 逻辑连接 |
| `\| reboot` | 管道 |
| `%0a reboot` | 换行注入(HTTP 参数) |

> 也就是说,能触发的话一般是 `;reboot;` / `$(reboot)` 这类,**而不是裸的 `reboot`**。

### 2. 裸 `reboot` 也能生效的特例

少数固件(尤其是"快速设置向导"里)会把某个字段**整个当作命令**传给 `system()`,此时输入 `reboot` 就可能直接生效。

### 3. 崩溃 → 看门狗重启(不是注入,但结果一样)

如果密码字段存在**缓冲区溢出 / 格式字符串**漏洞(`%n%s` 等),输入特定内容会让 CGI/守护进程崩溃,系统**看门狗(watchdog)**检测到后自动重启。

---

## 三、为什么会"循环重启"(最危险)

```mermaid
flowchart LR
A[写入恶意密码] --> B[保存到 NVRAM / 启动脚本]
B --> C[重启]
C --> D[开机时重新执行该配置]
D --> E[再次触发 reboot]
E --> C
```

只要**被污染的配置在每次开机时都会被执行**(例如写进了 `nvram`、`rc.local`、WiFi 初始化脚本),就会形成:

$$\text{重启} \rightarrow \text{加载坏配置} \rightarrow \text{再重启} \rightarrow \cdots \rightarrow \text{无限循环}$$

这比单次重启更麻烦,因为路由器可能再也进不了后台管理页面。

## 四、如何验证(安全研究角度)

<details>
<summary><strong>静态分析</strong></summary>

1. 提取固件:`binwalk -e firmware.bin`
2. 解包文件系统:`unsquashfs squashfs-root.img`
3. 找 CGI/守护进程:`find -name "*cgi*"`
4. 反汇编/字符串搜索危险调用:
   - `system`、`popen`、`execve`、`doSystemCmd`
   - 用 `ghidra` / `ida` 看密码参数是否拼进命令
</details>

<details>
<summary><strong>动态验证</strong></summary>

- 用 `chromium`/`burp` 抓提交 `SetWifi` 的 HTTP 请求
- 观察参数(常叫 `wpapsk` / `key` / `pswd`)
- 先用无害注入 `;id;` / `;cat /etc/passwd;` 试探,确认漏洞存在
- **切勿直接对生产设备测 `;reboot;`**,避免变砖
</details>

## 五、如果真的变砖/循环重启,如何恢复

| 方法 | 说明 |
|---|---|
| **Reset 按钮** | 长按 10~30s 恢复出厂 |
| **Failsafe / 安全模式** | 开机瞬间连按复位键进入 |
| **U-Boot / TFTP 恢复** | 上电时通过串口或 TFTP 重刷固件 |
| **UART 串口** | 接 TTL 进 bootloader (`tftpboot`) |
| **固件升级模式** | 部分品牌有专门的 recovery 页面 |

## 六、防御建议(给开发者)

1. **不要用 shell 拼接用户输入** —— 用 `execve` 传数组参数,或专用 API(`libnl`、`iw` 的库调用)。
2. **白名单校验** —— WiFi 密码只允许可见 ASCII 字母数字,拒绝 `; & | $ ( ) \` \n` 等。
3. **参数化调用** —— `system("iwconfig wlan0 key '%s'", escaped)` 前先转义。
4. **配置写入原子化 + 校验** —— 启动脚本执行前验证配置合法性,坏配置回退默认值。
5. **最小权限** —— Web CGI 不要以 root 运行。

---

### 一句话总结

> 裸填 `reboot` 一般不会重启;但若固件存在**命令注入**,用 `;reboot;`、`$(reboot)` 等就能触发,且若污染了开机加载的配置,就会**循环重启**。验证时务必用无害 payload,并准备好 Reset / TFTP 恢复手段。
