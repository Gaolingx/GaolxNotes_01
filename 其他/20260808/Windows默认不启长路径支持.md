# Windows默认不启长路径支持

### 🧑‍💻 User

为什么Windows默认不启用长路径支持？

---

### 🤖 Assistant

**主要原因是向后兼容性（application compatibility）。** Windows 默认不启用长路径支持，是为了避免破坏大量依赖 `MAX_PATH`（260 字符）限制的旧应用程序、库和工具。

### 历史背景与限制
- Windows 传统 API 使用 `MAX_PATH` 常量，路径长度上限约为 **260 字符**（包括驱动器号、路径、文件名和结尾的 null 字符）。这源于早期设计和兼容性考虑。
- 许多程序硬编码了 260 字符的缓冲区、假设路径不会超长，或使用旧版 Win32 API 行为。
- 虽然 NTFS 本身早就支持更长路径，且从很早的版本起就可用 `\\?\` 前缀绕过限制，但普通 API 调用默认仍受 `MAX_PATH` 约束。

Windows 10 版本 1607（Anniversary Update）及更高版本引入了**长路径支持**（最长约 32,767 字符），但通过**可选启用**的方式提供：
- 系统级策略/注册表项 `LongPathsEnabled`
- 应用程序清单中的 `longPathAware` 声明

默认关闭，是因为这是一个**全局性变更**，会影响整个系统的文件 API 行为。

### 为什么默认不启用（核心原因）
1. **应用程序兼容性风险最高**
   启用后，不兼容的程序可能出现：
   - 缓冲区溢出或截断
   - 崩溃、错误处理失败
   - 文件/目录操作异常
   - 安装程序、卸载程序、备份工具、脚本出错
   Windows 生态中有大量遗留软件、企业定制程序、旧版库和第三方工具，它们从未针对长路径进行测试或更新。默认开启会立刻影响这些软件。

2. **需要应用程序显式 opt-in**
   即使开启系统策略，应用程序通常也需要在清单中声明 `longPathAware` 才能真正享受无前缀的长路径支持。系统默认关闭可避免强制改变所有进程的行为，给开发者时间适配。

3. **部分系统组件和工具仍有限制**
   并非所有 Windows 组件都完全支持长路径（即使开启策略后）：
   - 某些旧版 Shell 组件、命令行工具、资源管理器历史行为
   - 部分第三方文件系统过滤驱动、备份/杀毒/同步软件
   - 网络共享、某些协议或旧版 API 组合
   默认关闭可降低意外问题的发生率。

4. **Microsoft 的保守策略**
   Windows 强调“不破坏现有功能”。引入长路径时采用**opt-in**（用户/管理员主动启用 + 应用声明），而不是默认开启，这与许多其他重大 API 变更的做法一致。企业环境尤其需要可控性，管理员可根据自己的软件清单决定是否开启。

5. **其他实际考虑**
   - 长路径可能暴露或放大某些路径处理 bug（例如规范化、比较、安全检查中的问题）。
   - 不同文件系统、网络重定向器或第三方组件的支持程度不一致。
   - 普通用户场景下，超长路径相对少见，默认关闭对大多数人影响较小。

### 如何启用（如果需要）
**推荐方式（组策略，Windows 专业版/企业版/教育版）：**
1. 运行 `gpedit.msc`
2. 转到：计算机配置 → 管理模板 → 系统 → 文件系统
3. 启用 **“启用 Win32 长路径”**（Enable Win32 long paths）
4. 重启或注销生效

**注册表方式（所有版本）：**
```reg
Windows Registry Editor Version 5.00

[HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\FileSystem]
"LongPathsEnabled"=dword:00000001
```
修改后重启电脑。

**应用程序侧：** 在 manifest 中添加：
```xml
<application xmlns="urn:schemas-microsoft-com:asm.v3">
  <windowsSettings>
    <longPathAware xmlns="http://schemas.microsoft.com/SMI/2016/WindowsSettings">true</longPathAware>
  </windowsSettings>
</application>
```

### 注意事项与建议
- **测试后再大规模启用**：在开发/测试环境先开，检查关键软件（尤其是安装器、备份、同步、老旧工具、脚本）。
- 现代开发工具链（较新的 .NET、Visual Studio、Git、Node.js、Python 等）对长路径支持较好，很多已推荐或自动适配。
- 即使不开启系统策略，程序仍可使用 `\\?\` 前缀 + 宽字符 API 来处理长路径（这是长期可用的方法）。
- 开启后并非“万能”：某些旧组件、网络路径、第三方驱动或特定场景仍可能失败。
- Windows 11 / 较新版本中，资源管理器等对长路径的体验有改善，但系统默认策略依然是关闭的。

**总结**：默认不启用是**有意为之的兼容性保护**。Microsoft 提供了机制，但把决定权交给用户和管理员，避免因为少数需要长路径的场景而破坏大量现有软件。如果你的工作流经常遇到路径过长问题（深层嵌套项目、node_modules、长文件名等），可以安全地启用并配合应用适配使用。
