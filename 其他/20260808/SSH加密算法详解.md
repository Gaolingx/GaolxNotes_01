# SSH加密算法详解

### 🧑‍💻 User

ssh的加密密钥用到什么算法？

---

### 🤖 Assistant

SSH 的加密涉及多个环节，不同环节使用不同类型的算法。下面按用途分类说明：

### 1. 主机密钥与用户认证密钥（非对称算法）
用于验证服务器身份（Host Key）及客户端登录（User Key），常见算法：

| 算法 | 密钥类型标识 | 安全性说明 |
|------|------------|-----------|
| **RSA** | `ssh-rsa`（已废弃）<br>`rsa-sha2-256`、`rsa-sha2-512`（推荐） | 经典的非对称算法。原 `ssh-rsa` 使用 SHA-1 已被认为不安全，新版改用 SHA-256/512。<br>常见密钥长度 2048/4096 位。 |
| **ECDSA** | `ecdsa-sha2-nistp256`<br>`ecdsa-sha2-nistp384`<br>`ecdsa-sha2-nistp521` | 基于 NIST 椭圆曲线的 ECDSA，256 位安全性已足够。<br>依赖系统随机数质量，曾有因随机数问题暴露私钥的案例。 |
| **Ed25519** | `ssh-ed25519` | 基于 Edwards 曲线 25519，**目前最推荐**。<br>128 位安全强度，速度快，实现简洁，无已知漏洞。 |
| **DSA** | `ssh-dss` | **已废弃**，原密钥长度受限且不安全，OpenSSH 7.0 起默认禁用。 |

### 2. 密钥交换算法（Key Exchange，KEX）
用于安全协商出一个临时对称密钥，常见算法：

- **Diffie-Hellman 系列**
  `diffie-hellman-group14-sha256`、`diffie-hellman-group16-sha512`、`diffie-hellman-group18-sha512`（模幂运算，长度从 2048 到 8192 位）。
- **椭圆曲线 Diffie-Hellman（ECDH）**
  `ecdh-sha2-nistp256`、`ecdh-sha2-nistp384`、`ecdh-sha2-nistp521`。
- **Curve25519**
  `curve25519-sha256`（推荐，高效且安全）。
- **旧版** 如 `diffie-hellman-group1-sha1` 已废弃。

### 3. 数据加密算法（对称算法）
用 KEX 协商出的对称密钥加密实际会话流量，常见：

- **AES**
  `aes128-ctr`、`aes192-ctr`、`aes256-ctr`、`aes128-gcm@openssh.com`、`aes256-gcm@openssh.com`（CTR/GCM 模式，通用）。
- **ChaCha20-Poly1305**
  `chacha20-poly1305@openssh.com`（移动端/无硬件 AES 时高效）。
- **旧算法** 如 `3des-cbc`、`arcfour` 等已废弃或不再推荐。

### 4. 消息认证码（MAC，用于完整性）
- `hmac-sha2-256`、`hmac-sha2-512`、`hmac-sha2-256-etm@openssh.com`
  （ETM = Encrypt-then-MAC，更安全）
- 曾用的 `hmac-md5`、`hmac-sha1` 已淘汰。

**总结**：
- 如果你问的是 “`ssh-keygen` 生成了什么算法的密钥”，最常见且推荐的是 **Ed25519**（`ssh-keygen -t ed25519`）和 **RSA 4096**（使用 `rsa-sha2-512` 签名）。
- 整个 SSH 连接的安全性由 **非对称密钥 → 密钥交换 → 对称加密** 层层算法共同保障。

查看可支持的算法：
```bash
ssh -Q key       # 客户端支持的密钥类型
ssh -Q cipher    # 加密算法
ssh -Q mac       # MAC
ssh -Q kex       # 密钥交换
```

### 🧑‍💻 User

根据ed25519/rsa原理，为什么我们很难从pub key反推出pri key？

---

### 🤖 Assistant

要理解为什么 Ed25519 和 RSA 的公钥无法反推出私钥，就要明白它们各自依赖的**单向陷门函数**——在一个方向上计算很容易，反过来算在数学上极度困难。下面分别说明。

---

## Ed25519：椭圆曲线上的“离散对数”

Ed25519 是一条特殊的椭圆曲线，它的安全性建立在 **椭圆曲线离散对数问题（ECDLP）** 上。

### 公私钥关系

- 私钥是一个大整数 $a$（256 比特的随机数）。
- 曲线上有一个公开的基点 $G$（所有参与者都知道）。
- 公钥是点 $A = a \cdot G$，这里 $\cdot$ 表示椭圆曲线上的标量乘法（把点 $G$ 连续加自己 $a$ 次）。

### 为什么知道 $A$ 和 $G$ 却算不出 $a$？

标量乘法本身很好算：给定 $a$ 和 $G$，利用“倍加法”可以在极短时间内算出 $A$。
**但要逆向求解 $a = \log_G A$**，目前已知的算法都相当于把所有可能的 $a$ 尝试一遍（暴力搜索），需要 $2^{128}$ 次运算。

- 即使动用全世界所有计算机，算到太阳熄灭也算不完。
- 数学界至今没有找到椭圆曲线离散对数的**亚指数时间算法**（RSA 的整数分解已经有亚指数算法了，但 Ed25519 更“硬”）。

**直观类比**：给你一个球，在一维数轴上跳 $a$ 次找到最终落点很容易，但只告诉你起点和落点，让你猜一共跳了几次，几乎不可能——尤其是在“椭圆曲线”这个更高维、结构更复杂的空间里。

---

## RSA：大整数分解难题

RSA 的安全性基于“两个大质数相乘容易，把乘积分解回去极难”。

### 公私钥关系

- 选两个大质数 $p, q$，计算模数 $n = p \times q$。
- 公钥包含 $(n, e)$，其中 $e$ 是公开指数（通常为 65537）。
- 私钥 $d$ 满足 $e \times d \equiv 1 \pmod{\phi(n)}$，而 $\phi(n) = (p-1)(q-1)$。

### 为什么知道 $n$ 却算不出 $d$？

要算出 $d$，必须知道 $\phi(n)$，而求 $\phi(n)$ 等同于分解 $n$ 得到 $p$ 和 $q$。

- 当 $p, q$ 都很大（如 2048 比特的 $n$）时，对 $n$ 做质因数分解极其困难。
- 目前最先进的分解算法（数域筛法）也需要**亚指数时间**，对 2048 位 RSA 而言仍不现实。
- 如果能轻松分解 $n$，就能算出 $\phi(n)$，继而算出 $d$；但分解一个 600 位的大数至今仍需要庞大的计算资源，更别说 617 位（2048 比特）以上。

**直观类比**：告诉你 $15 = p \times q$，你立即知道是 3 和 5；但告诉你一个 600 多位的数是由哪两个质数乘出来的，就像把两本厚书撕成纸屑混在一起，再让你完美还原哪一页属于哪一本书。

---

## 总结对比

| 算法 | 依赖的数学难题 | 攻击复杂度 | 直观理解 |
|------|----------------|------------|-----------|
| **Ed25519** | 椭圆曲线离散对数（ECDLP） | $O(2^{n/2})$，完全指数级 | 跳跃游戏中的步数反推 |
| **RSA** | 大整数分解 | 亚指数时间（仍超多项式） | 拆解两个质数的积 |

两者都利用了**正向计算非常高效，逆向计算无比困难**的单向性。只要私钥长度足够，且没有量子计算机能有效运行 Shor 算法（该算法可同时破解两类难题），从公钥反推私钥就依然是数学上的不可能任务。
