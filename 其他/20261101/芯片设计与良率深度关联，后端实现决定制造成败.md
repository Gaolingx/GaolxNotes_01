# 芯片设计与良率深度关联，后端实现决定制造成败

## 🧑‍💻 User

话说芯片设计里边，良率还跟design有关系吗？

---
## 😀 默认助手 (7)

有关系，而且先进节点下关系越来越大。良率从来不只是 fab 的事——设计端有一整套叫 **DFM / DFY / DFT**（design for manufacturability / yield / test）的方法学，本质就是在设计阶段“买良率”。

## 一、先把“良率”拆成三类，才看得清设计的作用点

| 良率成分 | 物理来源 | 设计能不能影响 | 典型设计手段 |
|---|---|---|---|
| 随机缺陷良率 | 颗粒、针孔、断线短路，按缺陷密度 $D_0$ 随机落 | 能，通过**关键面积** | 减面积、放宽线宽/间距、冗余 via、减少 contact 数量 |
| 系统性良率 | 光刻热点、CMP 碟形凹陷、刻蚀负载、应力、天线效应 | **强相关**，几乎全由版图决定 | 光刻友好版图、dummy fill、密度均匀化、OPC/SRAF 协同、天线二极管 |
| 参数良率 | 工艺波动（$V_t$、$L$、$T_{ox}$）导致速度/漏电超规格 | 强相关，靠**设计余量** | margin、SRAM 读写 margin、ABB/DVFS、body bias、自适应电路 |

$$Y_{\text{total}} \approx Y_{\text{random}} \times Y_{\text{systematic}} \times Y_{\text{parametric}} \times Y_{\text{repair}}$$

设计对每一项都有杠杆，只是杠杆类型不同。

## 二、随机缺陷：设计通过“关键面积”直接影响

经典 Murphy 模型：

$$Y = Y_0 \left(\frac{1 - e^{-A_c D_0}}{A_c D_0}\right)^2$$

其中 $A_c$ 是**关键面积**（critical area，能让某个尺寸的颗粒造成失效的等效面积），不是芯片面积。设计上：

- 同样的功能，用更宽松的规则（更大线宽/间距、更少 via、更少最小尺寸图形）→ $A_c$ 下降 → 良率上升。这就是为什么成熟节点上“面积换良率”是常见 trade-off。
- **冗余 via / 双 via**：单个 via 失效即开路，双 via 把开路概率近似从 $p$ 降到 $p^2$，在大规模布线里收益非常可观，是 signoff 阶段的标配 DFM 项。
- 大芯片天然吃亏：$\text{die per wafer}$ 和单 die 良率双重衰减。所以 **chiplet / 多 die 拆分本身就是一种良率设计决策**——用小 die 换高良率，再做 KGD（known good die）筛选。

## 三、系统性良率：这才是“设计害的”那部分

先进节点（N7 以下）系统性缺陷占比明显上升，随机缺陷占比反而下降，所以设计端责任变重：

- **光刻热点**：某些图形组合在特定 defocus/剂量下桥连或断线。设计要用 litho-friendly 规则、restricted design rules、via 冗余，signoff 跑 LRC（litho hotspot check）。
- **图形密度均匀性**：CMP 会导致 dishing/erosion，金属和 poly 密度不均会带来厚度偏差 → 电阻/电容偏移。靠 **dummy fill** 和密度窗口规则（min/max density per window）解决，这是纯版图/dummy 层面的设计动作。
- **天线效应**：等离子刻蚀时长金属“收集”电荷击穿栅氧，属于直接良率杀手。设计端加antenna diode、跳层（metal jump）解决。
- **多重曝光的 coloring 冲突**：SADP/LELE 下版图染色不合法直接做不出来，是设计规则层面的硬约束。
- **EM/IR drop、latch-up、ESD**：这些偏可靠性，但表现为早期失效或筛选后失效，也计入有效良率。

## 四、参数良率与“可修复性设计”：设计端的两个大杠杆

<details>
<summary><b>参数良率：让电路对工艺波动不敏感</b></summary>

- 时序 signoff 的 margin（OCV/AOCV/POCV）本质就是拿面积和功耗换参数良率；margin 收太紧 → 良率掉，放太松 → 性能竞争力掉，是个显式优化问题。
- **SRAM 是参数良率的命门**：bitcell 的 read margin / write margin / hold margin 在低电压下急剧恶化，直接决定 chip 的 $V_{min}$ 分布。设计上靠 bitcell 选型、assist 电路（WL boost、negative BL、read assist）、冗余列来救。
- 模拟/混合信号靠 matching（Pelgrom：$\sigma_{\Delta V_t} \propto 1/\sqrt{WL}$）、斩波、校准、trim，本质都是设计换良率。
- 自适应手段（ABB、AVS、DVFS、片上 PVT 传感器）把“规格内才合格”变成“runtime 调到合格”，是先进 SoC 提高有效良率的重要设计特性。

</details>

<details>
<summary><b>可修复性：把失效 die 救回来</b></summary>

- **存储器冗余 + BISR**：大 SoC 里 SRAM 占面积 50%+，一个 bit 失效整颗报废。加冗余行/列 + 熔丝/efuse 修复，实测能把这类 die 的良率提升到“接近无缺陷”的水平——这是设计对**有效良率**影响最直接、ROI 最高的一项。
- 冗余时钟/电源网络、可编程 trim、片上自校准，都属于“设计出来的良率”。
- 代价是面积、测试时间、修复逻辑本身的失效风险，需要算经济账。

</details>

## 五、还有一类常被忽略的：测试与筛选取舍造成的“良率损失”

- **测试覆盖不足 → 逃逸（escape）**，坏品流到客户手里；**测试限太紧 → 好品被误杀（yield loss）**。这个 lim 的设定是设计与测试共同决定的。
- DFT（scan、BIST、boundary scan）覆盖率、测试时间（test time 直接摊进成本）、以及“测试引起的失效”（test-induced damage），都会反映到最终良率数字上。
- 产品 ramp 阶段良率上不去，很多时候根因不是工艺漂移，而是**某个设计 corner 没覆盖到**——这也是为什么 NPI 阶段 design 和 fab 要一起做 yield ramp 分析（yield diagnosis、fail bin 分析、volume diagnosis 反推版图特征）。

## 一句话总结

良率 = 工艺能力 × 设计的“可制造性”。设计通过**面积/关键面积、版图几何、冗余、余量、可修复性、可测性**六个抓手直接决定良率上限；到先进节点，设计对系统性良率与参数良率的话语权甚至超过工艺本身。所以大厂里 DFM/DFY 团队是跟 design 和 fab 平级的常设组织，不是“流片前补个 DRC”那么简单。

## 😀 默认助手 (7)

理解对了，而且你抓到的正是要害。你说的这些，其实就是把「良率是制造问题」这句话，从“是，但不完整”这个角度讲清楚了。我接着你的框架补充几个可以更精确的地方。

## 一、你的第 1 点：容错是由架构设计出来的

这一点我完全同意，不过其中有两种机制常被混在一起，实际上它们的逻辑并不相同：

| 机制 | 做法 | 提高的是什么 | 代价 |
|---|---|---|---|
| **冗余修复** | SRAM 多一组冗余行与冗余列，并配 BISR 和 efuse | 把本应报废的 die 救回来，直接提高有效良率 | 面积、测试时间、修复逻辑自身的失效风险 |
| **缺陷分档与降级** | Nvidia 砍 SM、AMD 屏蔽 core 或 cache way | 把部分缺陷 die 降级成低配 SKU 卖出去 | SKU 管理复杂、需要设计时就预留屏蔽粒度 |

关于 **Nvidia 砍 SM**，更严谨地说：它的首要动机往往是 product segmentation（市场分层），但同一套硬件机制确实被当成 defect harvesting 使用。所以用“良率分档”来理解没问题，只是不要认为每次砍 SM 都因为良率。AMD 的 core、L3 屏蔽也一样：一部分原因是良率 harvest，一部分原因是产品线切分。

关于 **SRAM 塞 10% 冗量**：10% 是个量级上合理的数，但实际比例要按 array 大小和缺陷密度算（泊松或负二项分布），极小 array 不需要那么多，超大 array 可能还不够。关键点是：冗余通过一条完整的链路才真正生效，包括 **BISR 逻辑、efuse/熔丝、测试程序（MBIST + 修复算法）、修复后重测**。只在版图上多画冗余列，并不能自动提升良率。

顺着这个思路还能推一层：**片上网络（NoC）、互连、时钟树、电源网络**也都可以做冗余或可配置降级，只是越往上冗余，代价越大。这也是为什么“大 die SoC 的架构设计从一开始就把缺陷容忍写进规格”。

## 二、你的第 2 点：制程物理特性 → 后端约束

这一点是关键，而且可以举出很具体的例子：

- **FinFET 的 fin quantization**：$W/L$ 只能在离散的 fin 数量里取，设计没有连续调节的余地，性能目标必须凑到“可实现的档位”上。
- **GAA / nanosheet**：除了 width quantization（sheet 宽度也是离散的），还多了 **self-heating**（nanosheet 被氧化物包围、散热路径变差）和新的 defect mode（sheet 桥接，以及 inner spacer 相关工艺）。
- **背面供电（BSPD）**：把电源网络挪到晶圆背面，正面的布线资源被释放出来，IR drop 显著改善，这是实打实的 yield/PPA 红利；但代价是 **nTSV 密度受限、背面工艺成熟度低、热路径改变、新的缺陷模式**。你在 physical design 阶段为它做的电源网格规划，跟正面供电完全是两套工程。
- 你说的“避免造成电源层压力大的做法”就属于这类：**高翻转率模块的位置、电源网格的 mesh 密度、去耦电容的摆法、IR drop 的局部热点**，这些在设计阶段就要主动避开，否则最终成品率就会被 EM/IR 吃掉。

所以物理设计真正做的，是在制程给定的可行域边界上找一个点；它并不是“我要实现 1”这种拍脑袋设目标。

## 三、你那套“五个项目打 60/80/70/90/100 分”的类比

这个类比实质上就是 **constrained optimization / Pareto 前沿**，学术界和工业界叫 **DTCO（Design-Technology Co-Optimization）**。

更准确的一句话是：设计应当**重新分配预算**，而不能在这些项目之间简单“妥协”。比如某个制程的电源网络很宽（IR 好、但布线资源紧），你就把频率目标降一点，把省下的资源投到面积和布线拥塞上；某个制程的 $V_t$ 分布很宽，你就把 margin 加在时序上，同时用 ABB/DVFS 在 runtime 补回来。你说的“1 项目妥协、4 和 5 推到极限”，正是这个意思，而且**哪几项可以推、哪几项必须让，是每个制程独有的，只能靠流片数据积累才知道**。

## 四、Intel 那个案例，你指的应该是 Rocket Lake

最贴切的就是 **Rocket Lake（Cypress Cove，把 10nm 的 Sunny Cove 核回搬到 14nm）**：核心数从 10 退到 8，功耗爆炸，多线程反而打不过上一代 Comet Lake。原因就是 10nm 设计假设的**密度、供电、漏电特性**在 14nm 上全都不成立，回搬之后面积和功耗预算被彻底打乱。这是“设计-制程耦合”代价最经典的教科书案例，你举得很对。

## 五、“前端 / 后端”这个划分，可以再收紧一点

你说的没错，而且值得指出一个中文语境里的歧义：IC 圈的“front-end / back-end”有时指**设计 vs 制造封测**，有时指 **RTL/逻辑（front-end）vs 物理实现（back-end physical design）**。你说的是后者，这个区分很关键，因为：

- **前端**决定“要不要做容错、冗余多大、架构上怎么屏蔽”，这关乎 PPA 和良率上限。
- **后端**决定“这套逻辑在这个制程上到底能不能被印出来、印出来还剩多少良率”，这才是 foundry 不管的那部分。

再补一个链条：后端不等于只有 place & route，还包括 **signoff（DRC/LVS/RC extraction/STA/EM-IR）、DFM、封装协同设计（chiplet/CoWoS 的 bump 与 RDL 规划）、测试程序开发**。DFM 和 yield ramp 分析常常是独立团队在做的。

## 六、“台积电只是打印店”这个比喻很好，但可以再狠一点

实际上它已经不只是打印店，而更接近“**指定纸张、油墨、排版模板的印刷厂**”：

- 它给你 **PDK**（器件模型、corners、DRC/LVS deck、DFM rule、density 规则、critical area 参数），这就是“排版规范”。
- DRC/LVS 就是“格式检查”，只拦得住显而易见的错误。
- 但 **选错字体照样照印不误**，这就是为什么需要大量流片（tapeout + 多批 silicon）来验证：PDK 是**抽象过的**，它不会告诉你“某一类版图组合在特定 focus 下会桥连”，也不会告诉你这颗 die 的真实缺陷密度分布长什么样。**silicon correlation**（用实测数据回灌修正模型和规则）是设计厂的核心能力，foundry 帮不了。

这也解释了为什么先进节点的自由度其实更小：你必须用它的 **reference flow + 标准单元库 + memory compiler + IP 生态**，能自己发挥的空间被压缩到“怎么在这些既定组件里把 PPA 榨干”。玄戒这类自研 SoC 的差异化，恰恰常常不在前端架构（那部分相对“常规”），而在于**后端实现质量，以及把某个制程的可行域边界摸到多准**。

## 一句话收

你的理解没问题，而且已经越过了“良率 = 制造”这个外行分界线：**良率是设计在制程可行域里的位置决定的**，架构层面靠冗余或降级，物理层面靠 DFM 与电源、热、可靠性的主动避让，测试层面靠修复与筛选。剩下唯一要补的一句是：这一切都有成本，**过度设计（over-margining）会直接输掉 PPA 竞争力**，所以真正难的是知道在哪一项上让步、让多少。
