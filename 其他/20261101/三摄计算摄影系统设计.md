# 三摄异构 CMOS 的高效计算摄影：从预算分配开始设计

## 0. 核心结论先摆出来

> **分辨率预算由衍射决定，不取决于像素数量。因此，像素位移超分只应给"广角主摄"用；小底长焦已经接近衍射奈奎斯特，做超分只是浪费帧和带宽。**
>
> **ISO 包围不能扩展高光动态范围（进光量没变），它做的是暗部信噪比。真正的 HDR 要么靠快门包围，要么靠双转换增益读出。**
>
> **流畅预览的关键是"只让一支镜头跑全速"，不是把带宽压给三条链路。**

下面按这个顺序展开：参数量化 → 焦段/分辨率分配 → 超分 → HDR/ISO 包围 → 三摄协同 → 带宽 → 时延 → 光谱传感器。

## 1. 先把系统量化：三个公式定生死

任何合成策略之前，先算出每条通道的**角采样**和**衍射极限**。

$$\underbrace{\theta_{pix}=\frac{p}{f}}_{\text{像素角采样}}\qquad \underbrace{f_c=\frac{1}{\lambda F\#}}_{\text{衍射截止频率}}\qquad \underbrace{p_{Nyq}\le \frac{\lambda F\#}{2}}_{\text{采样充分条件}}$$

其中 $p$ 为像素间距，$f$ 为实际焦距。注意 $p_{Nyq}$ 与焦距无关——**只看 $p$ 和 $F\#$**，所以"这支镜头值不值得做超分"在选型阶段就能拍板。

<div>

示例三摄（典型旗舰配置）：

| | C0 广角 | C1 中长焦 3× | C2 潜望 6× |
|---|---|---|---|
| 传感器 | 1/1.3″, 50MP | 1/2.5″, 50MP | 1/2.55″, 12MP |
| 像素间距 $p$ | 1.20 µm | 0.61 µm | 1.15 µm |
| 光圈 | f/1.6 | f/2.6 | f/2.7 |
| 实际焦距 $f$ | 6.5 mm | 10.4 mm | 20.3 mm |
| 等效焦距 | 23 mm | 70 mm | 140 mm |
| 角采样 $\theta_{pix}$ | 0.185 mrad | 0.059 mrad | 0.057 mrad |
| 衍射奈奎斯特 $p_{Nyq}$ | 0.44 µm | 0.72 µm | 0.74 µm |
| **采样富余度** $p/p_{Nyq}$ | **2.7×** | 0.85×（已过采样） | 1.55× |
| **超分是否值得做** | ✅ 值得，收益最大 | ❌ 无收益 | 🔸 收益约 1.3–1.5× |

</div>

**读法**：

- C0 的像素比衍射极限粗 2.7 倍，意味物理上还有 ~2× 线性解析力没采到 → 2×2 像素位移（2× 线性、4× 像素数）是**物理上有依据的**，不是营销数字。
- C1 的 $p$ 已经小于 $p_{Nyq}$，**光学上已经分辨不出更多细节了**，50MP 里真实解析力大概只有 8–12MP 等效。它的价值是"3× 焦段的视场"，不是"像素"。
- 角采样上 C1 与 C2 几乎相等（0.059 vs 0.057），说明这对焦段组合是**设计正确**的，2×~3× 切换时解析力不会掉台阶。

> 由此得到第一条设计铁律：**长焦底面积应约等于 $\text{广角底面积}/z^2$** 才能在 $z$ 倍变焦时维持同等角分辨率。实际产品普遍做不到，所以长焦必然靠"更细的角采样"来补偿，代价是单像素 SNR 崩掉——这也是长焦必须多帧融合的根本原因。

## 2. 焦段覆盖与"拍摄分辨率"的分配

### 2.1 焦段覆盖

推荐相邻镜头变焦比 **2×–2.5×**，视场重叠 **15–25%**：

- 重叠太少 → 切换瞬间视场跳变、融合区没有冗余做对齐；
- 重叠太多 → 浪费一支镜头。

对上面的例子：C0 有效区间 0.7×–2.2×，C1 覆盖 2.2×–5×，C2 覆盖 5×–12×（数字变焦上限由 C2 的角采样决定）。

切换判据不用等效焦距，而用**角分辨率匹配点**：

$$z^* \text{ 满足 } \frac{\theta_{A}}{z^*}=\theta_{B} \;\Rightarrow\; z^*=\frac{\theta_A}{\theta_B}$$

两支镜头在该变焦倍率下像素级解析力相等，此时切换视觉最平滑（对上面的例子 $z^*=0.185/0.059\approx3.1$，所以标称"3×"是对的）。

### 2.2 每支镜头的拍摄分辨率怎么定

| 用途 | 建议分辨率 | 理由 |
|---|---|---|
| 超分主帧（C0） | 全分辨率 50MP | 需要覆盖亚像素网格 |
| HDR 长曝光帧 | **2×2 binning 到 12.5MP** | 长帧只贡献暗部，本来就是噪声受限；合并后读出噪声改善 2×，带宽省 4× |
| HDR 短曝光帧 | 全分辨率 | 高光是细节所在，且短帧无运动模糊，适合做对齐参考 |
| 预览/3A | 2×2 binning 或 ROI skip | 见第 6 节 |
| 长焦 C1/C2 | 全分辨率即可，不做超分 | 已到衍射极限，多帧只用于降噪 |

**关键点：一簇多帧里不要所有帧都同分辨率。** 长帧降采样是近乎免费的带宽与信噪比双赢。

## 3. 像素抖动超分：可行性、帧数、算法

### 3.1 两种实现路径

| | 传感器位移（IBIS 微动） | 手持抖动（自然抖动） |
|---|---|---|
| 亚像素相位 | 确定可控，可精确 0.5px 步进 | 随机，需足够帧数覆盖相位空间 |
| 最小帧数 | 4 帧（2×2 全相位） | 8–16 帧 |
| 单帧曝光上限 | 不限（可长曝） | 受抖动模糊限制，约 $\le 1/(2f_{eq})$ |
| 运动主体 | 完全失效 | 局部失效，可掩膜回退 |
| 适用 | 静物、风光 | 通用 |

### 3.2 帧数与收益

- **4 帧 2×2 位移**：每个输出像素获得完整的 R/G/B 四相位采样，等价于取消 CFA 内插 + 4× 像素数。实际线性解析力提升约 **1.7–2.0×**（受衍射 MTF 拖累）。
- **8 帧**：加入噪声平均（$\sqrt{8}\approx2.8\times$，实测 ≈1.2–1.5 stop）+ 相位冗余（抗个别帧模糊）。
- **超过 16 帧**：收益进入 $\sqrt{N}$ 平台，而采集时间线性增长，**不值得**。

### 3.3 算法上必须做的三件事

1. **在 Bayer 域直接合并**，不要先 demosaic 再合并 —— 计算量省 3×，且避免内插伪影累积成"糊"。
2. **对齐分级**：IMU/陀螺积分出全局单应 → 1/8 分辨率 luma 上做验证与修正 → 只在高运动 ROI 跑稠密光流。全程不做 50MP 全图光流。
3. **运动掩膜 + 单帧回退**：掩膜内用参考帧（最短曝光帧）双三次上采样，掩膜外用 SR 结果，接缝处用 $\alpha$ 混合。**超分不能作用于运动物体**，这是硬限制。

> 补充：位移 SR 的帧间模糊必须 $<0.5$ 像素，否则相位信息被抹掉。所以 2×2 位移的每帧曝光应限制在 $\approx 1/(2f_{eq})$ 以内（23mm 等效 → 约 1/50 s）。

## 4. HDR 与 ISO 包围：一次诚实的分析

### 4.1 ISO 包围到底能干什么

固定光圈 + 固定快门 + 改变模拟增益时：

- 入射光子数 $N$ **完全相同**；
- 高光端的饱和点由**势阱容量**决定，与增益无关 → **高光一比特都不会多**；
- 变化的是读出噪声/量化噪声相对于信号的比例 → 只是**把暗部提亮得更干净**。

$$\text{DR}_{usable}\approx \log_2\frac{\text{FWC}}{\text{read noise}}\quad\text{——与 ISO 设置无关（模拟增益只是把量化噪声挪位置）}$$

所以结论是：

| 手段 | 高光 | 暗部 | 结论 |
|---|---|---|---|
| 快门包围 | ✅ 真扩展 | ✅ | **真正的 HDR** |
| ISO 包围（固定快门） | ❌ | 🔸 略改善 | 不是 HDR，只减少量化噪声 |
| 双转换增益 DCG | ✅ ~1 stop | ✅ | 同快门下的真扩展，强烈推荐 |
| 交错 HDR（单帧周期内两次读出） | ✅ | ✅ | 预览 HDR 唯一可用的方案 |

### 4.2 推荐配置

$$\text{包围步长 }\Delta EV = 2\text{–}3\text{ stop},\quad N = 3\text{–}5$$

- **3 帧 / 0 + 3 + 6 EV**：时延与质量的最优点。
- **5 帧 / 2 stop 步长**：极高 DR 场景（逆光海面），但增益递减。
- **步长不要超过 4 stop**：合并权重会出现色调反转（tonal inversion），需要额外的单调性约束，实现复杂度陡增。

**快门锁定的场景**（PWM LED、50/60Hz 荧光灯、闪光同步）：此时只能用 ISO 包围 + DCG。判据：光谱/闪烁传感器检测到周期性亮度调制 → 快门强制为 $10\,\text{ms}$ 的整数倍 → 靠 DCG 拿 1–1.5 stop，靠 binning 拿 SNR。

### 4.3 与超分共用一簇帧（关键的效率技巧）

不要"先拍 16 帧超分、再拍 3 帧 HDR"——那是 48 帧、1.6 秒。

**做法：把包围和亚像素抖动塞进同一簇帧。**

- 4 个曝光档 × 每档 3 次重复 = 12 帧；
- 每档的 3 次重复之间，手持抖动天然提供了不同的亚像素相位；
- 同一档内的 3 帧既做噪声平均（$\sqrt{3}$），又做相位填充；
- 12 帧 × 30 fps = 400 ms 采集。

$$\text{总帧数}=N_{EV}\times N_{rep},\quad \text{SR 相位覆盖}\propto N_{rep},\quad \text{SNR 增益}=\sqrt{N_{rep}}$$

**采集顺序用"短–长 – 短–短–长–长"的交错**，而不是"所有短帧、所有长帧"，这样同一曝光档的时间间隔最小，减少场景变化造成的对齐误差。

### 4.4 无鬼影合并的工程要点

- **参考帧永远锁定最短曝光帧**（运动主体最锐），所有长帧向它对齐；
- 长帧只在"参考帧信噪比低于阈值 **且** 局部运动矢量低于阈值"处参与融合，其余区域用参考帧；
- 权重用**噪声模型解析式**（$\sigma^2 = k\cdot I + \sigma_r^2$）而非经验曲线，参数随增益和温度标定；
- 色调映射放在降采样引导图上做，再用 joint bilateral 上采样回全分辨率（省 90% 的计算）。

## 5. 三摄要不要同时全分辨率拍？

**默认不要。** 三条链路同时全速 = 带宽 ×3、热 ×3、功耗 ×3，而收益有限。

| 场景 | 策略 |
|---|---|
| 单点变焦（1×–12×） | 只让目标镜头跑全速，其余只做 AF 相位检测 + 白平衡一致性（低分辨率、低帧率） |
| 2×–4× 中间倍率 | 长焦做 detail injection：把 C1 的高角频细节注入 C0 的视场内（需视差补偿） |
| 远景 / 无穷远 | 跨摄融合有效（视差可忽略） |
| 近距 / 有明显视差 | 关闭融合（用双目视差做深度补偿，复杂度高、ROI 受限），改纯数字变焦 |

**视差门限**：由两光心基线 $B$ 与最近物距 $Z_{min}$ 得 $\Delta x = fB/Z$，当 $\Delta x > 1.5$ px 时禁止跨摄融合。

## 6. ISP 带宽不够时的预览架构

### 6.1 先算清楚量级

$$R = W\cdot H \cdot b \cdot \text{fps}$$

| 链路 | 计算 | 带宽 |
|---|---|---|
| C0 全分辨率 12b@30 | 50.3M × 12 × 30 | **18.1 Gbps** |
| C1 全分辨率 12b@30 | 同上 | 18.1 Gbps |
| C2 12MP 12b@60 | 12M × 12 × 60 | 8.6 Gbps |
| **三路全开** | | **~45 Gbps ≈ 5.6 GB/s** |

一条 4-lane D-PHY 约 10 Gbps，显然撑不住三路全开。但**预览根本不需要这个数据量**：

$$2.5\text{MP（显示）}\times10\text{b}\times60\text{fps} = 1.5\ \text{Gbps}$$

问题在于 ISP 前端为保持画质/AF，习惯按 ~12.5MP@60 跑，于是变成 7.5 Gbps/路。

### 6.2 分级降载杠杆（可叠加）

| 手段 | 倍数 | 备注 |
|---|---|---|
| 传感器内 2×2 binning | ÷4 | 首选，SNR 还更好 |
| 12b → 10b 预览通路 | ÷1.2 | |
| 非活动镜头帧率 60→30/15 | ÷2–4 | 只保留 AF 统计 |
| ROI 裁切到显示宽高比 | ÷1.3 | |
| 传感器/CSI 无损压缩（DPCM） | ÷1.5–2 | 很多 sensor 支持 compressed CSI |
| 3A 统计在 sensor 内算（直方图/AF 窗口） | 省整帧搬运 | 最有效但依赖 sensor 能力 |

**组合后：C0 预览 12.5MP@30 10b ≈ 3.8 Gbps；C1/C2 各 15 fps ROI ≈ 1 Gbps。**总带宽降到约 6 Gbps，完全可控。

### 6.3 架构上的三条铁律

1. **只有"活动镜头"跑高帧率预览，其余镜头跑低帧率"感知流"**（AF 相位、深度、白平衡一致性），不做全图处理。
2. **捕获与预览解耦**：全分辨率帧直接 DMA 进 DRAM 环形缓冲，NPU 异步消费。预览通路始终跑 binning 流，不因拍照而中断。
3. **DRAM 预算**：12 帧 × 50MP × 1.5 B = 900 MB。写入速率 900 MB / 0.4 s ≈ 2.3 GB/s，LPDDR5 轻松。**真正贵的是读取侧**——合并时要读 12 次，所以**合并必须在一次遍历里完成所有帧的加权**（不能 12 遍 read-modify-write）。

> 预览 HDR 的取巧：**交错 HDR 读出**（同一帧周期内长/短两次读出）在 sensor 内完成，对 ISP 完全透明，带宽只增加 1 路低分辨率长帧。这是解决"预览 HDR 不卡"最干净的办法。

## 7. 合成时延预算

目标：**快门到出图 < 1 s**，最好 < 600 ms（快路径）。

| 阶段 | 数据量 | 实际耗时 | 说明 |
|---|---|---|---|
| 采集 12 帧 @30fps | 900 MB | 400 ms | 与处理流水重叠 |
| 全局对齐（1/8 luma） | 0.8 MP × 12 | 20–40 ms | IMU 初值 + 单应 |
| ROI 光流（仅高运动区） | <10% 面积 | 30–80 ms | 自适应 |
| Bayer 域噪声感知合并 | 900 MB 读 | 80–150 ms | **内存带宽受限**，非算力受限 |
| SR 重建（2× 线性） | 50MP 出 | 150–300 ms | INT8 小网络 or 位移-反卷积 |
| 色调映射 + 编码 | 50MP | 100–200 ms | 引导图降采样 |

$$\text{总时延}\approx 0.7\text{–}1.0\ \text{s（全分辨率 12 帧 SR-HDR）}$$

### 优化手段（按性价比排序）

1. **双路径输出**：先出 12.5MP 快路径结果（~250 ms）供用户确认，全分辨率在后台 refine 并替换。感知时延直接砍到 250 ms。
2. **流水线化**：第 2 帧到达即开始对齐，采集结束时对齐已完成，只等合并尾部。上表已按此估算。
3. **Bayer 域合并 + 一次遍历**（避免多遍 pass）。
4. **SR 用"位移-叠加 + 反卷积"代替 MAP 迭代**：把 PSP 当线性算子，用一次 Wiener/Richardson 反卷积收尾，比迭代求解快 5–10×，质量损失很小。
5. **分块处理（512×512 + halo）**，避免整图驻留，提高 cache 命中。
6. **只在中高频区域做 SR**：平坦区（天空、虚化背景）用双三次，省 40–60% 算力。

## 8. 光谱传感器：色彩与色温的正确用法

### 8.1 为什么需要它（三通道 AWB 的死穴）

三通道 AWB（灰世界/白块/学习式）在**窄带 LED**（450 nm + 610 nm 双峰，CRI < 80）下会系统性偏色——因为"灰色假设"在这个光谱下根本不成立。你看到手机在廉价 LED 下拍出紫/绿偏色，就是这个原因。

光谱传感器直接测 **SPD**，把"猜光源"变成"测光源"。

### 8.2 硬件选型与布置

- **8–16 通道窄带滤光阵列**（FWHM 20–30 nm，400–700 nm）：成本低、体积小（2×2 mm）、I²C，足够反演 SPD 与 CCT。
- **微型光谱仪**（衍射式，500–900 nm）：能算显色指数、同色异谱指数，适合专业场景。
- **布置**：带余弦校正的漫射窗，朝向与主摄同向，确保测到的是"照亮被摄体的光"而非环境光。

### 8.3 反演与使用

测量模型是欠定的（N 个通道推连续 SPD）：

$$\mathbf{m}=\int \mathbf{R}(\lambda)\,S(\lambda)\,d\lambda$$

用基函数展开 + 正则化求解：

$$S(\lambda)=\sum_k a_k B_k(\lambda),\quad \hat{\mathbf{a}}=\arg\min_{\mathbf{a}}\|\mathbf{R}\mathbf{B}\mathbf{a}-\mathbf{m}\|^2+\gamma\|\mathbf{a}\|^2,\ \ \text{s.t. } S\ge 0$$

基组 $B$ 用「黑体族 + 日光特征向量 + LED 窄峰基」，比纯平滑先验准得多。

由 $S(\lambda)$ 算出：

| 输出 | 用途 |
|---|---|
| 色度 $(x,y)\to(u,v)$ → **CCT + Duv** | 写入 EXIF；预览锁定 AWB |
| **光源自适应 CCM** | $A^*=\arg\min_A\sum_j w_j\,\Delta E_{00}\!\left(A\cdot\mathbf{r}_j(S),\,\mathbf{t}_j\right)$，比固定 D65 CCM 在异色光源下 ΔE 降低 30–50% |
| **逐摄 WB 增益** | 三支镜头 CFA/IR-cut 不同，用同一 $S(\lambda)$ 解析算出各自增益 → **变焦切换时色彩无缝**，且省产线逐模组标定 |
| 闪烁指标 | 测纹波周期/占空比 → 直接定快门（10 ms 整数倍） |

### 8.4 和图像 AWB 的融合

光谱传感器只测**一个点**，图像 AWB 提供**空间分布**。正确的融合是把它当锚点而非替代：

$$g_{final}=g_{img}\cdot\left(\frac{g_{spec}}{g_{img}}\right)^{\alpha},\quad \alpha\approx0.5\text{–}0.7$$

或者做贝叶斯融合：以光谱测得的 CCT 为高斯先验，图像 AWB 的每区块估计为似然，得到空间增益图（再做平滑防止边界突变）。这样既解决"整片红墙导致灰世界失效"，又不丢掉混合光源的空间信息。

<details>
<summary><b>光谱传感器的坑（点开）</b></summary>

1. **PWM 闪烁**：LED 调光会让瞬时 SPD/CCT 大幅跳变。必须积分满一个 PWM 周期或 ≥ 20 ms；输出同时报告纹波幅度，纹波大时降低 $g_{spec}$ 的权重。
2. **漫射窗余弦响应**：不做余弦校正时，斜入射光会让短波被低估 → CCT 偏移几百 K。
3. **温度漂移**：滤光片中心波长随温度漂 ~0.01–0.05 nm/K，必须逐温度点标定。
4. **单点代表性问题**：逆光/大面积高饱和物体时，传感器看到的光 ≠ 主体的光。用图像 AWB 的空间图纠偏。
5. **标定成本**：$R(\lambda)$ 需要用单色仪或 LED 阵列逐台测，或用产线抽检 + 批次参数。这一项常常是项目最大的隐性成本。
6. **它与主摄的光谱响应耦合**：CCM 自适应依赖相机 SSF 的准确标定，SSF 错了，光谱信息反而放大误差。

</details>

## 10. 落地优先级（按 ROI 排序）

1. **预览分级架构 + 捕获/预览解耦** —— 不改画质，纯工程，收益最大（流畅度）。
2. **MFNR（8 帧噪声平均）** —— 1.2–1.5 stop，算法成熟，先做这个。
3. **快门包围 HDR + DCG** —— 真正的动态范围。
4. **光谱传感器自适应 AWB/CCM** —— 感知质量提升最明显，且顺手解决三摄色彩一致性。
5. **广角 2×2 像素位移** —— 物理上有依据，但需要高精度 OIS/VCM 与位置反馈，工程难度最高。
6. **跨摄 detail injection / 无缝变焦** —— 视差问题最难，只对远景开。

---

**最后一句提醒**：这套系统里最容易被忽略的约束是**热**。12 帧 50MP 连续读 + NPU 满载，模组温升会在 20–30 帧内改变暗电流和黑电平，进而破坏你精心标定的噪声模型权重。**噪声模型必须带温度项，并且在连拍结束后做一次暗帧校正**——否则 HDR 合并出来的暗部会横向条纹化，这个 bug 极难定位。

# 0.98″ / 50MP 主摄 + 14 通道光谱 + 长焦 + 超广角：合成阶段的注意事项

## 1. 先做一次主摄检查：它会改变整个合成策略

| 检查项 | 影响 | 如果答案是… |
|---|---|---|
| **是否 2×2 OCL（共享微透镜）** | 决定“50MP 是否为真正采样” | 是 → 输出实际是 remosaic 内插，真实空间采样间距 3.2 µm，**亚像素位移必须 ≥1.6 µm 才有新信息** |
| 是否 DCG 双转换增益 | 决定 HDR 能否单帧扩展 | 是 → 少拍 1 帧，且在合并权重上要分两段处理 |
| 最快快门 / 最低等效 ISO | 决定高光天花板 | 若 1/8000 + ISO100，**晴天 f/1.6 需要 1/12800 —— 顶到快门极限**，高光帧会被保护快门卡住 |
| IR-cut 与 CFA 光谱响应 | 决定逐摄 CCM 与色彩一致性 | 三支镜头必不同，必须逐摄标 SSF |

### 1.1 真正的解析力上限由镜头决定，像素不是限制

1.6 µm 像素的奈奎斯特是 **312 lp/mm**。而现实中的手机 1″ f/1.6 镜头，中心 MTF50 大约 **150–250 lp/mm**，边缘更低；衍射截止在 1136 lp/mm 处，完全不是瓶颈。

$$\text{实际极限}=\min(\text{镜头像差},\ \text{衍射},\ \text{像素奈奎斯特})\approx\text{镜头像差}\approx200\,\text{lp/mm}$$

**结论（很重要）**：在 1″/1.6 µm 这个组合上，**像素位移超分的解析力收益只有约 1.2–1.3 倍线性，且集中在中心，边缘接近零**；如果传感器是 2×2 OCL，收益主要来自“去掉 remosaic 的插值伪影”，而不会翻倍解析力。即使做 4×4（16 帧）位移动也无法达到这个收益。

> **因此帧预算应该压在 MFNR（降噪）+ HDR（动态范围）上，而不是超分上。**
> 推荐：**8–10 帧一簇**，其中 3 档曝光 × 3 次重复；不要上 16 帧。每多一帧都是 20–30 ms 采集 + 100 MB 内存搬运。

大底 + 三摄异构，几何对齐可以用单应近似解决；**光度不匹配才是融合边界出现台阶、色块、噪斑的根本原因**。

<summary><b>合成前必须拉平的 6 项光度量（点开）</b></summary>

| 项目 | 在本系统上有多严重 | 合成时的处理 |
|---|---|---|
| **镜头 shading（相对照度）** | 1″ f/1.6 边缘掉 40–50%（约 1.2–1.5 stop），三支镜头曲线完全不同 | 融合前统一校正到**绝对辐射亮度**；不能用各自的“归一化到中心 1.0” |
| **黑电平 / OB 漂移** | 大底功耗高、升温快，暗电流约每 6–8 K 翻倍 | 每帧读光学黑行实时更新；帧间线性插值；burst 后补暗帧 |

| **曝光归一化** | 12 帧 EV 不同，直接加权平均会导致画面变糊 | 先除以曝光比归一到同一辐射亮度，再按噪声模型加权 |

## 3. 大底带来的四个专属合成陷阱

### 3.1 浅景深导致跨摄融合出现“清晰度断层”

$$H=\frac{f^2}{Nc}=\frac{8.7^2}{1.6\times0.0032}=14.8\,\text{m}$$

- 物距 **1 m** → 景深仅 **13.6 cm**
- 物距 10 m → 景深 5.97 m – 30.9 m

主摄景深如此之浅，**长焦与主摄的清晰面几乎不可能重合**。做 detail injection 时，融合边界会出现“这边锐、那边虚”的断层，比噪点更显眼。

处理：
- 用双目视差算粗深度图，**只在两摄失焦模糊都低于阈值的区域融合**；
- 或者把跨摄融合限制在远景物距（见 3.3）；
- 必要时按深度做**清晰度匹配**（给虚的一侧做匹配程度的模糊，让过渡自然）——反直觉但有效。

### 3.2 暗角导致 SNR 在视场内非常不均匀

角落已经少了 1.2–1.5 stop 的光子，再叠加 1″ 的高读出速率，**角落的噪声比中心差 2–3 倍**。

必须做**空间变化的处理**，否则融合结果会出现“中心干净、四角花”：
- HDR 合并权重按 $(x,y)$ 缩放；
- 锐化强度按视场衰减（不能全图统一 USM）；
- SR / detail injection 在 0.7 视场外降权到 0。

### 3.3 视差：跨摄融合只在远景有效（给出可执行门限）

基线 $B\approx30$ mm，$f=8.7$ mm，1.6 µm 像素：

$$\Delta x_{px}=\frac{fB}{Z\,p}$$

| 物距 | 视差 | 能否跨摄融合 |
|---|---|---|
| 1 m | **163 px** | ❌ 绝对不行 |
| 10 m | 16 px | ❌ 需精确深度补偿 |
| 30 m | 5.4 px | 🔸 勉强，需 flow 精修 |
| 100 m | 1.6 px | ✅ 可用 |

**门限建议**：$\Delta x < 2$ px 才允许 detail injection 全权重，2–6 px 线性衰减，>6 px 关闭。**近摄、人像、微距一律走单摄 + 数字变焦。**

### 3.4 滚动快门不同步

1″ 50MP 全分辨率读出约 **20–30 ms**，长焦小底只要 5–10 ms。三摄同一“帧号”的**实际曝光时刻不同**。

- 运动物体在融合时错位；
- 多帧包围时，长焦帧与主摄帧的时间戳差 → 对齐残差；
- 必须**按行时间戳做几何校正**，不能只用单一全局时间戳。IMU 积分要用每行的实际时刻。

## 4. HDR 合成：这套系统的单帧 DR 已经很高，不要过度包围

1″ 1.6 µm、FWC ≈ 12000 e⁻、高 CG 读出噪声 ≈ 1.5 e⁻：

$$\text{DR}=20\log_{10}\frac{12000}{1.5}=78\,\text{dB}\approx13\,\text{stop}$$

加 DCG 可达 ~14 stop。所以：

| 场景 | 包围策略 |
|---|---|
| 普通逆光 | **2 帧**（0 / +3 EV）足够 |
| 极端（逆光海面、夜灯） | 3 帧（0 / +3 / +6 EV） |
| 晴天高光 | **快门上限卡住**，需 ISO 50（低 CG）或多帧 ND，靠增益而非时间拿高光 |

### 4.1 三个必须处理的细节

1. **DCG 两段不能混算权重**：高 CG 段读出噪声 1.5 e⁻、低 CG 段 3 e⁻ 且 FWC 不同。合并权重必须按“该像素实际处于哪个增益段”分段计算，否则 DCG 切换点会出现环状伪影。还要做**逐列增益匹配校正**（两段的列固定模式噪声不同）。
2. **长短帧网格必须统一**：如果你把长曝光帧 2×2 binning 到 12.5MP（3.2 µm 网格），短帧是全分辨 50MP（1.6 µm 网格），**两者网格不同，直接合并必须重采样，会引入半像素相移和 MTF 损失**。
   - 要么 **全部用全分辨率帧**，要么 **整个 HDR 合并都在 12.5MP binned 域做**。
   - 不要混用。这一条在实际项目里经常被忽略，表现为“HDR 出图偏软”。
3. **参考帧锁定最短曝光帧**，长帧只在“参考帧 SNR 低于阈值 且 运动矢量低于阈值”处参与；运动掩膜内回退到参考帧。

## 5. 像素位移：在这套硬件上的真实配置

| 情形 | 可用位移步长 | 推荐帧数 | 实际线性增益 |
|---|---|---|---|
| 非 2×2 OCL | 0.8 µm（半像素） | 8 帧（2×2 相位 + 噪声平均） | 1.2–1.3×（镜头受限） |
| **2×2 OCL（1″ 50MP 常见）** | **≥1.6 µm（半个 OCL 块）** | 4–8 帧 | 1.5–1.8×（同时消除 remosaic 插值伪影） |

**2×2 OCL 的关键物理约束**：一个微透镜覆盖 2×2 同色像素，4 个子像素对应光瞳的 4 个象限 —— 它们是**角度采样，不是空间采样**。所以：
- 全分辨 50MP 输出是 **remosaic 内插结果**，真实空间采样间距 3.2 µm；
- 位移量小于 1.6 µm 时，**四个子像素看到的是同一个光学点，拿不到任何新信息**；
- 采样孔径是 3.2 µm 的 box，MTF 在 312 lp/mm 处有 sinc 零点 —— 恰好等于 1.6 µm 采样的奈奎斯特，所以 2× 位移拿到的最高频对比度很低。

**结论：别用 16 帧做 4×4。** 8 帧（4 相位 × 2 次重复做降噪）是这套硬件的收益拐点。

## 6. 14 通道光谱传感器在合成流程里如何接入

### 6.1 它只该接在三个点上

| 接入点 | 做什么 | 不要做什么 |
|---|---|---|
| **AWB** | 由 $S(\lambda)$ 算 CCT/Duv 作高斯先验，图像 AWB 出空间增益图 | 不要用它替代逐像素 AWB |
| **CCM** | $A^*=\arg\min_A\sum_j w_j\Delta E_{00}(A\cdot\mathbf{r}_j(S),\mathbf{t}_j)$，**逐摄各算一套** | 不要三支镜头共用一套 CCM |
| **高光彩色恢复** | 通道先饱和时用 SPD 约束通道间关系，减少“高光发白/发粉” | 不要用它做曝光决策（那要看直方图） |

### 6.2 14 通道带来的额外注意

- **标定维度上升**：$R$ 矩阵是 14×λ，逐台或批次标定；通道间串扰必须进矩阵，否则反演会系统偏移。
- **温度补偿要逐通道做**：不同滤光片的中心波长温漂系数不同（~0.01–0.05 nm/K），统一补偿会引入色偏。
- **积分窗口必须覆盖整个 burst**：多帧包围跨越 400 ms，PWM 光源下 SPD 在变；应连续采样并加权平均，而不是只测一次。
- **同步**：光谱采样窗口必须与三摄的快门窗口重叠；滚动快门的行时刻不同，取中间行时刻。
- **空间代表性**：光谱传感器是**单点**，只代表“照亮场景的光”。遇到大面积高饱和物体（红墙、绿植）时，必须以图像 AWB 的空间图为主、光谱只做全局锚定：$g=g_{img}\cdot(g_{spec}/g_{img})^{\alpha}$，$\alpha\approx0.5\text{–}0.7$，纹波大/检测到混合光时把 $\alpha$ 降到 0.3 以下。

### 6.3 额外收益：解决变焦色彩切换

三支镜头的 CFA、IR-cut、相对照度都不同，出厂标定各自为政就会在变焦时跳色。**用同一个 $S(\lambda)$ 解析算出三套增益/CCM**，是解决“变焦色彩无缝”最省事的路径，也能砍掉产线逐模组的光源箱标定。

## 7. 融合顺序和数据域（顺序错了，前面全白做）

```text
raw(12b) 
 → OB/黑电平（逐帧 + 温度插值）
 → 坏点校正 DPC
 → shading 校正（逐摄 LUT，统一到绝对辐射亮度）   ← 必须在合并之前
 → 噪声模型估计（位置 × 增益 × 温度 三维）
 → 几何对齐（IMU 行时间戳 → 全局单应 → 1/8 luma 验证 → ROI 光流）
 → 【Bayer 域】曝光归一化 → 时域加权合并（HDR + MFNR 一次遍历）  ← 权重用 raw 未乘增益域
 → 去马赛克 / remosaic
 → SR 重建（可选，仅主摄、仅中心 0.7 视场）
 → WB 增益（14ch 光谱） ← 在合并之后
 → CCM（SPD 自适应，逐摄）
 → 色调映射（降采样引导图 + joint bilateral 上采样）
 → 空间变化锐化（按视场与 SNR 衰减）
 → 编码 + metadata（CCT/Duv/曝光表/光谱 SPD 摘要）
```

### 数值精度（很容易出错）

- 12 bit × 12 帧累加需要 **17 bit** → 中间缓冲用 **int32 或 fp32**。
- **不要用 fp16** 做累加：11 bit 尾数装不下 12 bit raw × 增益，会在暗部产生阶梯。
- 归一化分母（权重和）单独用 fp32 维护。

## 8. 时延与热：这套组合的瓶颈不在算力

| 阶段 | 这套硬件的实际耗时 |
|---|---|
| 采集 8–10 帧 | 8×~30ms（读出）+ 曝光时间 → **250–400 ms** |
| 对齐（1/8 luma + ROI flow） | 30–70 ms |
| Bayer 域合并（8 帧 @50MP） | 80–150 ms（**内存带宽受限**） |
| SR（可选，2× 线性） | 100–200 ms |
| 色调映射 + 编码 50MP | 120–200 ms |
| **合计** | **0.6–1.0 s** |

优化要点：
1. **双路径输出**：先出 12.5MP binned 结果（~250 ms），全分辨率后台 refine。
2. **一次遍历合并**：8 次 read-modify-write 会让内存带宽炸掉。
3. **热**：1″ 全速 + NPU 满载，30 帧内模组温升可达 3–5 K → 暗电流涨 30–60% → **必须带温度项的噪声模型 + burst 后补暗帧**，否则 HDR 暗部出横向条纹，这个 bug 极难定位。

## 9. 验收指标（建议直接进 CI）

| 指标 | 方法 | 目标 |
|---|---|---|
| MTF50 中心 / 0.7 视场 | 斜边法 | 分别记录，边缘不应比中心差 >30% |
| 融合边界 seam 度量 | 边界处梯度突变 + 二阶差分 | 无可见台阶 |
| $\Delta E_{00}$ | 24 色卡 × 3 光源（D65 / A / 窄带 LED） | 均值 <1.5，最大 <3.5 |
| 高光恢复率 | 已知 DR 靶标 | >90% 可恢复 |
| 变焦解析力连续性 | 1×–12× 扫描 MTF50 | 曲线无凹坑（凹坑 = 焦段切换点没对齐） |
| 快门到出图 P50 / P95 | 端到端打点 | P50 <700 ms，P95 <1.2 s |

---

<details>
<summary><b>最容易出问题的 8 条（可直接当 checklist 用）</b></summary>

1. **以为 50MP 是真采样** —— 2×2 OCL 下是 remosaic 内插，SR 步长必须 ≥1.6 µm。
2. **长短帧网格不统一就合并** —— 长帧 binning、短帧全分辨，直接合并会偏软。
3. **shading 放在合并之后** —— 各帧辐亮度基准不同，权重全错。
4. **WB 增益在合并前乘** —— 三通道权重不同，暗部偏色。
5. **跨摄融合不设视差门限** —— 1 m 处 163 px 视差，直接糊成鬼影。
6. **DCG 两段用同一套噪声参数** —— 切换点出环状伪影 + 逐列偏移。
7. **fp16 累加 12 帧** —— 暗部阶梯。
8. **光谱只测一次、且测在 burst 之外** —— PWM 光源下 SPD 在变，白平衡漂。

</details>

---

**一句话总结**：这套硬件的瓶颈是**镜头像差与光度一致性**，算力通常不是瓶颈。策略上应把帧预算给 MFNR 和 HDR，把工程预算给 shading / OB / DCG / 视差门限 / 逐摄 CCM，而不要花在 16 帧超分上；14 通道光谱的最大价值是**用物理量替换“猜光源”**，让三支镜头在变焦时色彩无缝，并省掉产线逐模组标定。
