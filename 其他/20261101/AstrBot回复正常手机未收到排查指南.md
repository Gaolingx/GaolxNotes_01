# AstrBot回复正常手机未收到排查指南

## 🧑‍💻 User

我看astrbot日志发现bot有回复为什么手机端没收到

---
## 😀 默认助手 (7)

## 先说结论

日志里出现“回复内容”（通常是 `[信息]` / `reply` / 模型输出那几行）只能说明 **LLM 已经生成并交出了文本**，并不代表 **消息已经成功投递到平台**。

AstrBot 的发送链路是这样的：

```
LLM 生成 → 事件响应器 → 消息段组装 → 平台适配器 → 平台 API/WebSocket → 平台服务器 → 你的手机
```

从第 3 步开始，任意一步失败，日志里都可能已经留下了“已回复”或“发送: xxx”的字样，但手机端仍然收不到。因此关键是要查看 **那条回复之后** 的几行日志。

---

## 第一步：在日志里定位这 3 处

| 要找的位置 | 关注点 | 说明 |
|---|---|---|
| 回复内容**前一行** | `unified_msg_origin` 或会话 ID | 例如 `aiocqhttp:GroupMessage:123456`。如果这个 ID 不是你手机端的会话，就说明消息发到了别处 |
| 回复内容**后 3 到 10 行** | `发送失败` / `send` / `retcode` / `code=` / `ERROR` / `Traceback` | 这里才是真正的发送结果 |
| 同一时间段的**平台侧日志** | NapCat / Lagrange / Telegram 自身的日志 | 很多失败只记录在平台端，AstrBot 侧看起来一切正常 |

> 一个典型误区：AstrBot 日志里出现 `[信息] 回复: ...` 之后，适配器抛出了一个被捕获的异常，而且只记录为 `[警告]`，于是你只看到“有回复”。

---

## 第二步：按可能性从高到低排查

**1. 平台风控 / 主动消息被拦截（QQ 系最常见）**

QQ 侧对机器人发送的消息有严格限制：

- **被动回复**（引用刚收到的消息）可以发送
- **主动推送**（没有触发消息就发送）几乎都会被拦截，而且不会报错
- 私聊需要对方是好友；群聊需要 @ 或者被允许发言；临时会话基本发送失败

如果你使用的是 NapCat 或 Lagrange，请到它们的日志里搜索 `风控`、`send`、`retcode`。

**2. 发到了错误的会话或实例**

- 多个 AstrBot 实例连接了同一个 bot 账号，双方争抢同一个 WebSocket 连接，事件被其中一个实例接收，而回复又从另一个实例发出，结果导致消息丢失。
- 配置了“白名单群”或“指定会话”，回复被路由到了其他会话。
- 在 WebUI 的对话测试里看到的回复，和手机端的会话根本不是同一个。

**3. 消息段平台不支持**

- 回复里包含 Markdown、公式或 HTML，而 QQ 不识别这些内容，整条消息可能被丢弃。
- 包含图片、文件或语音，并且用的是容器内的本地路径，NapCat 读不到这些文件，导致整条消息发送失败。
- 文本超长，超过平台的单条上限后被截断或直接拒收。

**4. 流式输出或合并消息失败**

如果开启了流式输出，AstrBot 会先累积再一次性发送。如果中途出现异常或超时，日志里会有“回复”记录，但最终没有发出。

**5. 与网络或连接状态相关**

反向 WebSocket 已经断开，但 AstrBot 仍认为连接存在，于是发送请求没有响应，也不会报错。

- [ ] 查看平台端（NapCat、Lagrange 控制台或 Telegram）在同一秒的日志
- [ ] 临时把回复改成纯文本 `test`，排除消息段问题
- [ ] 临时关闭流式输出
- [ ] 私聊和群聊各测一次，看是否只有一种场景失败
- [ ] 检查是否有第二个 AstrBot 实例正在连接同一个账号
- [ ] 如果是 Docker，确认图片、音频使用可访问的 URL，而不是本地路径
- [ ] 如果是 QQ 官方机器人，确认是否触发了“主动消息”限制

## 我需要你补充三件事

要给出确切原因，至少需要以下信息：

1. **平台和接入方式**：QQ（NapCat、Lagrange 或官方机器人）、Telegram、微信、飞书？
2. **一段日志**：从那行“回复”往前 5 行、往后 10 行，直接粘贴原文即可，敏感信息可以打码
3. **场景**：是群聊还是私聊？是第一次触发，还是之前正常、突然就收不到了？

有了这些，我基本能直接指出问题出在生成、组装、适配器还是平台风控的哪一环。
