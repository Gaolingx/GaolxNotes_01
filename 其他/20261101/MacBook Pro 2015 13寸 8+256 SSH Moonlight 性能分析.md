## 结论先行

- **SSH：完全够用，性能过剩。** 就算是 2015 年的双核 i5，用来跑 SSH + tmux + vim，也只用掉个位数的 CPU。
- **Moonlight：1080p60 + H.264 够用，但有明确的上限。** 关键问题是它只有一次 H.264 硬解能力，**没有 HEVC 硬解**，所以 4K、HDR、高码率 HEVC 这几条路基本走不通。

---

## 拆开看：两个用途差异很大

| 项目 | 2015 13" 的配置 | SSH | Moonlight |
|---|---|---|---|
| CPU | i5-5257U 2.7GHz（双核四线程，Broadwell，28W） | 压力可忽略 | 够用（硬解不占 CPU） |
| GPU | Iris 6100（无独显，共享内存） | 无关 | **只能 H.264 硬解** |
| 内存 | 8GB LPDDR3（**焊死，不可升级**） | 够 | 够（客户端不吃内存） |
| 硬盘 | 256GB PCIe SSD | 够 | 够 |
| 屏幕 | 2560×1600，60Hz | 无所谓 | 60Hz 上限，不能 120fps |
| 系统 | 最高 macOS Monterey 12 | 无影响 | 满足 Moonlight 要求（10.13+） |

## Moonlight 真正的限制在哪里

<details>
<summary><b>1. 编解码：只能用 H.264（最重要）</b></summary>

Broadwell 世代的 Intel Quick Sync 只有 **H.264 / VP8 / JPEG** 硬解，**HEVC 硬解是从 Kaby Lake 才开始完整支持的**。所以：

- 在 Moonlight 里可以选 **H.264**，走 VideoToolbox 硬解，1080p60 轻松无压力，CPU 占用通常在 10% 以内。
- 一旦选择 **HEVC**，就会退回到软解，双核 2.7GHz 在 1080p60 下会掉帧、发烫、风扇狂转，**不建议**。
- **HDR 就别想了**：Moonlight 的 macOS HDR 要求 HEVC Main10 硬解，这台机器硬件上就不支持，选项很可能是灰的。

</details>

<details>
<summary><b>2. 分辨率：1080p 是较稳妥的选择</b></summary>

- 不要因为它屏幕是 1600p 就顺手选择 2560×1600 或 4K。解码本身没问题，但 Iris 6100 还要做缩放和合成，Retina 全屏时帧时间会抖动。
- **建议固定 1920×1080（或 1920×1200）@60fps**，码率 20–40 Mbps，画质和流畅度超出大多数人的预期。

</details>

<details>
<summary><b>3. 网络比性能更容易成为瓶颈</b></summary>

2015 13" 是 **3×3 802.11ac（BCM43602，理论 1.3Gbps）**，硬件不差，但 Wi-Fi 的抖动和蓝牙外设干扰会直接变成串流卡顿：

- 有条件就 **Thunderbolt 2 → 千兆网卡转接器** 走有线，这是这台机器做 Moonlight 客户端性价比最高的一个投入。
- 只能 Wi-Fi 的话：确保连 5GHz、靠近 AP、关掉蓝牙耳机以外的 2.4G 干扰源。

</details>

## 建议的 Moonlight 设置（2015 13" 专用）

```
分辨率:   1920×1080
帧率:     60 FPS
码率:     20–40 Mbps（局域网可以拉到 50）
编解码:   H.264（强制，别选 HEVC）
HDR:      关闭
垂直同步/帧率同步: 开
```

快捷键记一下：`Ctrl+Alt+Shift+S` 打开性能统计，看 `decode time` 和 `frame latency` 是否稳定；`Ctrl+Alt+Shift+Q` 退出会话。

## 几个必须提醒的问题

1. **8GB 内存是难以改变的硬伤**，不是今天的瓶颈，但基本封死了这台机器的未来。如果打算长期当主力，同时开 Chrome 几十个标签 + Docker + 串流就会开始 swap。SSH 和 Moonlight 单独使用时没有压力。
2. **电池**：2015 年的机器如果还是原装电池，健康度大概率已经很差（可能鼓包）。长期插电使用没问题，想移动使用先查一下循环次数和健康度。
3. **散热**：双核 28W，H.264 硬解时风扇会转但不至于起飞；如果发现风扇很吵，多半是走了软解（说明编码器选错了），或者后台在跑索引。
4. **宿主端才是关键**：Moonlight 客户端的门槛很低，体验好坏 90% 取决于**宿主 PC 的编码器（NVENC / AMF / QuickSync）**和局域网质量。现在主流方案是用 **Sunshine** 当宿主（GeForce Experience 的 GameStream 已经不再推荐），宿主端支持 HEVC 的话，也别忘了给这台 Mac 客户端单独降级到 H.264。
5. **SSH 硬件无关**：真正影响体验的是终端软件和网络延迟，`iTerm2` / `Warp` / 原生 Terminal 都能跑。注意 Warp 这类新终端对系统版本要求较高，Monterey 上可能装不了最新版，原生 Terminal + tmux 最稳。

---

## 总结

**这台机器恰好落在“够用”这条线上：** SSH 毫无压力，Moonlight 在 1080p60 H.264 下有不错的体验，该有的硬解它都有；但它**明确不支持** HEVC 硬解、HDR、高刷和 4K，这也是 2015 年平台的技术上限，而不是配置不足。

如果你的用法就是“远程办公 SSH + 局域网/异地串流游戏到 1080p”，这台机器完全能用；如果指望 4K HDR 串流或者当主力生产力机，那就该换 M 系列了。
