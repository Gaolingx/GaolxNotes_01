# 队列自动机是图灵完备的

## 🧑‍💻 User

DFA/NFA -> DPDA -> NPDA -> Turing machine，那么Queue Automaon也是图灵完备的吗

---
## 😀 默认助手 (7)

## 先给结论

**是。队列自动机（queue automaton / queue machine，一个 FIFO 队列 + 有限状态控制 + 可检测空队列）是图灵完备的，而且确定型版本就已经完备。**

也就是说：你那条链在 DPDA 之后的"下一步"看起来应该是更强的 NPDA，但一旦把记忆结构从 **LIFO（栈）** 换成 **FIFO（队列）**，跳过的不是一小级，而是**直接跳到天花板**：

| 机器 | 记忆结构 | 语言类 | 确定型 vs 非确定型 |
|---|---|---|---|
| DFA / NFA | 无（有限状态） | 正则 | $\mathrm{D} = \mathrm{N}$ |
| DPDA / NPDA | 1 个栈（LIFO） | 确定型/上下文无关 | $\mathrm{D} \subsetneq \mathrm{N}$ |
| **DQA / NQA** | **1 个队列（FIFO）** | **RE（递归可枚举）** | $\mathbf{D = N = TM}$ |
| 2 栈机 / 2 队列机 | — | RE | 同上 |
| TM | 纸带（可双向访问） | RE | 同上 |

所以这里有一个很有意思的"层级断裂"：**栈的情况里，非确定性真的买到了力量（DCFL ⊊ CFL）；队列的情况里，非确定性买不到任何东西，因为确定型就已经到达了 RE 的天花板。** $\mathrm{DQA} = \mathrm{NQA} = \mathrm{RE}$，这一层没有"确定型子类"可言。

---

## 为什么？核心直觉

关键在于**下标/访问方式**，而不是内存大小：

- **栈**：只能访问一端。栈底被"压死"了，你**永远回不去**，所以内存内容只能被单向消耗 → 等价于一棵推导树 → 上下文无关。
- **队列**：虽然两端都只能各做一件事（队首读、队尾写），但**每个元素最终都会回到队首**。也就是说，队列天然是一个**可循环的环形纸带**：把队首读出的符号重新入队，就是"读指针前进一格"。

一旦"绕圈"成为可能，你就拥有了一条**无界长的环形纸带 + 一个标记**，而"环形带 + 一个标记"和 TM 的纸带在表达能力上是一回事（只差一个整体旋转的等价类）。这就是 FIFO 一跃到 RE 的根本原因。

一句总结：**栈是"一次性"的存储，队列是"可回收"的存储；可回收 ⇒ 可以做扫描-修改循环 ⇒ 图灵完备。**

<summary><b>构造思路（两条路线，含一处容易踩的坑）</b></summary>

### 路线一：直接模拟 TM —— 环形纸带 + 两个标记

把队列内容看成一条环形带，里面放两类特殊符号：

- $\triangleright$：**起点标记**（固定，用来"对齐"和对"一圈"计数）
- $\hat{\sigma}$：**头部标记**，表示读写头在存着符号 $\sigma$ 的格子上

模拟一步的流程（每次做一次"绕环扫描"，用 $\triangleright$ 的再次出现判定"一圈结束"）：

1. **读/写**：绕行时遇到 $\hat{\sigma}$，就是头部所在格；可以把它改成 $\widehat{\sigma'}$。
2. **右移**（头部标记右移一格）：遇到头部标记时先写入普通符号，把"标记"这个信息**暂存在有限状态里**，等处理下一格时再输出 $\hat{\cdot}$。这就是"延迟一格输出"，一步完成。
3. **左移**：**不要**试图把标记往左放（左邻格已经过去了），而是改用"**把整条纸带相对 $\triangleright$ 右移一格**"。实现方式是流水线式延迟：先输出 $\triangleright$，之后每读入一个符号就输出上一个暂存的符号；当 $\triangleright$ 再次出现在队首时，这一圈的结束点就是已知的，最后把手里暂存的符号冲出去即可。

关键点：**必须有"起点标记"来做对齐**。因为一个纯队列的"整体延迟一格"从队首对齐看恰好是恒等操作（$y_1\ldots y_n \to y_1\ldots y_n$），只有相对 $\triangleright$ 对齐，延迟才是真正改变头部相对位置的操作。这是这类证明里最容易写错的地方。

代价：模拟一步要绕一圈，$O(n)$ 时间（$n$ 为纸带非空白区长度），所以整体是平方级慢化 —— 对可计算性/可判定性的转移毫无影响。

### 路线二：走 tag system（这是文献里最干净的严格路线）

Post 的 **tag system** 本质上就是队列机：

> 每步读队首符号 $a$，从队首**删掉 $p$ 个**符号，再按有限映射 $a \mapsto w(a)$ 向队尾**追加**字符串 $w(a)$。

而 **2-tag system 是图灵完备的**（Cocke–Minsky 定理：任意 TM 可被 2-tag system 多项式时间模拟；这也直接给了 tag system 停机问题的不可判定性）。队列机显然能实现 tag system 的每一步（"删掉 p 个"就是连续出队 p 次而不写回；"追加字符串"就是连续入队）。所以：

$$\text{TM} \;\Longrightarrow\; \text{2-tag system} \;\Longrightarrow\; \text{确定型队列自动机}$$

同族的还有 Cook 的**循环标签系统**（cyclic tag system）—— 二进制字母表、完全确定、单队列，也是通用计算模型。这条路线的好处是每一步都是严格构造，不依赖"直觉上的环形带"。

<details>
<summary><b>"完备"的边界条件（这些限制一旦加上，就掉下来了）</b></summary>

- **队列长度必须有界吗？** 必须**无界**。若限制长度 $\le k$（常数），不同配置只有 $|Q|\cdot|\Gamma|^k$ 个 → 退化成**有限自动机**，只认正则语言。（和"栈深度有界 ⇒ 正则"是同一个道理。）
- **字母表大小**：需要 $|\Gamma| \ge 2$ 才能编码信息。**单符号字母表**的队列只是一根长度计，退化成**单计数器机**（能算 $a^n b^n$ 之类，但远非完备）。
- **确定性**：**不需要**非确定性，确定型就够了（见上表）。这一点和 PDDA/NDPA 的对比正是最有教学价值的点。
- **模型细节**：不同教材对"是否允许出队后不写回""是否允许 $\varepsilon$-动作""接受方式（终态 / 空队列）"的约定不同，但不影响完备性结论。
- **后果**：队列自动机上的一切非平凡问题都不可判定 —— 停机、空性（$L(M)=\varnothing$?）、等价性、包含关系全部 undecidable。这里**没有**类似 CFL 那样的可判定算法体系。这也是为什么"队列语言"不是一个值得单独命名的语言类：它**就是** RE。

</details>

<details>
<summary><b>顺带一提的几个相邻结论（说明"一条队列"有多便宜）</b></summary>

- **2 个计数器**（counter machine）就图灵完备 —— 比队列还"穷"。
- **1 栈 + 1 队列**、**2 队列**、**2 栈**：显然完备（2 栈是经典结果）。
- **1 个队列就已经够**，不需要任何其他结构 —— 这正是反直觉之处。
- **有损通道系统（lossy channel systems）**：允许消息随机丢失的无界 FIFO 通道系统，直觉上应该更弱，但 Brand–Zafiropulo (1983) 证明它**仍然图灵完备**，是并发验证里著名的"反直觉"结果。而**有界**的通道系统（如 PN 网、有界 FIFO 网）才是可判定的。
- 工程含义：协议/中间件里用**无界 FIFO 队列**做语义，几乎必然把模型推到 TM 力量，从而把验证问题变成不可判定的 —— 这是"为什么模型检测工具都要求队列有界"的根本原因。
- 编程语言文化里：队列机是 esolang 的常客（tag system、cyclic tag system、Bitwise Cyclic Tag 等），"Bitwise Cyclic Tag 是图灵完备的"这件事就是这条线的直接产物。

</details>

---

**一句话回你的问题**：是的，队列自动机图灵完备；而且它是"最小"的完备模型之一 —— 它揭示的不是"更强的自动机"，而是**存储访问纪律**（能否循环访问）比存储容量更决定计算力量。栈与队列之间这一步，跨过的正是从 CFL 到 RE 的全部距离。
