## 结论先行

我把四份源码全部读过并逐行比对：`diffusers/transformer_flux2.py`、`diffusers/transformer_qwenimage.py`、BFL 官方 `flux2/src/flux2/model.py`、`flux2/src/flux2/util.py`，以及两个 HF 仓库的真实 `config.json`。

**三个最重要的结论：**

1. **Flux2 和 Qwen-Image 都没有 cross attention**。文本注入靠 **joint attention**（把 txt 和 img 的 q/k/v 沿序列维拼起来做一次 self-attn），只是 diffusers 里参数名叫 `added_kv_proj_dim`、`add_q_proj`，是从 cross-attn API 继承下来的历史命名，容易误导。
2. **Flux2-dev 和 Qwen-Image-2512 的 block 拓扑完全相反**：Flux2 是 8 个 double-stream + 48 个 single-stream（hybrid，8 层之后就合并成一条序列）；Qwen-Image 是 **60 个纯 double-stream，永远不合并隐状态**，只合并 q/k/v。
3. **调制层（adaLN）的设计是两者最大的架构分歧**：Flux2 把 modulation 提到 block 外面、全模型共享（3 个 Linear，占总参数 1.8%）；Qwen 是每个 block 两套 `Sequential(SiLU, Linear(dim, 6*dim))`（占 **33%** 参数，约 6.8B）。

> 附带确认：**Qwen-Image-2512 的 transformer 配置和 2025-08 首版 Qwen-Image 逐字段一致**（60 层 / 24 头 / head_dim 128 / in_ch 64 / patch 2 / joint_attn_dim 3584 / out_ch 16），架构没变，变的是权重和训练。下面所有分析对两者都成立。

## 三、逐项展开

### 3.1 joint attention ≠ cross attention（这是最容易搞错的一点）

真正的 cross-attn 是 $Q$ 来自图像、$K,V$ 来自文本、没有文本 query。MMDiT 是**两个流各自算完整 q/k/v，然后沿序列维拼接做一次 softmax**。所以它有 $2\times$ 的 qkv 投影，softmax 是共享的。

Flux2（BFL 原版）：

```python
q = torch.cat((txt_q, img_q), dim=2)   # [txt, img]
k = torch.cat((txt_k, img_k), dim=2)
v = torch.cat((txt_v, img_v), dim=2)
```

注意两个流各有**独立的** `img_attn` / `txt_attn`（各自的 `qkv`、`QKNorm`、`proj`），拼的只是张量。Qwen 在 diffusers 里把它塞进一个 `Attention` 模块（`to_q` vs `add_q_proj`），功能等价，而且 **txt 流也真的有 query 和 output 投影**：

```python
txt_query = attn.add_q_proj(encoder_hidden_states)   # ← 有 query，所以不是 cross-attn
...
joint_query = torch.cat([txt_query, img_query], dim=1)   # 顺序 [txt, img]
...
txt_attn_output = attn.to_add_out(txt_attn_output.contiguous())
```

**结论**：`added_kv_proj_dim`、`add_q_proj`、`to_add_out` 这套命名纯属沿用 cross-attn 的 API 壳子，本质是 joint/self attention。Flux1 也是这样，Flux2 没改。

---

### 3.2 调制层（scale / shift / gate）——最大分歧

数学形式两者都一样（adaLN，非 adaLN-Zero 的写法但通常是 zero-init 语义）：

$$x' = (1+\text{scale})\cdot \mathrm{Norm}(x) + \text{shift}, \qquad h \leftarrow h + \text{gate} \cdot \mathcal{F}(x')$$

gate 乘在**分支输出**上（不是输入），这是 DiT 系列相对 Llama 的核心新增——Llama 的残差是裸加。

<details>
<summary><b>FLUX.2：modulation 被提到 block 外、全模型共享（← 相对 Flux1 的重要改动）</b></summary>

```python
# 模型级，只此一份
self.double_stream_modulation_img = Flux2Modulation(h, mod_param_sets=2, bias=False)
self.double_stream_modulation_txt = Flux2Modulation(h, mod_param_sets=2, bias=False)
self.single_stream_modulation     = Flux2Modulation(h, mod_param_sets=1, bias=False)

# forward 里算一次，然后喂给全部 8/48 个 block
double_stream_mod_img = self.double_stream_modulation_img(temb)
```

`Flux2Modulation` = `SiLU → Linear(h, 3·h·sets)`，`bias=False`。block 内部只做 `split`：

```python
(shift_msa, scale_msa, gate_msa), (shift_mlp, scale_mlp, gate_mlp) = Flux2Modulation.split(temb_mod_img, 2)
```

**参数量**：$2\times 6144\times 36864 + 6144\times 18432 = 566\text{M}$，占 32.1B 的 **1.8%**。

对比 Flux1：那时 `Modulation` 在**每个 block 内部**，8+38 个 block 各一套。Flux2 把它抽出去共享，等于用 566M 换掉了原本几 B 的参数。
</details>

<details>
<summary><b>Qwen-Image-2512：per-block、per-stream 的两套 modulation</b></summary>

```python
self.img_mod = nn.Sequential(nn.SiLU(), nn.Linear(dim, 6 * dim, bias=True))
self.txt_mod = nn.Sequential(nn.SiLU(), nn.Linear(dim, 6 * dim, bias=True))
```
6 = norm1 的 (shift, scale, gate) + norm2 的 (shift, scale, gate)，`img_mod_params.chunk(2, dim=-1)` 切成两组。

**参数量**：$60 \times 2 \times (3072\times 18432) \approx 6.79\text{B}$，占 20.4B 的 **33%**。

也就是说 Qwen-Image 有 1/3 的参数花在 adaLN 上，而 Flux2 只花 1.8%。这是"每层独立调制（表达力强、参数贵）" vs "全局共享调制（极省、表达力靠共享的时间向量）"的两种路线。
</details>

`gate` 的位置细节：Flux2 的 **single block 只有一个 gate**，因为 attn 和 MLP 是并行分支、输出先 concat 再一起投影：

```python
attn_output = self.attn(hidden_states=norm_hidden_states, ...)   # 内部已含 MLP
hidden_states = hidden_states + mod_gate * attn_output           # 一个 gate 管两路
```

Qwen 是串行，所以 attn 和 mlp 各一个 gate。

---

### 3.3 流拓扑：hybrid vs 纯双流

| | Flux2-dev | Qwen-Image-2512 |
|---|---|---|
| double block | 8 层，img/txt 各有 norm1/norm2/attn/mlp，只在 attn 处合流 | 60 层，同结构，但**每层 modulation 独立** |
| 合并点 | 第 8 层后 `torch.cat([encoder_hidden_states, hidden_states], dim=1)` 成一条序列 | **永不合并隐状态** |
| single block | 48 层 parallel block：`to_qkv_mlp_proj` 一次投影出 3h+2m，`to_out` 吃 h+m | 无 |
| 输出取谁 | merge 后再切掉 txt | 只用 img 流，txt 流被丢弃 |

Flux2 的 48 层 single block 是 **ViT-22B 式 parallel block**（attn 和 FFN 共享输入投影和输出投影的 buffer），Llama 完全不是这种结构。数学上：

$$\text{Linear}_1: h \to 3h + 2m,\quad m = \text{int}(3h)$$

这样单层参数 $h(3h+2m) + (h+m)h = 490.7\text{M}$，48 层 = 23.5B，占了全模型 73%。

Qwen 保留 60 层双流的代价：text token 永远跟着算 60 层 MLP，但好处是文本-图像交互一直在全带宽进行，不需要压缩到单流。

---

### 3.4 FFN / MLP

- **Llama**：SwiGLU，$\text{down}(\mathrm{SiLU}(W_{gate}x)\cdot W_{up}x)$，中间维 $\approx \frac{8}{3}d$。
- **Flux2**：**SwiGLU 但 fused** —— 官方注释明确说"`Flux2SwiGLU` 没有可训练参数，因为 up/gate 已融进前一层 Linear"：

  ```python
  half = x.shape[-1] // 2
  x = self.gate_fn(x[..., :half]) * x[..., half:]
  ```
  `linear_in: h → 2·inner`，`linear_out: inner → h`，`mult=3.0`。single block 里再和 QKV 融合成一个大 `to_qkv_mlp_proj`。
- **Qwen-Image**：`FeedForward(dim, dim_out, activation_fn="gelu-approximate")`，**GELU(tanh 近似)**，不是 SwiGLU，`mult=4.0`。

这是三家各不相同的：SwiGLU(3 矩阵) / Fused-SwiGLU(2 矩阵+切半) / GELU(2 矩阵)。

---

### 3.5 timestep / guidance embedding

| | Flux2-dev | Qwen-Image-2512 |
|---|---|---|
| 时间编码 | `Timesteps(256, flip_sin_to_cos=True, downscale_freq_shift=0)` | `Timesteps(256, flip_sin_to_cos=True, downscale_freq_shift=0, scale=1000)` |
| 缩放 | 模型内 `timestep = timestep * 1000` | 编码器内 `scale=1000` |
| 投影 | `MLPEmbedder(256→h)`：`Linear → SiLU → Linear`，**bias=False** | `TimestepEmbedding(256→h)`：`Linear → SiLU → Linear`，**bias=True** |
| guidance | **独立** `guidance_in` MLP，`vec = time + guide`（同构相加） | **没有**（`guidance_embeds=False`），靠外部 CFG |
| 额外条件 | 无 pooled vector（**Flux2 删掉了 Flux1 的 CLIP pooled `vector_in`**） | `use_additional_t_cond` 开关（2512 关）→ 否则会有 `nn.Embedding(2, h)` |
| 文本编码器 | Mistral-Small-3.1-24B，取第 10/20/30 层 hidden 堆叠 → $3\times5120=15360$ | Qwen2.5-VL-7B → 3584 |

Flux2 的 `context_in_dim=15360` 不是随便的数，是 Mistral-Small-3.1 的 5120 维 × 3 层拼接。Klein 变体用 Qwen3，所以是 $2560\times3=7680$（4B）和 $4096\times3=12288$（9B）。

### 3.6 RoPE：3 轴 vs 4 轴，语义完全不同

这是"两个 MMDiT 之间"差异最大的地方（相对 Llama 就更不用说了，Llama 是纯 1D 文本 RoPE）。

**Flux2：4 轴 $[32,32,32,32]$, $\theta=2000$，坐标是 (T, H, W, L)**

```python
# 主图 latent：T=0, H=arange(H), W=arange(W), L=0
latent_ids = torch.cartesian_prod(torch.arange(1), torch.arange(height), torch.arange(width), torch.arange(1))

# 文本：只有第 4 轴（L）在变 → 文本是一条"L 轴上的线"
text_ids = torch.cartesian_prod(t, h, w, torch.arange(L))

# 参考图 i：T = 10 + 10*i，H/W 照常，L=0
t_coords = [scale + scale * t for t in torch.arange(0, len(image_latents))]   # scale=10
```

即：**第 4 轴专门留给文本序列，第 1 轴用来区分"第几张参考图"**（Flux.2 支持最多 10 张参考图），H/W 给空间。文本坐标和图像坐标在 4 维空间里是**不相交的**（文本在 L 轴，图像在 T-H-W 超平面）。

**Qwen：3 轴 $[16,56,56]$, $\theta=10000$，坐标 (frame, H, W)**

关键差异是 `scale_rope=True` —— 图像做**中心化** RoPE，用负索引填上半/左半，让不同分辨率共享同一个中心：

```python
freqs_height = torch.cat([freqs_neg[1][-(height - height // 2):], freqs_pos[1][: height // 2]], dim=0)
```

文本则直接用 `pos_freqs[max_vid_index : max_vid_index + L]`，即在**同一套轴上接在图像网格之后**（1D 式偏移），不换轴。

<details>
<summary>实部/复数实现差异（性能细节）</summary>

- Flux2：`get_1d_rotary_pos_embed(..., repeat_interleave_real=True, use_real=True)` → 实数 cos/sin 表（为了 compile / 低精度友好）。
- Qwen：`torch.polar` 复数 + `apply_rotary_emb_qwen(..., use_real=False)`，且代码里专门警告"不要 register_buffer，否则复数虚部会丢"。

数值等价，但内存布局和 kernel 选择不同。
</details>

---

### 3.7 Norm 与 QK-Norm

- **Llama**：`RMSNorm(d, eps)`，$\gamma$ 可学习，pre-norm。
- **Flux2 / Qwen**：block 内全部 `LayerNorm(d, elementwise_affine=False, eps=1e-6)` —— **没有可学习参数**，尺度全部来自 modulation。这是纯 DiT 风格。
- 两者都加 **QK-Norm**（Flux2 显式 `nn.RMSNorm(dim_head)`；Qwen 走 `Attention(qk_norm="rms_norm")`），作用在 **per-head 的 $d_{head}$ 上、RoPE 之前**，是 MMDiT 训练大模型必需的稳定性手段（Llama 2/3 没有）。
- Qwen 额外在文本进 `txt_in` 之前有一个 `RMSNorm(3584)`（`txt_norm`），Flux2 没有这一步。

---

### 3.8 输出层

两者都是 `AdaLayerNormContinuous` + 一个 Linear，**只有 shift/scale，没有 gate**：

```python
self.norm_out = AdaLayerNormContinuous(h, h, elementwise_affine=False, bias=False / eps=1e-6)
self.proj_out = nn.Linear(h, patch_size ** 2 * out_channels, bias=False/True)
```

输出是 flow-matching 的**速度场** $\hat{v}$，没有 logits、没有 softmax、没有词表——这是和 Llama 最本质的差异（回归 vs 分类）。

`patch_size`：Flux2 用 1（VAE 侧先 2×2 patchify，`in_channels=128`）；Qwen 用 2（`in_channels=64 = 16×2×2`）。

## 五、常见误解 / 容易踩的坑

<details>
<summary><b>1. 以为 Flux2 用了 cross-attention</b></summary>

diffusers 里 `Flux2Attention(added_kv_proj_dim=dim)` 长得像 cross-attn 的构造，但 `Flux2AttnProcessor` 里对 encoder 也算了 `encoder_query` 并拼进去，输出还要 `split` 回两个流。是 joint self-attn。
</details>

<details>
<summary><b>2. 以为 Flux2 的 modulation 是 per-block</b></summary>

Flux1 是 per-block，Flux2 抽到了模型级共享。看 diffusers 代码时 `self.double_stream_modulation_img` 挂在 `Flux2Transformer2DModel` 上而不是 block 上，这是关键。
</details>

<details>
<summary><b>3. 以为 Qwen-Image 也有 single-stream block</b></summary>

没有。60 层全是 double，`hidden_states` 从不与 `encoder_hidden_states` 合并。反过来 Flux2 的 single block 里 `encoder_hidden_states=None` 传进去，因为已经拼好了。
</details>

<details>
<summary><b>4. Flux2 完全没有 attention mask</b></summary>

文本 pad 到 512（`padding="max_length"`）后，transformer 里**不传任何 mask**，pad token 被当正常 token 参与 attention。Qwen 反而认真地把 `encoder_hidden_states_mask` 拼成 `[txt_mask, ones(img)]` 传进 SDPA。这是一个容易被忽略的行为差异。
</details>

<details>
<summary><b>5. Qwen 源码里那些"开关"在 2512 里全是关的</b></summary>

`transformer_qwenimage.py` 里有 `zero_cond_t`、`modulate_index`、`use_additional_t_cond`、`use_layer3d_rope`、`_compute_condition_freqs`（condition image 的 layer index = -1）——这些是给 **Qwen-Image-Edit / Layered** 等多图条件变体用的。2512 的 `config.json` 里这几个 key 都不存在，走默认 `False`，所以是干净的原版 MMDiT。如果你照抄官方 repo 代码，别把这些路径当成 t2i 的默认行为。
</details>

<details>
<summary><b>6. Flux2 的 KV cache 对 dev 无效</b></summary>

`Flux2KVCache` / `forward_kv_extract` / `causal_attn_fn` 只在 `FLUX2_MODEL_INFO["flux.2-klein-9b-kv"]`（`use_kv_cache: True`）里启用；dev 调用时 `num_ref_tokens=0`，`causal_attn_fn` 直接退化成全 attention。所以 dev 的注意力是纯 bidirectional，没有 causal 成分。
</details>

---

## 六、一句话总结

> Llama 是"同构层 + 无调制 + 因果 + GQA + 1D RoPE"的纯文本解码器；MMDiT 把**时间条件做成了 LayerNorm 的仿射参数和残差门（adaLN + gate）**、把**位置编码改成多轴 RoPE**、把**跨模态交互从 cross-attn 换成序列拼接的 joint attn**、并把**模态结构从单流改成双流**。在这个共同骨架上，Flux2-dev 选择"modulation 全局共享 + 8 双流后转 48 层 parallel 单流 + 4 轴 RoPE（文本独占一轴、参考图占 T 轴）"，Qwen-Image-2512 选择"60 层纯双流不合并 + 每层每流独立 adaLN（吃掉 1/3 参数）+ 3 轴 centered RoPE + GELU FFN"。
