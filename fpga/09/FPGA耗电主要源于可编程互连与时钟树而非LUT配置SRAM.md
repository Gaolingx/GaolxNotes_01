# FPGA耗电主要源于可编程互连与时钟树而非LUT配置SRAM

## 😀 默认助手 (7)

## 先给结论

**你的直觉方向对了一半，但对“耗电”的归因不太对。** FPGA 确实比同功能 ASIC 费电（通常动态功耗高 5–10 倍），但**并非因为“那些 SRAM 一直在那里被读写”**。真正主要消耗动态功耗的是**可编程互连（路由矩阵）和时钟树**；配置 SRAM 只是面积中占比很大的一项，静态漏电时也会漏一些。

<details>
<summary><b>一、先澄清一个概念：LUT 里的 SRAM 到底在干什么</b></summary>

一个 N 输入 LUT 本质是一小块 **$2^N \times 1$ 的配置 SRAM**（6-LUT = 64 bit）+ 一棵**多路选择器树**。

关键在于：

- 配置位在**上电配置时写一次**，之后**永远保持不动**。它们不翻转、不被“读改写”。
- 运行时真正在高频翻转的是**输入信号驱动的 mux 树**（pass-transistor 网络）。
- 所以 LUT 的**动态功耗来自输入信号的翻转**，并非来自“访问 SRAM”。

也就是说：一个 LUT 如果输入不翻转，它动态功耗≈0，只剩下一点点漏电。这就是为什么 FPGA 里**大片没被用到的 LUT 几乎不耗动态功耗**（但仍然在漏电，见下文）。

顺带说，配置位的确占了 FPGA 芯片相当大的晶体管数和面积（常见说法是配置存储占全芯片晶体管数的 30–50%），但它主要是**面积和静态**问题，不是动态功耗问题。
</details>

<details>
<summary><b>二、FPGA 功耗的真实构成</b></summary>

动态部分：

$$P_{dyn} = \alpha \, C_L \, V_{DD}^2 \, f$$

其中 $\alpha$ 是**翻转活动率**，$C_L$ 是被驱动节点的总电容，$f$ 是时钟频率。注意 $V^2$ 和 $f$ 都是平方修正后的功耗；降频降压非常有效。

静态部分（漏电）：

$$P_{leak} = V_{DD} \cdot I_{leak}(T), \qquad I_{leak} \propto e^{-qV_{th}/nkT}$$

先进工艺下漏电对**温度呈指数敏感**，这是 FPGA 热失控风险的来源。

典型大芯片（如 UltraScale+ / Stratix 10）里的功耗占比大致是：

| 功耗项 | 典型占比 | 说明 |
|---|---|---|
| **可编程互连（switch matrix / routing）** | **30–50% 的动态功耗** | 最大单项。可编程交叉开关的 mux 多、走线长、电容大 |
| **时钟树** | 20–40% | 全局时钟网络要驱动整片芯片，$C_L$ 巨大 |
| **I/O** | 20–50%（看接口） | DDR、高速 SerDes 常是总功耗首要项 |
| **逻辑/寄存器翻转** | 15–30% | 你写的“逻辑功能”本身其实占比不大 |
| **漏电（静态）** | 10–20%（28nm）～30–50%（16nm 高温） | 与设计无关，与温度/电压强相关 |
| **配置/上电** | 瞬时冲击电流 | 一次性，但电源设计必须扛住 |

**你说的“matrix 寄存器乱七八糟”里，那个 switch matrix（路由交叉开关）恰恰是头号消耗动态功耗的大户**：它为了可编程性，要在每个节点摆一堆 mux，通路比 ASIC 定制走线长得多、电容大得多。
</details>

<details>
<summary><b>三、为什么 FPGA 天生比 ASIC 费电</b></summary>

1. **互连开销**：ASIC 用最短定制金属走线；FPGA 信号要穿过一堆 switch box/mux，路径长 $C_L$ 大。
2. **过驱动**：为了通用性，FPGA 的驱动器和 mux 都做得很足（宁可大不可小），静态和动态都亏。
3. **毛刺（glitch）雪上加霜**：LUT + 不平衡路由导致一个周期内输出多次毛刺，等效翻转率 $\alpha$ 远高于逻辑函数的名义值，实测可高出 1.5–3 倍。
4. **时钟树覆盖全片**：即使某区域没用，时钟网也可能一直摆着。
5. **硬核缺失**：ASIC 里一个乘法器几百个门，FPGA 里不用 DSP slice 就要拿几千个 LUT 拼——所以**用不用硬核，差好几倍功耗**。
6. **漏电**：未使用的资源不翻转，但**照漏不误**，且 FPGA 通常面积大，漏电总量下不来。

粗略的经验倍数（同功能、同工艺）：**动态功耗约 5–10×，面积约 10–20×**。但如果任务极度并行、ASIC 根本做不起（产量太小），FPGA 反而是唯一现实选择。
</details>

<details>
<summary><b>四、那和 CPU/GPU 比，到底“费不费电”？</b></summary>

要看规模，不能一概而论：

| 器件档次 | 典型功耗 |
|---|---|
| 小容量 FPGA（Artix-7 35T 一类） | **0.1–1 W** |
| 中端 SoC FPGA（Zynq 7020 一类） | **1–3 W** |
| 大型 FPGA（VU9P / VU13P） | **30–100 W** |
| 超大（VU19P / Stratix 10 GX 10M） | **100 W 以上** |

所以：**小 FPGA 比你家路由器还省电；大 FPGA 和高端 GPU 一个量级。** 而“每瓦能做多少有效运算”上，对**位宽窄、并行度高、控制流简单**的任务（DSP、推理、网络包处理、曾经的挖矿），FPGA 往往比 GPU/CPU 能效高一个数量级；对分支复杂、串行依赖强的任务，它就很吃亏。

而且 FPGA 功耗**高度依赖设计**：同一块板子，时钟门控做好 vs 做差，功耗能差 2–3 倍。
</details>

<details>
<summary><b>五、想在 FPGA 上省电，抓这几条</b></summary>

- **降频优先于降逻辑**：$P \propto f$，而且降频常能顺带降压（$V^2$ 收益）。
- **时钟门控 / 时钟使能**：用 CE 而不是靠 mux 选数据，别让无用逻辑跟着时钟空转。时钟树是第二大动态功耗来源。
- **把大数组塞进 BRAM，别用寄存器拼**：寄存器阵列面积和翻转功耗都爆炸。
- **能用 DSP/硬核就用**：DSP48、SerDes、PCIe 硬核比软逻辑省太多。
- **减少毛刺**：多打一拍、均衡流水线深度、关键路径加寄存器切分。
- **I/O 是最容易被忽视的大头**：降低 DDR 频率、减少同时翻转的 IO、用合适的驱动强度和 slew rate。
- **关注静态功耗与散热**：高温 → 漏电↑ → 更热，正反馈。大芯片必须配好散热和电源余量。
- **别开着不用的高速接口**：不用的 transceiver 一定要关掉电源。
</details>

---

**一句话总结**：FPGA 费电主要是**“为了可编程性付出的互连和时钟代价”**，不是“SRAM 在乱读乱写”；配置 SRAM 是静态的，主要影响面积与漏电。是否“很耗电”，取决于芯片规模和你的设计——小片子几瓦，大片子跟 GPU 同级，而能效高低完全看任务类型和实现质量。
