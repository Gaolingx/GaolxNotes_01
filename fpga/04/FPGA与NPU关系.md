# FPGA与NPU关系

## 🧑‍💻 User

AI FPGA使用场景面临着一个大问题 为什么我不用NPU+FPGA呢（甚至进一步为什么我不用NPU+CPU呢）
对于确定的固化的权重 我为什么不直接刻在硅片上呢

## 🤖 Assistant

# AI 场景里 FPGA 的定位：先把问题拆开

你这个问题的三个"为什么不"其实指向的是**同一个坐标轴上的不同点**——不是并列的三个方案，而是"灵活性 vs 效率"光谱上的一段。先把抽象讲清楚，剩下的答案会自己浮现。

设一次推理就是求值

$$y = f_W(x)$$

其中 $f$ 是计算结构（数据流/算子/数据通路），$W$ 是权重，$x$ 是输入。于是：

| 方案 | $f$（结构） | $W$（权重） | 灵活性 | 能效/面积 |
|------|------------|------------|--------|-----------|
| CPU | 指令流，最灵活 | 数据 | 最高 | 最低 |
| GPU | SIMT 核 + 调度 | 数据 | 高 | 中 |
| **FPGA** | **比特流定义的硬件** | 数据 | 高（重构级） | 中高 |
| **NPU** | **固化数据通路**（脉动阵列等） | 数据 | 低 | 高 |
| **ASIC（权重也刻死）** | 固化 | **固化** | 最低 | 最高 |
| 纯 ROM 查表 | 固化 | 固化 | 无 | ——（只对小输入可行） |

**关键洞察：你现在问的"权重刻进硅片"，本质就是 NPU/ASIC 这条路——它不是一个新选项，而是光谱的右端点。** 所以真正的问题是：这条光谱上，应该在哪个点落子？

## 一、为什么不干脆用 NPU+CPU（或 NPU+FPGA）？

### 现实中它们本来就共存
现代 SoC 几乎都是 **CPU + NPU + DSP + FPGA/可编程逻辑** 的异构体。不是"用哪个"，而是"哪部分交给谁"：

- **NPU**：标准、成熟、映射良好的稠密矩阵乘（CNN、Transformer 主体）。能效高、面积小、工具链现成。
- **CPU**：控制流、调度、小 batch、分支密集、预处理/后处理。
- **FPGA**：NPU 覆盖不到的**缝隙**——这才是它真正活下来的原因。

### FPGA 赢在"缝隙"，输在"主路"
只要负载是标准 DNN、权重已冻结、算子映射友好，**NPU+CPU 确实优于 FPGA**，这点你是对的。FPGA 的 MAC 能效/面积通常比同代 ASIC/NPU 差约 $10\times$ 量级，因为硬连接的乘法器阵列更密、频率更高。

但以下场景 FPGA 仍然赢：

<details>
<summary><b>点开：FPGA 相对 NPU 的真实优势场景</b></summary>

1. **算子不标准 / 数据流不规则**：稀疏模式奇异、图神经网络、动态形状、非规则访存。NPU 的固定阵列利用率会崩。
2. **极低且确定的延迟**：控制回路、雷达/传感器前端要求 ns 级、无抖动。NPU 要走"CPU 发起 kernel"的路径，启动开销就把延迟吃掉了；FPGA 是纯流水线，不需要 batching。
3. **算法尚未冻结**：产品迭代期、研究阶段。NPU 是死的，FPGA 可以现场重构——这是开发/部署早期的核心价值。
4. **与 I/O / 传感器 / 自定义协议的紧耦合**：FPGA 能把 ADC 采样、自定义总线、预处理直接熔进数据通路，CPU 得靠中断+拷贝。
5. **非标准精度**：实验 INT2/INT4、对数域、混合格式。NPU 的精度是焊死的。
6. **预处理/后处理与网络融合**：把裁剪、归一化、NMS 融进同一流水线，省掉来回搬数据。

</details>

一句话：**NPU 优化"平均情况"，FPGA 处理"长尾 + 低延迟 + 未定形"。** 这不是替代关系。

## 二、为什么不把权重直接刻在硅片上？

这是问题里最锋利的一刀。答案分三层。

### 1. 首先，"刻权重"往往不等于"省算力"
你可能会想：权重是常数，那乘法不就能常量折叠、变成移位/加法了吗？这确实可行——**分布式算术（Distributed Arithmetic, DA）** 和**无乘法器常数乘法**就是干这个的，FPGA 信号处理里很常用。

但它有两个致命缩放问题：

- **查表爆炸**：DA 用输入切片作索引查表，表的规模随输入位宽 $B$ 和抽头数 $N$ 指数增长，量级约

$$2^{N}\ (\text{每比特切片}),\quad \text{总规模} \sim 2^{N}\cdot \text{words}$$

网络一大，$N$ 上千，直接不可实现。
- **权重只是操作数，不是瓶颈**：推理开销的大头是 **MAC 数量 + 数据搬运**，而不是"权重是不是常数"。你固化权重，乘加器和加法树还得存在。省的是局部，不是主体。

### 2. 对大模型，这条路根本不通
以 LLM 为例，瓶颈是 **存储带宽**，不是算术（算术强度只有约 $1\text{–}2$ ops/byte）。权重必须物理地待在 HBM 里再流向计算单元。**上亿参数塞不进片上 ROM**，刻权重给不了任何带宽收益。所以对 LLM，连 FPGA 的灵活性理由都变弱了——H100/NPU 才是主战场。

### 3. 真正劝退的，是工程与经济现实
即便理论上能刻，实际会被下面这些按死：

<details>
<summary><b>点开：把权重/结构刻进硅片的现实代价</b></summary>

| 维度 | 硬刻权重（ASIC 路线） | FPGA 路线 |
|------|----------------------|-----------|
| **NRE / 掩膜成本** | 先进节点掩膜 $10^7\text{–}10^8$ 美元级，总 NRE 可达 $10^8\text{–}5\times10^8$ | 几乎为零，买片即可 |
| **上市时间** | 18–36 个月 | 数周–数月 |
| **模型版本迭代** | 权重一改，芯片报废 | 重构比特流即可 |
| **精度灵活性** | 焊死，无法切 INT4/8/FP16 | 随便改 |
| **产量摊薄** | 只有超大出货量才划算 | 小批量也能用 |
| **良率 / 面积** | 大而专用 ⇒ 良率低、面积大 | 通用可复用 |
| **纠错** | bug 是致命的 | 重配置即可修 |
| **熵/安全性** | 固件无法更新、易被逆向 | 可现场升级 |

</details>

### 4. 那什么时候"刻权重"是对的？
- **极小、永远不动的模型**：唤醒词、关键词检测，权重只有 KB 级，放 ROM 做查表真的省电。学术界有 "LUT-Network"、"weights-in-ROM" 这类做法。
- **存内计算（CIM / 忆阻器 crossbar）**：把权重写进模拟阵列，是"刻权重"的现代形态——但它**又退化成了 NPU 式的固化数据通路**，灵活性照样丢失。
- **真正海量且永久冻结的场景**：视频编解码器、标准单元就是这类，但前提是"标准十年不变"。

## 三、把三者放回同一张决策图

你现在应该能看到：**"NPU+FPGA"、"NPU+CPU"、"刻权重"三个选项，其实是沿同一条轴滑动**——越往右越高效、越不灵活。

| 你的约束 | 应该落子 |
|----------|----------|
| 模型标准、已冻结、追求能效、量产大 | **NPU / ASIC**（不是 FPGA，也不是刻权重——NPU 就是"部分刻死的 ASIC"，是甜点） |
| 模型未定形、要迭代、要低延迟/非标准算子 | **FPGA**（或 NPU + FPGA 异构） |
| 控制流、小 batch、胶水逻辑 | **CPU** |
| 极小模型 + 极致功耗 + 永不变 | **权重 ROM / CIM** |

**核心结论：**
1. FPGA 不是要和 NPU 抢主路，它是填补 NPU 覆盖不了的**长尾、低延迟、未定形**缝隙。
2. "刻权重"在数学上常等于"退化成 NPU/ASIC"——所以它不是被忽略的第三条路，**它就是光谱右端**，只不过被 NRE、模型迭代、存储墙和精度刚性挡在了通用场景之外。
3. 真正决定落子的不是"哪个更快"，而是三个问题：**负载有多标准？权重会变吗？出货量能摊平掩膜吗？** 三者都偏向"稳定/大"，就一路向右滑到 NPU/ASIC；只要有一个偏"变化/小"，就退回 FPGA/CPU。

> 一句话：**FPGA 的价值不在"把 AI 跑得快"，而在"在 AI 还没定型、或长尾太怪的时候，仍然能跑起来"。** 一旦它定型了，你就该把它刻掉——这正是 NPU 存在的理由。
