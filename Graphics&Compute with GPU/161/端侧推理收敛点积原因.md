# 端侧推理收敛点积原因

### 🧑‍💻 User

为什么端侧ai推理框架，任何要跑遍异构硬件的端侧部署最终都收敛到INT8点积，包括llama.cpp都是这样干的，使用mma level instruct效率不更高吗？

---

### 🤖 Assistant

这是个很好的问题，而且它其实戳中了一个常见误解。先给结论，再展开：

> **不是"所有路径都收敛到 INT8 点积"，而是"可移植的基线路径收敛到 INT8 点积"。而 INT8 点积指令本质上就是一个最小的 MMA（$M=N=1, K=4$）。**

框架在真正算力敏感的旗舰后端（CUDA 张量核、Apple AMX、Intel AMX/XMX、ARM SME）上**确实**用了 MMA/张量核；点积是那个"到处都能跑、只写一次"的通用兜底。下面分几层说清楚。

---

## 1. INT8 点积指令 = 最小的 MMA

一条点积指令做的事就是：

$$
\text{acc}_i \leftarrow \text{acc}_i + \sum_{k=0}^{3} A_{i,k}\cdot B_{k,i}
$$

即 `int8×int8 → int32` 累加，$K=4$，输出是标量（$M=N=1$）。这和一个 16×8×16 的张量核 MMA 在**语义上完全相同**，区别只是 tile 尺寸和数据搬运方式：

| 平台 | 指令 | 语义 |
|---|---|---|
| ARMv8.2+dotprod | `vdotq_s32` | 16×int8 点积 → 4×int32 |
| x86 AVX-VNNI | `vpdpbusd` | 8×int8 点积 → 4×int32（每 128b lane） |
| NVIDIA PTX | `dp4a` | 4×int8 点积 + int32 |
| AMD RDNA3/CDNA | `v_dot4_i32_i8` | 同上 |
| RISC-V（扩展） | `vdot` | 同上 |

所以"收敛到点积"并不是放弃了矩阵单元，而是**收敛到了唯一一个被各 ISA 标准化、可移植的最小矩阵乘原语**。

---

## 2. 为什么收敛点是它，而不是更大的 MMA

**(1) 它是异构硬件的最大公约数**

`dp4a` / `vdotq_s32` / `vpdpbusd` 在所有现代 CPU、手机 SoC、GPU 上都有，甚至很多**根本没有张量核**的边缘芯片（入门 NPU、老手机、嵌入式 CPU、RISC-V）也至少有一条 SIMD 点积。要"跑遍异构硬件"，你只能依赖这个交集。

**(2) 数据布局/寄存器契约可移植，tile MMA 不可移植**

点积指令的操作数是"塞在寄存器里的 4 个 int8"，布局是平凡且统一的——一个寄存器装 4 个数，谁写都是一样的。而 16×8×16 张量核 MMA 的 fragment 如何分布在 32 个线程的寄存器里、`ldmatrix` 怎么搬、结果 fragment 怎么喂给下一轮，是**每家厂商的架构决策**，不存在跨厂商的写法。一句话：点积的寄存器语义是 ISA 级的，tile MMA 的寄存器语义是微架构级的。

**(3) 量化契约简单**

`int8×int8→int32` 累加器是各平台一致的：对称量化、per-channel / per-row scale 可以在 MMA 结束后统一乘回去，中间不引入舍入。而张量核 int8 常要求**对称量化**（zero-point = 0），非对称量化要做 zero-point 补偿（多出 3 次额外的乘加），约束更严。

**(4) 维护成本：组合爆炸**

一个框架要支持 W4/W5/W8/A8 等 N 种量化格式 × M 个后端。如果每个都用各家 tile MMA 手写内核，就是 $N\times M$ 个深绑定内核；而点积路径**写一次、按架构换一条指令**即可（llama.cpp 的 `ggml_vec_dot_qX_K_q8_K` 就是这个思路）。

**(5) INT8 本身就是量化甜点**

FP16 点积并不普遍（x86 原生 fp16 到很晚才出现，很多 CPU 只有转换指令），INT4 没有标准化 SIMD 点积指令（要么打包进 int8 用 `dp4a`，要么靠专用张量核）。所以"INT8 + 点积"是精度、速度、可移植性三者唯一的公共交点。

---

## 3. "MMA 效率更高，为什么不用？"—— 不是不用，是没法当唯一路径用

**(1) MMA 不是一条指令，是一族互不兼容的硬件单元**

- NVIDIA：`mma.sync` / `wgmma`，需要 fragment 布局、`ldmatrix`、warp 协同
- Intel AMX：`tileloadd` + `tdpbusd`，要管理 tile 配置、XSAVE 状态、上下文切换
- ARM SME：`ZA` tile，要进入 streaming 执行模式
- Apple AMX：干脆**没有公开指令**，只能走 Accelerate 框架

它们之间没有任何可共享的代码，所谓"用 MMA 级指令"对每个厂商都是**独立的一份内核**，这恰恰和"跑遍异构硬件"的目标冲突。

**(2) 边缘 LLM 推理的瓶颈常常不是算力**

decode 阶段是内存带宽受限，prefill 在边缘场景 batch 很小、序列不长。张量核的高峰值 TOPS 在这些负载下兑现率很低；点积内核简单、延迟低、能处理任意 shape 和 tail，小矩阵下反而更划算。张量核的铺砖对齐、流水深度、同步开销在"小矩阵"上会把收益吃回去。

---

## 4. 实际框架是"分层"的，llama.cpp 就是典型

llama.cpp 的真实结构是一个**梯度**，不是"只做点积"：

- **CPU 基线**：`ggml_vec_dot_*`，AVX2/AVX512-VNNI、NEON dotprod、wasm SIMD、标量兜底 → 全是点积
- **CUDA 后端**：`mul_mat_q`（mmq 路径）走张量核/`mma`，向量路径走 `dp4a`
- **Vulkan/SYCL**：`dp4a` / 子组点积，Intel Arc 上有 XMX/`dpas`（张量核）路径
- **Metal**：SIMD 点积 + 通过 Accelerate 调 Apple AMX

所以准确的表述是：**点积是通用基线，MMA 是按厂商单独维护的热路径**。你看到"收敛到 INT8 点积"，其实是看到那个写得最少、跑得最广的兜底层——而它之所以兜得住，正是因为它本身就是一个可移植的最小 MMA。

---

## 一句话总结

> INT8 点积不是"效率更低的选择"，它是**唯一被所有 ISA 标准化的最小 MMA 原语**，是异构硬件矩阵乘的公共接口；而各家的大 tile MMA/张量核是不可移植的架构私有物，只能作为每厂商单独维护的加速路径叠加在点积基线之上。llama.cpp 等框架的收敛，本质是"用点积定义契约、用 MMA 兑现峰值"的分层策略。
