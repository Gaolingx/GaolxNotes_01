## 先把“MIMD”这个词掰正

硬件层面现代 GPU **从来不是 MIMD**。NVIDIA/AMD/Intel 的 shader core 都是 SIMT/SIMD:一个 warp/wave 里所有 lane 共享同一条指令流,分支靠 predication + 掩码。说“光追是 MIMD”,指的是**工作负载特性**——相邻线程的 ray 命中不同材质、走不同 BSDF、发射不同数量的二次射线,指令流分叉,有效利用率掉到

$$U = \frac{\text{活着的 lane}}{32}$$

所以准确的说法不是“现代光追早就不是 MIMD 了”,而是**业界一直在把这种 MIMD 式的发散负载重新压回 SIMT 友好**。你列的三条路线,正好是同一条光谱上的三个点:

| 路线 | 重排粒度 | 重排发生在哪 | 代表 | 主要代价 |
|---|---|---|---|---|
| SER / TSU | thread / warp | 片上硬件队列 | Ada SER、Xe-HPG TSU | 只能局部重排,受 bucket 与 key 质量限制 |
| Wavefront / defer 全排序 | stage→material(粗) 或 ray(全) | 内存 ray queue | Laine 2013、各类 sort-last | 带宽 + 状态落到显存 |
| Work Graph + persistent thread | 动态 work item | runtime / 硬件调度器 | D3D12 Work Graphs | 生态、工具链不成熟 |

<details>
<summary><b>① 保守派:SER / TSU(你说的“流行 ser”)——在 megakernel 里加重排点</b></summary>

- NVIDIA **Ada Lovelace(2022)** 引入 **Shader Execution Reordering**。HLSL 侧是 `MaybeReorderThread`,Vulkan 侧是 `VK_NV_ray_tracing_invocation_reorder` 的 `reorderThreadNV`。
- 机制:你在 shading 里给一个 **32-bit coherence hint**(通常是 material ID、hit kind、或量化后的 ray direction),硬件把发散的 invocation 攒进 reorder queue,再按 key 重新打包成更同质的 warp 发射。
- 关键点:它**不换编程模型**——仍然待在 DXR 的 megakernel / uber-shader 里(`SBT` + 动态 dispatch),只是在你要发散的地方插重排点。所以叫“保守”。
- Intel **Xe-HPG(Arc)** 里有对应的 **Thread Sorting Unit**,思路一致:硬件排队重排 invocation。
- 局限:收益强依赖 key 的信息量;重排本身有 latency 和队列压力;它对 **traversal 本身没用**,只解决 shading 侧的 hit/miss coherence。真实收益从几成到几十个百分点不等,场景相关。

</details>

<details>
<summary><b>② 激进派:defer 全排序(你说的“完全 SIMT”)——把 sort 推到 ray 粒度</b></summary>

- 本质就是 **sort-last**(Molnar 1994 那篇 *A Sorting Classification of Parallel Rendering* 的经典分类):先做 traversal + 命中分类,把 hit point / ray payload 写进 buffer,按 material / BSDF **全排序**,再分批发 coherent batch 做 shading。
- 好处:每个 batch 内近乎纯 SIMT,lane 利用率逼近满;shader 可以特化,甚至为每个材质生成专门 kernel。
- 代价:就是**把 megakernel “状态常驻寄存器”的优势丢了**。payload 要落显存再取回,带宽和排序(radix / bucket sort)成本很高;场景一大就炸。
- 参照系:经典 **wavefront**(Laine et al. 2013, *Megakernels Considered Harmful: Wavefront Path Tracing on GPUs*)是这个思想的**粗粒度版**——按 stage/材质分 pass。你说的“全排序”是把它推到 ray 粒度。
- 实战判断:在离线渲染/研究 demo 里很能打,但实时大场景下“全排序”常常打不过 SER,因为**带宽是硬瓶颈**。这正是 NV 做 SER 的动机之一。

</details>

<details>
<summary><b>③ 混合派:RT sorting + Work Graph + persistent thread——兼顾 wavefront 与 megakernel</b></summary>

- **Work Graphs(D3D12)**:GPU 自己动态生成 work,runtime 负责把 node 产出的 work item 在 SM 间调度。对光追这种不规则负载,等于把“重排 + 负载均衡”下沉给调度器。
- **Persistent thread**:kernel 常驻、从队列拉 work(Aila & Laine 2009 *Understanding the Efficiency of Ray Traversal on GPUs*;Gupta et al. 2012),省 launch 开销、天然负载均衡。
- 组合:eRay 按 coherence 排序 → 作为 work item 喂给 graph node → persistent thread 处理同质 batch 时状态仍在寄存器里。**wavefront 的 coherence + megakernel 的 locality/状态常驻**,这正是你说的“兼顾”。
- 现状:生态不成熟,编译器/驱动/工具链还在补;但方向是对的,尤其适合 GPU-driven、几何/材质高度动态的场景。

</details>

<details>
<summary><b>几个容易混淆 / 需要补的点</b></summary>

- **DXR 本体就是 megakernel 式的**:SBT + 动态 dispatch,所有 hit/miss group 在同一 pipeline 里分派。所以“DXR = wavefront”是误解;SER 正是在 megakernel 模型内部加 coherence。
- **硬件 RT core 只加速 traversal,不加速 shading**。重排解决的是 shading 的发散,别把两者混为一谈。
- **Blackwell(2025)** 又往前推了一步(Mega Geometry、neural shaders,SER 也有增强),但具体收益得看最新资料。
- **AMD**:到 RDNA3 为止没有 SER 对等物,主要靠软件 ray sorting / 编译器;RDNA4 提升了 RT 吞吐,但**是否加了硬件级重排我不确定**,这块建议查最新的架构文档。
- 关键区分:**SER ≠ ray sorting**。SER 是 warp 内的**局部**重排,几乎零额外带宽;ray sorting 是**全局**重排,要落内存。两者解决的问题同源,代价差一个数量级。

</details>

## 结论:没有谁“终结”了 MIMD

硬件始终是 SIMT;“MIMD”只是对负载发散的描述。三条路线是同一条光谱上的取舍——**发散成本只是被搬到了别的地方**:SER 搬到片上队列容量与 key 质量,全排序搬到带宽,work graph 搬到调度与生态。

选型上大致是:

- 想**最小改动吃现成硬件红利** → SER / TSU(前提:Ada+ / Arc)。
- 想**极致 per-batch SIMT 效率、能扛带宽** → defer 全排序(更适合离线或高端实时)。
- 想**长期架构、GPU-driven** → Work Graph + persistent thread。
