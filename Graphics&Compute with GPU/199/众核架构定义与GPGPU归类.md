## 先说结论

**众核（manycore）不是“很多个核”，也不是“必须配 scratchpad + 显式通信”。** 它是一个**设计点（design point）** 的名字：**为吞吐率优化、而不是为单线程延迟优化的并行架构**。SPM（scratchpad）和显式数据搬运是这个设计点的**典型后果和伴生特征**，不是定义本身。

因此，你的直觉的后半段是对的：**GPGPU 是标准的众核**，而且 GPU 不但“算”，它连你那条严格标准（SPM + 显式搬运）都满足。反倒是 **Xeon Phi 是“有缓存、有一致性”却被公认是众核** 的反例——它恰好证明 SPM 不是必要条件。

---

## 1. “众核”这个词的出身

这个词被正式化基本是 Berkeley 那篇 *The Landscape of Parallel Computing Research*（Asanović et al., 2006）的功劳。那里给的不是核数阈值，而是**优化目标**：

| 术语 | 原文含义 |
|---|---|
| **multicore** | 少量核，每核仍为**单线程性能**优化（OoO、深流水、大 cache、分支预测） |
| **manycore** | 大量核，每核为**吞吐率/能效**优化（in-order、多线程、宽 SIMD、极小 cache） |

同一篇里还有 *wimpy core vs brawny core* 的说法。**“众核 = wimpy cores 的阵列”** 比任何数字都更接近本意。Niagara T1（8 核 × 4 线程，2005）当年被 Sun 当众核宣传，核数比今天的手机 SoC 还少，但没人觉得不对——因为它是吞吐率设计的。

> 反证：AMD EPYC 9654 有 **96 核**，Intel/AMD 的 128 核也都存在，业界一律叫 multicore / 多核，不叫众核。**核数根本不是判据。**

## 2. 为什么 SPM 和显式通信“总是跟着众核出现”

因为有四条硬物理约束，逼着众核设计者放弃由硬件自动管理的内存层次：

1. **一致性不 scale。** 目录/嗅探的状态与线数同核数成正比，一致性流量随 $N$（甚至 $N^2$）增长。到几十核以上，“全芯片单一一致性域”在功耗和面积上都不划算——于是要么把一致性域**切小**（SW26010 只在 4 个 MPE 之间做一致性），要么干脆不要。
2. **cache 每次访问都要付 tag 查找 + 相联比较 + 替换策略的能耗/面积**，而流式计算的数据访问模式是**编译期已知**的，硬件做的预测和复用全是白付的电费。
3. **可预测延迟**。SPM + DMA 给你确定性的访存延迟，才能做**双缓冲/软件流水**，不依赖硬件的乱序和推测。这才是 GPU shared memory、Sunway LDM 存在的真正理由。
4. **功耗**。1.45 GHz 的 260 核、1.0 GHz 的 61 核、1.7 GHz 的 132 SM——低频 + 宽 SIMD + 多线程填延迟，是“dark silicon”时代唯一能把晶体管用满的路子。

所以“SPM + 显式搬运”是**众核的省钱方案**，不是入场券。KNL 甚至把这件事做成了显式的选择题：

> **KNL 的 MCDRAM 有 `cache` / `flat` / `hybrid` 三种模式**——`cache` 模式就是“让硬件替你管”，`flat` 模式就是“把它当 16 GB scratchpad，你自己管”。**同一个芯片，两种哲学，官方承认这是连续谱。**

## 3. 三个案例的坐标（这是你最需要的表）

| | 申威 SW26010 | Xeon Phi KNC | Xeon Phi KNL | H100 GPU | EPYC 9654 |
|---|---|---|---|---|---|
| 核数 | 260（4 CG×(64 CPE+1 MPE)） | 61 | 68–72 | 132 SM × 128 lanes | 96 |
| 单核形态 | CPE: in-order、无数据 cache、只有 16 KB I-cache；MPE: 完整 OoO | in-order、4 线程/核、512-bit SIMD | in-order、4 线程/核、2×512-bit FMA | SIMT、32 宽 warp | OoO、SMT2、AVX-512 |
| 片上存储 | 每 CG 一块 **64 KB SPM (LDM)**，64 CPE 共享 | 512 KB L2/核，**纯 cache** | 512 KB L2 + **16 GB MCDRAM**（可 cache / 可 flat） | 每 SM 最多 ~228 KB，**L1 与 shared memory 同一块 SRAM 分区** | 1 MB L2/核 + 32 MB L3 |
| 一致性 | **仅 MPE 之间**；CPE 之间无一致性 | 有（ring + 分布式 tag directory） | 有（2D mesh） | 无（device 内不保证） | 全芯片有 |
| 数据搬运 | `get/put` DMA + 行列广播寄存器 | 硬件 cache | 硬件 cache（或 flat 模式下手写） | `cp.async`/TMA、`__syncthreads`、warp shuffle | 硬件 cache |
| 归谁 | **异构众核** | 同构众核（MIC） | 同构众核 | **异构 SIMT 众核** | 多核 |

看表就清楚了：**“有 SPM + 显式搬运”的（申威、GPU）和“没有的”（KNC）、和“两者皆可的”（KNL），都被叫众核；唯独核数最多的 EPYC 不被叫众核。** 判据显然不在存储层次上。

## 4. 那么真正的判据是什么

我给你三个可操作的提问，**三个都偏向“吞吐率”那一边，就是众核**：

1. **单线程延迟是设计目标，还是事后凑合？**（OoO/推测/深流水 vs in-order/多线程/宽 SIMD）
2. **内存层次是硬件替你隐藏的，还是被逼暴露在代码里？**（cache+一致性 vs SPM+DMA/消息/`__syncthreads`）
3. **规模是否已经超出“单一一致性域”的经济性边界？**（这条是**硬边界**：一旦越界，即使你想全硬件管理也做不到，必须切域或交给软件）

不过第 2、3 条不是“是否”，而是“**在哪里划线**”。所以：

> **众核 = “我放弃了单线程性能，换每瓦每平方毫米的吞吐率”这个决策。**
> SPM、显式 DMA、显式通信、宽 SIMD、低主频、异构（管理核 + 计算核）——都是这个决策在具体工艺和预算下的**最优解组合**，会随年代和厂商变化。

顺带把你说的“explicit route rule”拆清楚：真正被暴露给程序员的通常是**数据搬运和拓扑感知**（DMA 描述符、`athread_get/put`、Sunway 的 8×8 行/列广播寄存器、GPU 的 cluster 内 distributed shared memory），而 **NoC 的路由算法本身几乎总是硬件做的**。Cell BE（MFC DMA + 256 KB local store）、RAW（静态路由）是更早期的“真·显式通信”案例，它们塑造了“众核=手工搬数据”的刻板印象。

## 5. 正确的心理模型：众核是一个多维空间里的区域

把“众核”当成一个**带 6 个坐标的空间**，而不是一个布尔属性，一切就通了：

| 轴 | 两极端 |
|---|---|
| ① 规模 | 几核 ↔ 上千核 |
| ② 单核强弱 | brawny（OoO）↔ wimpy（in-order/无 cache） |
| ③ 存储层次管理 | 隐式（cache/一致性）↔ 显式（SPM + DMA） |
| ④ 通信 | 隐式（共享内存 + 一致性）↔ 显式（消息/广播/DMA） |
| ⑤ 同构性 | 同构 ↔ 异构（MPE+CPE / host+device / PIM） |
| ⑥ 通用性/ISA | 通用（x86/ARM）↔ 专用（SIMT、张量） |

**“众核”主要断言的是 ①+② 的方向**（规模大 + 单核弱 + 吞吐优先）；③④⑤⑥ 是**自由变量**。于是：

- **申威 SW26010** = ①高 ②弱 ③显式 ④显式 ⑤异构 ⑥通用 → 中国教科书的标准“异构众核”
- **Xeon Phi KNC** = ①高 ②弱 ③**隐式** ④隐式 ⑤同构 ⑥通用 → 同构众核，**打破你的假设**
- **KNL** = 同上，但 ③ 可选（MCDRAM flat） → 连续谱的活证据
- **GPGPU** = ①极高 ②极弱 ③显式（+部分隐式） ④显式 ⑤异构 ⑥专用 → **最纯粹的众核**

**“众核必须有 SPM”为什么流行？** 因为最有影响力的早期样本（Cell BE、GPU、申威）恰好都有；加上 Berkeley 那套 “explicitly managed memory hierarchy” 叙事把众核和“一致性不可扩展”绑死了。这是**从样本反推定义**的典型错误——就像看到天鹅都是白的。

**“很多核”为什么不是判据？** 因为“多”没有阈值。有人说 32，有人说几十到几百。真正的相变点是**一致性域的经济性边界**，而它在不同工艺/功耗预算下位置不同，所以只能是个模糊地带，不能当定义。

**为什么厂商爱用这个词？** “many-core” / “MIC (Many Integrated Core)” / “众核” 都是**营销话术 + 学术标签**的混合体，用来暗示“这是下一代，不是你把现在的服务器核数堆上去”。技术上它对应的是真实的设计点差异，但边界被话术故意模糊了。

**趋势：这个分类正在溶解。** GPU 在加 cache 和硬件管理（unified memory、TMA、Hopper 的 distributed shared memory）；CPU 在加显式控制（AMX tile register file 本质就是片上 scratchpad、NUMA-aware 分配、prefetch、非临时存储）；chiplet 化让“多核”也变成 NUMA + 显式局部性。**所有大规模并行芯片最终都得让你显式管理层次**——“众核”作为一个独立类别，正在被“所有芯片都变众核”吃掉。

## 一句话记住

**众核 = 用单线程性能换吞吐率/能效的设计点。** scratchpad 和显式数据搬运是它在功耗墙下的**惯用手段**（也是申威和 GPU 的共同点），不是**定义**；Xeon Phi 证明了没有 scratchpad 也能叫众核；而 **GPGPU 不但算众核，还是这条谱系上最极端的那一端**——它连你那条严格标准都满足，因为 `shared memory` 就是一块带 bank 的软件管理 SPM，`cp.async`/TMA/`__syncthreads`/warp shuffle 就是显式数据搬运与显式同步。
