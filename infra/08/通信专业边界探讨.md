# 通信专业边界探讨

### 🧑‍💻 User

rdma/roce 万卡通信 nvlink nccl sharp那些属于通信专业的内容吗？

---

### 🤖 Assistant

这是一个很典型的“专业边界”问题。直接说结论：

**这些内容严格来说不属于通信专业的传统核心，而是“通信 × 计算机 × 高性能计算（HPC）”的交叉地带。** 但通信专业会给你一部分底层基础。

下面拆开看，你就清楚了。

## 逐个归类

| 技术 | 本质 | 更贴近的专业方向 |
|------|------|------------------|
| **RDMA / RoCE** | 网络协议（远程直接内存访问 / 基于融合以太网的 RDMA） | 计算机网络、网络工程（通信专业有基础课，但深入的是计算机/网络方向） |
| **万卡通信** | 大规模分布式训练的网络拓扑、拥塞控制、调度 | 高性能计算、数据中心网络（计算机/系统方向） |
| **NVLink** | GPU 间高速互连（SerDes、信号完整性、链路层协议） | 微电子/电子科学/硬件（高速信号传输） |
| **NCCL** | 集合通信软件库（纯软件） | 计算机（分布式系统、并行计算） |
| **SHARP** | 网络内计算（在交换机里做归约） | 高性能计算 + 网络研究 |

## 为什么说通信专业“沾边但不属于核心”

**通信工程（信息与通信工程）的传统核心课程是：**

- 通信原理、信息论与编码、信号与系统、数字信号处理
- 电磁场与电磁波、微波/天线、无线通信、光纤通信
- 交换技术、计算机网络（基础层）

这些课程的侧重点是 **信号传输、编码调制、无线/光传输链路**，而不是 **大规模分布式系统的网络协议和集群互连**。

而 RDMA/RoCE/NCCL/SHARP 这些技术的内核是：

1. **协议与软件栈**（RDMA verbs、NCCL 的 ring/tree 算法）→ 偏计算机
2. **拥塞控制与拓扑**（DCQCN、Fat-Tree/Dragonfly、ECN/PFC）→ 偏计算机网络/系统
3. **高速 SerDes 与物理层**（NVLink 的 112G/224G 信号）→ 偏微电子/硬件

所以你会发现，这些内容在 **计算机专业的“高性能计算”“分布式系统”“数据中心网络”课程/实验室**里出现得更直接、更深入。

## 通信专业能切入的点

如果你已经在读通信，其实是有接口的：

- **计算机网络、交换原理** → RDMA/RoCE 协议的基础
- **光纤通信、光互连** → 万卡集群的光模块、光交换（CPO/OCS）
- **信息论、信号处理** → 高速 SerDes 的均衡、信道建模
- **研究生阶段** → 很多通信实验室也在做数据中心网络、RDMA 拥塞控制、AI 集群网络优化（属于交叉课题）

## 结论与建议

- **如果目标就是做 AI 集群通信/高性能网络**：选 **计算机（系统/网络方向）或专门的网络工程** 更直接。
- **如果已经在通信专业**：完全能切入，但需要自己补计算机系统、分布式计算、操作系统这些课，因为核心差距在“系统软件”而不是“信号”。
- 一句话概括：**通信专业给你“底层链路和网络基础”，计算机专业给你“系统和协议栈”，而这个领域恰恰在两者的交汇点上。**
