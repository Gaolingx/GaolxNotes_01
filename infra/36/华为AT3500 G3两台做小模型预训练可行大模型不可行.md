## 先纠正两个前提

<details>
<summary><b>1.「AT3500 G3」不是华为自有型号，是华鲲振宇（HuaKun）的 SKU</b></summary>

- `HuaKun AT3500 G3` = 华为 **Atlas 800I A2** 的 OEM 贴牌机（华鲲振宇是昇腾/鲲鹏整机伙伴，四川长虹系）。
- 官方定位是**推理服务器**：鲲鹏 920 + 8× **昇腾 910B4**，单机 8 卡、双机 16 卡；市场宣传语是「DeepSeek V3/R1 671B 满血版开箱即用」。
- 同系列还有 `3500 G3`，芯片同为 910B4。

所以严格说，你手上是**昇腾生态的推理机型**，不是 Atlas 800T A2/A3 那种训练机型。这一点对后面的结论影响很大。

> 注：AT3500 G3 的官方规格页我没能抓到（源站 502），下面的参数来自二手资料交叉验证，建议你用 `npu-smi info` 复核一下实际芯片型号（910B4 / 910B3 差别约 12%）。
</details>

<details>
<summary><b>2. Qwen3.5 没有 8B 这个尺寸</b></summary>

HF 上 Qwen3.5 官方系列是：**0.8B / 2B / 4B / 9B / 27B / 35B-A3B / 122B-A10B**。8B 是上一代 **Qwen3-8B**。

我按 **Qwen3.5-9B** 来算（读了它 `config.json`）：32 层、hidden 4096、FFN 12288、词表 248320、**混合线性注意力**（3× gated DeltaNet : 1× full attention，`full_attention_interval=4`）、原生多模态（27 层 ViT）、含 MTP 层，实际参数 ~**8.6–9.0B**。

如果你要的是 Qwen3-8B（纯 dense 全注意力），数字除以 1.1 即可。
</details>

## 一、能做多大规模的训练？

**显存维度上：能放得下 ~30B，但这是假象。**

Adam + bf16 混合精度全参训练，每参数约 16 字节状态（2 参数 + 2 梯度 + 4 主权重 + 4+4 动量）：

| 模型 | 优化器状态总量 | 分摊到 16 卡 |
|---|---|---|
| 2.1B | 34 GB | 2.1 GB |
| 8.8B | 141 GB | 8.8 GB |
| 27B | 432 GB | 27 GB |
| 35B | 560 GB | 35 GB |

1TB 显存用 ZeRO-3 / FSDP 全分片，30B 级别确实塞得下，还剩一半给激活值。

**但吞吐维度上，现实上限是 ~14B 做训练、~30B 只能做微调/续训。** 瓶颈从来不是显存，是 4.48 PFLOPS 这个数——它大约等于 **4.5 张 H100** 的峰值算力。

---

## 二、能不能做小模型预训练？—— 能，而且这是这台机器唯一合理的预训练场景

按 N 参数 6ND 估算，MFU 取 30%（小模型 + 16 卡，通信占比高，这个值已偏乐观）：

| 模型 | 吞吐 | 10B tokens | 30B tokens | 100B tokens | 1T tokens |
|---|---|---|---|---|---|
| 0.8B | 26.4 万 tok/s | 0.4 天 | 1.3 天 | **4.4 天** | 44 天 |
| 2B | 10.7 万 tok/s | 1.1 天 | 3.3 天 | **11 天** | 108 天 |
| 9B | 2.5 万 tok/s | 4.5 天 | 13.6 天 | **45 天** | 455 天 |

结论：**0.5B–2B 从零预训练是完全可以做的正经工作**（一个 100B token 的 2B 模型，两周出结果）。这也是练 pipeline、验证数据配比的标准做法。

## 三、Qwen3.5-9B 跑 1 epoch 要多久？

单 token 训练开销：

$$C_{\text{token}} = 6N = 6 \times 8.8\times10^{9} \approx 5.3\times10^{10}\ \text{FLOPs}$$

16 卡有效算力 $= 4.48\times10^{15} \times \text{MFU}$，换算成吞吐：

| MFU | 吞吐 | 每天产出 | 单卡 |
|---|---|---|---|
| 25% | 21,200 tok/s | 1.83 B | 1,326 tok/s |
| **30%** | **25,500 tok/s** | **2.20 B** | 1,591 tok/s |
| 35% | 29,700 tok/s | 2.57 B | 1,856 tok/s |

**1 epoch 时间 = tokens ÷ 2.2B(每天)**，按 MFU 30%：

| 语料规模 | 1 epoch 时间 | 说明 |
|---|---|---|
| 1B tokens | **0.5 天** | 玩具级、过拟合验证 |
| 10B tokens | **4.5 天** | |
| 30B tokens | **14 天** | |
| 100B tokens | **1.5 个月** | 「能拿出来说话」的最低配 |
| 180B tokens | **2.7 个月** | Chinchilla 最优（20×N） |
| 1T tokens | **1.25 年** | |
| 36T tokens | **约 45 年** | Qwen3-8B 的实际预训练量 |

所以，直接回答你的问题：**跑 1 个 epoch，取决于你有多少数据。100B token 是 1.5 个月，1T token 是 1 年多，对齐 Qwen 官方量级要几十年——也就是「不可行」。**

## 四、比算力更致命的四个隐性障碍

<details>
<summary><b>① 你买的是推理机型，不是训练机型</b></summary>

910B4 是 910B 家族里定位推理的降频档（280 TFLOPS / 64GB）。真正做训练应该用 **Atlas 800T A2（910B3，313 TFLOPS + 训练向拓扑验证）**，或者 **Atlas 800T A3 / 910C**（官方称实测性能为上代 2.2 倍）。用 800I A2 做预训练，等于开家用车跑拉力赛。
</details>

<details>
<summary><b>② 跨机 25GB/s 是最疼的一刀</b></summary>

机内 HCCS 392GB/s，跨机 200G RoCE 只有 ~25GB/s。16 卡只能切 **TP8（机内）× DP2（跨机）**：
- 每步梯度同步约 9GB/节点 → 网络耗时 ~0.36s
- global batch 65536 tokens 的话，每步计算 ~2.6s

→ 通信开销 ~13%。做 TP16 或 DP16 跨机直接崩掉。必须上 ZeRO-1/2 + 梯度分桶 + 通信隐藏，否则 MFU 会掉到 15% 以下。
</details>

<details>
<summary><b>③ Qwen3.5 的混合线性注意力在昇腾上基本没有现成支持</b></summary>

这是最容易被低估的一条。Qwen3.5 用的是 **3× gated DeltaNet : 1× full attention** 的混合结构 + 原生多模态 + MTP 层，`mamba_ssm_dtype: float32` 那条也意味着有状态扫描。

MindSpeed / MindFormers 里**没有 `qwen3_5` 的现成并行切分、fused kernel 和分布式 checkpoint 支持**。你得自己给 gated delta net 写 NPU 上的 chunked scan kernel——这部分工作量经常比训练本身还大，而且效果直接决定 MFU 能不能到 30%。
</details>

<details>
<summary><b>④ 显存够但 batch 上不去</b></summary>

64GB/卡、seq 4096、9B 模型，还要留 HBM 给激活值，micro-batch 大概只能到 1–2。梯度累积能救 batch size，但救不了 step 时间——每步 2.6s 意味着 100B token 要 152 万步。
</details>

## 结论

| 问题 | 答案 |
|---|---|
| 能做多大规模的训练 | **训练 ≤14B，微调/续训可到 ~30B**。显存不是瓶颈，算力（4.48 PFLOPS ≈ 4.5×H100 峰值）才是 |
| 能否做小模型预训练 | **能，而且是推荐用法**：0.5B–2B × 几十~上百 B token，2 周内可交付 |
| Qwen3.5-9B 1 epoch | **100B token ≈ 1.5 个月；1T ≈ 1.25 年；对齐官方 36T ≈ 45 年**（MFU 30%，乐观估计） |

**建议路线：**
1. 先用 0.8B/2B 把数据、tokenizer、ckpt、昇腾算子这条路打通；
2. 9B **只做 SFT / LoRA / 续训（≤ 几十 B token）**，不要碰从零预训练；
3. 真要做 9B 级预训练，两台 800I A2 最多算个「调试节点」，得去租 **Atlas 800T A3** 集群，或者按 100–1000 卡规模做预算；
4. 开工前先 `npu-smi info` 确认芯片型号，并实测一遍 `torch_npu` 下 9B 的 tokens/s——本文的 25.5k tok/s 是理论推算，实测值如果低于 15k，说明线路或算子有问题，先修再谈训练。
