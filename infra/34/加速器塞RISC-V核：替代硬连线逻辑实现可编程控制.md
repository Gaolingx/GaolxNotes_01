# 核心结论

加速器里放 RISC-V 核，**99% 不是用来做矩阵乘法的**，主要是为了“管”：负责控制、调度、隔离、可观测性，以及给硬件增加一层可编程能力。更准确的概括是：

> AI 加速器正在从“一个大 MAC 阵列 + 硬连线状态机（ASIC）”变成“少量专用算子单元 + 一大批小 CPU + 可编程 NoC（网络芯片）”。

RISC-V 只是在这个范式中最便宜、最自由的一块基础组件。真正的驱动力是“**用 CPU + 固件来替代硬连线逻辑**”，而不只是指令集选择。

---

# 一、加速器里的 RISC-V 核分成五类，不要把它们混为一谈

| 层级 | 作用 | 典型位置 |
|---|---|---|
| ① 控制/管理核（**最常见**） | 驱动卸载、电源管理、复位、错误处理、MIG/SR-IOV 隔离、遥测 | NVIDIA GSP、各 IP 里的 RPM 微控制器 |
| ② Dataflow / “baby core” | 让数据流、算子支持由编译器决定，避免重新流片 | Tenstorrent Tensix 的 5 个小核 |
| ③ 通用大核 | 在卡上直接运行控制面甚至一部分计算 | Tenstorrent Blackhole 的 16 颗 SiFive X280 |
| ④ 专用引擎的 front-end | 压缩/解压、加密、格式转换、RDMA、collectives | 各家 DMA / 网络 / 集合通信单元 |
| ⑤ 安全岛（root of trust） | secure boot、密钥、fuse、带外恢复与调试 | OpenTitan 一类 |

**关键点**：这五类核的成本和设计目标完全不同。①⑤ 追求“极小、可验证、永远在线”；②追求“够快、够多、能被编译器当成流水线使用”；③才是真正意义上的 CPU。看到“塞了 RISC-V”时，先问它属于哪一类，否则很容易理解错。

# 二、为什么选 RISC-V，而不用 ARM、MIPS 或自研 ISA

1. **成本结构**：免费、无版税、可裁剪。一颗芯片上铺几百上千个核时，授权费会变成决定性因素。
2. **可修改**：可以添加自定义指令和紧耦合加速器端口，做 domain-specific 扩展不需要跟别人谈判。
3. **工具链和验证复用**：GCC/LLVM、RTOS、Rust、形式化验证、开源 debug/trace 全都现成，微型核的验证工作量极小。
4. **生态中立**：不属于任何一家公司，在供应链和地缘政治上是“安全”的选择。
5. **有历史路径依赖**：NVIDIA 早年自研 Falcon ISA，后来整体换到 RISC-V，相当于减少“自研 ISA + 自研工具链”的负担。NVIDIA 公开表示 2024 年一年出货约 **10 亿颗** RISC-V 核，分布在 GPU、SoC、网络芯片的 30 多个内部单元里。

**反向的账也算得过来**：一次流片几千万美元、周期 18 个月，而专用加速器的算法/精度（FP8 → FP4 → MX）几乎每代都变。用 2~3% 的面积换“不用流片也能改行为”，在现代 AI 芯片上极其划算。

# 三、为什么是**现在**才普遍采用

<details>
<summary><b>展开：4 个结构性原因</b></summary>

1. **芯片规模超过状态机可维护的极限**
   一颗 Blackwell 级 die 上有几十个时钟域、几百个控制点。全部用 RTL 状态机写，“能跑起来”就已经用尽验证资源，更不用说后期能修改。改用 CPU + 固件后，控制逻辑可以用 C 写、可以打 microcode patch。

2. **异构集成（chiplet / D2D / CXL / 光互连）**
   每个接口都是一套协议栈 + 状态机 + 错误恢复，而且**必须支持现场升级**。没有可编程核做不到。

3. **主机侧成本**
   GPU 从“协处理器”变成“一台计算机”。把驱动的一部分搬到卡上（NVIDIA GSP 就是典型），host CPU 和 hypervisor 就能少管非常多事，虚拟化和多租户隔离也更干净。

4. **功耗与能效**
   小核能快速睡眠/唤醒，比全局状态机更容易做细粒度 clock/power gating。

</details>

# 四、三家的具体做法（差异巨大）

**NVIDIA Blackwell**
这里 RISC-V 承担“基础设施”角色：从 Turing 起的 GSP（GPU System Processor）就是 RISC-V，负责固件、电源、错误、独立刷新；Blackwell 上更是遍布微控制器（GPC、内存子系统、NVLink、显示、安全）。意义在于：**驱动/固件的边界前移**，卡自己变成一个自洽的小系统，MIG 隔离、独立复位、遥测都由卡上固件负责。这也是 NVIDIA 软件壁垒的另一半，只是很少被讨论。

**Tenstorrent**
这里 RISC-V 的角色完全不同，它不只是配角，而是 **架构本体**：每颗 Tensix 核 = 5 个小型 RISC-V “baby” 核 + 1 个 math unit + SRAM + NoC 路由；Blackhole 上还有 16 颗 SiFive X280 当通用核。设计哲学是“**硬件只提供稀疏的算子，其余全部由软件数据流编排**”，新算子靠编译器而不是新流片。这是 Jim Keller 那派（“RISC-V + 可编程 dataflow”）的典型样本。

**Google TPU v7 (Ironwood)**
Google 官方 TPU7x 文档里公开的结构是：每颗 chiplet 1 个 TensorCore + 2 个 SparseCore、双 chiplet、各自独立 HBM。⚠️ 说句实话：**我没能核实 “Ironwood 里明确有 RISC-V 核” 这一条**（Google 的架构文档不谈这个层级，RISC-V 也不是其公开卖点）。从设计逻辑上推断，像 SparseCore、DMA/collectives、per-chiplet 本地管理 agent 这类“胶水”用可编程小核实现非常合理，但我建议把这条当成“很可能、未公开确认”，别当定论。

# 五、代价：并非只有好处

- **面积/能效换灵活性**：对纯推理、算法已经固化的场景，fixed-function 仍然更省。塞核是“为未来不确定”付费。
- **编程模型反而碎片化**：核一多就要自己造多核 runtime、消息传递、内存模型。现在每家一套（tt-metal、各家私有 firmware ABI），生态比 CUDA 更碎。
- **控制面会成为新瓶颈**：一次 kernel launch、一次描述符链的穿越动辄几百 cycle；所以常见的组合是“大核极少 + 小核极多 + 加专用指令”，而不是堆通用核。
- **验证难度转移**：几百个核的死锁、内存序、一致性问题，比一条大流水线更难 debug；而且“能靠固件打补丁”容易变成“反正能打补丁”。
- **护城河换位置**：以前锁定在 ISA/编译器，现在锁定在**固件与驱动**，这其实是更深的锁。

---

# 六、一句话判断

“往加速器里塞 RISC-V”本质上是一次 **从 ASIC 回到可编程 SoC 的回归**，动力来自算法迭代速度超过了流片周期、芯片复杂度超过了状态机可维护性。看到这种设计，正确的问法不是“为什么用 RISC-V”，而是：

> **“这颗核负责的是控制面、数据面，还是安全面？它省下的是流片风险、验证成本，还是主机的软件复杂度？”**

想深入的话，我可以就其中一条展开：比如把 NVIDIA GSP 的驱动卸载机制、Tenstorrent 的 baby-core 数据流编程模型，或者“控制核为什么常年是延迟瓶颈”单独讲透。
