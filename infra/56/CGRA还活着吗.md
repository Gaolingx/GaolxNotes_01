## 😀 默认助手 (7)

先说明一下这篇文章。这是 IEEE Spectrum 那篇讲“和零值做朋友”的译文，主角是斯坦福 Kunle Olukotun 组的 **Onyx**：一颗以 CGRA 为骨架的稀疏加速器，PE 直接取用压缩格式（fibertree 或类 CSC），把间接寻址和非零元解码做进硬件，再靠重新配置来覆盖 SpMV/SpMM 和 dense GEMM。因此它正好落在你问的这几个点上。

## 一、CGRA 还活着吗？

它活着，但“CGRA”这个词的指代已经发生了变化。分成三类来看会更清楚：

| 类型 | 代表 | 状态 |
|---|---|---|
| 真正量产出货的 | **AMD/Xilinx Versal AI Engine**（VLIW SIMD 阵列 + 2D NoC + AXI-Stream 邻接） | 确实在大量出货，用于 5G 基带、相控阵雷达、汽车、医疗影像 |
| 商业公司 | **SambaNova RDU**（数据流 + 可重构 crossbar）、清微智能（国内清华系可重构数据流） | 活着，规模不大，靠“对冲模型演进”卖 |
| 学术界 | Plasticine、Thinker/STICKER（清华）、Flexagon、**Onyx** | 论文多，但落地少 |

但更值得注意的是第四种情况：**CGRA 正在被吸收，不再作为一种独立芯片类型存在**。TPU/GPU 的 tensor memory、warp specialization、Triton 的 layout 抽象、MLIR 的 `linalg` + 静态调度，本质上就是“编译期 spatial scheduling + 片上数据流”。CGRA 的核心思想（静态调度、空间并行、算子融合、显式 scratchpad）已经进入主流，只是名字不再叫 CGRA。所以与其说“CGRA 活着吗”，不如说“它作为方法论活着，作为架构标签在淡化”。

商业上，CGRA 真正有竞争力的卖点在于**对冲模型演进风险**，而不在峰值能效比。边缘 SoC 里“主控 RISC-V + CGRA 加速器”这个形态存在的原因是：新算子出现时重新编译配置就能运行，不必再次流片。这是一个商业论点，并非性能论点。如果只看 TOPS/W，它打不过硬化的 systolic。

## 二、粒度与变体：你的感觉是对的，这个词已经快要失去意义

差异大到不适合用“一种架构”来讨论。真正决定它是什么的，是下面这几个正交维度：

- **PE 粒度**：1-bit ALU（接近 FPGA）→ 4/8-bit MAC → $16\times16$ MAC tile → 带 32-lane SIMD 的完整 VLIW 核（Versal AIE）。跨度两个数量级。
- **存储粒度**：分布式小 RF（RF-CGRA，面积省、编译难）vs 每 PE 带独立 scratchpad vs 共享多 bank SM（好编译、面积大）。
- **互连**：neighbor + bypass mux / 分层 crossbar（面积大、扩展性差）/ 片上 NoC / 网络-on-chip + 全局共享。
- **控制模型**：静态配置（“配置一次跑 N cycle”，VLIW 式时间展开）vs 动态 tagged token（dataflow，Plasticine/Wave）vs 混合。
- **编译栈**：有没有 PyTorch → MLIR → 配置位流这条链，决定了 90% 的成败。

所以变体多的根本原因是：**“灵活性”这个维度是连续的**，并且每个点都可以作为论文的卖点。这也是学术界 CGRA 论文给出的可复现结果偏少、benchmark 各自定义的原因。

## 三、“期待规整负载、好 prefetch”：需要细化一下

方向对，但更准确的说法是：**它期待 affine、静态可判定的访存模式**，这比“好 prefetch”严格得多。

- CPU 的 prefetch 是**投机**的：猜错了只是多花几个 cycle，功能没错。
- 静态调度 CGRA 的地址必须在**编译期确定**（或至少是 affine function of loop index），否则要么插动态同步，要么直接跑不起来。猜错会导致功能错误或死锁。

由此推断出它的优势应用场景：5G 物理层（LDPC/FFT/波束成形）、stencil/ISP、conv 层。这些全是静态、确定、双缓冲就能处理完的。它的劣势场景：GNN、MoE 路由、动态稀疏 attention、任何 pointer-chasing。

但 Onyx 这类工作恰恰是反例：它没有回避“不规整”，反而把不规整性**下沉到硬件里**（压缩格式解码单元 + indirect load 单元），从而把“数据布局的不规整”转成“结构上的可重构”。代价是 PE 里塞了一堆稀疏专用逻辑，做 dense 计算时这些逻辑闲置。这就是文章最后说下一代要做“稠密/稀疏加速器架构更高效率集成”的原因。

还有一点：现在的 LLM decode 和 prefill 其实相当规整（分块 GEMM + softmax 融合），真正不规整的是 MoE 和稀疏 attention。所以 CGRA 的新机会窗口在 MoE，但要和 GPU 的 HBM 带宽 + SRAM 容量竞争，很难。

## 四、CGRA 当脉动阵列打不过真脉动阵列，这个判断基本对

而且不是“差一点”，是**架构层面的必然**。原因是：

1. **配置开销**：脉动阵列的“权值”是数据流，天然每 cycle 前进一格；CGRA 要把 config word 广播/存到每个 PE 的配置存储器，这部分面积和动态功耗是纯开销。
2. **互连成本**：脉动阵列的互连就是 FF 链加定向短线，几乎“免费”；CGRA 的 bypass mux + 长线，经验上物理实现里能吃掉面积/功耗的三到五成（量级估计，随工艺和拓扑波动很大）。而一次 MAC 的能量是 $\sim 0.1\text{–}0.2\,\text{pJ}$ 量级，一次 32-bit RF read 或一级 bypass mux 也是同量级，因此**互连和 RF 读取节省下来的能耗比算力节省更值钱**。
3. **端口带宽**：一个通用 PE 若要做到每 cycle 32 个操作数（等价 $16\times16$ MAC），RF 需要读写端口数 $P \propto K^2$，于是面积为 $O(K^2)$ 增长，不现实。真正脉动阵列靠邻居直传规避了端口问题，这是“真脉动阵列”的核心优势。
4. **频率**：局部短线 + 规整流水可跑高频；CGRA 的 bypass 长线拖慢关键路径。
5. **利用率**：dense GEMM 上脉动阵列的每个 MAC 可以接近 100% 忙；CGRA 的 PE 是通用 ALU，做 MAC 时必然有控制和路由 bubbles。

但请注意“打不过”的**边界条件**：

- 当 shape 大而规整时，结论是：确实打不过，不必强行去做。
- 当“算子链被融合”时，结论反过来：conv+BN+ReLU+pool、attention 的 $QK^\top \to \text{softmax} \to PV$、不规则 K 维的稀疏 GEMM，这些场景下脉动阵列的 tile 边界浪费 + 中间结果往返 SM 的能耗会暴露，CGRA 的 spatial fusion 能扳回来。脉动阵列省的是“阵列内”，代价是“跨算子”全部要回到 SM。
- 现在的正确解法是**异构**，而非二选一：把 systolic MAC tile 作为 CGRA 里的一等公民（一类可重构 tile），编译器按 kernel 选。Versal AIE-ML、以及 Onyx 下一代说的“集成稠密和稀疏架构”，走的就是这条路。

所以对你们组那颗“CGRA 当矩阵运算单元”的芯片，我猜它的真实价值在于：一颗芯片覆盖多形状 GEMM + 后处理融合 + 边缘 batch=1，而不是峰值 TOPS/W。如果是后者，那是拿自己的弱点去比别人最强的部分。

## 五、判断一个 CGRA 项目值不值得做

我会看三条，按重要性排序：

1. **编译器团队是不是比硬件团队更受重视**（或者说，是否受到同等重视）。Plasticine 的挫败很大程度在编译栈；Onyx 的贡献里，编译器能把 sparse expression 映射上去才是关键。
2. **目标负载是否静态可分析**。如果 benchmark 里有大量 pointer-chasing，或者动态 trip count，就别用 CGRA。
3. **能效对比的 baseline 是否诚实**。文章里 565× EDP、70× 能耗都是对比 12 核 Xeon + 稀疏库；而且稀疏库在 CPU 上本来就不够快。这类数字要打折看，换 GPU 做 baseline 结论未必成立。

---

**一句话总结**：CGRA 活着，但它的胜利是“方法论层面的胜利”：静态空间调度 + 显式数据流 + 算子融合已经扩散到所有加速器里了。作为独立架构标签，它在稠密大 GEMM 上必然输给 systolic，而在“多算子融合 + 中低算力 + 边缘 + 需要能重编译适配新模型”的应用场景里仍有竞争力；这也是 Versal AIE 和 Onyx 各自成立的场景。

## 😀 默认助手 (7)

几个问题合起来其实能串成一条线：**可编程性具体加在哪一层，决定了它的开销；不可编程性又出现在哪一层，决定了它能否覆盖不规则负载。** 下面按这个顺序来。

## 1. 脉动阵列为什么要可编程？先问“可编程在哪一层”

可编程性不是布尔值，而是分层的；而且越往上的层越贵：

| 层级 | 内容 | 代价 | 现实 |
|---|---|---|---|
| 形状 | tile 的 $M,N,K$、causal mask、GQA 的 $G$ | 几乎为零（地址生成器 + FIFO 长度） | 必做，TPU 就做 |
| 数据流 | weight/output/row-stationary 切换、双缓冲深度 | 很低 | 做，收益实在 |
| 精度 | INT8→INT4，FP16→2×FP8（乘法器 bit 可分割） | 中（乘法器加 by path） | 已大规模做，**收益最大的一个** |
| 算子 | MAC 变成 max/sort/softmax 的最小单元 | 中 | 很少有人做，**被低估** |
| 路由 | 逐 cycle 配置 PE 间连线 | **高**：mux + bypass + 配置字广播 | 这就是 CGRA 付出巨大代价的地方 |

TPU v1 只有 12 条指令，FMA 阵列是一条指令——这是工业界对“脉动阵列需要可编程吗”的真实回答：**指令级可编程，FMA 级不可编程**；再加上编译器里的 tiling/mapping 决定，实际“可编程性”大半都在编译器里。

## 2. FMA 能变成什么有意义的东西

关键观察是：**整个乘加单元里，只有乘法器无法低成本通用化**。乘法器是 $O(N^2)$ 的部分积矩阵加压缩树，专用且昂贵；而它周围的加法器、比较器、移位器、选通网络都很便宜，并且天然多用途。所以好的方向是**把乘法器固化，把周围全部通用化**：

- **可分割乘法器**：一个 INT8 乘法拆成 $2\times2$ 个 INT4 部分积，FP16 拆成两个 FP8。这是唯一已被证明划算的“算子柔性”。
- **归约树复用**：MAC 阵列的压缩树本质是一棵加法归约树。同一棵树上可以取 **max**（maxpool / softmax 最大值）、**sum**（layernorm 均值、softmax 分母）、**argmax**、甚至 **prefix-sum**。让 softmax/layernorm 在阵列的归约网络里顺带完成，而不是回片外向量单元——这个方向实际收益不小，但做得少。
- **比较-交换 = 排序网络**：top-k、MoE 路由。乘法器改成 min/max 几乎免费。
- **移位/对齐器**：FP 加法、量化反量化、normalize。
- **permutation / 桶形移位网络**：这是唯一有希望处理“不规则”的硬件，值得单独讲（见后面 gather 那段）。

一句话：**乘法器专用、周边通用**，比“所有 PE 都做成通用 ALU”（CGRA）和“所有东西都固化”（纯 systolic）都更靠近最优。

## 3. im2col 那段澄清一下

你说得对，脉动阵列天生带 im2col——因为 **im2col 在算术层面并不存在，它只是地址模式**。weight FIFO 和 activation FIFO 的地址生成器按 stride/dilation 生成地址流，滑窗复用就自然发生了。这部分成本就是几个地址计数器和 FIFO，约等于零。Eyeriss 讲的 row-stationary 也是一样：conv 与 GEMM 的真正区别是**复用模式**（输入复用 / 权重复用 / 部分和复用），不是运算单元。

反过来，**CGRA 上“写死 conv 指令”反而会适得其反**：滑窗移位的 shift register 要占用 PE 和邻接链路，等于拿重构资源去实现一个本来只该由地址生成器完成的事。所以“CGRA 可以写死卷积”在技术上能成立，在资源账上并不划算。

## 4. “上不去下不来”——同意，但我想加一条更关键的约束

先记住一组量级（数值粗糙，但比例是决定性的，按 Horowitz 那套）：

$$\text{MAC}_{\text{int8}} \sim 0.1\text{pJ} \ll \text{RF 读} \sim 0.5\text{pJ} < \text{SRAM 读} \sim \text{几 pJ} \ll \text{片外字节} \sim 10\text{-}20\,\text{pJ/byte}$$

片外和计算差**两个数量级**。因此：

> **架构优化的目标几乎从来都不是“提高 ALU 利用率”，而是“减少字节数”。**

这一下就把整个问题变了味。**CGRA 的可重构性带来的是“硅面积利用率的提升”，无法减少“字节数”。** 而面积利用率只在**硅面积/功耗是硬约束**的地方才值钱。所以：

- **边缘端**（面积功耗受限、batch=1、算子碎）→ CGRA 有账算。
- **云端**（带宽受限、HBM 是瓶颈、模型巨大）→ CGRA 完全没有账算，它的灵活性对 bytes 毫无帮助。

这是“上不去下不来”的量化版本：它想卖的东西（利用率）在需要它的地方不赚钱，在赚钱的地方不需要它。再叠加一笔**编译器债务**——细粒度 CGRA 的 placement/routing 是 NP-hard，工具链要养一个团队好几年；而 granularity 越粗，编译越 tractable。所以历史上每次算力需求上涨，粒度都是**单向变粗**：Wave 死了、Blaize 死了、Groq 转成 VLIW+systolic、Versal AIE 活下来是因为它是 DSP 形状、TPU 赢是因为它最大最不灵活。

## 5. DSP 假设——我强烈同意，而且这是历史上唯一被验证过的

而且我认为你漏掉了一个**决定性的技术理由**：不太常被提及——

> **静态调度 = 可给出 WCET（最坏执行时间）上界 = 确定性。**

实时性不只是“快”，而是“**抖动可证**”。汽车、医疗、雷达、无线基带、工控、军工，这些场景是**法规要求确定性**，GPU 结构上给不了。CGRA 静态调度的“缺点”（不能投机、不能乱序）在这里恰恰是**认证资产**。这一点比能效更关键，也是 FPGA 在这些领域长期占据位置的根本原因。

CGRA 相对 FPGA 的真实差异也在这里清晰了——对比对象是 **FPGA 里的 DSP48 + 软逻辑**，并非“FPGA 整体”：

- CGRA 赢：编译时间（分钟级 vs 小时级 place&route）、同吞吐下动态功耗、无 bitstream 配置开销、同面积下 DSP 类 ALU 利用率。
- CGRA 输：峰值吞吐（FPGA 的 DSP48 跑 500MHz+ 很凶）、I/O 灵活性、以及**几十年的 EDA/生态**。

而市场其实已经给出了答案：**FPGA 厂商自己把 CGRA 概念吸收进去了**（Versal AI Engine、Agilex 的 AI tensor block）。所以“CGRA 在 DSP 领域打赢 FPGA”的正确表述是：**CGRA 在 DSP 领域没有独立胜出，它的概念赢了，并获胜后被并入 FPGA 的下一代产品线。** 这个生态位确实存在，但它的经济回报已被先占者拿走。

## 6. XDNA 是不是 CGRA——你的爆论严格化之后是成立的

而且我认为存在一个比“粒度”更好的分类轴：

> **被重构的到底是 {PE 的功能} 还是 {PE 之间的连线路由}？**

| | PE 功能 | 互连 | 重构粒度 |
|---|---|---|---|
| FPGA | LUT，位级可配 | 位级可配 | bit |
| 经典 CGRA | 半固定（ALU+RF） | **word 级可配路由** | word |
| XDNA / AIE、VLIW 数据流阵列 | **程序存储器可编程**（运行时改） | **固定**（stream + 2D NoC） | tile/program |
| 脉动阵列 | 固定 | 固定 | 无 |
| GPU | 可编程 | crossbar/NoC，靠存储汇合 | warp |

按这个表，**XDNA 属于“固定互连 + 可编程 PE 的粗粒度数据流机”**，经典 CGRA 是“可编程互连 + 半固定 PE”。这是两个不同的物种，但确实**同处一个生态位**——都是“静态可调度 + 确定 + 中高吞吐 + 长期运行的 kernel”，也就是 GPU 结构上占不了的位置。

而 XDNA 的用户接口（window / stream / lock buffer、AIE API）进一步证明它是数据流机，而非“配置位流”意义上的可重构阵列。经典 CGRA 每个周期都在重配路由，XDNA 则是一次装载程序、长期流式运行。所以你说“严格定义下不成立、但结构很像”——我觉得可以反过来讲：**是“CGRA”这个旧词已经装不下这类东西了**；XDNA 才是这个生态位目前最成功的实现。

## 7. 对“越细粒度赌控制流细”的细化

你的直觉我认为可以再准确一点：

> 细粒度赌的是**不规则性在空间上被切碎后，其不规则度可以被局部吸收**；粗粒度赌的是**规整性在时间上能持续足够多个周期**。

补上一条经济学推论：**重构频率必须远低于计算密度**。配置能量被摊薄的这个关系是：

$$\frac{E_{\text{cfg, per-cycle}}}{E_{\text{compute, per-cycle}}} \propto \frac{1}{T_{\text{reconfig}}}$$

所以只要算力密度需求一直涨，粒度就一直变粗，这就是那个**单向棘轮**。

## 8. LLM 那段——我部分不同意

我的看法是：**LLM 推理现在是有史以来最规整的负载**（dense GEMM、大 tile、形状可预测），这恰恰是“需要柔性”这一侧最不利的时期。而“稀疏/MoE 会带动数据流架构”这个推论，我更倾向反向解读：

- 2:4 稀疏喊了很多年，实际没兑现；
- MoE 的“不规则”在**粗粒度**上——专家选择是一次大 gather，$k$ 很小、粒度是整个专家权重块；
- 序列长度变化、prefill/decode 分离，也是粗粒度。

这些不规则性**真正的解决方法是大容量 SRAM + HBM 带宽 + 批处理**，而不是细粒度计算阵列。GPU 的 HBM 就是用来承受这类粗粒度不规则的缓冲器。所以 LLM 时代数据流机器的机会，我认为落在**边缘端 decode + 强实时**上——而那就是 DSP 形状。**结论绕回第 5 节。**

## 9. 稀疏访存——“没有能力”还是“代价太高”

严格说是后者。数据流机有机制：动态标签、握手（等价 Tomasulo 的 token 流）、间接寻址单元（Onyx 的 indirect load、Plasticine 的 configurable memory）。问题是**代价**：静态调度要求延迟可知，而数据相关访问的延迟不可知，桥接它只有两条路——**多线程去容忍，或握手去容忍**，两者都消耗面积/功耗。而且更深一层：**稀疏格式无法摊销地址生成，也无法预取**，预取深度再大也没用，因为缺的是*时间上的松弛*，而静态调度本来就没有松弛。

关于 gather，我修正一下你的“几乎没有现实硬件为此优化”——**向量机是认真优化过的**：

- **ARM SVE/SVE2**：`LD1B {Zt.S}, Pg/Z, [Zn.S, Zm.S]`，向量基址 + 每 lane 向量偏移，是**架构级一等寻址模式**，并非微码兜底。Fujitsu A64FX 的 gather/scatter 确实被用于 Fugaku 的不规则代码。
- **NEC SX-Aurora**：向量引擎里 gather/scatter 由专门单元高吞吐执行，目标就是稀疏求解器，是真实商用产品。
- **x86 的 AVX2 gather 确实很差**（微码、接近每 cycle 一个元素），AVX-512 才勉强能看。你的判断在 x86 上成立。

真正的瓶颈我认为可能不是数据搬运，而是**每 cycle 需要 $N$ 次独立地址翻译**——TLB 才是根本成本。所以出路是（a）大页/预翻译描述符，（b）**块 gather**（每 lane 取 8 个连续元素——这正是 block-sparse 的形态），（c）把索引表放进加速器自己的地址空间，绕开 TLB（Onyx 和所有稀疏加速器都这么干），（d）交给 DMA/TMA 用描述符做间接搬运。

## 10. FGMT/SMT——方向对，但市场已经给出了相反的票

给点历史坐标，因为我怀疑这正是这个方向一直没成的原因：

- **Tera MTA**：每处理器 128 线程、无数据 cache、纯靠线程容忍延迟。**技术上非常成功**——不规则、指针追踪、图、稀疏代码跑得很好，NAS integer 也不差。**商业上彻底失败**：每线程面积/功耗巨大，单线程性能很差。
- **Sun Niagara/T1–T4**：直接从 128 线程退到每核 4 线程，就是因为 FGMT 的 ILP 损失和频率代价不划算。
- **最后赢的是**：2–4 way SMT + 深 OoO + 深预取 + 大 SRAM cache + HBM 带宽。

也就是说：**“用线程买延迟容忍”败给了“用存储和带宽买延迟容忍”。** 原因是前者付的是**计算面积**（摩尔定律越走越贵），后者付的是**存储面积**（几十年里跌得最快）。这是个残酷但有解释力的经济学结论，也解释了为什么所有“不规则专用机”（GNN、稀疏、数据库）最后都被“大 HBM + 软件 gather 的 GPU”吃回来——因为不规则负载在**粗粒度上仍有规整性**，批处理就把它吃掉了。

---

**如果把整段对话压成一句话**：

> 硬件只能容忍**粒度比自身重构粒度更粗**的不规则性。
> FPGA 靠支付面积来吸收细粒度不规则；脉动阵列直接放弃不规则；CGRA 卡在中间是因为它想用 word 级路由去吸收细粒度不规则，而那个层级的 mux/配置代价吃掉了它能提供的全部好处。
> 所以真正的解不是“更灵活”，而是**把不规则性做成粗粒度的**（block-sparse、描述符 DMA、块 gather、专家路由）——也就是业界一直在做的、且看起来并不那么光鲜的事。
