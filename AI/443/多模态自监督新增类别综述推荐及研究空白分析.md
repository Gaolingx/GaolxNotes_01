## 先给结论

**没有一篇 survey 正好覆盖“多模态自监督 + 新增类别（transfer）+ fine-grained”这个完整交集**：这个交集目前还是空白区，最近的综述都把这三块拆开写。所以推荐方式是 **1 篇主干 + 3 篇补位 + 几条 frontier primary papers**。

---

## 一、主干必读

| 论文 | 覆盖你的哪块需求 | 为什么选它 |
|---|---|---|
| **Category Discovery: An Open-World Perspective**<br>He, Liu, Han · arXiv `2509.22542`（2025.09） | 新增类别（主干） | 目前**最新、最全**的 category discovery 综述。把 NCD / GCD 作为两个 base setting，再扩展到 continual、skewed distribution、federated 等派生设定；每类都从 **representation learning / label assignment / class number estimation** 三个部件拆解，还做了统一 benchmark。作者是 Kai Han 组（GCD 那条线的主要贡献者），维护 living repo | 
| **Novel Class Discovery: an Introduction and Key Concepts**<br>Troisemaine et al. · arXiv `2302.12028` | transfer learning 视角 | 全文的组织轴就是“**知识怎么从 labeled set 迁移到 unlabeled set**”，分成两阶段式与联合一阶段式，并把 pseudo-labeling / self-supervised / contrastive 这些工具单独成章。你问 transfer learning，这篇的框架最贴 |
| **Self-Supervised Multimodal Learning: A Survey**<br>Zong, Mac Aodha, Hospedales · TPAMI · arXiv `2304.01008` | 多模态自监督 | 归纳为三个内在挑战：无标签表征学习、跨模态融合、unaligned 数据；并且明确区分 **coarse-grained 与 fine-grained 对齐**（pair-free 学习那一节）。你把多模态模型当作特征来源时，可以直接用它作为分类框架 |

## 二、补位（fine-grained / open-world 侧翼）

| 论文 | 用途 |
|---|---|
| **Fine-Grained Image Analysis with Deep Learning: A Survey**（Wei et al., TPAMI, `2111.06119`） | 细粒度识别与检索的标准参考，做 fine-grained GCD 必引 |

## 三、交集空白区 → 直接读这几篇 primary paper

综述目前追不上这两年的进展，多模态 GCD 和 fine-grained GCD 基本只能看原文：

**多模态 GCD（新，几乎没被综述覆盖）**
- **MM-GCD: Multimodal Generalized Category Discovery**（`2409.11624`）—— 第一个把 GCD 推到多模态的任务定义，核心论点是异质模态对齐，特征空间和输出空间各做一次对齐；数据集 UPMC-Food101、N24News。
- **SpectralGCD**（ICLR 2026, `2602.17395`）—— 用 CLIP cross-modal image-concept 相似度当统一表征，把图像表示为概念字典上的混合分布，再用 teacher-student 蒸馏做频谱过滤；优点是算力便宜，且有可解释性。
- **xNCD: Explainable Novel Category Discovery in Semantic Concept Space**（`2607.04548`）—— 直接在语义 concept space 里做发现，理论部分讨论了 concept bottleneck 对假设类的限制。CUB-200 上比 UNO 提升明显。

**fine-grained GCD（self-supervised 手段最集中）**
- **SelEx: Self-Expertise in Fine-Grained GCD**（ECCV 2024, `2408.14371`）—— 用 supervised + unsupervised 双路 self-expertise 解决“对比学习分不开细粒度”的问题，是你这个题最贴的一篇。
- **PartGCD**（`2503.16782`）与 **APL: Adaptive Part Learning**（CVPR 2025, `2507.06928`）—— 都基于 DINO 的 part-level 表征，明确指出全局 CLS token 在 “discriminability vs. generalization” 上存在 trade-off。这条 part 路线目前是 fine-grained GCD 的主流。
- **PromptCAL**（CVPR 2023, `2212.05590`）—— GNCD setting 的经典 baseline，CUB-200 上接近 +11%，细粒度上的对照点。
- 另有两个值得注意的新方向：**MOS**（CVPR 2025, `2503.12035`）把场景信息当先验，细粒度上 +4%；**ATCG**（CVPR 2026, `2603.19918`）用类比生成文本概念，把 discovery 变成 visual-textual reasoning。

## 四、建议的阅读顺序

$$\text{Category Discovery Survey} \rightarrow \text{NCD (Troisemaine)} \rightarrow \text{SSML Survey} \rightarrow \text{SelEx / PartGCD} \rightarrow \text{MM-GCD / SpectralGCD}$$

前两篇建立**问题分类框架**，第三篇补充**多模态自监督工具箱**，后两篇是**方法从视觉路线到多模态路线的桥**。

## 五、一个术语上的提醒

你说的“新增类别”有两种常见歧义，对应完全不同的文献：

1. **数据里本来就有未知类，要求同时分类旧类 + 聚类新类** → 这是 NCD / GCD / C-GCD 那条主线，读上面第一、二节。
2. **模型已部署，靠文本/语义空间 zero-shot 兜住新类** → 那是 open-vocabulary / OVLearning 那条线，读 `2306.15880` 加 `2602.17395`。

如果两者都要，其实正是 **MM-GCD 这类工作的研究动机**——你可以考虑把“多模态（尤其 vision-language）在 GCD 里承担什么角色、SpectralGCD 的 concept-dictionary 路线和 xNCD 的 concept bottleneck 路线谁更 generalizable”做成一个还空着的 survey 选题。

## 但“frozen → feature → your model 随便就行”这句话，我要加三个保留条件

结论先说：**“frozen 是主流且强” ✅；“frozen 之后下游随便” ❌**。对 *fine-grained + 新增类别* 这个特定组合，下游恰恰是全部难点所在。

### 1. Frozen 确实成立，但 burden 转移了

`Category Discovery` 综述（`2509.22542`）benchmark 后的关键结论里，第一条就是 **large-scale pretrained backbones 有益**——所以冻住 encoder 是正当的、甚至是推荐的。

但代价是：一旦表征固定，剩下的信息量就只能从两个地方获取：

- **类别数估计（estimation of class number）** ← 综述明确点名仍是 open challenge
- **标签分配（label assignment）** ← 同上

这两块就是你说的“your model”所在的位置。它并不轻松——**这是全篇唯一的可变部分**。frozen 让问题变干净，但没让它变简单。

### 2. Fine-grained 场景下，frozen 的 global CLS 有已知的 trade-off

这是最需要你警惕的一点。`PartGCD`（`2503.16782`）和 `APL`（CVPR 2025，`2507.06928`）的原话几乎一样：

> 只使用 DINO 的全局 CLS token，会在 **discriminability 与 generalization 之间**形成内在 trade-off。

换句话说：**frozen global feature 在 CIFAR-100 / ImageNet-100 这种 generic 数据上很好看，到 CUB-200 / iNat 上会明显掉。** 所以 `SelEx`（ECCV 2024）、`PartGCD`、`APL` 全都在做同一件事——把表征从“一个 CLS 向量”换成“一组 part 表征”。若你要做细粒度，这是必须改的一处，不能“随便”。

### 3. 多模态场景下，frozen 到底意味着“两个未对齐的 encoder 拼起来”

`MM-GCD`（`2409.11624`）的核心 observation 就是这个：多模态 GCD 的困难是异质模态对齐，所以它**在 feature space 和 output space 各做一次对齐**（对比与蒸馏）。单纯 frozen 双塔后 concat，正是它要批评的 baseline。

## 实操：frozen 之后真正需要调的几处细节

<details>
<summary>展开（这些细节直接决定你能不能在 fine-grained 上复现论文的数字）</summary>

1. **取哪一层**：DINOv3 / Pixio 的中层 patch feature 常比末层更适合细粒度（末层偏语义）。别默认 `x_norm_clstoken`。
2. **CLS 还是 patch 聚合**：细粒度一定要试 patch token 的 mean / 加权，或 `APL` 式 learnable part query。
3. **分辨率**：frozen ViT 在 224 上 patch 太粗，细粒度通常要提到 448/518 甚至 sliding-window。
4. **归一化**：L2-normalize 后再聚类，否则 cosine 与 k-means 的假设不一致。
5. **类别数 k**：先测试“已知 k 的做法”和“半自动估计”的差距，这个差距往往比换 backbone 的影响还大。
6. **baseline 要够强**：frozen DINOv2/DINOv3 + 简单聚类本身就是很硬的 baseline（`UNO`，ICCV 2021 oral，至今仍是被引用来对照的强基线）。你的方法若打不过它，说明增益来自 backbone，不来自你的 model。

</details>

## 一句话总结

`input → frozen SSL → feature → 你的模型 → 用例` 这条管线**没问题，且是当前 GCD 的标准做法**；backbone 选 DINOv3 或 Pixio 都合理。但“feature 之后随便”只在 **generic 粗粒度** 数据上成立——**一旦进 fine-grained，global CLS 的 frozen 表征就是瓶颈本身**，你的 model 必须至少做一件事：把单一向量换成 part / patch 级、或引入文本概念空间。这恰好也是现有多模态 GCD 论文之间存在差异的地方。
