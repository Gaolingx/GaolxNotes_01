# 显存不随卡数增

## 🧑‍💻 User

pytorch lightning中使用fully_shared（FSDP2），为什么不同worldsize的per gpu显存占用是一样的？比如dp*2->dp*4，bs不变但每张卡显存占用几乎相同，不应该是拆的卡越多每张卡显存占用越小吗？已知激活检查点off

---
## 🤖 Assistant

## 结论先说

你观察到的现象大概率不是 bug，而是**激活值（activation）而不是分片参数在主导每卡显存**，而**Lightning 里 `batch_size` 是 per-GPU（每进程）的**。所以当你把 dp 从 $2$ 加到 $4$ 而 `bs` 不变时：

- 每卡的**激活值**几乎不变（因为每卡算的 micro-batch 没变，checkpoint off 下激活是大头）；
- 每卡被 FSDP 分片的**模型状态（参数/梯度/优化器）**确实减半了，但它在总显存里占比很小。

于是每卡总占用看起来「几乎不变」。

---

## 1. FSDP2 到底分片了什么

`fully_shard`（FSDP2）在每卡只 **shard 三类静态状态**：

| 状态 | 每参数字节（混合精度 Adam 粗估） | 是否 $\div N$ |
|---|---|---|
| 参数 shard | ~2 (bf16) | ✅ |
| 梯度 shard | ~2–4 | ✅ |
| 优化器状态 $m, v$（fp32） | ~8 | ✅ |
| **合计** | **~12–18 B/param** | ✅ 随 world size 线性缩小 |

它 **不分片** 下面这些：

- **激活值**（checkpoint off 时通常是最大项）；
- **all-gather 缓冲区**：FSDP2 在 forward 前会把当前 FSDP unit（通常一个 transformer block）的**完整、未分片参数**物化出来，这块大小与 world size **无关**；
- matmul / NCCL / 通信 workspace、CUDA context、碎片（reserved − allocated）。

---

## 2. 核心：Lightning 的 `batch_size` 是「每卡」的

这是最容易被忽略的一点。`DataLoader(batch_size=...)` 在 Lightning/DDP 里是**每个进程各取这么多**。所以：

$$\text{global batch} = b_{\text{per-gpu}} \times N_{\text{dp}}$$

你「bs 不变」意味着：

- **每卡 batch 不变** → 每卡 token 数不变 → **激活值不变**（checkpoint off 下主导项）；
- 而全局 batch 实际上翻了倍。

而 FSDP 省下的那部分静态状态是 $\div N$ 的，占比又小，所以总量几乎不动。

> 如果你的意思是「全局 batch 固定」（即每卡 bs = global/dp），那每卡激活会减半，显存应该明显下降。既然没下降，说明实际是**每卡 batch 固定**这一种。

<details>
<summary>用一个近似公式看得更清楚</summary>

$$M_{\text{per-gpu}} \approx \underbrace{\frac{c_{\text{state}}\,\Psi}{N}}_{\text{FSDP 分片，}\div N} + \underbrace{c_{\text{act}}\, b\, s\, h\, L}_{\text{只看每卡 } b} + \underbrace{C_{\text{buf}}}_{\text{与 } N \text{ 无关}}$$

- 翻倍 $N$：第一项减半，但 $\frac{c_{\text{state}}\Psi}{N}$ 本身小；
- 第二项 $b$ 不变 → 不变；
- 第三项常数。

$\Rightarrow$ 总占用几乎不变。✔ 与你的观察一致。

</details>

## 3. 什么情况下「拆卡越多越省显存」才成立

| 条件 | 结果 |
|---|---|
| **固定全局 batch**（每卡 bs = global/dp） | 激活按比例下降 → 显存明显下降 |
| **开启 activation checkpointing** | 激活变小，静态状态占比上升 → 分片收益可见 |
| **模型巨大、序列很长、batch 很小** | 静态状态（参数+优化器）成为主导 → 分片收益显著 |
| **你现在的情形**（checkpoint off + 每卡 bs 固定） | 激活主导且不变 → 显存几乎不变 |

## 4. 怎么验证 / 怎么让它降下来

1. **打印显存分解**，确认谁是大头：
```python
# 每个 step 后
print(torch.cuda.max_memory_allocated() / 1e9, "GB allocated")
print(torch.cuda.max_memory_reserved() / 1e9, "GB reserved")
```
如果激活在主导，跨 world size 的 `allocated` 曲线会几乎重合。

2. **固定全局 batch**：设 `batch_size = global_batch // N`（或固定 `global_batch`、让每卡 bs 随卡数缩小）。这样才能看到 per-GPU 显存随卡数下降。

3. **开启 checkpointing**：`gradient_checkpointing` 或 FSDP 的 activation checkpoint，把激活压下去后，分片带来的参数/优化器显存下降才会「显形」。

4. **确定性排查项**：确认 `strategy="fsdp2"` 真正生效（不是退化成 DDP）、`reshard_after_forward` 设置、all-gather 缓冲区大小、以及是不是被 CUDA 碎片/reserved 撑大。

---

## 一句话总结

> FSDP2 只把**参数/梯度/优化器状态**做成 $\div N$；你对显存贡献最大的**激活值**是「按每卡 micro-batch」算的。由于 Lightning 里 `batch_size` 是每卡的，「bs 不变」时每卡激活不变，所以增大 dp 只是把本来占比很小的静态状态再切细，**总显存自然看起来不变**。想要显存随卡数下降，请固定**全局** batch，或打开 activation checkpointing。
