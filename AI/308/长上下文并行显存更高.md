### 🤖 Assistant

# 为什么长上下文训练中 Tensor Parallelism 的显存占用大于 FSDP？

这是一个非常深刻的问题。要回答它，需要从两种并行策略的**通信模式**和**激活值分布**两个维度来剖析。

---

## 1. 先回顾两种策略的核心差异

| 维度 | Tensor Parallelism (TP) | FSDP |
|------|------------------------|------|
| 切分对象 | **层内参数**（矩阵被横切/纵切） | **层间/全模型参数**（按 layer 维度分片） |
| 通信时机 | 每个 forward/backward 都要通信 | forward 前 all-gather 参数，之后释放 |
| 通信量 | 非常大（每层多次 all-reduce） | 中等（仅参数 all-gather） |
| 典型部署 | 单节点内（NVLink） | 跨节点 |

---

## 2. 核心原因：激活值无法被 TP 分片

这是最关键的差异。在长上下文训练中，**激活值显存才是真正的瓶颈**（与序列长度 $S$ 呈 $O(S)$ 或 $O(S^2)$ 增长），而非参数。

### TP 的激活值分布

以 Megatron-LM 风格的 TP 为例，一个 Transformer 层经历：

```
列并行 Linear → All-Reduce → ... → 行并行 Linear → All-Reduce
```

**每个 All-Reduce 之后，所有设备都持有完全相同的完整激活值副本**。这意味着：

- 对于 hidden states：每个设备存储 $\text{[B, S, d\_model]}$，**无任何分片收益**
- 对于 Attention Matrix：每个设备存储 $\text{[B, H, S, S]}$，**$O(S^2)$ 的显存在所有设备上完全冗余**

### FSDP 的激活值分布

FSDP 不切分层内计算，每个设备独立完成完整的 forward：

- 激活值同样是 $\text{[B, S, d\_model]}$ 和 $\text{[B, H, S, S]}$
- **但**：FSDP 在 forward 完成后立刻释放 all-gather 来的参数，把显存留给激活值
- **更关键的是**：FSDP 与 activation checkpointing 的结合远比 TP 自然

---

## 3. Activation Checkpointing 的效率差异

这是实践中最重要的因素：

### TP 下的 Checkpointing

- TP 每层涉及多次跨设备通信（all-reduce / all-gather）
- 重新计算时，**通信也必须重放**，开销巨大
- Attention matrix 的重新计算尤其昂贵（涉及跨设备的 all-gather + softmax）
- 因此 TP 下往往**只能使用较粗粒度的 checkpointing**，省下的显存有限

### FSDP 下的 Checkpointing

- 重新计算时只需再次 all-gather 参数（纯带宽开销，无同步等待）
- 可以灵活使用**选择性 checkpointing**（如只对 attention 层做 recompute）
- 甚至可以与 **CPU offload** 结合，将激活值 offload 到 CPU 内存

```python
# FSDP + Activation Checkpointing 的典型配置
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP
from torch.distributed.fsdp.wrap import transformer_auto_wrap_policy
from torch.distributed.algorithms._checkpoint.checkpoint_wrapper import (
    checkpoint_wrapper,
    CheckpointImpl,
    apply_activation_checkpointing,
)

# 对每个 Transformer Block 应用 checkpoint
apply_activation_checkpointing(
    model,
    checkpoint_wrapper_fn=checkpoint_wrapper,
    check_fn=lambda module: isinstance(module, TransformerBlock),
)
```

## 4. 数值对比（直观示例）

假设一个 70B 模型，序列长度 $S = 128K$，hidden dim $d = 8192$，heads $H = 64$，batch $B = 1$：

| 显存组成 | TP (TP=4) 单设备 | FSDP (FSDP=4) 单设备 |
|---------|-----------------|---------------------|
| 参数 | $\frac{70}{4} \times 2 = 35\text{ GB}$ | $\frac{70}{4} \times 2 = 35\text{ GB}$ |
| 优化器状态 | $\frac{70}{4} \times 12 = 210\text{ GB}$ | $\frac{70}{4} \times 12 = 210\text{ GB}$ |
| Attention Matrix | $4 \times 64 \times 128K^2 \times 2 = \mathbf{8192\text{ GB}}$ | 同左（但可通过 ckpt 消除） |
| Hidden States | $4 \times 128K \times 8192 \times 2 \approx 8\text{ GB}$ | 同左（但可通过 ckpt 消除） |

> 在 $S=128K$ 时，Attention Matrix 的 $S^2$ 项是绝对的显存杀手。**TP 无法对这 $8192$ GB 做任何分片**——4 个设备各存一份完整副本。

---

## 5. 总结

| 原因 | 说明 |
|------|------|
| **All-Reduce 导致激活值全冗余** | TP 每个 all-reduce 后所有设备持有完整激活，$S^2$ 级显存完全无法分片 |
| **Checkpointing 效率低** | TP 重计算需要重放通信，限制 checkpoint 粒度，无法有效削减激活值 |
| **FSDP 的参数释放时机** | FSDP forward 后立即释放参数，给激活值腾出空间 |
| **FSDP + Offload 生态更成熟** | FSDP 天然支持 CPU offload，TP 很难做 |

**一句话总结**：长上下文训练的显存瓶颈是 $O(S^2)$ 的 attention matrix，TP 无法对其分片（所有设备各存一份），而 FSDP 配合 activation checkpointing 可以在反向传播时重算它、在正向传播后丢弃它，因此实际显存占用远小于 TP。

---

> 💡 **实践建议**：长上下文训练通常采用 **FSDP（跨节点）+ Activation Checkpointing + CPU Offload** 的组合。TP 仅在单节点内 NVLink 带宽不足以支撑 FSDP 的全参数 all-gather 时才作为补充手段（即 **FSDP + TP 混合**），且通常只对 attention 层做小规模 TP（TP=2 或 4），以平衡通信和显存。
