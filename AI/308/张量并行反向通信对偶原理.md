# 张量并行反向通信对偶原理

### 🧑‍💻 User

大模型张量并行中的backward部分，Megatron 那套"正向做 X、反向做 X 的共轭操作"(f/g 函数)封装成了可复用积木——正向恒等的反向就 all-reduce,正向 all-gather 的反向就 split,正向 reduce-scatter 的反向就 all-gather。为什么要这样写算子，它们是如何保证梯度正确性的？

---

### 🤖 Assistant

**Megatron 的 f/g（或 copy/reduce/gather/scatter 等）是把通信集体操作封装成带正确伴随（adjoint）的可微算子，使张量并行的前向通信在反向自动产生对应的梯度聚合/分发，从而保证分布式局部计算 + 通信在数学上等价于完整模型的梯度。**

### 核心思想：为什么要“正向做 X、反向做 X 的共轭”
张量并行把权重（和部分激活）按列/行切分到多个 GPU。局部 matmul 只产生**部分结果**，必须靠集体通信（all-gather、reduce-scatter、all-reduce 等）把它们变成逻辑上完整的张量。

这些通信是**线性算子**。反向传播（reverse-mode AD）需要的是它们的**向量-雅可比积（VJP）**，也就是数学上的**伴随/转置算子**。Megatron 把这些配对封装成 `torch.autograd.Function`：

- 正向恒等（identity / copy） → 反向 all-reduce（求和）
- 正向 all-gather → 反向 split（scatter）
- 正向 reduce-scatter → 反向 all-gather
- （以及 all-reduce 正向 ↔ identity 反向 等变体）

这样写的直接好处：
- **可复用积木**：在模型代码里只需在正确位置插入 `f()` / `g()` / `gather` / `reduce_scatter` 等，PyTorch 自动微分会自动在反向插入对应通信，无需为每个层手写 backward。
- **正确性由构造保证**：伴随配对确保局部梯度 + 通信 = 完整模型的梯度（chain rule 成立）。
- **效率**：通信量和时机最优（例如用 reduce-scatter 代替 all-reduce + scatter，节省带宽；把 all-reduce 放到反向、正向保持 identity，方便 overlap 和避免多余通信）。现代实现还结合 sequence parallel 进一步省激活内存。

如果只做局部计算而不加这些伴随通信，梯度会缺失其他 partition 的贡献，结果错误。

### 如何保证梯度正确性（伴随算子视角）
把跨 rank 的张量看作“逻辑大张量”的分区。集体操作是从局部张量到局部（或复制）输出的线性映射 \(T\)。反向时，给定上游梯度，需要 \(T^\top\) 作用后的结果。

下面用常见配对说明（与 Megatron 的 `_CopyToModelParallelRegion`、`_GatherFromModelParallelRegion`、`_ReduceScatterToSequenceParallelRegion` 等对应）。

#### 1. 正向恒等（identity/copy），反向 all-reduce
**典型用途**：进入列并行区域（column-parallel linear 的输入）。输入 \(X\) 在各 rank 上逻辑上是复制/完整的，权重 \(A\) 按列切分 \(A = [A_1, A_2, \dots]\)。

- 前向：每个 rank 做 \(Y_i = X A_i\)（identity 后直接 matmul，无需通信）。
- 反向：\(\frac{\partial L}{\partial X}\) 需要 \(\sum_i (\frac{\partial L}{\partial Y_i} A_i^\top)\)。各 rank 先算出局部贡献，再 **all-reduce（sum）** 得到正确的完整 \(\mathrm{d}X\)。

**为什么是伴随**：逻辑上这相当于“广播/复制”输入到并行区域。复制的伴随正是求和（all-reduce）。插入后，autograd 在 \(\mathrm{d}X\) 路径上自动 all-reduce，保证与非并行 \(Y = XA\) 的梯度一致。

#### 2. 正向 all-gather，反向 split
**典型用途**：列并行输出需要拼成完整张量（或 sequence parallel 中 gather 激活），再送给后续需要完整输入的算子。

- 前向：各 rank 持有 shard \(y_i\)，all-gather 得到完整 \(Y = \mathrm{concat}(y_1, \dots, y_p)\)（每个 rank 都有完整 \(Y\)，或按需）。
- 反向：上游给出完整 \(\mathrm{d}Y\)。每个 rank 只需要自己那一份 \(\mathrm{d}y_i\) 去更新自己的参数/继续反传，因此 **split/scatter** 取出对应切片即可（通常无额外跨 rank 通信，或极轻量）。

**为什么是伴随**：all-gather（拼接/复制到所有人）是线性的，其转置就是“取出对应分区”（split）。没有 split 的话，各 rank 会错误地用完整 \(\mathrm{d}Y\) 去乘自己的局部权重，梯度尺度或内容都错。

#### 3. 正向 reduce-scatter，反向 all-gather
**典型用途**：行并行（row-parallel linear）的输出，或 sequence parallel 中对激活做 reduce-scatter 以节省内存。

- 前向：各 rank 算出局部贡献后，reduce-scatter：先对完整维度求和，再把结果按 partition 切开，每个 rank 只保留自己的 shard（通信量通常优于 all-reduce + 后续 scatter）。
- 反向：各 rank 只有局部 \(\mathrm{d}z_i\)。因为前向做了 sum，每个输入贡献的系数都是 1，所以需要把 \(\mathrm{d}z\) 的各 shard **all-gather** 成完整梯度，再分发给各局部输入路径。

**为什么是伴随**：reduce-scatter = reduce(sum) + scatter。sum 的伴随是“复制/广播”，scatter 的伴随是 gather，组合起来就是 all-gather。这样局部 \(\mathrm{d}Z_i\) 经过 all-gather 后能正确回传到所有贡献过 sum 的路径。

（all-reduce 可看作 reduce-scatter + all-gather，因此它的伴随是自身，常与 identity 配对使用。）

### 放到具体层里的效果（以 MLP 为例）
典型 Megatron 风格（列并行 + 行并行）：
- 输入 → `copy_to_parallel`（identity fwd / all-reduce bwd）→ 列并行 GEMM（\(Y_i = X A_i\)）→（可选 gather）→ GeLU 等 → 行并行 GEMM（局部 \(Z_i = Y_i B_i\)）→ `reduce_from_parallel` 或 reduce-scatter（sum 相关）→ 输出。

前向通信把 partial 变成逻辑正确结果；反向时 f/g 自动插入的 all-reduce / split / all-gather 把 partial 梯度聚合成完整 \(\mathrm{d}W\)、\(\mathrm{d}X\)。最终每个参数的梯度与把整个模型放在一个巨大 GPU 上算出的结果一致（数值上忽略并行带来的浮点求和顺序差异）。

### 实现与正确性要点
- 这些都是 `autograd.Function`，`forward` 里做集体通信（或 identity），`backward` 里做配对操作，并正确处理 `requires_grad`、异步通信、overlap 等。
- 数学上它们实现了通信算子的 VJP，因此整图的梯度链式法则成立。
- 实际代码还会处理：sequence parallel（激活也切分，进一步用 reduce-scatter/all-gather）、异步 all-reduce 与计算重叠、gradient accumulation 时的处理、以及与 pipeline / data parallel 的配合。
- 验证方式：小规模下对比“无 TP 的完整模型”与“TP 模型”的 loss 和各参数梯度是否一致（允许微小数值误差）。

### 总结
这样封装的原因是：**把“保证分布式梯度数学正确”的通信模式，变成可插拔、可自动微分的积木**，既正确又高效可维护。正确性来自“前向集体操作 ↔ 反向伴随操作”的配对，它们精确实现了分区线性映射的 VJP，使局部 matmul + 通信在前向产生正确激活、在反向产生正确聚合梯度，整体等价于未切分模型。

这套设计是 Megatron 张量并行（以及后续 sequence parallel 等扩展）能 scale 到大模型的关键工程与数学基础之一。
