# E2B 云沙箱 + slime Agentic RL 接入指南

下面是完整的两部分说明：**① 怎么用 E2B**，**② 怎么把它接进 slime 的 agentic RL 训练**。核心结论先说：

> slime 官方已经把 E2B 做成了内置的沙箱后端（`slime/agent/sandbox.py` 里的 `E2BSandbox`），并在 `examples/coding_agent_rl/` 提供了端到端的 SWE coding-agent RL 示例。你**通常不需要从零造轮子**，只需要：装好 E2B、准备一个 E2B 镜像模板、按格式准备数据、用 `--custom-generate-function-path` 挂上即可。

---

## 一、整体架构：E2B 在 RL 循环里的位置

```
┌──────────────────────── slime 训练循环 ────────────────────────┐
│                                                                 │
│  Megatron(训练)  ──权重同步──▶  SGLang + Router(推理/rollout)   │
│        ▲                                    │                   │
│        │                                    ▼                   │
│        │                          custom_generate()  ◀── 你写的 │
│        │                                    │                   │
│   Data Buffer ◀──────── Sample(带 loss_mask) ┘                  │
└────────────────────────────────────────────┬────────────────────┘
                                             │ 每条样本 boot 一个沙箱
                                             ▼
                          ┌──────────── E2B Cloud ────────────┐
                          │  Firecracker microVM 沙箱          │
                          │  Bash / Read / Edit / Grep 工具    │
                          │  git diff → 测试打分(第二个干净沙箱)│
                          └───────────────────────────────────┘
```

- **SGLang** 负责采样 token；**E2B** 负责"执行动作"（跑命令、改文件、跑测试）；
- 两者通过你写的 `custom_generate()` 函数串起来；
- 关键点：轨迹必须做到 **"string-in / token-out"**，即训练用的是 rollout 时真正采样的 token，环境观察（工具返回）的 token 打 `loss_mask=0`。

## 二、E2B 云沙箱基础使用

### 1. 准备

- 注册 <https://e2b.dev>（新账号送 $100 额度），在 <https://console.e2b.dev/?tab=keys> 拿 API key（形如 `e2b_xxxxxxxx...`）。
- 装 SDK（Python 3.10+）：

```bash
pip install e2b            # 核心包：命令 / 文件 / 生命周期
# pip install e2b-code-interpreter   # 需要 run_code 富结果(图表/表格)时才装
export E2B_API_KEY=e2b_...
```

### 2. 最小可运行例子

```python
import asyncio
from e2b import AsyncSandbox           # 同步版：from e2b import Sandbox

async def main():
    # 创建沙箱：timeout 单位是秒，到期会自动 pause 保留状态
    sbx = await AsyncSandbox.create(timeout=3600, metadata={"image": "my-swe-image:latest"})

    # 执行命令
    res = await sbx.commands.run("ls -l /")
    print(res.stdout, res.exit_code)

    # 读写文件
    await sbx.files.write("/tmp/hello.txt", "hello e2b")
    print(await sbx.files.read("/tmp/hello.txt"))

    await sbx.kill()                   # 用完务必销毁，按秒计费

asyncio.run(main())
```

### 3. 生命周期要点

| 操作 | API | 说明 |
|---|---|---|
| 创建 | `Sandbox.create()` | 可从模板 <1s 启动 |
| 重连 | `Sandbox.connect(id)` | 跨进程恢复同一沙箱 |
| 暂停/恢复 | `pause()` / `resume()` | 暂停保留完整状态，可无限期保留，重置运行窗口 |
| 改超时 | `set_timeout(sec)` | 运行中动态续命 |
| 销毁 | `kill()` | 释放资源 |

> 计费按 CPU/RAM 每秒计。Hobby 档：最长连续 1h、并发 20 个、8 vCPU/8 GiB；Pro 档：最长 24h、并发可达 1100+。

## 三、slime 的 Agentic RL 机制

slime 不引入独立的 agent 框架，而是通过**回调函数路径**把 agent 逻辑"挂"进默认 rollout loop：

| 接口 | 作用 |
|---|---|
| `--custom-generate-function-path` | **最核心**。替换单条样本的生成步骤，在这里写多轮循环、工具调用、沙箱交互 |
| `--custom-rm-path` | 自定义奖励（测试验证、规则奖励、外部 reward 服务） |
| `--rollout-function-path` | 只有当逐样本定制不够时，才替换整个 rollout 编排 |

`custom_generate` 的函数签名：

```python
async def custom_generate(args, sample: Sample, sampling_params: dict) -> Sample | list[Sample]:
    ...
```

> 多轮/子 agent 场景可返回 `list[Sample]`：一次 rollout 拆成多个可训练片段（如 compaction 前后、子 agent 轨迹）。**同一次 rollout 的兄弟样本必须共享同一个 `rollout_id`**，且若一条轨迹只有一个总奖励被切成 $K$ 段，通常给每段分配 $r/K$，避免奖励被放大。

## 四、接入 E2B：两条路径

### 路径 A —— 直接复用官方 `coding_agent_rl`（推荐先跑通）

slime 仓库的 `examples/coding_agent_rl/` 就是**用 E2B 做沙箱**的完整 SWE coding-agent RL：

- 每样本 boot 一个全新 E2B 沙箱 → claude-code CLI 驱动 `Read/Edit/Grep/Bash/Agent` 工具 → 产出 `git diff` → 在**第二个干净沙箱**里对数据集测试跑分（防作弊）；
- `slime.agent.sandbox.Sandbox` 是 provider 无关的最小契约：`__aenter__/__aexit__`、`exec()`、`write_file()`、`read_file()`；`E2BSandbox` 是它的 E2B 实现。

**① 训练栈按标准方式装好，额外准备：**

1. **E2B API key**：`export E2B_API_KEY=e2b_xxx`（用自建 gateway 时也需语法合法的 `e2b_` + 40位hex 占位符，SDK 本地会校验）。
2. **host 侧 tarball**（boot 时上传进沙箱）：
   - Node 22：`SLIME_AGENT_NODE_TARBALL=/path/node-v22.x-linux-x64.tar.xz`
   - Claude Code CLI：`SLIME_AGENT_CC_TARBALL=/path/anthropic-ai-claude-code-local-linux-x64.tgz`
3. **镜像路由键**：`SLIME_AGENT_SANDBOX_IMAGE_METADATA_KEY=image`（你的 E2B gateway 用哪个 metadata key 来路由镜像）。
4. **网络可达**：沙箱要能回连 host 上的 Anthropic adapter，`ADAPTER_PUBLIC_HOST` 必须是**路由可达 IP**（不能是 `127.0.0.1`），因为在沙箱内部访问。

**② 数据集格式**（标准 slime JSONL）：

```jsonc
{
  "prompt": "",
  "label": "",
  "metadata": {
    "image": "your-registry/swe-image:latest",   // E2B 沙箱镜像
    "workdir": "/workspace/",                     // 沙箱内仓库路径
    "problem_statement": "",
    "swepro": { /* SWE-bench Pro 测试 harness，优先 */ },
    "eval_cmd": "pytest -x tests/..."             // 兜底：退出码 0 = 解决
  }
}
```

**③ 启动：**

```bash
cd slime/
export HF_CHECKPOINT=/path/to/Qwen3.6-35B-A3B
export REF_MODEL_PATH=/path/to/Qwen3.6-35B-A3B_torch_dist
export PROMPT_DATA=/path/to/swe_train.jsonl
export SLIME_AGENT_NODE_TARBALL=/path/node-v22.20.0-linux-x64.tar.xz
export SLIME_AGENT_CC_TARBALL=/path/anthropic-ai-claude-code-local-linux-x64.tgz
export E2B_API_KEY=e2b_xxx
export SLIME_AGENT_SANDBOX_IMAGE_METADATA_KEY=image
bash examples/coding_agent_rl/run_qwen36_35b_a3b_swe_8nodes.sh
```

对应的 rollout 参数（由 launcher 注入）：

```bash
ROLLOUT_ARGS=(
  --custom-generate-function-path examples.coding_agent_rl.generate.generate
  --prompt-data "${PROMPT_DATA}"
  --input-key prompt --label-key label --metadata-key metadata
  --rollout-batch-size 8 --n-samples-per-prompt 8
  --rollout-max-context-len 96000 --rollout-max-response-len 32768
  --rollout-stop-token-ids 248046 248044
  --save-debug-rollout-data "${RUN_ROOT}/rollout_dumps/rollout_{rollout_id}.pt"
)
# SGLang 侧需暴露 Qwen 的 tool-call / reasoning 解析器：
# --sglang-tool-call-parser qwen3_coder --sglang-reasoning-parser qwen3
```

> **注意**：启动脚本要在 Ray head 节点的长驻 shell 里跑，**不要用 `nohup`**（Ray 子进程会随之被清理）。

### 路径 B —— 自己写 `custom_generate` 接 E2B（自定义任务）

如果你想训练**非 SWE 的 agent 任务**（数学工具、浏览器、数据库……），只需自己实现一个 `generate()`，内部用 E2B SDK 起沙箱、跑工具循环。骨架：

```python
# my_agent_generate.py
import asyncio
from e2b import AsyncSandbox
from slime.utils.types import Sample
from slime.agent.sandbox import E2BSandbox     # 也可直接用内置的 provider 无关封装

async def _one_turn(args, sample, sampling_params, sbx, messages):
    # 1) 用 SGLang 生成下一步（return_logprob=True 记录 rollout logprob）
    out = await generate_with_sglang(args, messages, sampling_params)   # 你封装好的调用
    text, tool_calls = parse(out)

    # 2) 模型输出的 token 打 loss_mask=1
    sample.record_output(text, loss_mask=1)

    # 3) 执行工具（在 E2B 沙箱里）
    if tool_calls:
        obs = await exec_tool_in_sandbox(sbx, tool_calls)
        messages.append({"role": "tool", "content": obs})
        # 4) 环境观察的 token 打 loss_mask=0（不参与梯度）
        sample.record_observation(obs, loss_mask=0)
    return tool_calls

async def generate(args, sample: Sample, sampling_params: dict, evaluation: bool = False):
    md = sample.metadata
    async with E2BSandbox(md["image"], timeout=1800) as sbx:   # 自动 create + kill
        await sbx.exec("git clone ... /workspace", check=True)
        messages = build_prompt(sample)
        for _ in range(args.max_turns):
            if not await _one_turn(args, sample, sampling_params, sbx, messages):
                break
        # 打分：优先在干净沙箱跑测试（防作弊）
        diff = await sbx.exec("cd /workspace && git diff")
        reward = await run_tests_in_fresh_sandbox(md["eval_cmd"], diff)
    sample.reward = reward
    sample.status = Sample.Status.COMPLETED
    return sample
```

挂载方式：

```bash
--custom-generate-function-path my_agent_generate.generate \
--custom-rm-path my_agent_generate.reward      # 或直接把 reward 写在 generate 里
```

`E2BSandbox` 已经帮你处理了生产环境的坑：**RPC 瞬时错误指数退避重试、非幂等命令不重放、长命令用 `setsid` 后台化 + done-marker 轮询（避免 HTTP/2 流被 sever 丢退出码，同时轮询兼作 idle-GC keepalive）**。所以即使自己写，也建议复用它而不是裸调 `AsyncSandbox`。

## 五、正确性关键：string-in / token-out

这是 agentic RL 最容易被忽视、也最容易静默出错的地方：

- 环境/工具是**字符串**交互，但训练必须**基于 token**；
- adapter 每轮用服务模型的 chat template 渲染，送 SGLang 得 `input_ids`，用 `return_logprob=True` 记录精确的 `prompt_ids` / `output_ids` / 每 token 的 rollout logprob；
- 后续轮次的 prompt 会重新 tokenize，靠 `TrajectoryManager` 与已保存 token 流对齐：
  - 工具/用户/环境上下文 → 追加并标 `loss_mask=0`；
  - SGLang 新生成 → 追加并标 `loss_mask=1`；
  - 若后续 prompt **无法 token 对齐**上之前采样输出 → 丢弃不匹配后缀；若漂移切在某个模型输出中间，则将该输出整段保留前缀也置 `loss_mask=0`。

> 一句话：**只在能证明"这些 token 确实是 rollout 模型采样出来的"的地方回传梯度**，否则字符串看着连续、token 级 provenance 已断裂，RL 会学到噪声。

## 六、替代方案：Dressage（更省事的封装）

如果你不想自己维护 `custom_generate` 与轨迹拼接，可以看 **Dressage**（阿里 Accio 基于 slime 构建的 agentic RL 框架）：

- 通过统一的 **Paddock / Sandbox / Proxy** 三层解耦交互语义、执行位置、token 级轨迹捕获；
- 明面支持 **E2B / bwrap / Kubernetes** 多种沙箱；
- 支持 **whitebox**（Python 工具循环）与 **blackbox**（`opencode`、`openclaw`、`claude_code`、`codex`）两类 agent；
- 官方有 SWE-Gym + Claude Code 的黑盒 RL 配方（Qwen3.5-4B 在 SWE-bench Verified 上 32.6% → 37.8%）。

## 七、避坑清单

1. **沙箱回收**：每条样本 `finally` 里 `kill()`；用 context manager（`async with E2BSandbox`）最稳。
2. **网络可达性**：`ADAPTER_PUBLIC_HOST` 必须是沙箱能路由到的 IP，别用 `127.0.0.1`。
3. **并发与限流**：注意 E2B 档位的并发上限与创建速率（Hobby 1/s、20 并发；Pro 5/s），用 `SWE_BOOT_CONCURRENCY` 之类做背压，避免 h2/SSL 长尾。
4. **长命令**：构建/测试等长命令别用一次性 `commands.run` 死等，用后台 + marker 轮询。
5. **防作弊**：diff 打分一定要在**全新干净沙箱**里跑测试，不能让 agent 篡改测试。
6. **成本**：E2B 按秒计费，boot 慢的镜像要预热成模板；Pro 的 24h 连续运行可用 pause/resume 突破。
7. **别用 `nohup`** 起 Ray 训练，子进程会被清掉。
8. **解析器匹配**：`--sglang-tool-call-parser` / `--sglang-reasoning-parser` 必须与所服务模型一致，否则工具调用解析错乱。
