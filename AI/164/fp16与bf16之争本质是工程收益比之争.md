## 😀 默认助手 (7)

这三句话表面上像是在给数据格式排一个「fp16 < bf16 < fp8」的总榜，实际上它们回答的是**三个不同的问题**。拆开来看就完全不矛盾了——而且最后你会看到一个挺讽刺的事实。

## 先看这三句话各自在说什么

| 说法 | 真正的问题 | 判据 |
|---|---|---|
| fp16 bad | 16-bit 训练**稳不稳、省不省心** | 动态范围、要不要 loss scaling |
| bf16 good | 16-bit 里**默认该选谁** | 同样字节数/吞吐下谁更鲁棒 |
| fp8 better | 能不能**再快一倍** | 吞吐收益 ÷ 工程代价 |

它们不在同一根轴上。你感觉矛盾，是因为默认了「难度」是唯一变量；但真正决定产业行为的变量是 **收益/难度比**。

## 一、fp16 的「bad」是动态范围，不是精度

| 格式 | 指数位 | 尾数位 | 最大值 | 最小正规数 |
|---|---|---|---|---|
| fp32 | 8 | 23 | $3.4\times10^{38}$ | $1.2\times10^{-38}$ |
| bf16 | 8 | 7 | $3.4\times10^{38}$ | $1.2\times10^{-38}$ |
| fp16 | 5 | 10 | **65504** | $6.1\times10^{-5}$ |
| fp8 E4M3 | 4 | 3 | **448** | $1.6\times10^{-2}$ |
| fp8 E5M2 | 5 | 2 | 57344 | $6.1\times10^{-5}$ |

注意两件事：

1. **fp16 的精度其实比 bf16 高**（11 位有效位 vs 8 位）。所以「fp16 bad」跟精度无关，纯粹是 **5 位指数 → 动态范围只有 $2^{\pm15}$ 量级**。
2. LLM 的 activation 是**重尾分布**——少数 channel 的幅值能飙到几百上千（attention logits、outlier features）。fp16 的上限 65504 看着不小，但一乘上 attention 的 $QK^T$ 缩放、一遇到 loss spike，就 inf 了；梯度那侧又会被压到 subnormal 甚至直接下溢成 0。

于是 fp16 必须配 **loss scaling**：动态试一个 scale 因子，溢出就跳过这一步、调小 scale；连续若干步没溢出就调大。这套机制能用，但它是**运行时反馈控制**：
- 有 inf/nan 就得跳步，吞吐掉；
- scale 因子调错了，梯度精度受损或直接炸；
- 万卡跑几周的 pretraining，一次没检测到的 NaN 就是几百万美元。

bf16 为什么好？因为它**就是 fp32 砍掉低 16 位尾数**：指数位一模一样，范围跟 fp32 等同，转换是一次移位+舍入，**永远不需要 loss scaling**。尾数少几个 bit 带来的噪声，被 fp32 累加和巨大的 batch 平均掉了。

所以 bf16 的定位是：**「不费任何额外工程就够用的最小格式」**。

## 二、关键在这：fp16 被 bf16 严格支配

这是整件事的核心，也是那句「wtf」的答案所在：

**在 Hopper/Ampere 上，fp16 和 bf16 的 tensor core 吞吐完全一样，内存带宽占用完全一样。**

| 格式 | H100 SXM 稠密算力 |
|---|---|
| fp16 / bf16 | ~989 TFLOPS |
| fp8 | ~1979 TFLOPS（2×） |

也就是说：

- **fp16 = bf16 的成本 + 额外的脆弱性** → 帕累托被支配，没有任何理由选它。所谓「解决 fp16」，收益是 **0**。
- **fp8 = bf16 的成本 ÷ 2** → 收益是 **2× 算力 + 半内存流量**。所以大家愿意为它烧工程。

你的直觉「能搞定 fp8 还搞不定 fp16？」——**对，搞 fp8 那套东西搬去 fp16 只会更容易，问题是你搞完之后它还是和 bf16 一样快。** 没人愿意为 0 收益支付复杂度。

一句话：**fp16 不是「做不到」，是「不值得」。**

## 三、更讽刺的是：fp8 在数值上比 fp16 难得多

E4M3 的最大值只有 **448**，尾数只有 **3 位**。范围比 fp16 窄两个数量级，精度还少 7 位。所以「fp8 better」**纯粹是速度意义上的 better，不是数值意义上的 better**。

fp8 之所以还能训，靠的不是「格式好」，而是一整套**外部脚手架**：

<details>
<summary>fp8 训练的真实配方（点开）</summary>

- **细粒度 scaling**：per-tensor → per-block（如 $128\times128$ 或 $1\times128$ 的 tile）动态算 scale，把张量压进 fp8 范围再 cast，算完反 scale。
- **高精度累加**：GEMM 输入是 fp8，累加器是 fp32；部分实现还会周期性用 CUDA core 做一次高精度累加来抑制误差漂移。
- **混合精度孤岛**：master weights 用 bf16/fp32，optimizer states 用 fp32，LayerNorm / softmax / MoE gating / loss 全程 bf16 或 fp32。只有纯 GEMM 的输入被量化。
- **前反向用不同格式**：前向多用 E4M3（要精度），反向按需 E5M2 或 E4M3 + 额外缩放（要范围）。

</details>

看到问题了吗？**这套「per-block 动态缩放 + 高精度累加 + 关键算子保高精度」，本质上是 loss scaling 的推广版。** 把它原样套到 fp16 上，你会得到一个极其鲁棒、比 bf16 还准的 16-bit 训练——只是速度和 bf16 一模一样。

所以「能解 fp8 却解不了 fp16」这个悖论的正确表述是：**fp8 的解药本身就包含了 fp16 的解药，只是没人去服用，因为药费比病贵。**

## 四、那这些话术为什么满天飞

<details>
<summary>人群与动机（点开）</summary>

- **说「fp16 bad」的**：日常训练/推理的人。PyTorch 在 Ampere+ 上 `torch.autocast` 默认就是 bf16，FlashAttention、transformers、几乎所有新 kernel 的默认 dtype 都是 bf16。fp16 已经变成「历史遗留 + 需要手动配 loss scaler」的选项。
- **说「必须 fp8 pretraining」的**：大集群 infra 团队 + 硬件厂。前者有 2× 收益、有专职团队踩坑、跑的是几万卡几个月的任务，省 50% 就是天文数字；后者（NVIDIA）的 roadmap 就是 fp8 → fp4，生态推力天然存在。确实有营销成分，但底层账是算得平的。
- **一个被忽略的例外**：**推理**场景里 fp16 经常比 bf16 更准（尾数多 3 位，且没有梯度/loss 的动态范围问题）。「fp16 bad」是训练语境的结论，被过度推广了。反过来也有坑——用 bf16 训的模型直接 cast 成 fp16 推理，可能被 outlier 撑爆。

</details>

## 结论

不是「fp16 < bf16 < fp8」的线性排名，而是**帕累托前沿**的问题：

$$\text{有效前沿} = \{\text{bf16},\ \text{fp8},\ \text{fp4}\},\qquad \text{fp16} \notin \text{前沿}$$

- bf16：免费拿到 16-bit 的全部好处，**零额外工程**。
- fp8：付出一套 scaling 工程的代价，换 2× 吞吐，**大集群划得来**。
- fp16：付出复杂度，换 0×——**被 bf16 支配**，所以社区直接跳过。

所以那句「你都能解 fp8 了怎么不能用 fp16」的答案是：**能，而且更容易；但解完它还是个 bf16，所以没人解。** 大家的意识不是「fp16 坏」，而是「fp16 多余」。

## ① 「爆炸论」是错的：fp16 的死因主要是下溢

这是你四条里唯一一条在**机制上**搞错了的。fp16 有两个失效端，你只看到了上面那端：

$$\underbrace{6.1\times10^{-5}}_{\text{最小正规数}} \;<\; |x| \;<\; \underbrace{65504}_{\text{最大值}}$$

**下端才是日常杀手。** LLM 里大量参数的梯度幅值在 $10^{-6}\sim10^{-8}$ 量级——在 fp16 里直接掉进 subnormal（最小到 $2^{-24}\approx6\times10^{-8}$）甚至归零。这不是「爆炸」，是**梯度被静默吃掉**。

而且这个**没法从模型结构上解决**：梯度幅值由 loss landscape 决定，不是你加个 norm 就能约束的。你能做的唯一「结构性」操作，就是**给梯度乘一个常数**——这个东西的名字就叫 loss scaling。你说「纯 skill issue」，但 skill 的极限就是发明 loss scaling。

更麻烦的是**窗口会关闭**：全局一个 scale，要同时满足「小梯度别下溢」和「大激活别溢出」。不同张量幅值差几十个数量级时，这个区间可以是空集。bf16 没有这个问题——它的指数位和 fp32 一样，$2^{\pm127}$，一个 scale=1 通吃所有张量。

至于「加 norm 就不爆炸」：

- **RMSNorm 约束的是范数，不是最大元素。** 实测 LLM 的 residual stream 里存在 magnitude 到 $10^4\sim10^5$ 的「massive activations / attention sink」，集中在极少数维度上，**穿透 LayerNorm 依然存在**（Sun et al. 2024）。$10^5 > 65504$，fp16 直接 inf。
- **softmax 是个硬阈值。** $\exp(x)$ 在 fp16 里 $x>11.09$ 就溢出，在 bf16 里是 $x>88.72$。而 attention logits 上到 20~50 是**常态**。这就是为什么 max-subtraction 是标配而不是优化——去掉它，fp16 立刻炸，bf16 还能撑。
- **gate 反而会制造 outlier**（MoE 路由分数、专家不均衡）。

「正常模型本来就不该爆炸」——在万卡尺度上这是幸存者偏差。你看到的是没炸的那些；炸掉的那 1% 是几百万美元。

<details>
<summary><b>② 关于「玄学精度问题」——这条你是对的，而且圈内谈得太少</b></summary>

bf16 在 1.0 附近的 ulp 是 $2^{-8}\approx3.9\times10^{-3}$，fp16 是 $2^{-10}\approx9.8\times10^{-4}$。差 4 倍，在某些环节是要命的：

- **权重更新被舍入吃掉**：若 $\Delta w \sim 10^{-4}$ 而 $w\sim1$，bf16 直接把它抹平。→ 必须留 fp32 master weights（或 stochastic rounding）。
- **方差/均值计算**：$\mathrm{Var}=E[x^2]-E[x]^2$ 在低精度下 catastrophic cancellation，Welford 算法存在的全部理由。
- **softmax 在浮点下不满足平移不变性**：减 max 是数学等价、浮点不等价。
- **梯度裁剪的范数统计**、**all-reduce 的归约顺序**、**MoE 路由分数**、**RLHF 的 logprob / importance ratio**——这些都在低精度下出过事。
- **不可复现性**：atomically 累加的次序差异，在低精度下放大成可见的 loss 曲线分叉。

**但这些几乎全部被一句话解决：敏感算子保 fp32。** norm、softmax、loss、optimizer states、master weights 全 fp32，GEMM 用 tensor core + fp32 累加。这已经是所有框架的默认配置，所以没人天天讲——它不构成 bf16 的罪证，因为 fp16 走同一套配方也一样要这么做。

真正的争议点是：**GEMM 里那 3 个尾数位值不值钱？** 在 fp32 累加下，点积相对误差 $\sim\varepsilon$，fp16 比 bf16 好约 8 倍。但实测 LLM pretraining 的 loss 曲线基本看不出差别——因为限制训练质量的是优化噪声和 batch 噪声，不是 $2^{-8}$ 的相对误差。这是经验事实，你很难用理论反驳掉。

</details>

## ③ 你对，而且历史上早就被证实了

`fp8 E4M3` 上限 448，`E5M2` 上限 57344，都 $\le$ fp16 的 65504。所以「能搞定 fp8 却搞不定 fp16」在逻辑上确实荒谬——**fp8 的整副脚手架（per-block scaling + fp32 累加 + 混合精度孤岛）本来就是 loss scaling 的推广版，原样搬到 fp16 上只会更准。**

但比你想的更进一步：**这件事根本不需要推理，它是已经发生的事实。**

- Megatron-LM (2019)：fp16 + loss scaling。
- **GPT-3 (2020)：fp16 + loss scaling + 梯度裁剪。**
- BERT / ResNet / 所有 Apex AMP 时代的模型：fp16 + GradScaler。

也就是说 **fp16 LLM pretraining 在万亿参数级早就跑通了**。所谓「LLM 用不了 fp16」是个伪命题。bf16 是 2020 年 A100 才有的东西，之前全世界都在 fp16 上硬扛。

## ④ 这条你记反了：CV 用的是 fp16 **+ GradScaler**

不是「CV 用 fp16 没事」，是「**CV 用 fp16 + 动态 loss scaling，并且天天见 NaN**」。Volta/Turing 时代没有 bf16，fp16 是唯一选项，所以 `torch.cuda.amp.GradScaler` 就是那个年代的标准配置，溢出跳步是日常操作。

所以 CV 和 LLM 的差别不是**领域**差别，是**时代**差别：
- 2020 前：CV 和 NLP 都用 fp16+缩放，都在扛。
- 2020 后：A100 带来 bf16，NLP（训得久、单次失败贵、激活 outlier 多）先叛逃，CV 随后跟上。

Reduction：「CV 行 LLM 不行」= 把不同年代的结论摆在一起比。

## 那 bf16 到底赢在哪（它不傻，但也没多神）

诚实地把 bf16 的全部优势列出来，其实只有一条半：

1. **把「有状态的全局控制回路」变成「没有」。** loss scaler 是一个跨 step、跨 dp rank、跨梯度累积、跨 MoE 路由的动态反馈控制器，必须同步、必须处理 inf 检测、必须和 clip/EMA/checkpoint 交互。在 10k 卡上，这不是「加个参数」，这是一整类 bug 的温床。
2. **失败模式是优雅降级**：bf16 精度差一点，训练继续；fp16 一溢出，整个 run 死。

代价是那 3 个尾数位——**经验上不值钱**。

所以最锋利的表述是：

> **fp16 + scaling 在数值上严格优于 bf16，但优出来的那部分换不来任何东西；bf16 放弃了那点精度，换来了零工程负担。这是个划算的交易，不是愚蠢。**

它和 fp8 的选择逻辑是同一个：**奖金/成本比**。fp16 相对 bf16 的奖金是 0×算力，bf16 相对 fp16 的奖金是「少一套全局状态机」。前者买不到，后者白送。

## 最后一件事：这场架已经过时了

你现在争论的是 2020 年的问题。2025 年真正决定用什么的是硬件曲线：

| 格式 | H100 稠密算力 | 相对 bf16 |
|---|---|---|
| fp16 / bf16 | ~989 TFLOPS | 1× |
| fp8 | ~1979 TFLOPS | **2×** |
| fp4 (B200) | ~2× fp8 | **4×** |

fp16 和 bf16 之间差的那点精度，在「fp8 GEMM + bf16/fp32 岛屿」的配方里根本进不了决策——GEMM 输入已经是 3~4 位尾数了，你还在纠结 8 位还是 11 位，这属于在四舍五入的误差里吵架。

所以我的结论跟你只差半句：

- **「fp16 被污名化了」——完全同意。** 它是可行、可靠、且在 GPT-3 上验证过的。说「fp16 训练不行」的人既不懂历史也不懂数值。
- **「bf16 是傻逼」——不同意，但它确实被神化了。** 它只是个「零配置的够用解」，不是什么更优的技术。
- **「fp16 is all u need」——在 16-bit 内部成立，但 16-bit 已经不是战场了。** 真正的问题是：你的敏感算子有没有保 fp32，你的 GEMM 能不能上 fp8。
