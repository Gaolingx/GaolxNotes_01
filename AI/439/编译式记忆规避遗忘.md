## 先澄清一个前提：Qwenputer 没在“写权重”

看 README 的关键句：*"none of their weights are learned: a compiler computes every one"*，以及 *"Qwen's own weights are unchanged"*（文本 KL 6e-4，噪声底 5e-4）。它的三个机制和“训练”无关：

1. **追加层 + 加宽 + 补零**：把 Qwen 的 hidden 从 4224 扩到 4608，原模型矩阵被零填充成新矩阵的子块。**基座函数是新模型的精确限制（restriction）**，所以遗忘在数学上被排除，没有“降低”，没有被“规避”。这是三道防线里最强的一道：**函数包含（containment）**。
2. **chip dims 清零**：电路只在新增维度上工作，在返回 Qwen 层之前清空。这是读写屏障。
3. **0/1 精确权重 + bf16 全程可表示**：算术做成查表，无浮点漂移。这是隔离得以成立的必要条件。

所以“不遗忘”是因为**基座参数一个 bit 都没动，而且新功能活在不相交的子空间里**，n-gram 本身并未为此提供保障。

这点很关键，因为它把问题从“如何在学习中不遗忘”变成“如何在不学的条件下加功能”，代价也换了个地方付。

## 你说的“切权重麻烦”，其实是这个架构自己制造、又自己解掉的问题

它把图灵机拆成两半：

- **转移函数 → 权重**：编译一次，永久冻结，全局共享。
- **纸带 / 程序 / 数据 → Gated DeltaNet state**：每个会话、每个任务不同。

一旦完成这个拆分，**你换的就不再是权重，而是纸带**。NPU 变体明确写出：*"Its weights are data in the CPU's memory, not compiled into the checkpoint, so any model that fits runs the same way."* 这里，stories260K 的 261k 个 int4 权重作为**被 CPU 处理的数据**进入 DeltaNet 行，而不是被合并进 checkpoint。文件系统变体同理：快照只有 11–30 MB 的 recurrent state；而换 checkpoint 是 14.65 GB。

对比一下成本结构：

| | 换权重（每能力一个 checkpoint） | 换纸带（state / 数据） |
|---|---|---|
| 载体 | 14.65 GB 合并模型 | 11 MB 快照 / 一段 token 流 |
| 隔离性 | 靠加宽补零，需重新 merge | 天然按 head/chunk 分区 |
| 组合性 | 特性必须预先一起编译 | 程序随意拼 |
| 失效模式 | 数值/架构漂移 | 容量上限（66k token）|

所以“切权重麻烦”是**缺少图灵机分解**的产物，并非原理性困难：只要你还想给每个新能力做一次权重手术，就得付 merge 和加载的账。真要走这条路，正确工程是**稀疏 delta**（电路只有约 0.7M 个非零权重，bf16 下约 1.4 MB，按任务惰性加载），并非整包 checkpoint；仓库里的 `q35-size.md` 已在处理这件事。

## “减少写入成本 + 规避遗忘”的共同骨架，其实只有三条

n-gram 侧记忆和编译式电路，看着毫无关系，但在数学上是同一件事的两端：

$$P(w\mid h) \;=\; \lambda_0\,P_\theta(w\mid h) \;+\; \sum_i \lambda_i\,P_{\text{mem},i}(w\mid h)$$

**关键性质**：λ→0 时你会退回到 $\lambda_0 = 1$，**最坏情况是没赚到，而不是把基座弄坏**。梯度更新没有这个性质，它的最坏情况无界。这就是为什么 kNN-LM、RETRO、Infini-gram、N-grammer 这一族结构上不会灾难性遗忘；**加性、独立寻址、可关闭**是原因。

由此得到判定标准（我认为这是这个问题真正的答案）：

$$\text{不遗忘} \iff \text{冻结基座} \;\wedge\; \text{不相交地址空间} \;\wedge\; \text{可门控的读取}$$

- 满足三条 → 不遗忘（编译电路、DeltaNet 专用 head 的 one-hot 覆写、n-gram 插值、检索记忆、稀疏 delta 叠加）。
- 违反第二条（in-place 全参数覆写）→ 必忘。ROME / MEMIT 的 ripple effect、LoRA 叠多了互相打架，都是同一个原因：**地址空间重叠**。

第三个分支“专用分区内的覆写”值得单独指出，因为 Qwenputer 的 RAM 就是它：ΔNet 里 $\alpha=1,\ \beta=1$ 配 one-hot key，**精确覆盖一行、其余不动**。它确实在覆写，只是在**自己的**行里覆写。这也是为什么 snapshot 等于“存 RAM”，并非“存知识”。

## 代价是真的，但不在你担心的那个位置

我读完两篇文档后，最值得警惕的是下面四件事：

**1. 编译成本替代训练成本，不能说成本消失了。** 需要一份 spec、需要有人手工写 circuit macro（“every one computed by a compiler” 背后是人工构造），并且**深度耦合架构**：依赖 Qwen3.5 GDN 的精确 delta rule、要加宽 config、要做 vocabulary surgery（id bits / id code）。换个基座就重做。n-gram 那侧的账则是数据量 + 索引规模 + 检索延迟。两边的账都很贵，只是记在不同科目。

**2. 数值脆弱性比切换权重严重得多。** 文档里 `q35-store.md` 自己列了两个 IR 测不出来的 bug：**norm absorption**（计数器的 $2^{64-n}$ 冲垮 RMSNorm 的分母，改成 $2^{26-n}$）和 **slot handover by subtraction**（$1 - 2^{26}$ 在 fp32 里直接舍掉）。这类东西一旦量化到 4bit、或换 kernel / speculative decoding，就会崩。也就是说：**它和整个部署趋势（量化、MoE 路由、投机解码）结构性对撞**。切换权重是运维问题；精度不可迁移是原理问题。

**3. 容量差好几个数量级。** 文件系统 512 文件 / 66,560 token；NPU 那边是 261k 个 int4 权重。这是**工具 / 草稿纸的替代品**，不是持续学习的替代品。用 66k token 的 store 去想“替代微调”是范畴错误。

**4. 瓶颈从“学习”搬到“接口”，而接口 bug 长得和 n-gram 的坑一模一样。** 100k 距离后 Qwen 根本不调工具，答“not available”——**坏在读取策略（routing），不在存储**。kNN-LM 爬不上去也是同一个地方：检索得到的东西该不该信、怎么融合。**存储是便宜的，读写策略才贵**，而这恰恰是唯一你**不能**靠编译解决、只能靠学的部分。

## 我的判断

- **能**，但仅限**可精确规定（specifiable）**的东西：算术、存储、执行、格式转换、确定性检索。这类东西有编译路径，把写入成本压到 1.4 MB 的稀疏 delta 级别，遗忘为零（因为基座是子矩阵）。你担心的切权重，在这里应该用“编译一次解释器 + 换纸带”消掉。
- **不能**，对**只能从分布里学**的东西：世界知识、风格、模糊意图、paraphrase 鲁棒性。这里没有编译器，你只有梯度或统计；而加性记忆只能补“记忆”，补不了“能力”。n-gram 侧的稀疏性也在同一处卡住（需要 backoff / smoothing，泛化不到改写）。
- 一句话总结：**抗遗忘是“冻结 + 分区 + 门控”三者共同作用的结果，并非 n-gram 或编译器本身带来的**。这两个东西真正的贡献是**提供了一个便宜、精确、可验证的地址空间**，让“新东西”可以待在那里而不污染基座。至于“写入权重”的成本——它没有被消灭，只是被换成了**工程、索引和验证**三种货币；而在需要泛化的地方，这笔账还是只能用梯度来付。
