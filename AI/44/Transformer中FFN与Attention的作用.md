# Transformer 中 FFN 与 Attention 的分工

一句话概括：**Attention 负责"信息从哪里来、到哪里去"（跨 token 的通信与路由），FFN 负责"信息如何被变换和存储"（逐 token 的非线性计算与知识记忆）**。两者交替堆叠，构成 Transformer 的基本计算单元。

## 核心对比

| 维度 | Attention | FFN |
|---|---|---|
| 混合方向 | 序列维（跨 token / token mixing） | 特征维（逐 token 内部 / channel mixing） |
| 是否感知其他位置 | 是 | 否（pointwise，各位置独立、共享同一组权重） |
| 权重是否数据依赖 | **是**，$QK^\top$ 由输入动态算出 | 否，参数固定 |
| 非线性来源 | softmax | 激活函数 $\sigma$ |
| 参数占比 | 约 1/3 | 约 **2/3** |
| 计算复杂度 | $O(n^2 d)$（长序列瓶颈） | $O(n \cdot d^2)$（宽度瓶颈） |
| 功能隐喻 | 通信、检索、路由 | 计算、记忆、特征变换 |

## Attention：动态的上下文路由

$$\mathrm{Attn}(X) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V,\qquad Q=XW_Q,\ K=XW_K,\ V=XW_V$$

- **内容寻址的检索**：$QK^\top$ 产生与输入相关的相似度矩阵，本质是对 value 做一次**数据依赖的加权平均**。
- **三件套分工**：$W_Q/W_K$ 决定"看哪里"，$W_V$ 决定"取回什么"，$W_O$ 决定"如何写回"。
- **多头 = 并行多子空间检索**：不同头学到不同关系（指代、语法依存、局部邻近、寻址/复制等）。
- **关键能力**：归纳头（induction head）实现了 in-context learning、模式复制与少样本学习；这被认为是"上下文学习"的机制基础。
- **固有局限**：单头输出秩不超过 $d_{\text{head}}$，是**低秩**操作；本身**置换等变**，不含位置信息，必须靠位置编码补足；长序列下复杂度平方增长。

## FFN：逐位置的非线性计算与记忆

标准形式：

$$\mathrm{FFN}(x) = W_2\,\sigma(W_1 x + b_1) + b_2,\qquad d_{ff} \approx 4d$$

现代 LLM 多用门控变体（GLU / SwiGLU）：

$$\mathrm{FFN}(x) = \big(\sigma(xW_1)\odot xW_3\big)W_2$$

- **升维 → 非线性 → 降维**：先把表示投影到高维，激活筛选特征，再压回原维度，是模型主要的**非线性容量来源**。
- **Key-Value 记忆**（Geva et al., 2021）：$W_1$ 的每一行是"模式检测器"（key），$W_2$ 的对应列是"要写回的内容"（value）——FFN 本质是一个巨大的、稀疏激活的关联记忆库。
- **承载事实性知识**：知识编辑工作（ROME / MEMIT）正是通过修改 FFN 权重来改写模型中的事实。
- **可解释性**：中间层神经元常对应人类可读的语义/句法/语言特征（如"DNA 序列""法律用语"检测器）。
- **MoE 的落点**：几乎所有权重稀疏化方案都是把 FFN 换成专家路由——因为参数瓶颈在 FFN，而不在 attention。

<details>
<summary><strong>深入一：为什么说"Attention 是通信、FFN 是计算"</strong></summary>

从**残差流（residual stream）**视角看最清楚：把 $d$ 维残差流当作贯穿全层的"共享总线/黑板"：

- Attention 从总线**读取**各位置的当前状态，聚合后**写回**总线 → 位置间的信息交换；
- FFN 从总线**读取**当前位置状态，变换后**写回** → 单点上的计算。

于是"一层 = 一轮通信 + 一轮计算"，**深度 = 多轮迭代**。这也解释了为什么两种模块都是必需的：只有通信没有计算，信息无法被非线性加工；只有计算没有通信，序列退化为词袋。

（Elhage et al., 2021, *A Mathematical Framework for Transformer Circuits*）
</details>

<details>
<summary><strong>深入二：消融实验说明了什么</strong></summary>

- **去掉 Attention**：模型变成逐 token 的 MLP。若无位置编码则对输入顺序完全不变——等价于词袋模型，无法处理指代、语法、上下文依赖，语言建模能力崩坏。
- **去掉 FFN**：模型退化为若干层加权平均 + 线性映射，参数量和表达力骤降，损失显著上升（在标准 LLM 上是灾难性的）。
- **结论**：两者承担的功能**不可互相替代**，是"通信"与"计算"的正交互补。

常见误解需要澄清：并非"Attention 管语义、FFN 管语法"，也不是"FFN 只是加个非线性"。事实上 **FFN 才是参数与知识的主体**，而 Attention 的单层能力远比直觉中弱，其强大依赖多层叠加。
</details>

<details>
<summary><strong>深入三：工程上的不同瓶颈</strong></summary>

- Attention 的 $O(n^2)$ 来自序列长度 → 催生了 FlashAttention、稀疏/线性注意力、滑窗注意力、位置插值等长上下文方案。
- FFN 的 $O(d^2)$ 来自模型宽度 → 催生了 MoE、低秩适配（LoRA 主要作用于 $W_Q/W_V/W_1/W_2$）、量化与参数共享。
- 因此**推理延迟瓶颈通常在 Attention（长上下文），模型体积与显存瓶颈通常在 FFN**，二者优化策略截然不同。
</details>

## 小结

| 问题 | 答案 |
|---|---|
| Attention 做什么？ | 让每个 token 动态地从其他 token 处**检索并聚合**信息（跨位置、数据依赖、低秩、置换等变） |
| FFN 做什么？ | 对每个 token 独立地做**非线性特征变换与关联记忆读写**（跨通道、位置无关、参数主体） |
| 为什么都要？ | 通信与计算分工互补；交替堆叠使模型能进行多轮"交换信息—加工信息"的迭代推理 |

**记忆锚点**：Attention ≈ 可微的、内容寻址的**查找表**；FFN ≈ 可微的、逐样本的**知识库 + 计算器**。

## 前半句：对，但可以再精确一点

"attn 找资讯、FFN 处理资讯"作为一句话记忆没问题，补两个细节会更准：

- **Attn 不只是"读"，也在"写"**：它的输出会被投影后加回残差流，改变后续所有层的 $Q/K/V$。所以它既是从别人那里取信息，也是在向共享黑板留言。
- **一次只找一跳**：单层 attention 只能做一轮加权平均。要多跳链式推理（A→B→C 式指代链、归纳头复现模式）必须靠多层堆叠——**深度在这里是必需的**。所以"找资讯"准确说是"每层找一跳"。
- **FFN 也不只是"处理"**：它同时是记忆载体（key-value memory 视角），删除/改写 FFN 权重能改变模型知道的事实。

## 后半句：需要拆成两种读法

> "输入形状固定 → 只用 FFN 就行"

这句话里的 "FFN" 有两种读法，结论截然相反。

### 读法 A：把 Transformer 里那种 FFN **逐层堆叠**用上去 → **不成立**

这是真正的陷阱。Transformer 的 FFN 是 **pointwise** 的：对每个位置 $i$ 独立作用，

$$\text{FFN}(x)_i = W_2\,\sigma(W_1 x_i + b_1)$$

两个 pointwise 函数复合仍然是 pointwise：

$$(f \circ g)(x)_i = f\big(g(x)_i\big) = f\big(g(x_i)\big)$$

所以**无论叠多少层，位置 $i$ 的输出永远只依赖位置 $i$ 的输入**。深度完全不扩大感受野——这和 CNN "越深视野越大" 的直觉正好相反。结果就是一个**带位置标签的词袋模型**：句子顺序、指代、语法全丢。注意这不是"训练不够"的问题，是结构性的。

反过来说，这恰好解释了 attention 的不可替代性：**它是唯一负责跨位置信息流动的模块**。有个有意思的佐证：把 FFN 和残差连接都去掉、只留纯 attention，模型会出现双重指数级的 rank collapse（Dong et al., 2021），表示迅速退化到低秩。也就是说**光靠 attention 自己也撑不住**——两者是互相需要的。

### 读法 B：把 "MLP" 当作唯一积木，允许它跨位置作用 → **理论上成立，但代价巨大**

如果输入形状真固定，比如 $X \in \mathbb{R}^{n \times d}$，你把它拉平成 $\mathbb{R}^{nd}$，喂给一个足够宽的 MLP——万能逼近定理说这可以逼近该紧集上任意连续函数，attention 自然也在其中。**表达力上，固定长度时二者等价。**

但关键区别不在表达力，而在下面这些：

| | Attention | 纯 MLP（跨位置） |
|---|---|---|
| 参数量与 $n$ 的关系 | **无关**，$O(d^2)$ | 随 $n$ 增长；要做全 pairwise 交互，宽度常需 $\sim n$ 量级 |
| 权重共享 | 天然在所有位置对之间共享同一个打分函数 | 没有；得自己从数据里学出"每对位置都干同样的事" |
| 长度泛化 | 换长度直接可用 | 换长度即失效，padding 还会污染语义 |
| 归纳偏置 | 内建"比较 query 与所有 key 再路由" | 白手起家，样本效率极低 |
| 精确检索/复制 | softmax 近似 top-1，一层就能做 | 要近似 argmax + 乘法，需很大宽度 |

举个量级感受：$n = 4096$ 时，"每个位置对都要有正确行为"这件事如果要 general 地实现，宽度就得往 $n$ 甚至 $n^2$ 的量级走，而 attention 只用 $\mathbb{R}^{d \times d}$ 的四个矩阵就搞定了。

还有匹配深度/宽度下的分离结果：固定参数预算时，attention 能做的关联召回（associative recall）、稀疏平均这类任务，MLP 做不到（Sanford et al., 2023 一类工作）。**"理论上可以"不等于"同代价下可以"。**

## 实证上也验证了这一点

- **gMLP / MLP-Mixer**：用 MLP 替代 attention，但必须保留一个**跨 token 的混合层**（把输入转置后沿 token 轴做 MLP）。注意这个 token-mixing MLP 的权重维度**是依赖 $n$ 的**——正好印证了你说的"形状必须固定"。
- **FNet**：干脆拿傅里叶变换做 token mixing，连 MLP 都省了，固定线性变换居然也能用。说明"token 混合"这一环才是本质，具体用谁实现是次要的。
- **Hyena / Mamba / S4**：用长卷积或状态空间递推替代 attention，同样在保留跨位置混合。
- 而所有**纯 pointwise** 的模型（读法 A）无一例外都退化成词袋，没有能打的。

所以规律很清楚：**可以换掉 attention，但不能换掉"跨位置的信息交换"这个功能。**

## 收束

你的直觉里正确的那部分是：**attention 不是神圣不可替代的模块，它只是一个 token 混合算子**，功能上完全可以用别的机制顶替。

需要修正的部分是：这个"理论上可以"的门槛有多高。真要设计一个既高效、又能跨位置共享参数、还能泛化长度的 MLP 版本，你最后大概率会**重新发明出 attention**——因为 attention 的精髓不是"用了 softmax 和 $QK^\top$"，而是**参数量与序列长度解耦的、内容寻址的权重共享**。架构的本质往往就藏在这个"权重怎么共享"的形式里；至于积木块叫 MLP 还是 attention，反而是次要的。

一句话：**表达力上，固定长度让二者等价；但参数效率、归纳偏置和长度泛化让二者天差地别——而后者才是"能不能训出来"的决定性因素。**
