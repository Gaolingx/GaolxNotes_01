# 大batch梯度范数更低

### 🧑‍💻 User

sft微调为什么bs越大梯度范数越低？

---

### 🤖 Assistant

在 SFT（Supervised Fine-Tuning，监督微调）过程中，增大 batch size (`bs`) 通常会导致观测到的梯度范数降低。这一现象的本质原因是**随机梯度的统计平均效应**。

具体可以从以下几个维度来理解：

### 1. 数学原理：方差随样本量减小
假设每个样本的损失函数为 $L_i(\theta)$，整个数据集的真实梯度为 $g = \nabla_\theta \mathbb{E}[L_i(\theta)]$，单样本计算得到的随机梯度为 $g_i = \nabla_\theta L_i(\theta)$。

在 batch size 为 $N$ 的情况下，我们计算的 mini-batch 梯度是单样本梯度的平均值：
$$g_N = \frac{1}{N} \sum_{i=1}^N g_i$$

根据统计学原理，mini-batch 梯度的期望等于真实梯度 $\mathbb{E}[g_N] = g$，而其方差则随着 batch size 的增大而线性减小：
$$\text{Var}(g_N) = \mathbb{E}[\|g_N - g\|^2] = \frac{\sigma^2}{N}$$
其中 $\sigma^2$ 是单样本梯度的方差。

我们观测到的梯度二阶矩（梯度范数的平方）可以分解为：
$$\mathbb{E}[\|g_N\|^2] = \|g\|^2 + \text{Var}(g_N) = \|g\|^2 + \frac{\sigma^2}{N}$$

由此可以看出，当 batch size $N$ 增大时，$\frac{\sigma^2}{N}$ 这一项减小。因为单样本梯度中包含了大量方向各异的噪声，这些噪声在求平均时相互抵消，使得最终计算出的梯度范数更接近真实梯度的范数 $\|g\|$，从而表现出整体梯度范数下降的现象。

### 2. 直观理解：向量的相互抵消
可以将每个样本产生的梯度看作一个向量。
* **小 Batch Size：** 样本少，参与平均的向量少。由于不同样本对模型权重的更新方向诉求不同（即存在梯度噪声），这些向量很难完全对齐，导致合成后的向量带有较大的随机波动，范数往往偏高且震荡剧烈。
* **大 Batch Size：** 样本多，参与平均的向量多。大量方向随机的噪声分量在求和与平均的过程中相互抵消（类似于正负相消），剩下的主要是所有样本共识的“主方向”。这个主方向通常更加平滑且精确，噪声变小了，其绝对长度（范数）自然也就降下来了。

<details>
<summary><b>深入探讨：这对训练有什么影响？</b></summary>

虽然大 batch size 降低了梯度范数，但这并不意味着模型学得“慢”了，而是意味着更新方向更加“确信”和“稳定”。为了适应这种变化，在实际 SFT 中通常需要做以下调整：

1. **学习率缩放：**
   因为梯度范数变小了，如果保持学习率不变，模型参数的实际更新步长 $\Delta \theta = -lr \times g_N$ 会变小。为了保持与小 batch size 相当的训练速度，通常需要增大学习率。
   常用的有**平方根缩放法则**：$lr_{new} = lr_{base} \times \sqrt{\frac{bs_{new}}{bs_{base}}}$。

2. **梯度裁剪的相对影响：**
   在 SFT 脚本中通常会配置 `clip_grad_norm`。由于大 batch size 下梯度范数本身较低，触发梯度裁剪的阈值（如 1.0 或 0.1）就更难被触发。这意味着大 batch size 下梯度的真实分布更少受到人为截断的干扰。

</details>

<details>
<summary><b>代码示例：观测不同 batch size 下的梯度范数</b></summary>

以下是一个使用 PyTorch 模拟该现象的简单代码片段：

```python
import torch
import torch.nn as nn
import torch.optim as optim

# 1. 定义一个简单的模型和损失函数
model = nn.Linear(10, 1)
criterion = nn.MSELoss()

# 2. 生成随机数据
inputs = torch.randn(1000, 10)
targets = torch.randn(1000, 1)

# 3. 测试不同 batch size 下的梯度范数
batch_sizes = [1, 8, 32, 128, 512]

for bs in batch_sizes:
    # 随机采样一个 batch
    idx = torch.randperm(len(inputs))[:bs]
    x_batch = inputs[idx]
    y_batch = targets[idx]
  
    # 前向传播与反向传播
    model.zero_grad()
    outputs = model(x_batch)
    loss = criterion(outputs, y_batch)
    loss.backward()
  
    # 计算并打印总梯度范数
    total_norm = 0.0
    for p in model.parameters():
        if p.grad is not None:
            param_norm = p.grad.data.norm(2)
            total_norm += param_norm.item() ** 2
    total_norm = total_norm ** 0.5
  
    print(f"Batch Size: {bs:4d} | Loss: {loss.item():.4f} | Grad Norm: {total_norm:.4f}")
```
运行上述代码，你会直观地看到 `Grad Norm` 随着 `Batch Size` 的增加而呈现下降趋势。
</details>

### 🧑‍💻 User

为什么当模型有过拟合迹象或者适配器容量耗尽时候gradnorm会膨胀？

---

### 🤖 Assistant

这是一个非常深刻的问题。在 SFT 或一般的深度学习训练中，当模型出现过拟合迹象，或者在使用 Parameter-Efficient Fine-Tuning (PEFT，如 LoRA、Adapter) 时适配器容量耗尽，我们经常会观察到梯度范数突然升高或持续膨胀的现象。

这并非偶然，而是由**优化过程中的数学极值、损失地形的几何特征以及参数空间的张力**共同决定的。具体原因可以分为以下两个场景来深入剖析：

---

### 一、 为什么过拟合会导致 Gradnorm 膨胀？

过拟合的本质是模型开始“死记硬背”训练数据，尤其是试图去拟合数据中的噪声。这会导致梯度膨胀，主要原因有以下三点：

#### 1. 拟合噪声导致的 Logit 爆炸
假设训练集中存在标注错误或固有的随机噪声。为了让损失函数下降，模型必须对这些错误的标签输出极高的概率。
以交叉熵损失为例：$L = -\log(p_{target})$。如果真实标签是错误的，模型为了让 $L \to 0$，就必须让预测概率 $p_{target} \to 1$。在 Softmax 函数中，这意味着模型对应的 Logit 值必须趋向于正无穷大。
当模型处于过拟合的冲刺阶段时，权重会被推向极端值以最大化错误类别的概率。此时，损失函数的梯度 $\nabla L$ 会随着 Logit 的极端化而急剧增大，导致梯度范数膨胀。

#### 2. 损失地形的高曲率
过拟合的模型在权重空间中构建了一个极其复杂、扭曲的决策边界。从优化的角度来看，这意味着损失函数的地形变得非常崎岖，充满了狭窄且极深的“峡谷”。
当优化器在这些高曲率的峡谷中穿行时，稍微的参数移动都会导致梯度的剧烈变化。模型在峡谷壁之间来回反弹，这种高曲率（Hessian 矩阵的特征值极大）直接表现为梯度范数的剧烈震荡和膨胀。

#### 3. 梯度方差主导
正如前一个问题所述，梯度二阶矩 $\mathbb{E}[\|g\|^2] = \|g\|^2 + \text{Var}(g)$。
在过拟合阶段，模型对大多数“正常”样本的损失已经接近 0（梯度为 0），但为了拟合极少数“困难/噪声”样本，模型会产生极大的单样本梯度 $g_i$。这就导致整个 batch 的梯度方差 $\text{Var}(g)$ 激增。此时，**梯度范数主要由方差项主导**，表现为 Gradnorm 居高不下。

---

### 二、 为什么适配器容量耗尽会导致 Gradnorm 膨胀？

当使用 LoRA、Adapter 等技术微调大模型时，可训练参数量极小。当这部分参数的“表达能力”（容量）达到极限，无法再拟合下游任务时，Gradnorm 也会膨胀。

#### 1. 受限优化中的持续张力
适配器容量耗尽，意味着在当前可学习参数构成的低维流形中，模型已经达到了它能达到的最优解，但这个最优解距离真正的全局最优解（或理想损失最低点）仍有距离。
从数学上看，这是一个**受限优化问题**。真实梯度指向流形外的“理想下降方向”，但优化器只能沿着流形内的方向移动。这种“想往外面走但被流形边界挡住”的状态，会在流形内部产生极大的**投影张力**。只要损失没有降到 0，这种受限的梯度推力就会持续存在，导致 Gradnorm 无法收敛而维持高位。

#### 2. 权重幅值的极端补偿
因为适配器参数量少（例如 LoRA 的低秩矩阵 $A$ 和 $B$），为了达到与大模型全量微调相当的拟合效果，优化器会驱使这极少量的参数产生极大的权重更新。
公式 $\Delta W = B A$ 中，为了弥补 Rank（秩）太小的缺陷，$B$ 和 $A$ 的元素绝对值会被推向极大。由于梯度的计算往往与权重本身的大小正相关（例如链式法则中的导数项），极大的权重幅值会反噬，产生极大的梯度，导致数值不稳定和 Gradnorm 膨胀。

#### 3. 冲突梯度的无法消解
在正常训练中，不同样本产生的方向各异的梯度可以通过足够的参数维度进行消解和折中。但在适配器容量耗尽时，有限的参数维度无法容纳多个冲突的优化方向。
模型陷入了“按下葫芦浮起瓢”的境地：降低样本 A 的损失会导致样本 B 的损失剧增。这种持续的正反馈冲突使得梯度无法平滑收敛，单样本梯度的方差 $\sigma^2$ 始终保持在极高水平，推高了整体的梯度范数。

<details>
<summary><b>💡 工程实践：遇到这种 Gradnorm 膨胀该如何处理？</b></summary>

如果在 SFT 训练监控中发现 Gradnorm 异常升高，且伴随 Loss 不再下降或验证集指标变差，可以采取以下策略：

1. **针对过拟合：**
   * **早停法:** 这是最直接的方法，在验证集 Loss 上升的节点停止训练。
   * **增加正则化:** 提高 Dropout 概率，或增加 Weight Decay（权重衰减）的系数，限制权重走向极端值。
   * **降低学习率:** 此时模型处于高曲率区域，过大的学习率会加剧震荡，适当降低学习率有助于模型稳定在平缓的极小值点。

2. **针对适配器容量耗尽：**
   * **增加适配器容量:** 如果使用 LoRA，可以适当增大 `Rank`（如从 8 提升到 16 或 32），或者将更多的线性层（如 `q_proj`, `k_proj`, `v_proj`, `o_proj` 甚至 MLP 层）加入 LoRA 微调范围。
   * **解冻部分原始层:** 在微调后期，解冻大模型的最后几层 Transformer Block 进行全参数微调，打破低维流形的限制。
   * **检查数据质量:** 如果容量耗尽发生在训练极早期，往往是因为数据中存在大量矛盾或噪声，此时需要清洗 SFT 数据集。
</details>
