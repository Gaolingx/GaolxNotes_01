# 中层复用提升模型效果

### 🧑‍💻 User

在每 token FLOPs、非嵌入参数总量和 KV cache 近似匹配的条件下，将 MoE Transformer 中间一半的层执行两遍（loop transformer），是否能够获得更低的 validation loss 和更高的下游任务成绩？

---

### 🤖 Assistant

## 结论

**可以。** 在“每 token FLOPs、非嵌入参数总量、KV cache 三项都近似匹配”的条件下，把 **MoE Transformer 中间 50% 的层循环执行两遍**，论文 **SMELT: Scaling Laws for Compute-Matched MoE Looped Transformers**（arXiv:2609.01343）发现：

- **validation loss 更低**：在 4 个模型尺度 × 4 个稀疏度上，SMELT 都比无循环 baseline 更低；在 compute-optimal frontier 上相当于省 **6.8%–18.0%** 训练 FLOPs。
- **下游任务成绩更高**：DCLM Completion 96/96 对全胜，DCLM Core 83/96，MMLU（baseline 显著高于随机猜的 30 对中）29/30；而且提升幅度**超过 validation loss 本身所预测的幅度**。

---

## 1. 怎么做到“三项预算近似匹配”

设物理层数 \(L\)，循环中间 \(m\) 层 \(r\) 次，则有效深度为

$$
L_{\mathrm{eff}} = L + (r-1)m
$$

循环会增加每 token FLOPs，因此 SMELT 用三套调整来抵消：

| 预算 | 调整方式 | 典型残余失配 |
|---|---|---|
| 每 token FLOPs | 缩窄 hidden dim \(H\)，或改深度 | \(<4\%\) |
| 总非嵌入参数 | 增加专家数量 | \(<1\%\) |
| KV cache | 调整 head size / GQA ratio | \(<4\%\) |

在 12 个稀疏 grid cell 中，最大绝对失配为：**FLOPs 3.9%、参数 1.0%、KV cache 3.6%**。所以这不是“偷偷多花算力”的结果。

---

## 2. Validation loss：更低，且随 compute 下降更快

论文分别给 baseline 和 SMELT 拟合了 Chinchilla 式 scaling law：

$$
\mathcal{L}(F,S,D)=E+\frac{A(1-S)^b}{F^a}+\frac{K}{D^c}
$$

拟合结果：

| 参数 | Baseline | SMELT |
|---|---:|---:|
| 容量指数 \(a\) | 0.3703 | **0.3892** |
| 数据指数 \(c\) | 0.6594 | **0.7011** |
| frontier 指数 \(\gamma=\frac{ac}{a+c}\) | 0.237 | **0.250** |

\(\gamma\) 高约 **5.5%**，意味着 SMELT 的 frontier loss 随 compute 下降更快。具体节省：

| 训练 compute | \(S\approx85\%\) | \(S\approx95\%\) | \(S\approx97\%\) |
|---|---:|---:|---:|
| \(10^{20}\) FLOPs | 10.0% | 7.8% | 6.8% |
| \(10^{21}\) FLOPs | 18.0% | 15.8% | 14.7% |
| \(10^{22}\) FLOPs（外推） | 23.5% | 20.9% | 19.6% |

一个 200M、\(S\approx85\%\) 的具体对比例子：

| 模型 | Val. loss ↓ | DCLM Core ↑ | DCLM Completion ↓ |
|---|---:|---:|---:|
| Baseline | 1.9445 | 24.92 | 2.2887 |
| Looped \(2\times\) | **1.9257** | **27.57** | **2.2635** |

---

## 3. 下游任务：更高，而且“超额”提升

论文用 baseline 的 96 个 endpoint 拟合“validation loss → benchmark score”的单调 sigmoid，再看 SMELT 的残差 \(\delta\)。正残差表示：**在同样 validation loss 下，SMELT 的下游成绩仍比 baseline 曲线更好**。

结果：

- **DCLM Completion**：96/96 全胜。
- **DCLM Core**：83/96 胜。
- **MMLU**：baseline 高于随机猜 10 个百分点以上的 30 对中，29 对胜。
- 残差在三个 benchmark、所有尺度上均为正，且随规模增大而增大。

领域上，**Code 收益最大**。在 \(C=10^{21}\)、\(S\approx95\%\) 时：

| 领域 | CE Gain |
|---|---:|
| Code | **20.4%** |
| Finance | 16.8% |
| Math/STEM | 16.6% |
| Knowledge | 14.9% |
| Web | 14.8% |

此外：

- 长样本收益更大：512–4096 token 桶的改进是 32–256 token 桶的 **1.52×**。
- ICL 收益随示例数增加：\(k=0\) 时差距 0.9 pp，有演示后约 **1.9 pp**；Dyck Languages 在 \(k=32\) 时 **29.8% vs. 26.4%**。

---

## 4. 机制上发生了什么

论文的 probing 给出一个一致的解释：**第二次执行不是简单重复，而是一次“refinement”**：

- 专家路由复用核心子集，同时增加多样性；
- 第二次 visit 写入 residual stream 的更新更大，且与第一次方向对齐（cosine 约 0.42–0.65）；
- attention sink 明显下降，注意力质量转向内容相关 token：Dyck 案例中 BOS 质量从 **0.60 降到 0.02**，演示答案 token 质量从 **0.24 升到 0.85**。

---

## 5. 需要注意的限定

<details>
<summary>论文自身的 caveats（点击展开）</summary>

- 三项预算只是**近似匹配**，不是精确相等；最大失配见上。
- 循环设计消融主要在 **200M 尺度**（约 3.9B 非嵌入参数）完成；scale-up 到 **54B 非嵌入参数**，但 active scale 最大为 1.6B。
- 训练数据约 **205B–215B tokens**，仅一次训练 run 每个配置，训练 run 间方差未捕获。
- 匹配的是算术 FLOPs、参数量、KV cache，不是 wall-clock；串行循环和稀疏路由可能带来实际系统效率差异。
- \(10^{22}\) FLOPs 的收益是外推，超出拟合窗口。
- 论文结论针对“中间 50% 层循环两遍、完全共享权重”的简单 loop 形式；其他 loop 变体仍待研究。

</details>

---

**一句话总结：在 SMELT 的严格三预算匹配设定下，MoE Transformer 中间一半层循环两遍，确实同时取得了更低的 validation loss 和更高的下游任务成绩；收益不是来自额外算力或参数，而是来自循环带来的“二次精炼”归纳偏置。**
