# 开源模型限幅激活趋势

## 🧑‍💻 User

感觉最近的开源模型大家都开始下意识的用带clamp的swiglu了怎么说（包括gptoss、deepseek v4 flash、kimik3、ripple-65b）

---
## 😀 默认助手 (7)

下面结合我刚好核对过的几个 config 和参考实现来讨论：你点名的四个模型，确实是“都带 clamp”，但细节差异比“大家都用了带 clamp 的 SwiGLU”这个说法大得多，而且“大家”这个概括并不完全准确。

## 先事实核查（我读了各家的 config 和 modeling 代码）

| 模型 | 配置里的 knob | 实际公式 | 类型 |
|---|---|---|---|
| gpt-oss-120b/20b | `swiglu_limit: 7`，`hidden_act: silu` | `gate.clamp(max=7)`，`up.clamp(±7)`，再 `(up+1)·σ(1.702·gate)·gate` | hard clamp，**gate 单边、up 双边** |
| DeepSeek-V4.1-Flash | `hidden_act: silu` + `swiglu_limit: 10` | 配置层确认，实现层我没找到公开 kernel | 待确认 |
| Kimi-K3 | `hidden_act: "situ"`，`activation_situ_beta: 4`，`activation_situ_linear_beta: 25` | $\beta\tanh(g/\beta)\sigma(g)$ 中的 $\beta=4$；up 分支 $25\tanh(u/25)$ | **soft clamp**，全程可导 |
| Ripple-65B-Preview（ricursiveAI） | `ffn_clamp_threshold: 20` | `gate.clamp(max=20)`，`up.clamp(±20)`，`silu(gate)*up` | hard clamp，**和 gpt-oss 逐行同构** |

几个值得指出的点：

- **gpt-oss 那个不是标准 SwiGLU**：它带 $\alpha=1.702$ 的 GEGLU 缩放，还加了 $+1$ 偏置（`(up+1)*glu`），所以叫“clamped”没问题，但它已经是一个变体。
- **Ripple 的实现几乎是照抄 gpt-oss 的 `_apply_gate`**，连“gate 只 clamp 上界、up 双边 clamp”这个不对称细节都一样。这个不对称其实没有理论必然性（silu 的负半轴本来就有下界 $-0.278$，所以只需要防正半轴；up 是线性的，两边都得防），更像是**代码文化的传播**而不是独立收敛。它还顺手继承了“gate 走 fp32”（`gate_full_precision: true`），和 gpt-oss 把 router 分支留在高精度是同一个思路。
- **Kimi K3 走的是另一条路**：不做 hard clamp，而用 SiTU 把两支都做成 tanh 饱和，$\beta=4$ 和 $25$ 意味着 FFN 单元输出的绝对上界是 $4\times25=100$。数学上是有硬界的，但梯度不会归零，只是指数衰减。
- **阈值的选择很有信息量**：7、10、20、(4,25)，全都是“比正常激活分布宽一到两个数量级”的位置。这说明目的不是让量化范围更好看，而是**只在灾难性 outlier 上触发的安全阀**。真正为量化做动态范围压缩的话，阈值会选得更紧。

## 但“大家”这个词有点过

我顺便查了同期两个大模型：**Qwen3.5** 和 **GLM-5.3** 都还是 `hidden_act: silu`，没有任何 clamp 相关字段，它们有 attention output gate、indexer 稀疏注意力、KDA/Gated DeltaNet 这些新东西，但 FFN 这一块很保守。

所以更准确的说法是：**在 FP8/FP4 + 长 RL 的重训练那一支里，clamp 正在变成默认项；但整个行业没有**。这四个更像一条技术谱系（都跟 OpenAI 那套低精度训练配方有关），不是“大家都”。

## 为什么是现在

我认为有几个动机叠在一起：

1. **4-bit 权重让 outlier 的“价格”变了。** gpt-oss 全 MoE expert 是 MXFP4，Kimi K3 的 routed experts 也是 mxfp4，DeepSeek 是 fp8 权重 + fp4 expert。per-block（32 或 128）缩放里，一个巨大 outlier 就能承担整块 scale，其余值全被压进尾数。clamp 把激活的动态范围固定住，让 scale 变得**可预测**，这是量化友好性的前置条件，比事后做 imatrix/AWQ 便宜得多。
2. **它是 massive activations 的零成本抑制器。** clamp 相当于一个可学习（几乎处处可微）的裁剪，直接处理 attention sink / FFN 通道 outlier，不用改架构、不用加 norm。
3. **长 CoT + RL 后训练的数值稳定性。** loss spike 常常来自个别 token 的 FFN 激活爆炸，clamp 在**源头**断开这条传播链（饱和区梯度为 0），比全局 grad clipping 更定点。对动辄几十万 token 的 rollout 来说，这是“避免一整批样本被污染”的保险。
4. **推理开销为零。** 一个 clamp 能 fuse 进 GEMM epilogue，q 量化 kernel 里本来就有 clamp-to-range。相比“换激活函数”“加一个新 norm”，这是最容易落地的改动。
5. **同源哲学**：Gemma 2 的 attention logit soft-capping、gpt-oss 的 attention sink 和 softmax 减 max，都是在网络里到处埋“软天花板”。clamp 只是这套思路在 FFN 上的自然延伸。

## hard 和 soft 两种设计

- **hard clamp 是梯度断开机制**：饱和区梯度为 0。好处是极端值彻底不传播；坏处是阈值设太紧会导致某些通道永远学不到东西（死通道），而且训练早期就饱和会拖慢收敛。所以实用的 hard clamp 阈值都放得很宽。
- **soft clamp（SiTU 型）处处可导**，梯度在饱和区指数衰减，训练更平滑，代价是理论上超大值仍以 tanh 速度通过，$\beta$ 选错就是没有作用。Kimi 选 $\beta_{gate}=4$、$\beta_{up}=25$ 其实相当宽松，更像是“防止数值溢出”而不是“对激活值塑形”。
- 还有个工程上的共同点：**都往 kernel 友好方向走**。gpt-oss 和 Ripple 把 `gate_up` 打包成一个 GEMM + 一个 `_apply_gate`；Kimi 把 `w1`/`w3` 拼接后送进 fused `SituAndMul`。clamp 之所以能进生产，很大程度因为它不破坏这个融合。

## 我认为后面的走向

- **阈值可能会变成学出来的**（per-layer learnable limit），或者直接和量化 scale 联合优化，既然目的是控制 outlier，把阈值和 block 的 scale 绑在一起最自然；
- **hard clamp 会被“天然有界激活”吃掉**，SiTU 这类是更优雅的版本；hard clamp 只是 silu 用户的最低成本补丁；
- 也别忘了**传播效应**，Ripple 那个逐行同构的实现说明这个东西已经进入“开源配方默认值”阶段。很多模型用 clamp 未必是因为自己做了 ablation，而是因为 gpt-oss 之后它从“奇怪 trick”变成了“大家都见过的 knob”。

一个提醒：DeepSeek 的 `swiglu_limit: 10` 我只能确认配置里存在这个字段（以及 `hidden_act` 写的是 silu），具体是 gate 单边还是双边、有没有 $\alpha$ 缩放，我找不到公开实现来核实。如果你手上有 vLLM/SGLang 对应实现或者 V4 技术报告里的那一段，这个可以补上，因为 DeepSeek 选择的语义应该能反推他们真正想解决的是哪类 outlier。
