### 🤖 Assistant

# `autograd.Function` + Forward/Backward Hooks 的组合威力

两者结合后，你可以在**自定义自动求导规则的基础上**，获得**对中间激活和梯度的细粒度控制**。下面从机制到实战逐一拆解。

---

## 1. 两种工具的职责划分

| | `autograd.Function` | Hook |
|---|---|---|
| **控制粒度** | 替换**整个算子**的正反向传播 | 在已有算子的**前后**插入逻辑 |
| **梯度控制** | 定义 `backward(ctx, grad_output)`，完全自定义梯度 | 读取/修改梯度，但不能改变 backward 图结构 |
| **典型用途** | 自定义不可导算子、STE、梯度反转 | 调试、可视化、梯度裁剪、特征保存 |

两者结合 = **自定义算子 + 在自定义边界内外插入监控/修改逻辑**。

---

## 2. 核心实战场景

### 2.1 梯度反转层（Gradient Reversal Layer, GRL）

这是领域对抗网络（DANN）的经典需求：前向不变，反向梯度取反。

```python
class GradientReversal(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, lambda_):
        ctx.lambda_ = lambda_
        return x.view_as(x)          # 前向：恒等映射

    @staticmethod
    def backward(ctx, grad_output):
        return grad_output.neg() * ctx.lambda_, None  # 反向：梯度取反

grl = GradientReversal.apply
```

**加上 hook 可以做什么？**
- 在 `backward` 返回之后用 **tensor hook** 监控取反后的梯度范数
- 用 **forward hook** 记录 GRL 前后的特征分布（Wasserstein 距离等）

```python
def grad_norm_hook(grad):
    print(f"GRL grad norm: {grad.norm().item():.4f}")
    return grad

x = grl(feature, lambda_=0.1)
x.register_hook(grad_norm_hook)   # 监控梯度反转后的梯度
```

### 2.2 自定义量化 / STE（Straight-Through Estimator）

量化函数前向离散化，反向直接用梯度：

```python
class QuantizeSTE(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, n_bits):
        scale = x.abs().max() / (2**(n_bits-1) - 1)
        x_q = (x / scale).round().clamp(-2**(n_bits-1)+1, 2**(n_bits-1)-1)
        ctx.save_for_backward(x, x_q)
        return x_q * scale

    @staticmethod
    def backward(ctx, grad_output):
        return grad_output, None   # STE: 梯度直通
```

**加上 hook 可以做什么？**

```python
# 用 hook 对比量化前后的量化误差
def quant_error_hook(module, input, output):
    err = (output - input[0]).abs().mean()
    print(f"Quantization MAE: {err:.6f}")

module.register_forward_hook(quant_error_hook)
```

### 2.3 梯度检查点 / Activation Checkpointing

`autograd.Function` 可以手动控制哪些中间结果被保存，而 **backward hook** 可以在重计算发生后捕获恢复出的激活值：

```python
class CheckpointFunction(torch.autograd.Function):
    @staticmethod
    def forward(ctx, run_fn, *args):
        ctx.run_fn = run_fn
        ctx.save_for_backward(*args)  # 只存输入，不存中间激活
        with torch.no_grad():
            outputs = run_fn(*args)
        return outputs

    @staticmethod
    def backward(ctx, *grads):
        args = ctx.saved_tensors
        with torch.enable_grad():
            outputs = ctx.run_fn(*args)  # 重计算
        torch.autograd.backward(outputs, grads)
        return (None,) + tuple(a.grad for a in args)
```

**加上 hook：**
- 在重计算后的中间激活上注册 `register_hook`，实时检测 NaN/Inf 梯度
- 记录重计算出的激活与原始激活的一致性（用于 debug）

### 2.5 调试 NaN / Inf 的"双向夹击"策略

这是工业界最实用的组合之一：

```python
class DebugFunction(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, name="unknown"):
        ctx.name = name
        if torch.isnan(x).any() or torch.isinf(x).any():
            print(f"[FORWARD NaN/Inf] {name}: shape={x.shape}")
        ctx.save_for_backward(x)
        return x

    @staticmethod
    def backward(ctx, grad_output):
        if torch.isnan(grad_output).any() or torch.isinf(grad_output).any():
            print(f"[BACKWARD NaN/Inf] {ctx.name}")
            # 可选择将 NaN 替换为 0，避免传播
            grad_output = torch.nan_to_num(grad_output, nan=0.0, posinf=1e5, neginf=-1e5)
        return grad_output, None

# 配合 hook：在任意 tensor 上同时监控
def nan_check_hook(grad):
    if torch.isnan(grad).any():
        print(f"[HOOK] NaN detected! Shape: {grad.shape}")
        breakpoint()  # 当场抓现行
    return grad
```

`DebugFunction.apply` 在关键位置**主动检测**，而 hook 在**任意被调用者无法修改的地方**做被动监控——两者形成"主动防御 + 被动监测"的双保险。

## 3. 组合模式总结

```
                    ┌─────────────────────────┐
                    │   autograd.Function      │
                    │   ┌────────┬────────┐    │
  input ──────────►│   │ forward│        │    │───► output
                    │   │   ctx  │        │    │
  forward_hook ────│───┤(before)│(after) │────│─── forward_hook
                    │   └────────┘        │    │
                    │         ▲           │    │
  backward_hook ◄───│─────────┤ backward  │◄───│── backward_hook
                    │         └───────────┘    │
                    └─────────────────────────┘
```

| 组合模式 | 核心价值 |
|----------|----------|
| `Function` 定义逻辑 + `forward_hook` 监控输入输出 | 验证自定义算子的数值正确性 |
| `Function` 定义逻辑 + `backward_hook` 监控梯度 | 检测梯度爆炸/消失、NaN 来源定位 |
| `Function` 自定义梯度 + `tensor.register_hook` | GRL 后的梯度监控、STE 后的量化误差分析 |
| `Function` 重计算 + `backward_hook` | Checkpointing 中验证重计算精度 |

---

## 4. 一句话总结

> **`autograd.Function` 让你"改写规则"，hook 让你"观察和微调执行过程"**——前者控制计算图的**语义**（前向算什么、反向传什么梯度），后者提供在不修改算子源码的前提下**插入横切关注点**（日志、监控、裁剪、保存）的能力。两者结合，你几乎可以任意操控 PyTorch 的自动求导系统。

在 Tensor Parallelism（TP）中，这个组合几乎是**实现通信原语、调试分布式梯度、以及性能优化的标配**。下面从 TP 的三个核心通信阶段拆解。

---

## 1. TP 中的三处关键通信 → 都需要 `autograd.Function`

Megatron-LM 等框架把 TP 拆成三个通信原语，每个都是自定义 `autograd.Function`：

```
ColumnParallelLinear:            RowParallelLinear:
                               
  X ──→ [f] ──→ all-gather       X ──→ [f] ──→ [g] ──→ reduce-scatter
              │   (不通信)                        │   (不通信)
              ▼                                   ▼
              Y                                  Y
```

| 通信点 | 方向 | 实现方式 |
|--------|------|----------|
| `f` — 列并行 forward | `all-gather` | `autograd.Function`：forward 做 all-gather，backward 做 reduce-scatter |
| `g` — 行并行 forward | identity (切分) | `autograd.Function`：forward 恒等，backward 做 all-reduce |
| `f⁻¹` — 列并行 backward 的梯度 | `all-reduce` | `autograd.Function`：forward 恒等，backward 做 all-reduce |

---

## 2. 核心实现：三个 `autograd.Function`

### 2.1 `_CopyToModelParallelRegion`（行并行 forward → g）

```python
class _CopyToModelParallelRegion(torch.autograd.Function):
    """Forward: 恒等映射（输入已经在各 rank 上）
       Backward: 对梯度做 all-reduce，使每个 rank 拿到完整梯度"""
  
    @staticmethod
    def forward(ctx, x):
        return x   # 不通信，直接返回

    @staticmethod
    def backward(ctx, grad_output):
        # 核心：反向时同步梯度
        torch.distributed.all_reduce(grad_output, group=mpu.get_tensor_model_parallel_group())
        return grad_output
```

### 2.2 `_ReduceFromModelParallelRegion`（列并行 backward → f⁻¹）

```python
class _ReduceFromModelParallelRegion(torch.autograd.Function):
    """Forward: 恒等
       Backward: reduce-scatter / all-reduce 梯度"""
  
    @staticmethod
    def forward(ctx, x):
        return x

    @staticmethod
    def backward(ctx, grad_output):
        torch.distributed.all_reduce(grad_output, group=mpu.get_tensor_model_parallel_group())
        return grad_output
```

### 2.3 `_GatherFromModelParallelRegion`（列并行 forward → f）

```python
class _GatherFromModelParallelRegion(torch.autograd.Function):
    """Forward: all-gather 拼接各 rank 的激活
       Backward: 只取属于自己 rank 的那部分梯度（reduce-scatter）"""
  
    @staticmethod
    def forward(ctx, x, group):
        ctx.group = group
        world_size = dist.get_world_size(group)
        output_list = [torch.empty_like(x) for _ in range(world_size)]
        dist.all_gather(output_list, x, group=group)
        return torch.cat(output_list, dim=-1)  # 沿最后一维拼接

    @staticmethod
    def backward(ctx, grad_output):
        # 从完整梯度中切出自己负责的那一段
        rank = dist.get_rank(ctx.group)
        world_size = dist.get_world_size(ctx.group)
        chunk_size = grad_output.shape[-1] // world_size
        return grad_output[..., rank*chunk_size : (rank+1)*chunk_size], None
```

## 3. Hooks 在 TP 中的 5 个实战用法

有了上述三个 `Function`，hooks 可以做这些**不侵入通信逻辑**的事情：

### 3.1 验证梯度同步正确性（最重要！）

TP 最隐蔽的 bug 是：某 rank 的梯度没正确 all-reduce，导致模型悄悄发散。

```python
def make_sync_verify_hook(param_name, group):
    """在 all-reduce 后的参数上挂 hook，验证所有 rank 梯度一致"""
    def hook(grad):
        # 广播 rank 0 的梯度范数，所有 rank 对比
        norm = grad.norm().detach()
        norm_list = [torch.zeros_like(norm) for _ in range(dist.get_world_size(group))]
        dist.all_gather(norm_list, norm, group=group)
      
        ref = norm_list[0]
        for i, n in enumerate(norm_list):
            if not torch.allclose(ref, n, rtol=1e-5):
                print(f"[RANK {dist.get_rank()}] Gradient mismatch for {param_name}: "
                      f"rank 0={ref:.6f}, rank {i}={n:.6f}")
        return grad
    return hook

# 挂到 column parallel 的 weight 上
for name, param in col_parallel_layer.named_parameters():
    if 'weight' in name:
        param.register_hook(make_sync_verify_hook(name, tp_group))
```

### 3.2 通信量分析 / Profiling

在不修改通信代码的前提下，精确统计每个 `Function` 的前向/反向通信量：

```python
comm_stats = {}

def make_comm_hook(op_name, group):
    def forward_hook(module, input, output):
        sz = output.numel() * output.element_size()
        world_size = dist.get_world_size(group)
        comm_stats.setdefault(op_name, {"fwd_bytes": 0, "bwd_bytes": 0})
        comm_stats[op_name]["fwd_bytes"] += sz * (world_size - 1)  # all-gather 流量
  
    def backward_hook(module, grad_input, grad_output):
        sz = grad_output[0].numel() * grad_output[0].element_size()
        world_size = dist.get_world_size(group)
        comm_stats[op_name]["bwd_bytes"] += sz * 2 * (world_size - 1)  # all-reduce 流量
  
    return forward_hook, backward_hook

fw_hook, bw_hook = make_comm_hook("col_parallel", tp_group)
module.register_forward_hook(fw_hook)
module.register_full_backward_hook(bw_hook)  # PyTorch 2.0+
```

训练结束后就能看到：`{"col_parallel": {"fwd_bytes": 128MB, "bwd_bytes": 256MB}}`。

### 3.3 通信-计算重叠验证

当你用 `autograd.Function` 实现了异步通信（比如 `all_reduce` 放在 `backward` 里异步发起），hook 可以验证重叠是否生效：

```python
class AsyncAllReduce(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, group):
        ctx.group = group
        return x

    @staticmethod
    def backward(ctx, grad_output):
        # 异步 all-reduce：返回一个 Future-like handle
        handle = dist.all_reduce(grad_output, group=ctx.group, async_op=True)
        ctx.handle = handle
        return grad_output  # 此时 communication 还在后台进行

# --- Hook 验证 ---
timeline = []

def fw_hook(module, input, output):
    timeline.append(("fw_end", time.time()))

def bw_hook(module, grad_input, grad_output):
    timeline.append(("bw_after_allreduce", time.time()))
    # 此时 handle.wait() 应该已经完成，或耗时极短
```

### 3.4 异常检测：TP 通信前的 NaN 筛查

在 `all_reduce` 之前如果某 rank 已经 NaN，它会把所有 rank 的梯度都污染——在 `_ReduceFromModelParallelRegion.backward` 之前加 hook：

```python
def sanitize_before_allreduce(grad):
    """在进入 all-reduce 之前检测并修复"""
    if torch.isnan(grad).any() or torch.isinf(grad).any():
        print(f"[RANK {dist.get_rank()}] NaN detected BEFORE all-reduce! "
              f"NaN count: {torch.isnan(grad).sum()}")
        # 可选：替换为 0 避免污染其他 rank
        grad = torch.nan_to_num(grad, nan=0.0, posinf=65504, neginf=-65504)
    return grad

# 在进入 _ReduceFromModelParallelRegion 之前挂 hook
activation.register_hook(sanitize_before_allreduce)
```

## 4. 完整 TP Layer 示例：Function + Hook 合体

```python
class ColumnParallelLinear(nn.Module):
    def __init__(self, in_features, out_features, tp_group):
        super().__init__()
        world_size = dist.get_world_size(tp_group)
        self.out_features_per_rank = out_features // world_size
        self.weight = nn.Parameter(torch.randn(self.out_features_per_rank, in_features))
        self.tp_group = tp_group
  
    def forward(self, x):
        # 1. 本地计算
        y_local = F.linear(x, self.weight)
        # 2. all-gather (autograd.Function)
        y = _GatherFromModelParallelRegion.apply(y_local, self.tp_group)
        # 3. 挂 hook 监控通信后的结果
        if self.training:
            y.register_hook(lambda g: print(
                f"ColumnParallel grad norm: {g.norm().item():.4f}"))
        return y
```

## 5. 总结

| TP 需求 | `autograd.Function` 实现 | Hook 增强 |
|---------|--------------------------|-----------|
| **通信原语** | `all_gather` / `all_reduce` / `reduce_scatter` 的正反向 | 监控通信量、延迟、正确性 |
| **梯度同步** | backward 中自动触发 collective | 验证 all-reduce 后各 rank 梯度一致 |
| **异步通信** | 在 Function 内使用 `async_op=True` | 验证重叠率、检查 handle 状态 |
| **NaN 隔离** | — | 在 all-reduce **之前**用 hook 拦截，防止单 rank 污染全局 |
| **调试分布式死锁** | — | Hook 日志标记每个 rank 的执行轨迹，发现哪一步开始不一致 |

> **核心洞察**：在 TP 中，`autograd.Function` 负责**实现通信语义**（这是图的骨架），而 hook 提供**零侵入的观察窗口**（这是调试和验证的视网膜）。两者结合，你可以在不改动模型代码的前提下，获得分布式训练的完整可观测性。
