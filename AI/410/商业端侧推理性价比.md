## 一句话结论

**没有一个"绝对冠军"，但如果把"大规模商业化推理"理解为高并发、稳态流量、成本敏感的生产负载，那么 \$/token 的排名大致是：**

$$ \text{自建 NVIDIA GPU} \;\approx\; \text{TPU(GCP 内)} \;>\; \text{Cerebras} \;>\; \text{Groq} $$

**而按"单位延迟的性价比"（tok/s/user）排名则完全反过来：Groq / Cerebras 吊打 GPU 和 TPU。**

Groq 和 Cerebras 卖的是**延迟溢价**，不是 \$/token 冠军。把它们和 NVGPU/TPU 放在同一个"性价比"榜上比较，本身就是错位竞争。

---

## 一、先看决定成本的那个物理量

商业推理的成本大头是 **decode（逐 token 生成）**，而 decode 是**访存带宽瓶颈**，不是算力瓶颈：

$$\text{tok/s} \approx \frac{\text{BW} \cdot B}{W + B \cdot k}$$

- $W$ = 权重字节数，$k$ = 每 token 的 KV 字节数，$B$ = batch size
- $B$ 很小时，分母被 $W$ 主导 → **算力再强也没用**
- $B$ 很大时，吞吐趋近于 $\text{BW}/k$ → **完全由带宽决定**

单位成本约等于：

$$\frac{\$/\text{M tokens}} \;\approx\; \frac{(\$/\text{hr}) \times 10^6}{3600 \times \text{tok/s}}$$

所以大规模商业推理真正比拼的是两个数：**每美元买到的 HBM 带宽**，和**每美元买到的 HBM 容量**（后者决定 KV cache 能塞多少并发）。

<details>
<summary>四家硬件关键参数（量级，具体规格请以官网为准）</summary>

| | 片上/片外内存 | 带宽 | 算力 | 定位 |
|---|---|---|---|---|
| **Groq LPU** | ~230 MB SRAM | ~80 TB/s 片上 | ~750 TOPS INT8 | 纯 SRAM，无 HBM |
| **Cerebras WSE-3** | 44 GB SRAM | ~21 PB/s 片上 | ~125 PFLOPS FP16 | 晶圆级，无 HBM |
| **TPU v5e / v6e** | 16 / 32 GB HBM | ~0.82 / ~1.6 TB/s | 197 TOPS int8 / 4.7× | 高算力/美元 |
| **TPU v7 (Ironwood)** | 192 GB HBM | ~7.4 TB/s | 大幅提升 | 对标 B200 |
| **H100 / H200** | 80 / 141 GB HBM | 3.35 / 4.8 TB/s | ~990 / ~990 TFLOPS | 通用主力 |
| **B200 / GB200 NVL72** | 192 GB / 13.4 TB(整柜) | ~8 TB/s / 柜级 | FP4 支持 | MoE 大模型最优 |

</details>

**最刺眼的一组对比：H100 有 80 GB HBM，Groq 单芯片只有 0.23 GB SRAM —— 差 ~350 倍。** 这就是整个故事的答案。

## 二、为什么 Groq / Cerebras 不是性价比冠军

### 1. 容量决定芯片数量，芯片数量决定成本

Llama-70B 的 bf16 权重约 140 GB：

- **1 张 H200** 装得下（141 GB，刚好）
- **Groq 需要 ~600 颗芯片**（Meta/Groq 早期部署 Llama2-70B 用了 576 颗）
- Cerebras 需要多张 wafer 做 weight streaming

即使单芯片成本很低，**600 倍的数量差距**在 \$/token 上是无法靠 SRAM 带宽优势补回来的。

### 2. MoE 时代对 SRAM 芯片是结构性打击

DeepSeek-V3/R1（671B）、Llama-4、Qwen3-MoE 这类主流前沿模型：

- **全部专家权重必须常驻**（或高速流式加载），体量 400–700 GB
- 纯 SRAM 方案装不下 → 必须依赖片外存储 → **SRAM 芯片赖以生存的带宽优势直接归零**
- 而 8×H200 = 1.1 TB、GB200 NVL72 = 13.4 TB HBM，天然适配 MoE 的稀疏激活

**趋势非常明确：模型越大、越 MoE 化、KV cache 越长，越利好 HBM 路线（NVIDIA / TPU / AMD）。**

### 3. 它们的真实优势：单流延迟

| | 单流输出速度 | 并发下的定位 |
|---|---|---|
| H200（常规部署） | ~50–100 tok/s/user | 稳态吞吐最优 |
| TPU | 类似 GPU | 稳态吞吐最优 |
| **Groq** | ~250–400 tok/s/user | 极致低延迟 |
| **Cerebras** | 1000–2000+ tok/s/user | 极致低延迟 |

如果你的业务是**实时语音助手 / Agent 高频工具调用 / 交互式代码补全**，延迟直接换算成产品体验和留存，那 Groq/Cerebras 的"贵"是买得到的溢价。但那是**延迟性价比**，不是 \$/token 性价比。

## 三、TPU vs NVGPU：谁更便宜？

这取决于瓶颈落在哪一侧：

- **Decode 为主（商业推理的常态）→ 带宽瓶颈 → NVIDIA 胜。**
  H100/H200/B200 的"TB/s per \$/hr"通常优于同价位 TPU。TPU 的强项是**算力/美元**，不是带宽/美元。
- **Prefill 为主 / 超长上下文 / 计算密集 → TPU 胜**，TOPS 和 int8/bf16 效率高。
- **如果你就是 Google 内部的量级**，TPU 是唯一答案——自研芯片省掉了 NVIDIA 的毛利，加上 XLA 与自家 serving 栈的深度优化（Gemini 就是这么跑的）。

**但外购租用 TPU 时，性价比优势会大幅收窄**：你要接受静态 shape、重编译开销、vLLM-on-TPU 等生态成熟度问题，以及只此一家（GCP）的锁定。

## 四、\$/M tokens 量级估算（供建立直觉）

<details>
<summary>70B 模型、FP8、高 batch 的粗算</summary>

H200，4.8 TB/s，FP8 权重 ~70 GB，$k \approx 0.33$ MB/token：

- $B=128$ 时：$4800 \times 128 / (70 + 42) \approx 5{,}500$ tok/s（理论），实际取 ~2,000 tok/s
- $\$3.5/\text{hr}$ → $\frac{3.5 \times 10^6}{3600 \times 2000} \approx \$0.49/\text{M}$

对比公开 API 价：Groq Llama-70B ≈ \$0.59/M，Cerebras ≈ \$0.65/M。

**结论：在 70B 这个尺寸上，自建 GPU 的 \$/token 与专用芯片 API 价基本同档，甚至更低。** 专用芯片的价格里包含了延迟溢价和对冲流量波动的成本。

8B 级别则各家都压到 \$0.05–0.15/M 区间，差异被压缩，届时**延迟和可用性**才是竞争维度。

</details>

## 五、按场景的选择表

| 场景 | 最优解 | 理由 |
|---|---|---|
| 高并发、稳态、成本敏感（推荐/搜索/批量） | **自建 H200/B200 集群** | 高 batch 下的 \$/token 最优，量化+PD 分离榨干吞吐 |
| 已在 GCP、大流量、计算密集 | **TPU v6e / Ironwood** | 算力/\$ 高，纵向整合省成本 |
| 前沿 MoE 大模型 | **GB200 NVL72 / 多卡 HBM** | 只有 HBM 容量装得下权重+长 KV |
| 实时语音/Agent 工具调用，延迟即体验 | **Groq** | 单流 300+ tok/s，无可替代 |
| 极致单流速度、中小 Dense 模型 | **Cerebras** | 1000+ tok/s，小模型 \$/token 极低 |
| 需要灵活性/量化/自定义算子 | **NVIDIA** | CUDA 生态是最大的隐性性价比 |

## 六、被低估的一点：真正的性价比来自软件，不来自芯片

大规模商业化推理里，**同一张 H100，不同 serving 栈的有效吞吐能差 3–5 倍**：

- 连续批处理（continuous batching）
- PD 分离（prefill/decode disaggregation）
- FP8 / NVFP4 量化、KV cache 量化
- Prefix caching / KV 复用（对 Agent、多轮对话收益巨大）
- 投机解码、chunked prefill

**这就是 NVIDIA 最深的护城河**：不是因为单芯片最便宜，而是因为你能把它的有效吞吐压榨到最高。Groq/Cerebras 的编译器虽好，但那是"厂商替你做优化"，你无法像在 CUDA 上那样针对自己的流量形态挖潜力。

---

## 最终判断

1. **纯 \$/token、大规模、稳态** → **NVIDIA GPU（自建）或 TPU（GCP 内）**，二者量级相近，NVIDIA 胜在带宽/\$ 与灵活性，TPU 胜在算力/\$ 与纵向整合。
2. **延迟敏感型产品** → **Groq / Cerebras**，但这是另一条价值曲线，不该用"性价比"这个词来比。
3. **模型越 MoE、上下文越长，SRAM 路线越吃亏。** 这是未来 2–3 年最重要的结构性趋势。

> 一句话决策：**先问你的约束是"每百万 token 多少钱"还是"每个用户每秒多少 token"。** 前者选 GPU/TPU，后者选 Groq/Cerebras——这两个问题没有共同答案。
