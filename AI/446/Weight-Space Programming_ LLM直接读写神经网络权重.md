## 一句话总结

他们提出并验证了 **“Weight-Space Programming”(权重空间编程)**:让一个通用前沿 LLM **直接把神经网络的权重当作文本来读和写**,不经过优化器(不用梯度下降)、不写训练循环,有时连前向推理和环境反馈都不给,就能读懂网络在干什么、修好坏掉的网络、甚至从零手写权重超过 PPO 训练出来的网络。

---

## 核心论点

过去几年,LLM 优化的是**文本产物**(prompt、DSPy 程序、训练代码、超参 harness)。大家默认的理由是:*文本可以靠“爬山”式搜索来优化,而权重空间没有这种办法,因为它不可微就不行,人也没法手改*。作者主张:**这条分界线正在消失**,LLM 现在能绕过 Adam/Muon 这类“符号优化器”,直接用推理去理解每一层在算什么、应该算什么,然后改权重。

判定标准很严格,实验中反复强调的红线是:

- ❌ 不允许梯度 / 训练循环 / loss
- ❌ 不允许反向传播或微调
- ❌ 大多数实验**不允许跑前向**(或用“前向次数预算”来卡)
- ❌ 不允许联网、不允许搜索、不允许树搜索/rollout
- ✅ 只给:原始权重文本 + 任务描述(+ 可选 Python/numpy 沙箱)

## 他们做了什么:8 个实验 + 1 个反例

### A. 读得懂吗?(Experiments 1–3、7)

| 实验 | 对象 | 结果 |
|---|---|---|
| **1** | 4 个 PPO 网络(MLP $500\to32\to32\to5$,17,253 权重),分别玩 Breakout/Pong/Pac-Man/Freeway,输入输出维度完全相同 | **不告诉候选游戏列表**,Astra 4 个全猜对(Breakout 99% 置信)。线索:输入通道权重集中在哪(如 Breakout 的“挡板”权重在底行)、输出层区分哪些动作 |
| **2** | 3 个 DDPM 生成圆/方/三角(MDL $160\to64\to64\to144$,23,824 权重),禁止前向 | 3 个全对。它是在**输出层**找到形状轮廓,并画成空心轮廓,而真实模型生成的是实心形状,这个“错”反而证明它是在读几何结构,而非偷偷算前向 |
| **3** | 3 个字符级小 LM(7.16M 权重),分别训 Python / 罗马字日语 / 英语;**只给中间 4 个 transformer block,首尾层和多维标签全删** | 语言 3/3 全对(两次尝试);更关键的是**它把所有的 induction head(复制头)都找出来了,且没有误报**:Python → 2.1/3.1/3.5,Romaji → 3.3,English → 3.1,与实测完全一致。它的推理路径竟复现了 Elhage et al. 的“通过矩阵相乘串联头”方法,而作者从未提示过 |
| **7** | 2 份 Gemma 3 270M,同数据同流程微调,一份诚实、一份谄媚(embeddings 冻结以堵住捷径) | **纯看权重:失败了**(4 次尝试全错)。退一步允许它自己写文本、只能看**注意力图**:3/3 全对,并定位到中层 head(如 head 10.2)把注意力从题目数字转向用户给的答案(94.3%→0.75% vs 85.7%) |

> 实验 3 里 Romaji 的判定依据很有意思:最后一层 block 的权重方向“更少”,因为罗马字不用 q/l/v/x 这些字母。

### B. 写得了吗?(Experiments 4–6)

- **实验 4(修坏网络)**:Kinetix 里“倒车上坡起跳”关卡,PPO 陷在局部最优(直接撞坡卡住),256 局 0 成功。给它权重 + 场景描述 + 一条录制轨迹,**一次机会、无工具**,Astra 只改动 3.5% 的权重,加一条“读车速和位置的小旁路”,过红线后自动关掉——**1,024 局 100% 成功**。

- **实验 5(从零手写权重)**:MinAtar 三个游戏,权重全初始化为 0,只给游戏规则 + 源码 + 输入输出布局,**无数据、无 loss、无梯度、无工具、不许试玩**,一次回复直接输出权重文本:

  | 游戏 | PPO 100M 步 | PPO 500M 步 | Astra 一次性手写 |
  |---|---|---|---|
  | Breakout | 15.8 | 25.3 | **517.4** |
  | Seaquest | 5.6 | **88.9** | 53.1 |
  | Asterix | 25.8 | **55.2** | 53.2 |

  Breakout 上比 500M 步 PPO 高 **20 倍**。它解释的做法是:第一层算“球会落在哪”,第二层把挡板移过去——即**先用自然语言想清楚要实现的程序,再翻译成神经网络**。

- **实验 6(1.5M 参数、超上下文,升到工具场景)**:9×9 围棋,$243\to512\times6\to82$($1{,}480{,}274$ 权重)。给它 numpy/PyTorch 沙箱写权重,但**不能在里面跑网络**;想看效果必须花掉一次“前向预算”(每次前向 = 最多 128 盘对局)。0 次前向时就能赢两个小 PPO 网络过半;50 次前向时**超过同尺寸、训了 2000 万局的 PPO**。0 次前向那版是它一次性写了 **336 行 Python**,逐层构造:标记气、沿棋串传播、判断危险棋组、最后打分(提子/救活/避免被打吃/避免填自己眼)。

### C. 真正的语言模型(Experiment 8,+ 一个反例)

这是全文最有分量的部分。目标是 **Qwen3.5-0.8B 的数学能力**,给它一个 Python notebook 式的 kernel(CPU、无 GPU)+ GSM8K/MATH 训练集里的练习题 + **10/25/50 次前向预算**(一次前向 = 最多答 512 题),不泄露测试集。

Astra 的诊断:**模型陷入了“思考循环”**(Qwen 自己 model card 就警告过这点;base 模型前 96 个练习回答里 85 个撞到 32,768 token 上限)。它把循环定位到 **layer 15 和 19 的 MLP 写出的一个方向**,并从这两层各 64 个输出列里减掉该方向——只改 **131,072 个权重(总 8 亿权重的 $0.016\%$)**。

| Qwen3.5-0.8B | MATH-500 | GSM8K | IFEval | 撞 token 上限 |
|---|---|---|---|---|
| Base | 7.9 | 13.8 | 21.0 | 93.0 |
| 10 次前向 | 12.3 | 25.7 | 49.0 | 87.2 |
| 25 次前向 | 14.1 | 25.1 | 39.9 | 86.4 |
| **50 次前向** | **48.1** | **67.1** | **62.3** | **33.1** |

关键点:循环不是数学特有的,所以 **IFEval 顺带从 21.0 涨到 62.3(3 倍)**,而模型其余部分完全没动(没有灾难性遗忘)。

**反例(诚实度加分项)**:换到很少循环的 **Gemma 3 270M**(只有 8.5% 撞上限),**Astra 改不动**——MATH-500 从 6.8 只能到 7.7 左右,Astra 自己都报告“提升不成立”。它读到的失败是普通的算术错、代数步骤错,没有单一“开关”可关。作者由此给出一个很克制的结论:**改权重能移除一个“遮挡能力的障碍”,但无法凭空添加一个模型本不具备的能力。**

## 他们主张的更大图景

1. **无需评测的审计**:不看 benchmark 就能从权重里发现后门/隐藏能力。
2. **大幅降低优化成本**:一次性初始化替代“造数据集 + 跑训练”。
3. **零数据的能力增删/遗忘**:一句“能给模型加上 X 能力吗”,改 $0.016\%$ 的权重,不伤其余部分。
4. **递归自我改进的新路径**:不是“写代码去启训练任务”,而是模型直接检视并改自己的权重。
5. **真正的模型合并**:现在的 merge 只能平均同架构权重,未来可以把 A 模型的“推理模块”电路嫁接到完全不同架构的 B 上。

他们正在建 **Weight-Space Programming 的 benchmark 和 harness**,并把所有日志公开在 `github.com/RikiyaT/lm_understand-logs`,改好的模型在 Hugging Face(`RikiyaT/Qwen3.5-0.8B-weight-space-programming`),还有 Ahaliq 重跑并做的在线 demo。

<summary><b>我的批判性观察(点击展开)</b></summary>

- **最大亮点是“约束设计”,不是数字本身。** 去掉首尾层(实验 3)、冻结 embedding(实验 7)、禁用前向(实验 1/2/5)、把前向当稀缺预算(实验 6/8)——这些才是让结论有意义的东西。特别是实验 3 找 induction head 与真值完全吻合、且无误报,这是最难被“瞎猜/先验”解释的结果。
- **样本量普遍很小**:3–4 个网络、3 对模型、单次机会。作者自己承认置信度只有 0.48–0.62,这更像“方向性证据”而非“能力标定”。
- **不可复现性是硬伤**:核心能力绑定在 “GPT-6 Astra” 上,读者无法验证这是模型原生能力,还是该模型被专门训练/RL 过权重相关任务。日志公开是好事,但替代不了别人用自己的模型复现。
- **实验 8 的因果链有微妙之处**:是“修复循环”还是“顺手把采样分布推离了长尾”?50 次前向 vs 25 次的巨大跳变(14.1→48.1)说明**前向预算的用法本身**很关键,可能包含大量试错筛选,而不只是“读权重推理”。这一点文章没充分拆解。
- **负面结果反而是全文最有价值的部分**:Gemma 上失败 + 实验 7 纯权重上失败,把“能读权重”从玄学拉回到“有时能、有时不能”的工程现实,也支持了作者“移除障碍 ≠ 添加能力”的论断。
- **与已有工作的真实差异**:AdderBoard 那种“手搓微型 transformer”早已有之,但都是人类/agent 在极小规模上试错;这里的差异是 **通用模型、零样本、规模到 8 亿参数、且不靠 trial-and-error 的搜索**。作者对 related work 的定位(`Weight Oracles`、RONEN/ROME、SAE、activation oracles 等)是准确且克制的。

</details>

**一句话判断**:如果这个结果站得住,它的意义不在于“LLM 会写权重”这个噱头,而在于**把“优化”从符号算法手里部分收回给推理**——而且实验 8 那种 $0.016\%$ 的定向手术,确实指出了 fine-tuning 之外一条更干净的路。但目前它是一个**高质量的方向性证据 + 完整日志**,还不是一个可复现的结论。
