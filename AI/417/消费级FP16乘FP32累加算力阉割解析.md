# 消费级FP16乘FP32累加算力阉割解析

## 🧑‍💻 User

消费级fp16mmfp32acc是不是算力阉割了

---
## 😀 默认助手 (7)

## 先说结论

**不是。** FP16 乘法 + FP32 累加的矩阵乘(Tensor Core 上的 `mma` / GEMM)在消费级卡上并没有被单独降速——**消费卡官方标的那个 "FP16 TFLOPS" 本身就是 FP32 累加的数值**(V100 的 125、A100 的 312、H100 的 989、4090 的 ~330 都是 FP32 accumulate)。

真正容易被误读成"阉割"的是下面三件事,它们都不是"FP32acc 被砍了一半"。

### 三个常见的误读来源

| 现象 | 实际情况 |
|---|---|
| 规格里的 `*` 号(如 4090 的 330→660、H100 的 989→1979) | 那是 **2:4 结构化稀疏**的 2×,不是累加精度档位。不走稀疏路径就只能拿到前半段 |
| 数据中心卡规格表里多出来的"FP16 accumulate"档 | T4 之后的数据中心产品资料里,FP16 那一行常带脚注区分 `FP32 accumulate` / `FP16 accumulate`,后者最高能到 $2\times$。**消费卡规格表基本不提供/不宣传这一档**——所以准确的说法是"消费卡少了这条便宜的快通道",而不是"FP32 累加被打折" |
| 拿 4090 和 H100/B200 比绝对值 | 那是产品定位差异(每个 SM 的张量吞吐、SM 数量、功耗墙、显存带宽)。按每 SM 每时钟算,Ada 消费卡的 FP16 张量吞吐大约只有 Hopper 的 $1/4$ 量级,但**它对自己是满血的** |

> 注:上表第二条依据的是 NVIDIA 数据中心产品的公开规格(带脚注的版本),具体数值请以你手上那张卡的 whitepaper/datasheet 脚注为准;我没法在这里替你查证每一代的确切数字。

### 消费级真正被砍的东西

- **FP64**:常年 $1/32 \sim 1/64$,Ada/Blackwell 消费卡基本等于没有(数据中心卡有 FP64 张量通道)。
- **Pascal 时代的 FP16 计算**:GP104/GP102 的 FP16 是 $1/64$(GTX 1080 Ti 只有 0.18 TFLOPS),而 GP100 是满速——这才是历史上最典型的"消费级 FP16 阉割",和现在的 Tensor Core FP16 是两回事。
- **NVLink、MIG、ECC、显存容量/带宽**。
- **特供卡的算力限制**:H20/L20 这类才是真正意义上的"算力阉割"(H20 的 FP16 只有 H100 的约 $1/6$,但 FP8/带宽给得高),那是出口管制口径,不是消费级的概念。

### 如果你实测只跑出标称的一半,先查这几条

1. 标称是否含稀疏(`*` 号),你的 kernel 有没有走稀疏路径;
2. 是否达到了标称 boost 频率(消费卡功耗墙下持续频率通常低于 boost);
3. 对齐与 tile:`K%8`(FP16)不整除、M/N 太小导致的 tile/wave quantization;
4. 框架路径:AMP/`torch.backends.cuda.matmul.allow_fp16_reduced_precision_reduction` 之类只改归约精度,不加吞吐;
5. 用 `cublasLt` 分别跑 `CUBLAS_COMPUTE_32F` 与 `CUBLAS_COMPUTE_16F` 对比一下,就能确认你这张卡上"FP16 累加"到底有没有加成。
