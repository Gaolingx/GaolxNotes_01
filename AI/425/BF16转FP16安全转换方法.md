## 😀 默认助手 (7)

## 先纠正一个前提

你担心的“截断”其实来自两个不同的问题，分清它们才能确定方案：

- **精度**：bf16 的尾数是 8 bit（1 个隐含位加 7 个显式位），fp16 的尾数是 11 bit（1+10）。因此 fp16 的精度更高，而不是更低。对于 fp16 正规数范围内的任何 bf16 值（$2^{-14} \le |x| \le 2^{16}$），转换都是**逐位精确**的，不存在尾数截断。
- **范围**：这才是真正的风险。bf16 的指数有 8 bit，范围大约到 $3\times10^{38}$；fp16 的指数只有 5 bit，最大值是 65504，最小值是 $2^{-14}$（正规数）。所以会出现：
  - $|x| > 65504$ 时，结果变成 `inf`（`inf - inf` 或 $0 \times \inf$ 之后就是 NaN，而且经常会**静默传播**，被 mask 掩盖）
  - $|x| < 2^{-14}$ 时，结果变成次正规数并逐步丢失有效位；$|x| < 2^{-24}$ 时直接变成 0

另外，PyTorch 的 `.to(torch.float16)` 是 round-to-nearest-even，不是截断。因此问题的本质是溢出或下溢，而不是舍入。

---

## Step 0：先诊断，不要盲目转换

绝大多数正常训练出来的 bf16 **权重**都在 $O(1)$ 量级，`absmax` 远小于 65504，直接 cast 就是无损的。真正出问题的往往是少数几个 tensor，所以先扫一遍：

```python
import math, torch
from pathlib import Path
from safetensors import safe_open

FP16_MAX = 65504.0
FP16_MIN_NORMAL = 2.0**-14      # 6.1e-5
FP16_MIN_SUB    = 2.0**-24      # 5.96e-8

def scan(model_dir):
    for shard in sorted(Path(model_dir).glob("*.safetensors")):
        with safe_open(shard, framework="pt", device="cpu") as f:
            for name in f.keys():
                t = f.get_tensor(name)
                if t.dtype != torch.bfloat16:
                    continue
                x = t.float()
                absmax = x.abs().max().item()
                nz = x[x != 0].abs()
                if nz.numel() == 0:
                    continue
                absmin = nz.min().item()
                n_ovf  = int((x.abs() > FP16_MAX).sum())
                n_zero = int((nz < FP16_MIN_SUB).sum())
                n_sub  = int((nz < FP16_MIN_NORMAL).sum())
                if n_ovf or n_zero or n_sub or absmax > 1e4:
                    print(f"{name:70s} absmax={absmax:12.5g} absmin={absmin:12.5g} "
                          f"OVF={n_ovf} sub={n_sub} ->0={n_zero}")
```

判读方式：

| 扫描结果 | 处理 |
|---|---|
| 全部 `OVF=0`，且 `absmax < 6e4` | 直接 cast，无损，收工 |
| 少量 tensor 有 OVF | 进行缩放（见下面 A 或 B） |
| 有 `->0` | 权重下溢，通常无害；除非该层对精度极敏感，否则可以忽略 |
| 源里本来是 `inf/nan` | 先查上游问题，转换只会把问题放大 |

## Step 1：三种可行方案（按推荐度）

### 方案 A（首选）：分 per-tensor 的 2 的幂缩放，在 checkpoint 里折叠进相邻 tensor

核心思路：把 $|x|>65504$ 的 tensor 除以 $s$（取 2 的幂，保证**精确**），同时把 $s$ 吸收进前一个算子，这样推理时**不需要改任何加载代码**，数学上恒等。

以 Linear 为例，目标是保持 $y = xW^\top + b$ 不变：

$$x' = s\cdot x,\qquad W' = W/s \quad\Rightarrow\quad x'W'^\top = xW^\top$$

而 $x$ 来自前一个 LayerNorm/RMSNorm，所以令 $\gamma' = s\cdot\gamma$ 即可。对 Llama 类结构就是：

- `q_proj / k_proj / v_proj` 要缩放时，就把同一层的 `input_layernorm.weight` 乘以 $s$
- `gate_proj / up_proj` 要缩放时，就把 `post_attention_layernorm.weight` 乘以 $s$
- `down_proj`、`o_proj` 不能单独缩放（它们的输出进入残差），需要走方案 B

```python
def convert_tensor(x, target=2.0**15):
    """bf16 -> fp16，必要时除以 2 的幂，返回 (tensor, scale)"""
    xf = x.float()
    absmax = xf.abs().max().item()
    if not math.isfinite(absmax):
        raise ValueError("source contains inf/nan")
    if absmax <= target:                       # target=32768，留足 headroom
        return xf.to(torch.float16), 1.0
    s = 2.0 ** math.ceil(math.log2(absmax / target))
    return (xf / s).to(torch.float16), s       # 除 2 的幂，指数平移，零误差
```

**优点**：加载侧无需改动，round-trip 逐位精确。

**必须检查的副作用**：$\gamma \cdot s$ 以及激活 $x\cdot s$ 自己会不会溢出到 fp16 之外，以及 $\gamma$ 缩放后精度是否够。如果某层激活极值本身接近 1e4，$s$ 又很大，这个折叠就会反过来导致问题；这种情况下，建议对那一层改用方案 B。

### 方案 B：侧挂 scale 元数据，加载后在 fp32 里还原

不折叠，而是把 scale 存成 sidecar，加载时在 fp32 里 `w * s`，再转回 fp16 用于计算：

```python
def convert_state_dict(sd, target=2.0**15):
    out, scales = {}, {}
    for k, v in sd.items():
        if not v.is_floating_point() or v.dtype != torch.bfloat16:
            out[k] = v
            continue
        t, s = convert_tensor(v, target)
        out[k] = t
        if s != 1.0:
            scales[k] = s
    return out, scales
```

注意坑：**不能在 fp16 里乘回去**（会再次溢出）。只能在 fp32 里反量化，或者让 kernel 在累积时带上 scale。所以这招只在你能改推理代码时可行，比如自己写加载器，或在 fused kernel 里传入 scale。

### 方案 C：混合存放或 clamp

- 混合存放：让溢出那几个 tensor 保持 bf16，其余用 fp16，前提是运行时允许逐层 dtype 混用；大多数 kernel 要求 matmul 两侧 dtype 一致，实际上很难支持。
- `clamp(-65504, 65504)` 再 cast：能避免 `inf`，但会**改变数值**，而且会把极值那一路的梯度、注意力分布扭曲。只在你确认这些极值是垃圾值（训练不稳定留下的）时才用。
- 纯 `nan_to_num` / clamp 方案适合应急，不适合作为常规流程。

别忘记：

- **`config.json` 里的 `torch_dtype`**：不改的话，`from_pretrained` 会按 bf16 读取，等于白做。
- **tied weights**：`embed_tokens` 和 `lm_head` 如果共享，两个 key 都要转，并且结果保持一致。
- **非浮点 buffer**：`rotary_emb.inv_freq`、`position_ids` 等不要强转，脚本里已经用 `is_floating_point()` 挡掉了。

- **敏感层不要转**：LayerNorm/RMSNorm 的 $\gamma$、LayerNorm 的 bias、embedding 里特别小的值，保持 fp32 更稳。

## Step 3：一定要验证，而且验证的是 logits 而不是权重

权重转换成功不等于推理正确——**fp16 推理的溢出绝大多数发生在激活侧**（attention logits、残差流、softmax 前后），而不是权重侧。同一个 bf16 checkpoint 转成 fp16，可能权重全部正常，跑起来还是 NaN。

```python
out_bf16 = model_bf16(**batch).logits.float()
out_fp16 = model_fp16(**batch).logits.float()
assert torch.isfinite(out_fp16).all(), "有 NaN/Inf"
print("max|Δ| =", (out_bf16 - out_fp16).abs().max().item())
print("KL     =", torch.distributions.kl_divergence(
    torch.distributions.Categorical(logits=out_bf16),
    torch.distributions.Categorical(logits=out_fp16)).mean().item())
```

判据：max|Δ| 在 $10^{-2}$ 量级、KL 在 $10^{-4}$ 量级以内属于正常 fp16 数值差异；出现 NaN，或 Δ 达到 1 以上则说明有问题。

如果用 HuggingFace 跑，务必开着 autocast 或手动规范地处理：残差流和 LayerNorm 保持 fp32，`softmax` 用 fp32。`torch.autocast("cuda", dtype=torch.float16)` 默认就这么做，别自己手搓全 fp16 forward。vLLM 的话直接 `--dtype float16`，它内部会处理；TensorRT-LLM 的 `convert_checkpoint` 也支持 fp16 并带 clamp 逻辑。

如果你只是想在推理时省显存或提速，先确认硬件：

- **V100 / T4 / 2080Ti / GTX 16xx / 老 MPS**：没有原生 bf16，必须转 fp16，这个转换值得做。
- **A100 / H100 / 4090 / L40S / 新 MPS**：原生 bf16，转 fp16 **没有任何收益**（带宽一样，算力一样），只会引入上面这些风险。这种情况直接用 bf16。

<details>
<summary><b>快速决策表</b></summary>

| 你的情况 | 做法 |
|---|---|
| 权重 absmax 全部 < 60000 | `.to(torch.float16)` 直接过，无损 |
| 少数 tensor 溢出、是 norm 后第一个 Linear | 方案 A：除以 $2^k$，折叠进 $\gamma$ |
| 溢出 tensor 的输出进残差（`down_proj`/`o_proj`） | 方案 B：sidecar scale，在 fp32 或 kernel 里还原 |
| 溢出的是 embedding / `lm_head` | 除以 $2^k$，把 $s$ 折叠进第 0 层 norm；若权重 tied 要同时补偿 head |

| 跑在 A100/H100/4090 上 | 不要转 |

一句话总结：**真正要处理的是范围，而不是尾数**——先扫一遍 `absmax`，99% 的 checkpoint 直接 cast 就是无损的；真溢出的少数 tensor 用 2 的幂缩放，并把 scale 折叠进相邻的 $\gamma$，这样既不改加载代码，也逐位精确。

## 结论先说

**方向是对的，而且比你想的更强：在纯 pre-LN 结构下，这套缩放是「精确等价变换」，数学上完全不改变模型函数——所以理论上连 QAT 都不需要。**

代价是它必须满足几个很硬的条件，否则就会从「精确变换」不声不响地变成「扰动」，那时候才需要 QAT 去补。下面把边界划清楚。

---

## 一、为什么它是精确的

写成一个 pre-LN block：

$$x_0 = E\,t,\qquad x_{l+1} = x_l + \underbrace{W_o^{(l)}\,\mathrm{Attn}\!\left(\mathrm{LN}(x_l)\right)}_{a_l} + \underbrace{W_d^{(l)}\,\mathrm{act}\!\left(W_g^{(l)}u_l\right)\odot\left(W_u^{(l)}u_l\right)}_{m_l}$$

做变换 $T_\lambda$（$\lambda = 2^{-k}$）：$E \to \lambda E$，**所有** $W_o^{(l)} \to \lambda W_o^{(l)}$，**所有** $W_d^{(l)} \to \lambda W_d^{(l)}$。

归纳法：

$$x_0' = \lambda x_0 \;\Rightarrow\; \mathrm{LN}(x_l') = \mathrm{LN}(\lambda x_l) = \mathrm{LN}(x_l) \;\Rightarrow\; a_l' = \lambda a_l,\; m_l' = \lambda m_l \;\Rightarrow\; x_{l+1}' = \lambda x_{l+1}$$

所以每层残差严格成比例缩小，而**每个 sublayer 的输入逐位不变**，最终 `final_norm` 输出不变，logits 不变。权重除以 $2^k$ 是纯指数平移，**零舍入误差**；matmul 的 fp32 累积也是逐位等价（只差一个指数偏移）。所以这不是近似，是恒等变换。

顺带一提：bf16→fp16 在 fp16 正规数范围内本来就逐位精确（fp16 尾数 11 bit > bf16 的 8 bit），**唯一的敌人是范围**。所以「精确缩小残差」正好是全部需要的修复——不存在需要 QAT 去恢复的舍入误差。

---

## 二、四个必须补的漏洞

### 1. ❗必须是**单一全局 λ**，不能 per-layer

这是最容易踩的坑。你可能想「哪层大就压哪层」，但那样 $x_l$ 就**不是**原值的等比缩放，而是各项比例变形了，$\mathrm{LN}(x_l') \ne \mathrm{LN}(x_l)$，函数立刻就变了。

因为这里的补偿机制是「LN 对整体缩放不敏感」，它只对**整体**缩放成立。想按层独立控制，必须走另一个补偿路径（把 $s$ 折进 $\gamma$、$s^{-1}$ 折进 $W$，上一轮说的做法），那才是逐 tensor 精确的。两者别混。

好消息：fp16 的动态范围有 ~9 个数量级（$6\times10^{-5}$ 到 $6.5\times10^4$），一个全局 λ 通常足够。

### 2. ❗`x_0` 必须一起缩，否则白做

残差是 $x_0 + \sum$ 的和。如果 embedding 不缩而只缩写入项，`x_0` 那一项还是大的，absmax 就压不下去。`embed_tokens` 必须乘 $\lambda$。

### 3. ❗ε 会破坏 scale-invariance

$$\mathrm{RMSNorm}(\lambda x) = \frac{\lambda x}{\sqrt{\lambda^2 \overline{x^2} + \varepsilon}} \ne \frac{x}{\sqrt{\overline{x^2}+\varepsilon}}$$

只有当 $\varepsilon \ll \lambda^2\overline{x^2}$ 时才近似成立。主流 $\varepsilon = 10^{-5}\sim10^{-6}$，残差 rms 通常 1~100，$\lambda = 2^{-4}$ 时 $\lambda^2\overline{x^2} \sim 10^{-2}$，远大于 ε，没问题。但如果某层 rms 只有 1e-2 而你用 $\lambda = 2^{-10}$，ε 就开始占比了。**建议 λ 不要小于 $2^{-6}$，并实际验证**。

### 4. ❗tied `lm_head` 是隐藏的地雷

Gemma / Qwen / Llama-3.2-1B/3B 等大量模型 `tie_word_embeddings=True`。你把 embedding 乘了 λ，tied 的 lm_head 就跟着缩了 λ，**logits 整体缩 λ = 悄悄改了 softmax 温度**，输出分布直接变。

补偿三选一：

- **把 $1/\lambda$ 折进 `final_norm.weight`**（最省，零代码改动）——但要检查最终 hidden 放大 $1/\lambda$ 后仍在 fp16 范围内
- 拆开 tie（多存 vocab×d 参数，config 里 `tie_word_embeddings: false`）
- 在 head 里 `logits = lm_head(h).float() / λ`（最干净，但要改推理代码）

---

## 三、它**修不了**什么：分支内部激活

关键在于：残差缩了 λ，但**每个 branch 内部的量完全没变**（LN 输入不变嘛）。所以如果溢出发生在这些地方，你的方案无效：

| 位置 | 是否被你的方案覆盖 |
|---|---|
| residual stream | ✅ 线性缩放 |
| MLP 中间激活 $h=\mathrm{silu}(W_g u)\odot(W_u u)$ | ❌ 完全不变 |
| attention logits $q^\top k/\sqrt{d}$ | ❌ 不变 |
| $v$ / KV cache | ❌ 不变 |
| 最终 logits | ❌ 不变（除非 tied 没补偿，那会更糟） |

好在实测里 residual 通常就是 absmax 的持有者（massive activations 都在残差流上，单个 channel 能到 $10^4\sim10^5$ 量级），但**别假设**，要测。

如果需要连内部一起精确压，还有两个免费的旋钮（同样只用 2 的幂，仍然精确）：

- **MLP**：$W_u \to \mu W_u$、$W_d \to (\lambda/\mu)W_d$。注意——**不能碰 $W_g$**！SwiGLU 里 $\mathrm{silu}(\mu z)\neq\mu\,\mathrm{silu}(z)$，缩 gate 立刻破坏精确性。走 `up_proj` 这条线性路径。
- **Attention**：$W_v \to \rho W_v$、$W_o \to (\lambda/\rho)W_o$。$P$ 是行和为 1 的随机矩阵，$P(\rho v)=\rho(Pv)$ 严格成立；顺带把 KV cache 也压小了。同理**不能碰 q/k**（softmax 对 logits 不是齐次的）。

所以：只要沿着「线性因子」这条路走，原则上整个 fp16 转换可以做到**完全精确、零 QAT**。

---

## 四、什么时候 QAT 才真的必要

既然精确缩放能解决，QAT 就是白花的算力——除非落到下面几种情况：

| 情况 | 需要 QAT 吗 |
|---|---|
| 全用 2 的幂 + 全局 λ + 补好 tied head | ❌ 完全不需要，做 logits 对比即可 |
| 残差 absmax 太大，λ 要缩到 $<2^{-10}$ 导致别处下溢 | 需要，但本质是模型数值已经退化，QAT 也救不回多少 |
| 想要 per-layer 独立缩放（为了压内部激活） | 需要，非精确 |
| 被迫用 `clamp`（引擎不接受 scale 元数据） | 需要，做 **clamp-aware 微调** 就够，不必完整 QAT |
| 模型真的是训练炸了（残差到 1e20+） | 需要的是继续预训练/回滚 checkpoint，不是 QAT |

关于「针对性 QAT」本身：注意 fp16 的舍入预算是 11 bit，**比训练时的 bf16 更宽**，所以在范围内的数值不需要「重新适应」。QAT 能教的只有「不要依赖被 clamp 掉的大值」。因此它是**裁剪失真恢复**，不是精度恢复——如果走精确路线就完全没有这一环。

---

## 五、更省事的替代方案（如果推理栈你能改）

真正的 fp16 推理标准做法是 **residual / LN / softmax 保持 fp32，只有 matmul 走 fp16**——`torch.autocast("cuda", dtype=torch.float16)` 默认就这么干。这样残差流**根本不进 fp16**，问题从根上不存在。

需要做 weight folding 的场景是：你要产出一个**纯 fp16 checkpoint** 交给不归你管的引擎（TRT-LLM、某些老版本 vLLM、端侧 runtime）。

## 六、落地代码

```python
import math, torch
from safetensors.torch import load_file, save_file

def residual_rescale(sd, k, tied_head=True):
    """
    lambda = 2^-k
      E, o_proj, down_proj (+ 对应 bias, 任何写残差的项)  *= 2^-k
      tied lm_head 时: final_norm.weight *= 2^k 作为补偿
    """
    lam, inv = 2.0 ** (-k), 2.0 ** k
    EMB  = ("embed_tokens.weight", "wte.weight")
    WRITE = ("o_proj.weight", "down_proj.weight",
             "o_proj.bias",   "down_proj.bias",
             "attn.output_proj.weight", "mlp.down_proj.weight")
    FINAL = ("model.norm.weight", "ln_f.weight")

    def mul(key, f):
        t = sd[key]
        sd[key] = (t.float() * f).to(t.dtype)   # 2 的幂，零误差

    for key in list(sd):
        if any(key.endswith(s) for s in EMB):    mul(key, lam)
        elif any(key.endswith(s) for s in WRITE): mul(key, lam)
        elif tied_head and any(key.endswith(s) for s in FINAL): mul(key, inv)
    return sd
```

## Q1：对典型 Pre-RMSNorm Transformer，推导的哪些部分成立

### 命题（residual gauge）

设 block 为 $x_{l+1} = x_l + F_l\big(\mathrm{Norm}(x_l)\big)$，$\mathrm{Norm}(x) = \gamma \odot x / \sqrt{\overline{x^2} + \varepsilon}$。对任意 $\lambda > 0$，变换

$$T_\lambda:\quad E \mapsto \lambda E,\qquad W_o^{(l)} \mapsto \lambda W_o^{(l)},\qquad W_d^{(l)} \mapsto \lambda W_d^{(l)}$$

满足 $x_l' = \lambda x_l\ \ \forall l$，从而 $f_{T_\lambda(\theta)} \equiv f_\theta$（$\varepsilon = 0$ 时严格成立）。

**证明梗概**：$\mathrm{rms}(\lambda x) = \lambda\,\mathrm{rms}(x)$，故 $\mathrm{Norm}(\lambda x) = \lambda x/\sqrt{\lambda^2 \overline{x^2} + \varepsilon}$，$\varepsilon = 0$ 时等于 $\mathrm{Norm}(x)$；于是 $F_l$ 的输出不变，写入项被 $\lambda$ 精确缩放；对 $l$ 归纳。∎

### 逐条判定

| 推导环节 | 状态 | 条件 / 备注 |
|---|---|---|
| $x_l' = \lambda x_l$ 归纳成立 | ✅ **严格** | 所有写入项 + $x_0$ 用**同一个** $\lambda$ |
| Norm 对整体缩放不变 | ✅ **严格 iff $\varepsilon = 0$** | 否则偏差 $\approx \varepsilon/(\lambda^2\overline{x^2})$。主流 $\varepsilon\!\in\![10^{-6},10^{-5}]$，$\lambda\!\ge\!2^{-6}$ 时偏差 $<10^{-4}$ 相对量 |
| 子层**内部**张量不变（$h$、$q,k,v$、logits、$P$） | ✅ **严格** | ⚠️ 这正是“修不了内部溢出”的根源，不是副作用而是**定义性质** |
| 模型函数等价 | ✅ 严格 | 需补 tied head / 无 final norm / 绝对 PE 等（见 Q2 清单） |
| per-layer 独立 $\lambda_l$ 也成立 | ❌ **不成立** | $\mathrm{LN}$ 只对**整体**齐次；不同 $\lambda_l$ 使 $x_l'$ 各项比例变形，不再是 $\lambda x_l$ |
| 降低动态范围 | ❌ 不成立 | 只是幅值平移 |
| 逐位等价（FP16 内） | ✅ 除 (i) $\varepsilon$、(ii) subnormal/overflow 边界 | 2 的幂缩放是纯指数平移，matmul 与残差加法的舍入完全同构 |

### 一个可用的强化结论（建议写进论文）

**Pre-RMSNorm 残差流允许的 gauge 群恰好是 $\{\lambda R : \lambda > 0,\ R \in O(d)\}$——一维标量 × 正交群。** 理由是 $\mathrm{rms}$ 是各向同性范数，$\mathrm{rms}(Dx) = \mathrm{rms}(x)$ 仅当 $D$ 是标量乘正交阵。这有两点推论：

1. **沿通道的非均匀缩放（per-channel scaling）在数学上不被允许**，所以“哪个通道大就压哪个通道”这条路在 Pre-LN 下是死路——这正是你不能像 SmoothQuant 那样做 per-channel 迁移的原因。
2. **$R$ 这一支是被浪费掉的免费资源**：$R$ 可完全吸收进权重（$E \to \lambda RE$、$W_o \to \lambda R W_o$、$W \to W R^\top$ for norm consumers、$\gamma \to R\gamma$），**零推理开销**，且对“少数通道异常大”这类 outlier 的抑制比 $\lambda$ 强得多（随机/Hadamard 旋转把 $\ell_\infty$ 从 $M$ 降到 $\sim M\sqrt{2\ln d/d}$，$d=4096$ 时约 $16\times$，等效于 $\lambda = 2^{-4}$ 却不动 $x_0$ 的 $\ell_\infty$ 之外的东西）。这就是 QuaRot / QuIP# 的机制，和你的 $\lambda$ 是同一 gauge 群的两个独立坐标。

⚠️ 冲突点：$R$ 和 **tied head** 不兼容（embedding 需同时作 $RE$ 和 $(RE)R^\top$），要么拆 tie，要么在 head 前单独插一个 Hadamard。$\lambda$ 没有这个问题。

## Q2：具体缩放哪里

**唯一判据**：残差流的**每一个加项**都乘 $\lambda$；**每一个只读** $\mathrm{Norm}(x)$ 的量都不动（除了 gauge 配对）。

### 精确变换代码

```python
import torch
from safetensors.torch import load_file

# 写残差流的投影（乘 λ）
WRITE = ("o_proj.weight", "o_proj.bias",
         "down_proj.weight", "down_proj.bias",
         "shared_expert.down_proj.weight",           # MoE 共享专家
         "experts.down_proj.weight",                 # 逐专家
         "crossattn.o_proj.weight", "crossattn.o_proj.bias",  # encoder-decoder
         "self_attn.o_proj.weight", "self_attn.o_proj.bias")
# 初始项 x0（乘 λ）
INIT  = ("embed_tokens.weight", "wte.weight", "shared.weight",
         "position_embeddings.weight",               # ⚠️ 绝对 PE 也是 x0 的加项
         "wpe.weight")
# tied head 的补偿（乘 1/λ）
FINAL = ("model.norm.weight", "ln_f.weight", "final_layer_norm.weight")

def gauge_scale(sd, k, tied_head: bool):
    lam, inv = 2.0 ** (-k), 2.0 ** k
    def mul(key, f):
        t = sd[key]; sd[key] = (t.float() * f).to(t.dtype)
    for key in list(sd):
        if   any(key.endswith(s) for s in WRITE): mul(key, lam)
        elif any(key.endswith(s) for s in INIT):  mul(key, lam)
        elif tied_head and any(key.endswith(s) for s in FINAL): mul(key, inv)
    return sd
```

### 逐项说明

| 位置 | 操作 | 原因 |
|---|---|---|
| `embed_tokens` | **× λ** | $x_0$ 是一个残差加项；不缩则 absmax 下不去 |
| 绝对位置编码表（GPT-2 / ViT / 老 BERT） | **× λ** | 它是 $x_0$ 的另一个加项，漏掉它 $\Rightarrow$ 不再是均匀缩放 |
| `o_proj` (+bias) | **× λ** | 直接写残差 |
| `down_proj` (+bias) | **× λ** | 直接写残差 |
| MoE 每个专家 + shared expert 的 `down_proj` | **× λ** | 都是写残差 |
| decoder 的 **cross-attn** `o_proj` | **× λ** | 也写 decoder 残差 |
| encoder 的 residual stream | **单独一个 $\lambda_e$** | encoder/decoder 是两个独立 gauge，不能共用一个 $\lambda$ |
| `q_proj` / `k_proj` | ❌ **不动** | softmax 对 logits 非齐次；动 q/k = 改 attention 温度 |
| `v_proj` | ⚠️ 仅在与 `o_proj` 配对时动 | 见下方配对表 |
| `gate_proj` | ❌ **绝不能动** | $\mathrm{silu}(gz) \neq \gamma\,\mathrm{silu}(z)$，任何 $\gamma\neq1$ 都破坏精确性 |
| `up_proj` | ⚠️ 仅在与 `down_proj` 配对时动 | 同下 |
| `input_layernorm` / `post_attention_layernorm` 的 $\gamma$ | ❌ 不动 | 它们是尺度不变的实现者，不是消费者 |
| `final_norm` 的 $\gamma$ | ⚠️ 仅 tied head 时 ×$1/\lambda$ | 补偿 head 随 embedding 被缩 |
| `lm_head`（untied） | ❌ 不动 | 它读 norm 输出，量级不变 |

### 允许的「精确配对」（这是解决内部溢出的唯一免费手段）

幅值可以在任意**线性因子链**上自由重分配，只要乘积不变：

| 配对 | 变换 | 效果 |
|---|---|---|
| MLP | $W_u \to \mu W_u,\quad W_d \to \frac{\lambda}{\mu}W_d$ | $h \to \mu h$（内部压 $\mu$ 倍），$W_d h \to \lambda W_d h$（残差仍 $\lambda$）→ **两个目标同时精确达成** |
| Attention | $W_v \to \rho W_v,\quad W_o \to \frac{\lambda}{\rho}W_o$ | $P(\rho v) = \rho(Pv)$（$P$ 行和为 1）→ 精确；KV cache 同时缩小 $\rho$ |
| Norm 消费者 | $\gamma \to s\gamma,\quad W_{q/k/v/g/u} \to W_{q/k/v/g/u}/s$ | 精确；对 fp16 溢出的帮助是间接的（改的是 `x̂·W` 的分解，不改变乘积集合），主要对 int8 有意义 |
| Tied head | $E \to \lambda E,\quad \gamma_{\text{final}} \to \gamma_{\text{final}}/\lambda$ | 精确；代价是 final hidden 放大 $1/\lambda$，要查范围 |

**通用规则：能用 gauge 解决的不要用训练解决。** 内部溢出优先用 $\mu,\rho$ 这两个旋钮（零成本、精确），QAT 只留给非线性项（如 `gate`/`silu` 路径）真正造成的问题。

## Q3：为什么不够——以及如何**定量**验证比例

### 结构性论证（这是你最强的先验论据，建议写进 motivation）

$$\|a_l\|_\infty = \|W_o\,\mathrm{Attn}(\mathrm{Norm}(x_l))\|_\infty \le \|W_o\|_\infty \cdot \max|v|$$

分支内部的所有量都受 $\mathrm{Norm}$ 的**范数钳制**，其幅值**与层数无关（depth-invariant）**；而

$$\|x_L\|_\infty = \Big\|x_0 + \sum_{l=1}^{L}(a_l + m_l)\Big\|_\infty$$

是 $L$ 项之和，**随深度增长（depth-growing）**（经验上 $\mathrm{rms}(x_l)$ 随 $l$ 单调上升，同时存在“massive activation”少数通道达到 $10^4\sim10^5$）。

**推论（可检验的预测）**：residual 主导 overflow 的程度应随**深度**增强。所以你的方法在深模型（$L \gtrsim 30$）上收益应显著大于浅模型。这是能写进论文的可判定预测。

### 三种溢出源的相对量级（先验判断，需实测覆盖）

| 类别 | 典型 absmax | 是否随深度增长 | $\lambda$ 能否作用 |
|---|---|---|---|
| residual stream | $10^3 \sim 10^5$（massive activation 通道） | ✅ 增长 | ✅ 线性缩放 |
| `down_proj` **输入** $h$（门控乘积） | $10^1 \sim 10^3$ | ❌ | ❌（需 $\mu$ 旋钮） |
| $q,k$ 输出 | $10^0 \sim 10^2$ | ❌ | ❌（且不能动） |
| attention logits $q^\top k/\sqrt d$ | $10^0 \sim 10^2$ | ❌ | ❌ |
| $\exp(\cdot)$ | 无 max-subtraction 时溢出（$e^{11.09}\to\infty$） | ❌ | ❌ |
| `up_proj` 前 / `gate_proj` 前 | $10^0 \sim 10^1$ | ❌ | ❌ |
| `logits` | $10^0 \sim 10^2$ | ❌ | 间接（tied 时） |

所以，**你的方法在理论上精确覆盖 residual 那一行（且仅那一行），另外两行不可约**。这也是为什么必须先做归因：如果你的模型 overflow 全在第一行，方法近乎完备；如果第二行占主导，$\lambda$ 完全无效，只能靠 $\mu$ 或训练。

### 关键简化：residual 那一行**不需要实验**

由命题，$x_l' = \lambda x_l$ **逐元素精确**，故

$$\text{absmax}_{\text{residual}}' = \lambda\cdot\text{absmax}_{\text{residual}}^{\text{baseline}}$$

也就是说 **residual 的溢出消除是解析可预测的**，做 $c\in\{0.5,0.25,0.125\}$ 的扫描只是在验证你的实现有没有 bug，不是在测科学假设。真正需要实验的只有：

1. 内部张量是否**确实不变**（应该是 null result；如果变了 = 你漏了一个 consumer 或有 $\varepsilon$ 漂移）→ **这是最强的 self-check**
2. $\varepsilon$ 引起的端到端漂移有多大
3. FP16 下，内部那两行里到底有没有超范围的

### 归因度量（不要用“比例”这个词含糊过去）

需要三个正交指标：

$$N_t = \#\{|t| > 2^{15}\},\quad S_t = \log_{10}\!\frac{\mathrm{absmax}_t}{2^{15}},\quad \text{span}_t = \log_2\!\frac{\mathrm{absmax}_t}{\mathrm{absmin}^{>0}_t}$$

- $N_t$：元素计数（严重度）
- $S_t$：超出多少（正数即危险）
- $\text{span}_t$：**这是判断“单 $\lambda$ 是否可行”的判据**。FP16 安全窗口约 $[2^{-14}, 2^{15}]$，跨 29 个 binade。若某层 residual 的 span $>29$，则任何单一 $\lambda$ 都无法让整层安全落入范围（此时需要 $R$ 或 fp32 旁路）

再加一个**因果**指标（比计数更有说服力）：对每个 overflow 的 op，把它的输出 clamp 到 $2^{15}$，看模型是否恢复正常。若单靠一个 op 的 clamp 就救回来，说明它是瓶颈；这是最便宜的 sensitivity 归因。

```python
import torch, collections
FP16_MAX, CAP = 65504.0, 2.0**15

CATS = [
    ("residual",   lambda n: "residual" in n),
    ("embed",      lambda n: "embed" in n),
    ("qkv",        lambda n: n.endswith(("q_proj","k_proj","v_proj"))),
    ("attn_logits",lambda n: "attn_weights" in n or "attn_scores" in n),
    ("attn_out",   lambda n: "attn_output" in n),
    ("o_proj",     lambda n: n.endswith("o_proj")),
    ("gate",       lambda n: n.endswith("gate_proj")),
    ("up",         lambda n: n.endswith("up_proj")),
    ("act_mul",    lambda n: n.endswith("act_mul") or "down_proj" in n and "in" in n),
    ("down_proj",  lambda n: n.endswith("down_proj")),
    ("logits",     lambda n: n == "logits"),
]
def cat_of(n):
    for c, f in CATS:
        if f(n): return c
    return "other"

class Audit:
    def __init__(self):
        self.d = collections.defaultdict(lambda: dict(amax=0., amin=float("inf"),
                                                     n=0, n_ovf=0, n_over_cap=0, ss=0.))
    def __call__(self, name):
        def hook(mod, inp, out):
            ts = out if isinstance(out, (tuple, list)) else (out,)
            for t in ts:
                if not torch.is_tensor(t) or not t.is_floating_point(): continue
                s, x = self.d[cat_of(name)], t.detach().reshape(-1).float()
                s["amax"] = max(s["amax"], x.abs().max().item())
                nz = x[x != 0].abs()
                if nz.numel(): s["amin"] = min(s["amin"], nz.min().item())
                s["n"] += x.numel(); s["ss"] += x.double().pow(2).sum().item()
                s["n_ovf"]      += int((x.abs() > FP16_MAX).sum())
                s["n_over_cap"] += int((x.abs() > CAP).sum())
        return hook

def run_audit(model, batch):
    a = Audit()
    hs = [m.register_forward_hook(a(n)) for n, m in model.named_modules()]
    with torch.no_grad(): model(**batch)
    for h in hs: h.remove()
    import math
    print(f"{'cat':12s} {'absmax':>10s} {'absmin':>10s} {'log2span':>8s} "
          f"{'>65504':>8s} {'>32768':>8s}")
    for c, s in sorted(a.d.items(), key=lambda kv: -kv[1]["amax"]):
        span = (math.log2(s["amax"] / s["amin"]) if s["amin"] > 0 else float("inf"))
        print(f"{c:12s} {s['amax']:10.4g} {s['amin']:10.4g} {span:8.1f} "
              f"{s['n_ovf']:8d} {s['n_over_cap']:8d}")
```

⚠️ 一个必须显式处理的陷阱：**“某个张量在 FP16 下会溢出”和“在 FP16 pipeline 里它真的溢出了”不是一回事。** 前者是静态幅值，后者取决于 kernel 的累加精度与 downcast 点。所以归因必须在**真实的 FP16 前向**里做（`model.half()`，关闭 autocast 的自动 upcast，除非你的部署契约就是这样），而不是在 bf16 前向里 hook。

## Q4：实验设计（按“可判定”重构）

你的 A/B/C/D 骨架是对的，但顺序上有一个大问题：**实验 A 里有大量工作量是解析决定不了的**，而那些解析上就能定下来的部分（residual absmax $= \lambda\cdot$ baseline）不应该占用实验预算。我把它重排成带**判定门（gate）**的链路，每一门都有明确的通过/失败判据，失败就改路线。

```
E0 基线刻画  →  Gate 0: 溢出源归因是否明确？residual 占比？
E1 精确性    →  Gate 1: FP32 是否 bit-exact？(不是 → 漏 consumer)
E2 范围      →  Gate 2: 内部张量是否不变？(null result 必须成立)
E3 端到端    →  Gate 3: 纯缩放后 FP16 NaN 率是否归零？
E4 消融/对照 →  Gate 4: 收益是否来自"精确性"而非"数值变小"？
E5 QAT       →  Gate 5: 剩余误差是否真的是非线性/裁剪导致？
E6 泛化
```

### E0｜基线刻画（补齐你列出的指标）

除 RMS / absmax / top-k 通道能量外，**必须补**：

- **per-layer depth profile**（$\mathrm{rms}(x_l)$、$\mathrm{absmax}(x_l)$ 随 $l$ 的曲线）——这是检验“depth-growing”预测的直接证据，也是论文里最有说服力的一张图
- **span**（见上）——判断单 $\lambda$ 是否在原理上够用
- **massive activation 通道的定位**（哪层、哪个通道、是否是 attention sink token）——决定是否需要 $R$
- **静态幅值 vs 真实 FP16 溢出**两张表并列，两者差异本身就是发现

### E1｜精确性（把用户说的“近似等价”升级为 bit-exact 验证）

**关键技巧**：把模型中所有 $\varepsilon$ 临时设为 0（RMSNorm 的 eps 是 config 里的，可以直接改），此时 $T_\lambda$ 应当给出**逐位相同**的 logits（FP32/FP64 下）。这是一次纯软件正确性验证，能在 10 分钟内定位你漏掉的 consumer。

```python
# 1) 全部 eps -> 0
for m in model.modules():
    if hasattr(m, "variance_epsilon"): m.variance_epsilon = 0.0
    if hasattr(m, "eps"): m.eps = 0.0

# 2) 双模型比对
la = ref_model(**batch).logits.double()
lb = scaled_model(**batch).logits.double()
assert torch.equal(la, lb), f"max|Δ|={(la-lb).abs().max().item():.3e}  <-- 有 consumer 漏了"
```

只有这一关过了，后面的 $\varepsilon$ 漂移才有意义（那时它是一个可测量的、被单独归因的小量）。

### E2｜范围（把“扫描 $c$”改成“验证 null result”）

由命题，内部张量在 $T_\lambda$ 下应**严格不变**。所以：

| 观测量 | 期望 | 若不成立 |
|---|---|---|
| `x_l` absmax | $=\lambda\cdot$ baseline，逐元素比例 | 实现 bug |
| `h`、$q,k,v$、attn logits、`up/gate` 输出 absmax | **完全不变** | 有 $\varepsilon$ 漂移（量化它）或漏了 consumer |
| `logits` | 不变（untied）/ 需补偿（tied） | tied 未补 |

这一关的产出不是“方法有效”，而是“方法的适用范围被证明地划定在 residual 那一行”。这个结论本身就值一篇 paper 的一节。

### E3｜端到端（补三个你漏掉的基线）

$c$ 只取 $\{1, 0.5, 0.25, 0.125\}$ 就够（再小进入 $\varepsilon$/$subnormal$ 区），但**对照必须补齐**：

| 基线 | 为什么必须 |
|---|---|
| **BF16 reference** | 上界 |
| **naive FP16 cast** | 下界，方法要打败的对象 |
| **FP16 + clamp@$2^{15}$**（不做任何缩放） | 最强的“廉价解”。如果你的方法打不过这个，价值就存疑 |
| **混合精度：residual/norm/softmax 保 FP32，仅 matmul FP16** | 这是工程上的正解，你的方法必须在**部署约束**（必须是纯 FP16 checkpoint）上赢它，而不是在精度上赢它 |
| **随机/错配缩放**（只缩 `down_proj` 不缩 embedding，或 per-layer 不同 $\lambda$） | **null control**：证明收益来自“精确等价”而非“数值变小”。这一组缺失的话，审稿人一定会说“你只是 scale 了一下 weight” |

指标：**NaN/Inf 发生率（跨 $N$ 条真实 prompt）** + task metrics + `max|Δlogits|`。注意 NaN 发生率是二值的毒化指标，一条 prompt 挂了就整段输出废掉，所以必须报**发生率**而不是均值误差。

### E4｜内部溢出定位（明确“不要用 residual 代替一切”）

你已经在提醒这一点了，我再加两条方法学要求：

1. **必须在真实 FP16 前向里做**（见上文陷阱）
2. 加**因果归因**：对每个超范围 op 单独 clamp，看是否救回。这比计数更能指导下一步（该给哪个模块加 QAT 或 $\mu$ 旋钮）
3. 若某层 `h` 超范围 → **先用 $\mu$ 旋钮（精确、免费）**，不要直接上 QAT

### E5｜QAT：把定位改准确，并大幅缩小范围

先纠正一个定位问题：**既然范围内 bf16→fp16 是逐位精确的，“量化误差”为 0**，所以这里严格来说没有“QAT”可言——它是 **clipping-aware distillation**（裁剪感知蒸馏）。这个区分很重要，因为它决定了训练成本和梯度性质：

- 硬 cast 的梯度是恒等（STE），**在未触发裁剪的地方梯度为零**，所以有效梯度极度稀疏 → 必须用**平滑替代**（soft clamp / `tanh` 饱和 / 温度退火）才能训得动
- 损失：$\mathrm{KL}\big(p_{\text{bf16-teacher}} \,\|\, p_{\text{fp16-student}}\big)$，可选加 $\lambda_h \|h\|_\infty$ 惩罚
- **冻结策略**：只解冻“其输出被观测到超范围”的模块（通常是某一层的 `gate`/`up`/`down`，因为它们是非线性路径，$\mu$ 旋钮管不了 `gate` 侧）
- **训练 dtype**：只在 bf16/fp32 里带模拟 FP16 前向训练，绝不要真的在 fp16 下反传
- **信任域**：$\|\theta - \theta_0\|$ 约束或极小 lr + 少量 step，防止蒸馏把模型带偏（你要的是数值稳健，不是新模型）
- **采样**：优先采能触发溢出的 prompt（否则梯度全是 0）

**判定门**：如果 E4 之后已经没有超范围 op，E5 直接跳过。你的顺序判断（先验证纯缩放）完全正确。

### E6｜泛化（补你漏的）

- **prefill vs decode 分开测**：两者用不同 kernel（prefill 走大 GEMM，decode 走 GEMV/fused attention），fp16 行为完全不同；overflow 往往只在其中一侧出现
- **KV cache**：$\lambda$ 不动 $k$（正确），若用了 $\rho$ 则 cache 同步缩小 → 需验证长上下文下 cache 的 absmax
- **长上下文**：attention logits 的极值随长度变化，$P$ 变得更尖锐
- **batch size**：改变 kernel 分块与累加顺序，可能改变 overflow 阈值（不是数值上应有的，但工程上会）
- **对抗性输入**：chat template、超长 tail token、重复 pattern（触发 attention sink）

## 把研究假设再收紧一版

你现在这版已经很好了，我建议再往上抬一层，把它表述成一个**受约束的最优化问题**——这比“重分配幅值预算”更有理论抓手：

$$\min_{\lambda>0,\ R\in O(d)}\ \mathcal{L}_{\text{FP16}}\!\big(T_{\lambda R}(\theta)\big)\quad \text{s.t.}\quad f_{T_{\lambda R}(\theta)} \equiv f_\theta$$

其中 $\mathcal{L}_{\text{FP16}}$ 是**溢出事件数 + 舍入误差的代理**（例如 $\sum_t \mathbb{1}[\text{absmax}_t > 2^{15}] + \frac{1}{2^{11}}\sum_t \|t\|$）。然后再放松约束到近似等价，得到 QAT/蒸馏那一支。

这个形式化的好处：

1. **gauge 群是精确已知的**（一维标量 × $O(d)$），所以搜索空间有清晰的结构，不是拍脑袋
2. **约束是硬约束**，所以 E1 的 bit-exact 验证是必要条件，方法论上无可指摘
3. $\lambda$ 有解析最优（由 residual absmax 与下溢边界夹出的区间），$R$ 有一个已知的有效选择（Hadamard），所以这个优化实际上是**可解且廉价的**，不是开放搜索
4. 放松约束后自然落到 clipping-aware distillation，$\mathcal{L}$ 给出了它的训练目标

以及一句可以直接写进 abstract 的话：

> Pre-Norm 的尺度不变性给残差流一个一维 gauge 自由度；我们在此 gauge 下重选代表元，将残差流的绝对幅值移入 FP16 指数窗口，同时保持模型函数严格不变，从而把“FP16 转换”从近似舍入问题化归为可解析预测的范围重排问题。

**最需要小心的一件事**：$R$（旋转）这一支是免费的，且对 massive activation 类 outlier 的抑制强于 $\lambda$，它和 tied head 有冲突但可以拆 tie 或用独立 head rotation 解决。如果 $\lambda$ 单独不够，$R$ 大概率是比 QAT 更便宜的下一步——**继续用 gauge，不要急着上训练**。
