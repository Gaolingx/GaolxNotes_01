# 结论先行

**能，但"能不能"取决于模型档次，而不是工具数量。** 用 bash + 文件编辑两个工具做 terminal agentic coding 在架构上完全成立——事实上 bash 一个工具就够（`cat/sed/grep/tee/heredoc/`运行测试都是 shell 能做的事），文件编辑工具只是个"更好用的包装"。

真正的分水岭在模型侧的长程能力：

- **GPT-4.1**：可以胜任真正的 terminal agentic coding（尤其配好 scaffold）。
- **GPT-4o**：只能在短程、单文件、低复杂度任务上勉强跑通；一旦进入几十轮的工具循环就会退化。

---

# 为什么"两个工具"不是瓶颈

工具少反而常常更好。核心概念是 **ACI（Agent-Computer Interface）**——决定成败的是：

- 输入是否清晰、错误信息（`stderr`、退出码、stack trace）是否可读；
- 编辑原语是否可靠（最小 diff / search-replace 块，而不是整文件重写）。

约束几乎全部来自模型侧：长程规划、状态保持、错误恢复、自我验证、避免死循环。把工具从 2 个加到 20 个，救不了一个规划能力弱的模型。

# GPT-4o vs GPT-4.1：量化差距

用 Aider polyglot 榜单（225 题多语言代码编辑，最接近"agentic 编辑 + 测试循环"的公开代理指标）：

| 模型 | 通过率 | 格式正确率 | 备注 |
|---|---|---|---|
| **gpt-4.1** | **52.4%** | 98.2% | 与 Claude 3.5 Sonnet 同级 |
| chatgpt-4o-latest (2025-03) | 45.3% | **64.4%** | 格式正确率暴跌 |
| gpt-4o-2024-08-06 | 23.1% | 94.2% | |
| gpt-4o-2024-11-20 | 18.2% | 95.1% | |
| gpt-4o-mini | 3.6% | — | |

**几个关键观察：**

1. GPT-4.1 相对 GPT-4o 提升约 **1.5–2.9 倍**，是代际差距而非微调。
2. GPT-4o 的"**格式正确率**"明显更差——它会输出破坏 diff 结构的内容。在纯 agentic loop 里，一次 malformed 编辑就意味着这轮失败甚至需要回滚，浪费大量 token。
3. SWE-bench Verified（更偏 agentic shell + patch）上大致是：GPT-4o 用好的 scaffold 约 $30\%$ 出头，GPT-4.1 约 $54\%\!-\!55\%$。

<details>
<summary><strong>GPT-4o 具体会在哪些地方崩（展开）</strong></summary>

- **长程状态丢失**：几十轮后忘记原始目标或隐含约束（例如"别动 public API"）。
- **死循环**：反复执行同一条失败命令，不做策略调整。
- **编辑不精确**：倾向整文件重写而非最小 diff，容易带入无关改动。
- **错误恢复弱**：看不懂复杂 `stack trace` / 非零退出码，误判根因。
- **幻觉成功**：没跑测试就宣布"done"。
- **上下文管理差**：不会主动裁剪或总结冗长的构建/测试输出，很快撑爆窗口。

</details>

<details>
<summary><strong>GPT-4.1 改善了什么、还缺什么（展开）</strong></summary>

**改善：**
- **1M context**（GPT-4o 只有 128k）——对读大仓库、吞长日志极其关键。
- 更强的指令遵循与 diff 格式稳定性（格式正确率从 64% 升到 98%）。
- 工具调用循环更稳，更愿意"先看再改"。

**仍缺：**
- GPT-4.1 是**非推理模型**，没有 interleaved thinking。真正复杂的多步规划（先定位再重构，跨 5 个文件的连锁修改）依然不如 o3 / Claude extended thinking 系列。
- 在长任务上仍会出现"过早收敛"。

</details>

# 实操判断

- **单文件 bug、写脚本、跑命令、格式化** → GPT-4o 勉强能用，别指望它自己闭环验证。
- **多文件、需要调试循环的中长任务** → 至少 GPT-4.1 或 Claude 3.5+ Sonnet。
- **严肃的 repo 级 / 需要规划的任务** → 上 reasoning 模型（o3、o4-mini high 或 Claude thinking）。

**若只能用弱模型（如 GPT-4o），靠 scaffold 补偿：**
强制 TDD（先写/跑测试）、每步限制工具调用次数、自动总结历史、外层脚本检测死循环并打断、把编辑约束成严格 search-replace 格式。

一句话总结：**工具数量不是门槛，模型的长程 agentic 能力才是。** 两个工具足够，GPT-4.1 能跑，GPT-4o 能跑但会频繁"半途而废"。
