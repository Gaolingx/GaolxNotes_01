# 零样本视觉模型与任务

## 🧑‍💻 User

图像分类中，要zero shot可以CLIPI 系，要detection可以grounding dino系，那么还有哪些可以用的？

---
## 😀 默认助手 (7)

你这个问题其实隐含了一个二维矩阵：**任务 × 词表是否开放**。CLIP 负责的是“图文对齐的通用编码器”这个角色，Grounding DINO 负责的是“文本条件下的开放词表检测器”。按照这个视角，能补位的模型还有很多，下面按任务分块列。

---

## 0. 先看全景矩阵

| 任务 | 闭集（要训练） | 开放词表 / zero-shot | 代表模型 |
|---|---|---|---|
| 分类 | ResNet / ConvNeXt / ViT | 双塔图文对齐 | CLIP、SigLIP 2、MetaCLIP 2、PE |
| 检测 | Faster R-CNN / DETR / YOLO | 文本条件检测 | Grounding DINO、OWLv2、YOLOE |
| 分割 | Mask2Former | 可提示 + 开放词表 | SAM 3、FC-CLIP、CAT-Seg |
| 深度 | 单目深度 | 零样本泛化 | Depth Anything V2/V3 |
| 表征（通用 backbone） | — | 自监督 | DINOv3、AIM |

---

## 1. Zero-shot 分类：CLIP 之外的几条路线

<details>
<summary><b>1.1 双塔图文对齐系（CLIP 的直接替代/升级）</b></summary>

| 模型 | 特点 | 什么时候选它 |
|---|---|---|
| **SigLIP / SigLIP 2** | sigmoid loss 替代 softmax，小 batch 也能训；SigLIP 2 加了 captioning + self-distillation | 目前**性价比最高的 CLIP 替代**，分类/检索普遍优于同规模 CLIP |
| **OpenCLIP** | 开源复现 + 多规模权重库（含 DataComp 系列） | 需要一堆不同尺寸权重做消融 |
| **EVA-CLIP / EVA-02** | 蒸馏自 EVA 视觉塔，视觉侧很强 | 需要强视觉特征，且能接受大模型 |
| **MetaCLIP / MetaCLIP 2** | 数据清洗策略（按概念均衡采样） | 追求原始图文对齐质量 |
| **DFN** | 数据过滤网络，Apple 系 | 高质量小数据偏好 |
| **Perception Encoder (PE)** | Meta，对标 CLIP 但感知任务更强 | 检测/分割下游也想要同一个编码器 |
| **MobileCLIP / JinaCLIP v2** | 端侧 / 长文本支持 | 移动端、需要长 caption |
| **Chinese-CLIP / AltCLIP / Taiyi** | 中文对齐 | 中文场景（CLIP 原版中文很弱） |

**领域特化 CLIP**（这些在垂直场景吊打通用 CLIP）：`BiomedCLIP`、`PLIP`(病理)、`CONCH`、`MedCLIP`、`RemoteCLIP`、`SkyCLIP`、`BioCLIP 2`(物种细粒度)。
</details>

<details>
<summary><b>1.2 纯视觉自监督：不用文本也能 zero-shot</b></summary>

**DINOv2 / DINOv3**、**AIM**、**MAE** 这类模型本身没有文本塔，但：

- 用 **kNN / linear probe / 原型匹配** 就能做 few-shot 分类，小样本下常超过 CLIP
- **DINOv3** 的密集特征（dense feature）质量很高，是检测/分割 head 的首选底座
- 适合“类别是视觉概念、不好用文字描述”的场景（缺陷、纹理、医学影像）

> 实践中常见组合：**DINOv3 特征 + 少量原型** 做闭集，**SigLIP 2** 做开放词表兜底。
</details>

<details>
<summary><b>1.3 少样本适配（few-shot 提升 10~30 个点）</b></summary>

CoOp / CoCoOp（prompt learning）、**Tip-Adapter**（training-free，cache 检索）、MaPLe、PromptSRC、CLIP-Adapter。
代价极低，每类 4~16 张就能显著提升，这部分常常被忽略但收益最大。
</details>

---

## 2. 开放词表检测：Grounding DINO 系之外

| 家族 | 模型 | 定位 |
|---|---|---|
| **GLIP 系**（最早的 grounding 检测范式） | GLIP、GLIPv2、**DetCLIP v1/v2/v3** | 学术基线，DetCLIP v3 在开放词表上仍有竞争力 |
| **Grounding DINO 系** | Grounding DINO (Swin-T/B)、**1.5 Pro/Edge**、**1.6**、**DINO-X**、MM-Grounding-DINO | 现在的主力，DINO-X 支持文本/视觉/自定义 prompt |
| **OWL 系** | OWL-ViT、**OWLv2**（自训练+自蒸馏，规模大时很强）、OWL-ViT2 | 架构最简洁（CLIP backbone + 轻头），好改好部署 |
| **实时 YOLO 系** | **YOLO-World**、**YOLOE**（text / visual / prompt-free 三种 prompt）、YOLO-UniOW | 要速度就上这个，YOLOE 已接近闭集 YOLO 的延迟 |
| **Encoder-Decoder 通用** | **Florence-2**（一个模型同时做 OD / 区域描述 / OCR）、OmDet-Turbo、APE | 一个模型多任务，工程上省事 |
| **MLLM 直接 grounding** | Qwen2.5-VL、InternVL3、Molmo、Kosmos-2、Shikra、GLaMM | 复杂指代、需要推理时；但坐标精度和速度不如专用检测器 |
| **开放词表计数** | **CountGD**（Grounding DINO + 计数头）、**T-Rex2**、GeCo、CounTR | “数出图里有多少只 X” 是独立任务，别指望检测器直接给对 |

⚠️ **别踩的坑**：开放词表检测器在**小目标、密集场景、长尾类**上普遍打不过同规模闭集检测器。生产上常见做法是“闭集检测器打主力 + 开放词表做新类冷启动”。
</details>

## 3. 分割：这是近年变化最大的一块

**可提示分割（promptable）**

- **SAM** → **SAM 2**（视频、带记忆）→ **SAM 3**（Promptable Concept Segmentation，**直接用文本/图像范例出所有实例 mask**，某种程度上把 Grounding DINO + SAM 的组合吃掉了）
- 轻量化：**EfficientSAM**、**MobileSAM**、**FastSAM**、**HQ-SAM**（高质量边缘）

**零样本语义分割**（逐像素分类，不是出 instance）

- `LSeg`、`OpenSeg`、`OVSeg`、`SAN`、**`CAT-Seg`**（当前强基线）、**`FC-CLIP`**（单模型全景开放词表）、`TCL`、`MaskCLIP`

**开放词表实例 / 全景**

- `ODISE`、`X-Decoder`、`SEEM`、**`Grounded-SAM`**（经典 detect-then-segment 组合）、`Semantic-SAM`

**视频**：`SAM 2` / `XMem` / `DEVA` / `Grounding-Prompter` / `SAMURAI`（带运动先验的跟踪）

> 选型口诀：**要 instance + 文本 → SAM 3 或 Grounded-SAM2；要逐像素语义图 → CAT-Seg / FC-CLIP；要速度 → FastSAM / EfficientSAM。**
</details>

## 4. 顺带覆盖的其他任务（常被漏掉但很实用）

| 任务 | 可用模型 | 备注 |
|---|---|---|
| 单目深度 | **Depth Anything V2/V3**、Marigold、Metric3D v2 | V3 已能输出带尺度的深度 |
| 通用表征 backbone | **DINOv3**、PE、SigLIP 2 vision tower | 换底座比换 head 收益大 |
| 零样本异常检测 | **AnomalyCLIP**、WinCLIP、**AnomalyDINO**、MuSc、INP-Former | CLIP 系 + DINOv2 系两条路都行 |
| 3D / 场景理解 | `OpenScene`、`ConceptFusion`、`LERF`、`Gaussian-Grouping`、`SAM3D` | 开放词表 3D 还很早期 |
| 遥感 / 医疗 | RemoteCLIP、SkySense；MedSAM、SAM-Med2D、Text4Seg | 垂直 domain 一定用专模 |
| OCR / 文档 | **Florence-2**、GOT-OCR2、dots.ocr | 一个模型搞检测+识别 |

---

## 5. 一句话选型建议

- **只想一个模型打所有开放词表任务** → `Florence-2` 或 `SAM 3` + `SigLIP 2`
- **分类/检索要 SOTA 且权重好拿** → `SigLIP 2`，中文选 `Chinese-CLIP` / `Taiyi`
- **检测要快** → `YOLOE`；**检测要准（复杂指代）** → `Grounding DINO 1.6` / `DINO-X`
- **小样本分类** → `DINOv3` 特征 + `Tip-Adapter`，往往比微调 CLIP 划算
- **工程最稳的组合** → `Grounding DINO` + `SAM 2`（生态成熟、可控）→ 新项目可以直接考虑 `SAM 3` 替代

---

**几个通用工程注意点**（比换模型更重要）：

1. **prompt 集成（prompt ensembling）** 能把 zero-shot 分类涨 2~5 个点，几乎免费
2. **阈值要按类别分别校准**，开放词表检测器的 score 不是概率
3. **多尺度 + 切片推理** 对小目标提升巨大（尤其遥感/工业）
4. 开放词表模型的 **box 精度普遍低于闭集检测器**，下游如果要做尺寸测量，别直接用它
