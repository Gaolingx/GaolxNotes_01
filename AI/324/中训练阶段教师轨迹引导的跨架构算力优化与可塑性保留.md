## 一、先把想法形式化：三个必须回答的问题

| 问题 | 为什么关键 | 你的想法里隐含的答案 |
|---|---|---|
| **① 轨迹的不变量是什么？** | 异构学生和教师之间没有任何参数对应关系，因此“参数轨迹” $\{\phi_j\}$ 根本不可比 | 只能是**函数轨迹**或**更新场轨迹** |
| **② 什么叫“回放到历史训练状态”？** | 是把学生拉回旧 checkpoint，还是把教师注入旧 checkpoint？ | 我理解是：从学生历史状态复现 rollout，并在该点上施加教师约束 |
| **③ “保持”保持什么？** | 是保持教师常驻 state，还是保持注入效果不衰减？ | 我理解两者都要 |

记号：学生 $s_\theta$，教师 $t_\phi$，教师轨迹 $\mathcal{T}=\{(\phi_j,u_j)\}_{j=0}^{J}$（$u_j \equiv \phi_{j+1}-\phi_j$）。取探针集 $\mathcal{P}=\{x_m\}$（无标签即可），定义

$$
F^S_k = f_{\theta_k}(\mathcal{P}),\qquad F^T_j = f_{\phi_j}(\mathcal{P})
$$

**这是唯一一个在异构架构之间合法可比的对象。** 一旦引入它，“轨迹”就可以干净地拆成两层：

$$
\text{状态级：} F^S_k \;\longleftrightarrow\; F^T_{j(k)} \qquad\text{速度级：} V^S_k \;\longleftrightarrow\; V^T_{j(k)},\quad V \equiv F_{\cdot+1}-F_{\cdot}
$$

> **核心洞察（我认为这是你真正想做的东西）**：现有蒸馏全部在匹配 $F$（结果），而你说的“轨迹能力”其实是 $V$——**教师“怎么学”的向量场**。而 $V$ 恰恰比 $F$ 更架构无关：$F$ 会被归纳偏置染色（ResNet 和 ViT 收敛到不同函数），但*学什么、先学什么、更新多大幅度*相对更普适。这是一个可证伪的假设，也是本工作最有力的卖点。

⚠️ 如果你说的“轨迹”是 **LLM agent 的推理 rollout**，那整个设计换成 on-policy distillation 的框架（见第四节），逻辑同构但工程量完全不同。

## 二、建议的方案：**速度场蒸馏 + 支配式回放 + 可塑性预算**

我叫它 TRD（Trajectory Replay Distillation），三个损失按“轨迹性”从弱到强：

```python
# ---- 训练状态 S = (theta, opt_state, teacher_buffer, alignment, probe_sampler) ----
teacher_buffer = load_checkpoints(T)     # 只读 buffer，永不参与梯度，才可能"保持"
A = AlignmentOp()                        # 异构对齐算子：stitching head / 低秩字典

for step in range(K):
    x_probe = probe_sampler()            # 关键：探针随学生 on-policy 刷新

    # (1) 状态级：经典 KD，端点对齐
    L_state = D(f_s(x_probe), A @ f_t(phi[j], x_probe))

    # (2) 速度级：匹配"功能位移"，这是"轨迹能力"本体
    L_vel = || (f_s(theta_plus, x) - f_s(theta, x))
              - A @ (f_t(phi[j+1], x) - f_t(phi[j], x)) ||^2

    # (3) 回放级：从历史状态复现 m 步，要求"不落后于"教师
    theta_i, j_i = replay_buffer.sample()          # 学生的历史状态 + 对应的教师轨迹位置
    theta_i_m = unroll(theta_i, m)                 # 复现 m 步
    L_prog = relu( prog(f_s(theta_i_m)) - prog(A @ f_t(phi[j_i+m])) )

    # (4) 可塑性预算：限制偏离 base 的方向与幅度
    L_plastic = beta * || M ⊙ (theta - theta_base) ||^2

    loss = L_state + λ1*L_vel + λ2*L_prog + L_plastic
```

### 四个非显然的设计选择（每个都不是随便选的）

**1. 用“支配约束”$\mathrm{relu}(\cdot)_+$ 而不是等式约束。**
这是避免 MTT 的**累积失配问题（AMP）** 的唯一办法。ATT（ECCV'24）明确指出：强制学生贴合教师的每一步轨迹，会让学生“扭曲地迎合教师轨迹”，**跨架构时直接崩**。等式约束对异构是致命的；单向不等式约束既保留了“不落后”的语义，又允许学生**超越**教师（这正是 Kickstarting 的 self-regulating 设计）。

**2. 时间对齐用“功能进度”而非步数。**
学生小、教师大，步数对齐毫无意义。用 $j(k)=\arg\min_j |\mathrm{prog}(F^S_k)-\mathrm{prog}(F^T_j)|$，即在“学到多少”这个度量上对齐。**这一点我几乎没看到有人做过**，值得单独作为一个贡献点写。

**3. 探针集必须轮换，且不能用于计算 loss 的同一批。**
否则 $\mathrm{prog}$ 会被 hack（学生只要在这批探针上超过教师就白拿 loss）。用一个 held-out 探针池轮换。

**4. 对齐算子 $\mathcal{A}$ 要约束。**

```python
# 让它别偷偷学会所有东西
A = nn.Linear(...)  # 或低秩
# warm-up 1000 步后冻结 A，或加 orthogonality / 秩惩罚
```
$\mathcal{A}$ 一旦无约束地自由学习，它就会自己变成“知识容量”，你就分不清到底传的是轨迹还是 $\mathcal{A}$ 的容量了。

## 三、“把 teacher 放进训练状态并保持”的三种落地方式

| 方式 | 具体做法 | 优缺点 |
|---|---|---|
| **A. 只读 buffer**（推荐） | 教师 checkpoint 序列 $+$ 各自 $u_j$ 作为 frozen buffers 常驻。任何时候可重新施加约束，**包括下游微调之后** | 干净、可复现；“保持”= 随时可重新 anchor。代价是存储 |
| **B. EMA shadow teacher** | $\phi \leftarrow \gamma\phi + (1-\gamma)\theta$，教师本身成为 state | 零存储。但这就退化成**自蒸馏**（Mean Teacher / Born-Again 家族），失去了“异构教师”的意义。**适合做第一个 sanity check** |
| **C. 共演化教师** | 教师也在训（Deep Mutual Learning / CoPD 的路子） | “保持”变成“track”，可解决 teacher-student gap，但两套优化器 |

**存储成本的正解**：不要存全部 checkpoint。两条路——
- **稀疏存 + 插值重建**：MCT（Matching Convexified Trajectory）的凸组合、或 WSM（checkpoint merging 可精确模拟 LR decay）——**轨迹可以“合并”出来，不必“存”下来**；
- **低秩/量化**：task-vector quantization 那套。

## 四、“保留 base model 后期微调能力”——这半个目标决定成败

这是审稿人第一个会问的地方。四条路线，按对 base 的侵入性递增：

| 路线 | 机制 | base 是否 bit-exact 保留 | 备注 |
|---|---|---|---|
| **(a) 非破坏式** | 全部蒸馏进 LoRA / adapter / side-branch，$\theta_{\text{base}}$ 一个字都不改 | ✅ 数学上保证 | **强烈建议作为主 baseline**，先把“能学到”验证掉 |
| **(b) 锚定插值** | $\theta = (1-\alpha)\theta_{\text{base}} + \alpha\theta_{\text{ft}}$，扫 $\alpha$ | ❌ 但可控 | WiSE-FT / model-soup 家族；跨异构噪声场景下**最鲁棒**的一招（见下“模型合并在野外”的结论） |
| **(c) 子空间保护** | 把蒸馏更新投影到 base 关键方向的正交补 | ❌ | TALL-masks / Consensus Merging / MergeHEIR 的 null-space projector |
| **(d) 零门控扩增** | 加旁路参数、初始化时门控≈0，函数严格不变地“扩容” | ❌ 但函数保持 | Net2Net / function-preserving growth；“What does model growth really add?”（2026）证明零门控增广**恰好增加 $K$ 维功能方向且不被后续训练抹掉**——这几乎是为你的需求量身定做的机制 |

### 必须测的可塑性指标（不测就等于没做）

- **下游 few-shot 微调增益**：蒸馏后在留出任务上 FT，和 base 自己的 FT 曲线比（这直接回答“保留微调能力”）
- **base 能力遗忘**：MMLU 类基准 / OOD robustness
- **可塑性诊断**：effective rank、NTK 谱、死单元比例、weight norm 增长、churn
- **丧失可塑性的起始 step**：如果在你的方法下提前了，方案就失败了

⚠️ **一个必须警惕的理论风险**：你持续把学生 anchor 到一个**固定**教师函数上，这恰好是 DASH（NeurIPS'24）研究的“stationary 数据 warm-start”场景——**那个场景下可塑性必然下降，机制是噪声记忆**。所以你需要 DASH 的 directional shrinking：在每次“回放进入旧状态”时，先做方向性收缩。或者用 L2 + LayerNorm（Lyle et al.）这套最便宜的组合。

## 五、Previous work 地图

<details>
<summary><b>【区块 1】轨迹匹配式蒸馏 —— 最直接的祖先，也是最重要的反证</b>（点击展开）</summary>

- **MTT: Dataset Distillation by Matching Training Trajectories** (Cazenavette et al., CVPR'22, arXiv 2203.11932) — 你的想法在*数据*上的对应版本：预存 expert trajectory，学生 rollout 后匹配。**必读，必引**。
- **ATT** (ECCV'24, arXiv 2407.14245) — 提出 **AMP（累积失配）**，明确指出轨迹匹配**跨架构时会失真**。这是你的方案最大的威胁，必须正面回应。
- **MCT: Matching Convexified Trajectory** (arXiv 2406.19827) — 用教师轨迹的凸组合做引导，解决存储和稳定性。
- **Inf-Match: Dataset Distillation by Influence Matching** (CVPR'26, arXiv 2607.16859) — **反向论点**：过程匹配不如“结果对齐”。你要论证的正是“在模型蒸馏里恰恰相反”。
- **The Composition Gap in Dataset Distillation** (arXiv 2609.34343) — 压缩后的轨迹**不满足可组合性**。如果你打算融多个教师轨迹，必读。
- **MKDT: DD via Knowledge Distillation** (ICLR'25, arXiv 2410.02116) — KD + 轨迹匹配的组合先例。

**这一段给你的关键判断**：轨迹匹配在 *data distillation* 里已被证明跨架构泛化差。你要么证明 *model distillation* 不同（因为不变量从“样本”换成了“函数位移”，维度更高更结构化），要么绕开它。我倾向于前者成立——这正是可发表的科学问题。
</details>

<details>
<summary><b>【区块 2】“教师的中间状态即教师” —— 你的“回放到历史状态”的先例</b></summary>

- **Efficient Knowledge Distillation from Model Checkpoints** (Wang et al., NeurIPS'22, arXiv 2210.06458) — **中间 checkpoint 比最终模型是更好的教师**，且弱 checkpoint 的 snapshot ensemble 能打赢强队。这是你方案最坚实的经验支撑。
- **HetComp** (Kang et al., WWW'23, arXiv 2303.01130) — ⭐ **最接近你的 prior art**：从**异构模型**蒸馏，并用**教师的训练轨迹**构造由易到难的知识序列，且按学生当前学习状态动态调整难度。**必须精读，你的差异化必须相对它来说清楚。**
- **Kickstarting Deep Reinforcement Learning** (Schmitt et al., 2018, arXiv 1803.03835) — ⭐ 学生模仿教师的**中间进步过程**（而非最终策略），架构无约束，且能**超越**教师。你的“支配约束”思想源头在这里。
- **Superteacher / Born-Again Networks / Self-distillation / Snapshot Ensemble / MrKD** — “教师=自己的过去”这一族，最便宜的第一个实验。
- **CoPD: Co-Evolving Policy Distillation** (arXiv 2604.27083) — 专家与学生在 RL 中并行训练、互为教师。对应你的“C. 共演化教师”。

</details>

<details>
<summary><b>【区块 3】异构学生的对齐机制</b></summary>

- **OFA-KD** (arXiv 2310.19444) — 把中间特征投影到 logits 空间再对齐，丢弃架构特有信息。最简洁的异构 KD 骨架。
- **Heterogeneous KD via Information Flow Modeling** (CVPR'20, arXiv 2005.00727) — 引入 **auxiliary proxy teacher** 做“解释者”，并显式按训练阶段给不同监督。**这几乎是“按轨迹阶段分配监督”的原始论文**。
- **SPOFA** (arXiv 2606.24557) — 用梯度的 EMA **历史基线**检测梯度冲突。异构 KD 里已经把“轨迹”当 state 用了。
- **LFCC / UHKD / HeteroAKD / CoCaRS / SFKD** — 频域/对比/解耦对齐的一系列工程改进，可当 baseline 池。
- **LLM 侧（tokenizer 异构）**：**ULD**（最优传输，TMLR'25）、**Approximate Likelihood Matching**（Minixhofer, NeurIPS'25）、以及 2026 那批 **cross-tokenizer OPD**（BPM / SimCT / CAST / ESCD / X-Token / DVLM）。如果学生教师 tokenizer 不同，这些是你的 $\mathcal{A}$ 的现成实现。

</details>

<details>
<summary><b>【区块 4】on-policy / 学生驱动式蒸馏（如果你的“回放”要 refresh）</b></summary>

- **GKD / MiniLLM / DistiLLM** 与 **DAgger** 视角：蒸馏 = 模仿学习，学生自己的状态分布才是正确的监督分布。
- **SCoRe** (ICML'26, arXiv 2509.14257) — 学生生成轨迹，教师只纠正**最早的一个错误**。解决累积误差。
- **Relay-OPD** (arXiv 2607.26057) — 教师在检测到失败前缀时**接管一小段**，然后交还学生。**这是“把教师临时注入训练状态”最干净的实现**。
- **WAM-OPD / PWTR** (arXiv 2609.34250) — **prefix-weighted trajectory replay**：固定轨迹池 + 按前缀重加权，避免重复 rollout。你的 replay buffer 设计可以直接抄这个。
- **Reverse-KL OPD 的理论极限** (arXiv 2610.30844) — 首次给出 online vs offline 蒸馏的 minimax 界：**教师生成的轨迹在 offline 下已足够**。这直接影响你要不要做 on-policy replay 的成本论证。
- **T3S** (arXiv 2601.10348) — 持续蒸馏会撞上性能瓶颈，机制是 Imitation-Anchor token 抑制了 yet-to-learn token。你做“持续回放”一定会遇到这个。

</details>

<details>
<summary><b>【区块 5】保 base 可微调 / 可塑性（这一块文献极多，只挑关键）</b></summary>

**机制类**
- **Loss of plasticity 主线**：Dohare et al. 的 continual backpropagation（arXiv 2306.13812）；Lyle et al. 的机制分解（arXiv 2402.18762）；Lewandowski et al. 的曲率解释（arXiv 2312.00246）；Spectral Collapse（arXiv 2509.22335）；UPGD（ICLR'24）；ReDo；AdaLin；Deep Fourier Features；ARROW（ViT 版）。
- **DASH** (NeurIPS'24, arXiv 2410.23495) — ⭐ warm-start 场景下可塑性下降的机制（噪声记忆）+ directional shrinking。**你的方案会精确落进这个失败模式。**
- **Experience Replay Addresses Loss of Plasticity** (arXiv 2503.20018) — ⭐⭐ **对你极其有利的一条**：experience replay 本身就能消除可塑性丧失。你的 replay 机制**同时**在做“传轨迹”和“保可塑性”两件事——这是一个漂亮的统一叙事。
- **Can Scale Save Us From Plasticity Loss in LLMs?** (arXiv 2606.24752) — 可塑性丧失的 **scaling law**，onset 随模型规模次线性增长。做消融时可以用来预测。

**保护 base 类**
- **WiSE-FT / Model Soups**；**MonoSoup**（arXiv 2602.09689，单 checkpoint SVD 分离 task / noise 方向，data-free、无超参）；**TALL-masks + Consensus Merging**（ICML'24）；**MergeHEIR** 的 null-space projector（arXiv 2609.32422）。
- **Zero-gated function-preserving growth**（arXiv 2607.14571）— 增广恰好多出 $K$ 维功能方向且持久。做 (d) 路线的理论依据。
- **From Memorization to Parameter Interference** (ICML'26, arXiv 2506.14126) — 过度的专家微调会**破坏可合并性**，早停能救。寓意：**想保住 base 可复用性，就别把蒸馏做到底。**

**警钟类**
- **A Systematic Study of In-the-Wild Model Merging for LLMs** (TMLR'26, arXiv 2511.21437) — 异构、冲突更新的合并在 LLM 上**基本只有 Task Arithmetic 靠得住**。
- **On Emergent Capabilities and Model Merging** (arXiv 2609.24504) — 合并会**更快稀释**只有单亲携带的能力。这直接预告了“轨迹能力 + base 能力”会互相吃。
- **Model Growth 的反思** (arXiv 2607.14571) — 几何容量与保留函数**解耦**：增容不等于保函数。别用参数数当指标。

## 六、最接近的 5 篇 & 你的 novelty 到底在哪

| 排名 | 论文 | 重叠 | 你相对它新增什么 |
|---|---|---|---|
| 1 | **HetComp** (WWW'23) | 异构教师 + 教师训练轨迹 + 由易到难 | 它只用轨迹做**课程排序**（teacher→student，一次性的）；你把轨迹当**可回放状态**，注入**更新场**，且显式约束可塑性 |
| 2 | **MTT** (CVPR'22) | 预存轨迹 + rollout 匹配 + replay | 它蒸馏的是**数据**，且等式匹配、跨架构失败；你蒸馏的是**模型**、用**支配约束**、不变量换成函数位移 |
| 3 | **Efficient KD from Model Checkpoints** (NeurIPS'22) | 中间 checkpoint 更好当教师 | 它把中间模型当**静态教师**；你要的是 checkpoint **之间的差分** |
| 4 | **Kickstarting** (2018) | 学生模仿教师“过程”、自调节、可超越 | 它是 RL、同任务、无“历史状态回放”、无 base 保护 |
| 5 | **DASH / Experience-replay-plasticity** | warm-start 可塑性、replay 保可塑性 | 它们不涉及知识迁移；你把“保可塑性”变成蒸馏目标的一部分 |

**明确的研究空白**：把**教师的更新场（function-space velocity）**——既不是输出、也不是权重——作为蒸馏对象，并把它做成**持久可回放状态**，同时给出**显式可塑性预算**。这个组合我没看到。你的论文骨架应该是：

1. 定义“轨迹能力”为架构无关的泛函不变量（$V$ 或 influence function）；
2. 提出支配式回放目标，绕开 AMP；
3. 提出可塑性预算式注入，使 base 的 FT 能力可量化保留；
4. 关键实证：**在模型蒸馏里，轨迹级监督比状态级监督跨架构泛化更好**——正好和 data distillation 的结论相反，这个张力就是卖点。

## 七、能立刻验证的最小实验（建议按此顺序，卡不住就别往下走）

```text
第 0 步｜自轨迹 sanity check（1–2 天）
  教师 = 学生的早期 checkpoint（Born-Again 设定）
  只加 L_vel，不加 L_prog。问：L_vel 下降能带来下游任务学习曲线形状的改变吗？
  → 如果不能，"速度场可迁移"这个假设就死了，早点知道。

第 1 步｜同族异构（ResNet→ViT，CIFAR-100）
  对比：L_state only / +L_vel / +L_prog / 等式 vs 支配
```

# 判词：有真东西，但位置需要挪动

你把它说成“类蒸馏非蒸馏”，直觉是对的；但你现在这个表述把**三个互相冲突的目标**揉成了一根绳，所以才会显得“没那么简单”：它确实不简单，因为三方在互相拆台：

| 目标 | 它想要什么 | 它会破坏什么 |
|---|---|---|
| **省算力** | 便宜、粗糙、低维的监督信号 | 想省钱就别传高维信息 → 跨架构难 |
| **跨架构** | 高维、结构化、架构无关的不变量 | 越丰富越贵 → 省不了钱 |
| **保留学习能力** | **不压缩**学生自己的学习信号 | 蒸馏的本质就是压缩 → 与省钱同源冲突 |

**所以真正的判断标准是：你的核心目标是省算力，那么“轨迹”这条路对省钱是劣解，对“保留学习能力”却可能是唯一有机制的解。** 正确的做法是**用便宜的路径省钱，只在“保 headroom”这个便宜路径解决不了的缺口上，才用轨迹**。下面我把账算清。

## 一、先算账（这一节决定一切）

学生 $N$ 参数、教师 $M=\lambda N$、语料 $D$ tokens：

$$
C_{\text{student}} = 6ND,\qquad C_{\text{teacher}} = 2MD = 2\lambda N D
$$

$$
\boxed{\ \frac{C_{\text{teacher}}}{C_{\text{student}}} = \frac{\lambda}{3}\ }
$$

| 教师/学生规模比 $\lambda$ | 教师推理 / 学生训练 | 需要多少倍加速才回本 |
|---|---|---|
| 2× | 0.67 | > 1.67× |
| 10× | 3.3 | > 4.3× |
| 50× | 16.7 | > 17.7× |

**这就是最关键的一点：全量 token 级蒸馏在预训练阶段几乎必然亏本**，因为教师做前向的成本比学生做训练还高。业界论文几乎都不摊销这一项，所以看起来“省了”。

再看存储（$V=128\text{k}$，fp16）：

| 阶段 | $D$ | 全量 logits | top-8 稀疏 |
|---|---|---|---|
| 预训练 | 1T | **256 PB** | 48 TB |
| 中训练 | 27B | 6.9 PB | **1.3 TB** ✅ |

**结论 1：预训练阶段做 token 级蒸馏在算力和存储上都不成立。** 别做。

回本条件严格写出来（教师被 $k$ 个学生共享、只标注比例 $f$ 的 token）：

$$
R > 1 + \frac{f\lambda}{3k}
$$

三个杠杆很明确：**共享教师 $k$↑、稀疏标注 $f$↓、或者 $f\to 0$（根本不用教师输出）**。

---

## 二、所以真正的甜区是**中训练**，而且理由比“便宜”强得多

**(a) 算力上**：$D$ 从 1T 降到 ~27B（PRISM 的规模），教师成本掉了 40 倍，$f$ 可以取 1 甚至更大。

**(b) 更重要的是——中训练恰好就是“学习能力”的形成阶段**：

> **PRISM**（arXiv 2603.17074）的实测：中训练**重构了 >90% 的权重**，而 RL 只做**稀疏的、前置加载的 ~5% 参数改动**；RL 对**任何起点**都施加**相同**的权重改动，但**只在 mid-trained 模型上有效**；中训练与 RL 之间的 CKA 保持 >0.998。
>
> → 中训练不是“多训一点”，而是**把模型放进一个 RL 才可用的 basin**。

> **On the Interplay of Pre-/Mid-Training and RL**（arXiv 2512.07783）：RL 只有在**预训练留下足够 headroom**、且数据落在**能力边缘**时才产生真实能力增益（pass@128）。

**这两条合起来，就是你这个课题的正确命题：**

$$
\text{用教师降低中训练成本} \;\wedge\; \text{不要因此吃掉 headroom}
$$

**结论 2：把战场从 pre-training 移到 mid-training。** 在那里“省算力”真的成立，“保留学习能力”才可测，而且它的评价指标已经现成（中训练后的 RL 增益）。

**结论 3（这句话是整条路的核心）**：你要做的是 **“蒸馏算力，不蒸馏 headroom”**。所有现有蒸馏工作都在优化 loss/benchmark，没人把 *post-trainability 的保留* 当作一等目标，这才是研究空白。

---

## 三、为什么普通蒸馏**必然**伤害学习能力（机制，不是猜测）

这不是玄学，有三条已知机制：

1. **熵/残差塌缩**：教师是确定性目标 → 学生的残差误差被抹平 → RL 没有可优化的“边缘”。（对应 headroom 的消失）
2. **Token 层级的不对称**：**T3S**（arXiv 2601.10348）发现持续蒸馏会让 confidence 分叉成 *Imitation-Anchor tokens*（快速锚住优化）和 *yet-to-learn tokens*（被抑制），**两类 token 不能共存**是持续蒸馏退化的根因。这就是“蒸馏吃掉可学习空间”的微观证据。
3. **模仿的复合误差**：**SCoRe**（arXiv 2509.14257）显示全轨迹模仿会被 teacher-student gap 的复合误差拖垮，必须改成“只纠正最早错误 + 短程 RL”。

反过来说，**你要的机制必须能抵抗这三条**。这就给了你一组明确的消融坐标（下面第五节）。

## 四、你的“轨迹”在哪一格：真值表

我把候选机制按“每个目标的有效性 / 成本”排了一张表。**你的原方案在最后一列是唯一的 ✅，在第一列是最差的 ❌**：

| 机制 | 省算力 | 跨架构 | 保 headroom | 教师侧成本 | 结论 |
|---|---|---|---|---|---|
| **函数保持增长 / init 迁移**<br>(HyperCloning, bert2BERT, LiGO) | ✅✅ 20–50%，且 **growth 改变 scaling 指数** | ❌ 需同族 | ✅ 学生仍全量自训 | 0 | **省钱首选** |
| **语料级离线蒸馏**<br>(MiniPLM, 分布重加权) | ✅ 一次推理、多学生、**跨 family** | ✅ | ⚠️ 未知 | $O(D)$ 一次 | **跨架构首选** |
| **RL/教师引导的数据调度**<br>(ReMiT, OctoThinker) | ✅✅ $O(fD), f\ll1$ | ✅ 与架构无关 | ✅✅ 不动学习信号 | 极小 | **保 headroom 首选** |
| **checkpoint 合并模拟退火**<br>(WSM, WSD) | ✅✅ 免费 annealing | ✅ | ✅ | 0 | 纯工程红利，白拿 |
| **教师 checkpoint 序列当课程**<br>(Efficient KD from CKPT, HetComp) | ⚠️ | ✅ | ⚠️ | $O(k\cdot D)$ | 中间档 |
| **更新场 / 轨迹回放**（你的方案） | ❌ 最贵（unroll + 存轨迹） | ⚠️ AMP 风险 | ✅ **唯一有机制的** | 高 | **补丁，不是主线** |

**关键读法**：前三行已经能给你 20–50% 的算力节省和跨架构能力；它们**都没解决 headroom**。所以你的课题不该是“再做一个蒸馏方法”，而应该是：

> **已经用便宜手段省了算力、把学生放进对了的位置之后，怎么保证它还学得动？——用轨迹。**

这就从“我要发明一个蒸馏变体”（审稿人会问：和 HetComp/MiniPLM 差别在哪）变成“我识别并解决了一个现有省钱路径的副作用”（审稿人无法说“已有人做过”）。

## 五、三个我能担保“有真东西”的题

<details>
<summary><b>题 A：教师当调度器，不当目标（成本最低、最可能是真新）</b> ⭐推荐先做</summary>

**做法**：教师**不提供任何 token 级目标**，只在一个小代理集（比如 0.1B tokens）上算 loss 曲线 / 难度梯度 / 学习顺序，用来定义学生的：
- mid-training 的 **token 排序与难度课程**（对应 HetComp 的 easy-to-hard，但用在 **mid-training 语料排序**而非 KD loss 上）
- **LR 衰减形状**（与 WSM 的“合并即退火”正交）
- 每个 token 的**更新幅度上界**（防止过早饱和）

**成本**：$O(fD)$，$f\sim 10^{-2}$。**装进 $R>1+f\lambda/3k$ 里，$f=0.01,\lambda=10$ → 只需 $R>1.03$。** 这是唯一能轻松回本的档位。

**为什么保 headroom**：学生仍然走完整 NTP，只是走得更聪明。没有任何 teacher 目标压熵。

**现有最接近**：ReMiT（用 **RL 模型** 重加权 mid-training token，不是用 **教师**）、OctoThinker（数据质量，不是轨迹）、DoReMi/DSIR（分布匹配，不看轨迹形状）。**“用教师轨迹的形状直接定义学生 schedule”我搜不到直接的**——但你必须自己再确认一遍，这是你唯一的判据。

**难度**：低。**风险**：“只是调了个更好的 schedule” → 见第六节的致命 null hypothesis。
</details>

<details>
<summary><b>题 B：中训练阶段的更新场回放 + 可塑性预算（你的原意，但要缩到 27B tokens）</b></summary>

把上一轮我给的 TRD 骨架**只用在 mid-training**，并且把目标函数从“匹配”改成“**约束**”：

$$
\mathcal{L} = \underbrace{\mathcal{L}_{\text{NTP}}}_{\text{主体，不许动}} + \lambda_1 \underbrace{\|V^S_k - \mathcal{A}V^T_{j(k)}\|^2}_{\text{更新场}} + \lambda_2 \underbrace{[\,\mathrm{prog}(F^S) - \mathrm{prog}(\mathcal{A}F^T)\,]_+}_{\text{支配，允许超越}} + \underbrace{\beta \|\Delta\|_{\text{null}}^2}_{\text{可塑性预算}}
$$

**三条让它不伤 headroom 的硬约束**（这是真正的技术贡献点，务必逐条消融）：
1. **保留 $\rho$ 比例的 token 只走纯 NTP**（~30–50%），不接任何教师信号 → 抗 T3S 的 Imitation-Anchor 塌缩
2. **可塑性预算放行在 base 的零空间**（TALL-mask / MergeHEIR 的 projector）→ 后续 RL 有方向可走
3. **teacher 侧做 EMA 平滑**，绝不回放到教师早期的噪声 checkpoint

**中训练规模下成本可接受**：$D=27\text{B}$ 时 top-8 logits 只要 1.3 TB；$\lambda=10$、$f=0.3$ → 需 $R>1.99$，也就是中训练里 2× 加速就回本——**这在 mid-training 尺度是有先例的**（见下）。

**难度**：中高。**为什么值得**：这是唯一能同时主张“省算力 + 跨架构 + 保可塑性”的机制。
</details>

<details>
<summary><b>题 C：把“growth 改变 scaling 指数”和“教师轨迹”接起来（最有理论味，风险最高）</b></summary>

**How Model Growth, Recursion, and Boundary Operators Influence Scaling Exponents**（arXiv 2609.19107）：模型增长**改变的是 scaling 的指数**，不是常数因子——7.4B 的 growth 模型用 **1/20 算力**持平 GPT-3 13B，而且**增益随规模放大**。

**对比**：蒸馏是**常数因子**（1.5–4×，随规模边际递减，见 Distillation Scaling Laws）；growth 是**指数**。**这是数量级上的差别，你的课题如果追“省算力”，这一条必须认真对待。**

**真新在哪里**：growth 需要决定**何时增容、增多少**（CAGE-NAS 的 functional gradient 判据）；**教师的轨迹恰好能告诉你“什么时候学生卡住了”**——因为教师在同一数据上的 loss 曲线下降形状是可参照的。于是：

> **教师轨迹 → 自适应 growth schedule → 指数提升提前到来**

这是一个干净的因果链，而且**每一环都有独立文献支撑**，中间那环是空的。

**难度**：高。但这是唯一可能做出“大结果”的方向。
</details>

## 六、判决实验：怎么判断自己是不是在做真东西

**指标必须换掉：**

| ❌ 别报 | ✅ 要报 |
|---|---|
| wall-clock 加速 | **达到同一 loss 的 student-side FLOPs**（含教师推理摊销，$6ND + f\cdot 2\lambda ND$） |
| 下游 benchmark 平均分 | **中训练后的 RL 增益**（pass@128 而非 pass@1）、RL sample efficiency |
| 参数量容量 | effective rank、functional Jacobian rank 增量（arXiv 2607.14571 的方法） |
| “没有灾难性遗忘” | **CKA(base, student)**、$\mathrm{KL}(\text{base}\|\text{student})$、entropy、residual loss gap |

**然后是那条决定生死的 null hypothesis：**

> $$
> H_0:\quad \text{“教师轨迹”的全部收益} \equiv \text{“一个调得更好的 LR schedule + data mix”}
> $$

**你必须击败一个被充分调优的 schedule/mix baseline**，否则你论文的结论就是“我找到了更好的超参”。我建议直接把这个 baseline 做成主对比表的第一行，并且在**它被调到你调不动的程度**之后再比。这个实验做在前面，能省你三个月。

**再加一个 falsification test**：把教师换成**同 loss、不同 family 的另一个模型**。如果收益不变 → 你传的是“通用的好 schedule”，和教师本人无关（这本身也是个结果，但就不是你要讲的故事了）。如果收益掉 → 教师确实是信息源，你的机制成立。

## 七、负面清单：什么情况下这条路是假的

| 信号 | 说明 |
|---|---|
| 教师/学生规模比 < 2× | 收益主要来自“更多有效步数”，不是轨迹 |
| 不摊销教师推理 FLOPs | 大多数公开结果都隐式忽略这一项 |
| 收益在 schedule baseline 调优后消失 | 你只是做了超参搜索 |
| 中训练 token 数 < 10B | 轨迹匹配的固定开销占比过高，不划算 |
| “保可塑性”靠早停/低 LR 得到 | 与轨迹无关，是普通正则的功劳 |
| 跨架构收益在 MiniPLM 式语料级蒸馏之后消失 | 说明你要的那部分信息，语料级已经给足了 |
| 只用 pass@1 衡量 RL 兼容性 | 会系统性高估（PRISM：RL 的真增益只在 pass@128 上暴露） |

- **Boomerang distillation / ADAPT** (arXiv 2608.22854) — 一次蒸馏产出 $L\times K$ 个模型，**摊销**成本的正解
</details>

<details>
<summary><b>“蒸馏吃掉 headroom”的证据链（你要解决的问题）</b></summary>

- **T3S** (arXiv 2601.10348) — Imitation-Anchor token 与 yet-to-learn token 不能共存 → 持续蒸馏退化
- **SCoRe** (arXiv 2509.14257) — 全轨迹模仿 → 复合误差；改成最早错误纠正 + 短程 RL
- **Subliminal learning as trait-direction drift** (NeurIPS'26, arXiv 2609.01091) — 蒸馏会传**非预期**特质，且沿训练轨迹累积
- **Cross-Tokenizer OPD 的理论极限** (arXiv 2610.30844) — offline 教师轨迹 vs online 查询的 minimax 界（决定你要不要做 on-policy，成本上关键）
</details>

## 一句话总结

**这条路有真东西，但你必须承诺三件事**：

1. **把战场从预训练移到中训练**——否则算力和存储两笔账都算不平（$C_T/C_S=\lambda/3$，1T token 全量 logits 256 PB）。
2. **把“省钱”和“保 headroom”当两个独立的问题**——前者用 growth / 语料级离线蒸馏 / 调度引导（20–50%，甚至改指数），后者才是“轨迹”的专属领地。别用一个机制同时干两件事。
3. **先建立那个致命 baseline（调优过的 schedule+mix）**，再谈机制。这一步做完你才知道到底有没有真东西。

要不要我把**题 A 的完整实验设计**（数据、代理集规模、教师成本核算、baseline 清单、指标表）和**那句“蒸馏算力不蒸馏 headroom”的形式化**写出来？这是三个题里最快能出结论、也最不容易被 Reviewer 打死的。
