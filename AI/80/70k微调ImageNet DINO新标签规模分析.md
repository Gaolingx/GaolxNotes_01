# 70k微调ImageNet DINO新标签规模分析

## 🧑‍💻 User

70,000 images fine tune imagenet DINO for new label这个scale够吗

---
## 😀 默认助手 (7)

## 一句话结论

**对「训练一个新的分类头 / 做迁移学习」来说，70k 完全够用，甚至偏充裕；对「从零训练 backbone」或「大规模类别体系（上千类细粒度）」来说不够。** 决定够不够的关键因素，是**每类样本数**和**你打算微调多少参数**，不是总图片数。

---

## 关键判据：每类样本数

设类别数为 $C$，则

$$N_c = \frac{70000}{C}$$

可以参考下面的分档：

| $C$（类数） | $N_c$ | 线性探测（frozen） | 部分微调 | 全量微调 |
|---|---|---|---|---|
| ≤ 100 | ≥ 700 | 很充裕 | 很充裕 | 充裕 |
| 100–500 | 140–700 | 充裕 | 充裕 | 够用 |
| 500–1000 | 70–140 | 够用 | 边缘 | **偏紧，慎重** |
| 1000–5000 | 14–70 | 勉强 | 不够 | 不够 |
| > 5000 | < 14 | 不够 | 不够 | 不够 |

核心直觉：**DINO 系列自监督特征非常数据高效**，frozen + linear probe 在每类 ~10–30 张时就已经有明显提升；而**全量微调**对 ViT-B 大约需要每类 $\gtrsim 100$–$200$ 张，才能稳定优于线性探测——低于这个量级，全量微调反而容易把预训练特征“洗掉”（catastrophic forgetting），验证集上不如冻住主干。

所以按 70k 算：**只要类数 $\lesssim 700$（即 $N_c \gtrsim 100$），全量微调是安全的；类数到 1000+ 时，建议直接走「线性探测 / LoRA / 只调后几层」。**

## 按方案细分

**① 线性探测 / kNN（最稳的 baseline）**
70k 图片对这个方案来说完全够用，甚至可以用 10% 子集先验证标签体系是否合理。**无论后面做什么，都应该先跑这个 baseline**，它是你判断“数据不够”还是“方法不对”的标尺。

**② 部分微调（推荐的主路线）**
冻结前 2/3 层 + 微调后几层，或 LoRA / adapters。数据效率接近线性探测，上限又高于它，70k 在这个区间非常舒服。

**③ 全量微调**
可行，但要**先做线性探测再加全量微调（LP-FT）**：先用线性头把分类头训到收敛，再解冻主干、用小 LR + layer-wise LR decay + 强增强 + EMA。这样能显著降低对数据量的要求。

**④ 继续自监督预训练（DINO/DINOv2 继续训练）**
**基本不够。** 70k 对 SSL 来说太少（DINOv2 级别是 1.4 亿张）。但如果你有**大量无标注的目标域数据**（几十万到百万级，标注很贵但未标注便宜），继续做 domain-adaptive SSL 再微调，是比“堆标注”更划算的路线。

## 实操 recipe（70k + 新标签体系）

<details>
<summary>展开：推荐流程与超参方向</summary>

1. **先换 backbone**：如果用的是 2021 年的原版 DINO（ViT-S/8、ViT-B/16，IN1k 预训练），换 **DINOv2 / DINOv3（ViT-B 或 L）** 通常比多标 3 倍数据带来的收益还大。老 DINO 的特征在细粒度任务上明显落后。
2. **切分数据**：train / val / test 按类分层抽样，确保每类在 val 里至少有 20–50 张，否则验证噪声会掩盖真实差异。
3. **三步走评估**：kNN → 线性探测 → LP-FT。每步都记录 val top-1。如果线性探测已经很好（比如接近你的目标），就别全量微调了，省事又稳。
4. **全量微调超参**：LR $\sim 10^{-5}$–$10^{-4}$（比从头训练小 1–2 个数量级）、layer-wise decay $0.65$–$0.8$、warmup 5–10%、强增强（RandAugment + Mixup/CutMix 适度）、EMA、早停。分辨率从 224 起，必要时最后阶段升到 448。
5. **多标签 / 长尾**：如果是多标签，用 BCE + asymmetric loss；长尾用 class-balanced sampling 或 logit adjustment，别指望 70k 能均匀覆盖尾部。
6. **模型融合**：线性探测头和微调头的权重做插值（WiSE-FT / model soup），几乎免费涨点，对小数据尤其有效。

</details>

## 什么情况下 70k 真的不够

- **类别极细粒度**（比如几万类商品/SKU、上千类工业缺陷），$N_c \ll 20$；
- **目标域与 ImageNet 差异极大**（医学影像、遥感、显微、工业检测），预训练特征迁移性差，7 万张里每类几十张撑不住；
- **要训练分割/检测的新类别**且标注是框/掩码——70k *图片* ≠ 70k *实例*，实例数要单独算；
- **要求从零学新模态或新概念**（预训练里根本没有的视觉类型），这时要么加 domain-adaptive SSL，要么加合成数据。

## 常见误区

1. **只看总图片数不看类数**——70k/10 类和 70k/2000 类是完全不同的两个问题。
2. **一上手就全量微调**——小数据下先做线性探测往往更强。
3. **validation 太小或不分层**——70k 数据下，验证集噪声可能比你调参带来的提升还大。
4. **把“类别不均衡”和“数据量不足”混为一谈**——前者靠采样/损失解决，后者靠加数据或减参数解冻量。

**总结**：70k 是一个很适合“在强预训练特征上做迁移”的规模。按 $N_c = 70000/C$ 算一下你的类数，$\ge 100$ 放心全量微调，$\sim 10$–$100$ 走线性探测/部分微调，$< 10$ 就要考虑加无标注数据做域适应或合成数据了。
