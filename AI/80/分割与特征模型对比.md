# DINOv3 vs. SAM：一句话结论

两者都出自 Meta，但**属于完全不同的模型类别**：

- **DINOv3 = 通用视觉"骨干网络"（特征提取器）**，输出稠密特征向量，本身不是任务模型，靠轻量 head 适配任意下游任务。
- **SAM = 可提示的分割模型（任务模型）**，输出像素级掩码，核心接口就是"给提示 → 出 mask"。

一句话：**DINOv3 回答"这是什么/这块像素长得像什么"，SAM 回答"这个东西的精确边界在哪里"。**

## 一、DINOv3 能做什么

**发布时间**：2025-08（arXiv:2508.10104，Meta FAIR）
**训练方式**：纯自监督（SSL），**无任何人工标注、无文本监督**，数据为 LVD-1689M（约 17 亿张网络图像）+ SAT-493M（卫星影像）。

核心技术点：
- **Gram anchoring**：解决长训练中稠密特征图退化（dense feature degradation）的已知难题
- 数据/模型双重 scaling + 精细数据清洗
- 后处理策略：分辨率适配、蒸馏（含 ConvNeXt）、文本对齐（`dino.txt`）

**输出**：一个全局 CLS embedding + 一张 patch 级特征图，形状约 $\frac{H}{16}\times\frac{W}{16}\times D$。**没有 mask、没有分类头、没有提示接口。**

**实际能力（冻结骨干 + 极轻量 head，多数无需微调）**：
- 图像分类：k-NN、linear probe 达到 SOTA
- 语义分割：ADE20K 线性探测 / M2F head
- 单目深度估计：线性探测 + DPT head（NYUv2、SYNTHMIX）
- 目标检测：COCO 上用轻量 head
- **稠密对应 / 匹配**：patch 间稀疏与稠密匹配（无需训练）
- **PCA 可视化即得前景分割**（"彩虹图"）
- 视频分割跟踪：基于特征的非参数方法
- 开放词汇分割：通过 `dino.txt` 做文本对齐（零样本）
- 领域应用：卫星影像、CHMv2 全球树冠高度图

> 关键卖点：**"不微调就超过专用 SOTA"**，尤其是密集预测任务的具身/视觉表示质量。

## 二、SAM 能做什么

SAM 是**可提示分割（promptable segmentation）**家族，三代演进：

| 版本 | 时间 | 能力 |
|---|---|---|
| **SAM 1** | 2023-04 | 图像上给点/框/掩码提示 → 单个对象 mask；空提示 → "分割一切" |
| **SAM 2** | 2024-07 | 增加视频：记忆（memory）机制，跨帧传播与交互式修正 |
| **SAM 3** | 2025-11 | **可提示概念分割（PCS）**：给"黄色校车"这类短名词短语 / 图像范例 → 分割并分配唯一 ID 的**所有**匹配实例（图像+视频） |

**SAM 3 要点**（arXiv:2511.16719）：
- 架构 = 图像级 DETR 式检测器 + 记忆式视频跟踪器，**共享一个骨干**，848M 参数
- 解耦检测与跟踪，加入 **presence head（存在性头）**，区分近似文本（"穿白衣服的球员" vs "穿红衣服的球员"）
- 数据引擎自动标注 400 万概念标签；新基准 **SA-Co**（27 万概念，比既有基准多 50 倍）
- 达到人类表现的 75–80%，图像与视频 PCS 精度**翻倍于既有系统**
- 后续 **SAM 3.1（2026-03）Object Multiplex**：共享内存做多目标联合跟踪，更快且不掉精度
- 同时保留 SAM 1/2 的交互式实例分割能力

**SAM 的输出永远是 mask（+ box + score + ID），它不知道"类别语义"**——SAM 1/2 是类无关的（class-agnostic），SAM 3 才具备开放词汇概念理解。

## 三、核心区别对照表

| 维度 | DINOv3 | SAM（1/2/3） |
|---|---|---|
| **模型定位** | 视觉基础骨干 / 表示学习 | 分割任务模型（端到端） |
| **输出** | 特征向量 + patch 特征图 | 像素级 mask（+bbox/score/ID） |
| **训练信号** | 自监督，**零标注、零文本** | 有监督掩码标注（SA-1B / SA-V / SA-Co） |
| **是否可提示** | ❌ 无提示接口 | ✅ 提示是其核心（点/框/掩码/文本） |
| **任务范围** | 分类、检索、聚类、深度、检测、匹配、分割……（靠 head 适配） | 分割 + 视频跟踪（专一） |
| **语义理解** | 隐式（特征相似度），本身无类别概念；`dino.txt` 可补文本对齐 | SAM1/2 无类别概念；SAM3 支持开放词汇文本提示 |
| **空间精度** | patch 级（stride 16），较粗 | 像素级高分辨率掩码 |
| **使用方式** | 冻结特征 + 线性头/轻量 adapter | 直接推理，一次前向出 mask |
| **典型分工** | "是什么" / 特征检索 | "在哪、边界如何" |
| **最小模型** | 21M（ViT-S/16），可上边缘设备 | 通常 ≥ 90M 级，需 GPU 更常见 |
| **许可** | DINOv3 License（自定义） | SAM License |

**最容易混淆的一点**：DINOv3 确实能做分割（线性探测语义分割、PCA 前景分割），但那是**在固定类别集上训练一个小头**，或者靠特征聚类"涂色"；它**无法"指哪儿分哪儿"**，也无法一次输出实例级精确轮廓。反过来 SAM 无法给你一个可迁移的通用表示去做检索或分类。

## 四、怎么选 / 怎么组合

**选 DINOv3，如果你要：**
- 图像检索、聚类、去重、最近邻
- 少样本/小样本分类，或为自定义任务省标注
- 深度估计、稠密对应、多模态对齐的基础特征
- 在边缘设备上跑（ViT-S/16 仅 21M）
- 领域迁移（卫星、遥感、医疗等），只要特征好

**选 SAM，如果你要：**
- 像素级精确分割与交互式标注工具
- 视频中的目标跟踪与掩码传播
- 文本指代分割某类所有实例（SAM 3："找出所有黄色校车"）
- 自动生成掩码数据集

**组合用法（工业界很常见）：**
1. **SAM 出掩码 → DINOv3 特征给掩码分类/命名** → 得到"开集实例分割"
2. **DINOv3 特征聚类/匹配 → 生成点提示 → 喂给 SAM**（自动标注流水线，SAM 的自动掩码生成器替代方案）
3. **DINOv3 骨干 + SAM 式分割头**：把 DINOv3 的重特征质量用在分割解码器上
4. 视频：DINOv3 做特征级非参数跟踪，SAM 2/3 做掩码级流式跟踪

**一句话记忆**：SAM 是"把东西抠出来"的专用工具，DINOv3 是"看懂图像"的通用底座——**抠得准找 SAM，看得懂找 DINOv3，既要又要就把两者串起来。**
