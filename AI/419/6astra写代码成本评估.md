## 一句话结论

**按旗舰档来算，它属于偏贵的；但“贵不贵”取决于你用它写什么代码。**

- 它的单价大约是上一代编程主力 `gpt-6.1-sol` 的 **5 倍**，是批量用 `gpt-6-luna` 的 **约 100 倍**。
- 日常写函数、补样板代码、写单测 → **严重超配，不划算**。
- 仓库级重构、长链路 Agent 任务、要它自己跑终端/看界面 → 省下的人工返工往往比单价差更值钱。

## 二、写代码到底花多少钱（含缓存命中）

按 1 美元 ≈ 7.1–7.2 元粗算：

| 场景 | Token 用量（缓存/未缓存输入 + 输出） | Astra | Sol | Luna |
| --- | --- | --- | --- | --- |
| 小任务：写个函数/答疑 | 3K 未缓存 + 1.5K 输出 | ≈ 0.11 美元（约 0.8 元） | ≈ 0.02 美元 | ≈ 0.001 美元 |
| 中等 Agent 任务：10 轮工具调用 | 300K 缓存 + 100K 未缓存 + 20K 输出 | **≈ 2.30 美元（约 17 元）** | ≈ 0.43 美元 | ≈ 0.02 美元 |
| 大改造：全仓重构 / 长程修 bug | 3.5M 缓存 + 0.5M 未缓存 + 150K 输出 | **≈ 16 美元（约 115 元）** | ≈ 2.85 美元 | ≈ 0.16 美元 |

即：同一份工作量，Astra 大约是 Sol 的 $5\times$、Luna 的 $100\times$。

<details>
<summary><b>三个最容易把账单打爆的坑（点开）</b></summary>

1. **一次请求超过 272K 输入，是整个请求涨价，不是只涨超出部分。**
   例：300K 未缓存输入 + 20K 输出
   - 短上下文计费：$0.3\times10 + 0.02\times50 = 4.00$ 美元
   - 触发长上下文：$0.3\times20 + 0.02\times75 = 7.50$ 美元

   → 直接变 $1.875\times$。Astra 有 105 万上下文，长会话很容易踩线，做预算前先确认单请求是否跨过 272K。

2. **推理 token 按输出价计费。** `reasoning.effort` 调到 `high/xhigh/max` 时，一轮的推理 token 可能几万起步，而这些都算 50 美元/1M。写代码时 `medium` 往往就够，别默认拉满。

3. **缓存有写入成本（12.5 美元/1M，即 1.25× 输入价）。** 只有当同一段前缀被反复命中时才赚得回来；提示词前缀频繁变动的话，缓存反而倒亏。

</details>

<summary><b>工具调用还会另外收钱（点开）</b></summary>

- File search：2.50 美元 / 1000 次调用 + 存储 0.10 美元 / GB·天

## 三、省钱的用法建议

1. **分层路由**：Luna / Codex 模型跑日常补全和批量改写，`gpt-6.1-sol` 跑大部分 Agent 编码任务，只有“一次做错代价很高”的长程任务才路由给 Astra。
2. **Astra 上开 `medium` + 稳定前缀吃缓存**，并在 Batch/Flex（50%）能接受的场景（离线批量重构）走 Batch。
3. **Fast / Ultrafast 慎用**：输出价 100 / 300 美元 per 1M，只为延迟买单，写代码基本用不上。
4. **个人开发者先看订阅制**：ChatGPT Plus / Pro 里的 Codex 额度，通常比直接打 API 便宜得多；API 更适合要嵌进自己流水线和做 A/B 的团队。
5. **别全量替换**：拿 20–50 个真实任务做 A/B，只有当 Astra 的首次成功率提升能抵掉多出来的 token 和工具成本时才切过来。

顺带提一句：Astra 官方 Terminal-Bench 4.0 是 **57.9%**，而 `gpt-5.6 Sol` 是 37.3%——难点任务的“一次做对率”差异，才是它值不值这个价的真正判据，纯看单价会误判。
