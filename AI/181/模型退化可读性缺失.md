# R1-Zero 式纯 GRPO 冷启动:"分数在涨,话不说人"的原因

这是一个被多个复现实验(包括 DeepSeek 自己在 R1 论文里也提到)反复观察到的现象。核心原因是:**可验证奖励只检查答案对错,不关心过程可读性**。可以从几个机制理解:

## 1. 奖励函数的标准答案是"瞎子"

GRPO 里规则奖励是:

$$R = \mathbb{1}[\text{answer}(y) = \text{answer}^*]$$

它只抽取 `$\boxed{}$` 或最终答案做匹配,中间的推理链对人类是语言,对奖励函数就是任意 token 序列。RL 的目标函数里根本没有"可读性"这一项,所以**可读性不在优化方向上**,只会被"顺手优化掉"。

## 2. 语言熵在 RL 中被消耗

GRPO/PPO 本质是拉大优势动作的概率。数学推理有大量"自由 token"(自然语言连接词、解释句),这些位置不影响答案对错,但策略更新会无差别地推高/压低所有 token 的 logprob。结果就是:

- 高熵的自然语言部分先坍缩(模型发现"固定模板 + 少量关键 token"风险更低、方差更小),
- 语言多样性崩塌 → 出现重复、复读机式循环、token 粘连,
- 因为 base model 对多语言都有概率质量,还会出现 **language mixing**(中英混杂、夹带奇怪字符),R1 论文明确报告了这一点。

简单说:pass@k 涨是因为正确答案相关的 token 概率被强化了;不说人话是因为"说人话"没有任何梯度信号来维护它,KL 不够就退化。

## 3. KL 约束太弱或没有用

R1-Zero 里 GRPO 对 reference model 的 KL 系数很小。理论上 KL 项应该锚定自然语言分布,但:

- 很多实现把 KL 做得很小甚至去掉(避免钳制探索),
- token 级 KL 估计本身方差大,
- 即使保留,base model 本身语言能力就粗糙,KL 只是锚定在"本来就不太稳的语言"上。

## 4. Base model 的"语言-推理"解耦得更脏

SFT 的作用不只是教格式,它是把数学能力**绑定到通顺的自然语言推理链上**。跳过 SFT 意味着 RL 直接在一个未经约束的巨大策略空间里搜索——它找到的最省力的高奖励区域,往往是格式怪异、语言退化的区域。格点原理告诉我们:策略梯度会走最近的奖励高地,不会走远路去"正确地好"。

## 5. pass@k 涨恰恰掩盖了问题

pass@k 甚至对语言退化是"敏感偏不敏感"的:只要采 k 次里有一次碰巧格式正常、答案对,就算赢。退化主要伤害:

- pass@1 / avg@k(平均质量),
- 可读性、可审计性(这对推理模型其实很重要——你要 trace 它的推理),
- 下游能力(蒸馏链条会污染,工具调用格式会坏)。

## 实验上常见的缓解

| 手段 | 效果 |
|---|---|
| 语言一致性奖励(la percentage 里某语言占比) | 多数有效,R1 正式版就这么做的 |
| 增大 KL / 周期性 SFT 锚定 | 防语言熵崩塌 |
| 冷启动少量 SFT(R1 的做法) | 最根本,绑定语言与推理格式 |
| 奖励加格式项(标签完整性) | 缓解复读,但不能保证可读性 |

**一句话总结**:GRPO 只奖励"算对了",不奖励"说人话";RL 会系统性消耗语言熵,把自然语言当成可以随意压缩的冗余自由度。"pass@k 涨但输出退化"不是 bug,是目标函数不含可读性时的必然产物——这就是为什么 DeepSeek 最终版 R1 还是乖乖做了冷启动 SFT 和多阶段交替。
