# 超大规模预训练如何实现等效05bs

### 🧑‍💻 User

在超大规模预训练中，由于模型大到一个节点都塞不下，且tp跨机通信成本高昂，到底怎么开0.5bs？

---

### 🤖 Assistant

**用节点内 TP + 跨节点 PP（主推）+ ZeRO/FSDP/SP 等，把 micro-batch 压到 1（或等效更低），再靠 gradient accumulation 凑 global batch；“0.5bs”通常靠 Sequence Parallel 把一条样本的序列切开实现等效内存。**

### 核心约束与原则
- 模型大到单节点（通常 8×A100/H100）塞不下 → 必须做模型切分（参数 + 激活）。
- TP 通信极其频繁且量大（Attention/MLP 里的 all-gather / reduce-scatter），跨机走 IB/RoCE 延迟和带宽都远不如 NVLink/NVSwitch，效率崩、很难 scale，所以 **TP 尽量锁在节点内**（TP size = 每节点 GPU 数，常见 8）。
- 跨机优先用通信模式更友好的并行：Pipeline Parallelism（阶段间点对点传 activation，量相对小、次数少）或参数分片类（ZeRO-3 / FSDP 的 all-gather / reduce-scatter，虽然也跨机但工程上可接受，尤其网络好时）。
- Batch size 相关：框架里样本数必须是整数，**真正的 micro-batch size 不能设 0.5**。大家说的“0.5bs”几乎都是指：
  - 内存上只够撑大约 0.5 条样本的激活（长序列时常见），或
  - 想把 per-GPU 有效负载降到更低。
  - 实现方式是 **Sequence Parallelism（SP）把 sequence 维度切开**，逻辑 micro-bs 仍是 1，但每张卡只看到 seq_len/SP，激活内存近似减半（等效 0.5bs 内存占用）。SP 通常和 TP 绑在一起，通信模式类似，所以同样优先放节点内。

### 推荐并行组合（超大规模预训练主流）
1. **节点内：TP（± SP）**
   TP=8（匹配节点 GPU 数）。加上 Sequence Parallel 后激活也能按 TP 度切分，大幅省激活内存，正好对应“塞不下 bs=1 时怎么开到等效 0.5”。通信全走 NVLink，成本可控。

2. **跨节点：Pipeline Parallelism（PP）**
   按层切 stage，把模型深度方向拆到多个节点。
   - 通信只是相邻 stage 之间的 activation 点对点（远比 TP 友好）。
   - 用 1F1B 或 interleaved 1F1B 调度压 bubble。
   - 微批数量（num microbatches）建议 ≥ PP degree，最好更大，才能流水线效率高。
   - 若层数和机器数导致 stage 不均，可做 uneven pipeline 或 virtual pipeline（interleaved scheduling）。

3. **剩余维度：DP + ZeRO / FSDP**
   总 GPU 数 / (TP × PP) 就是 DP size。
   - 用 ZeRO-1/2（切 optimizer + grad）或 ZeRO-3 / FSDP（再切 param）把每卡参数/状态压下去。
   - 超大模型几乎必开 ZeRO-3 或等价 FSDP，否则优化器状态就爆。
   - 通信发生在 DP group（跨机），靠梯度累积和通信计算 overlap 掩盖。网络差时优先保证 PP，ZeRO 度不要拉太满。

4. **激活与内存再抠**
   - Activation Checkpointing（重计算）几乎必开，激活内存可降数倍。
   - FlashAttention / 融合 kernel、序列打包（packing）、选择性重计算。
   - 再不够就上 Context Parallel / Ring Attention（把超长序列继续切到更多卡，通信是 ring P2P，有时比硬拉大 TP 更合适）。
   - 极端情况：CPU/NVMe offload（速度换内存，预训练一般能免则免）。

5. **Batch size 实际怎么“开到 0.5”**
   - 配置上：`micro_batch_size_per_gpu = 1`（整数），`gradient_accumulation_steps` 调大来达到目标 global batch（tokens 或 samples）。
   - 内存仍 OOM 时：开 SP（TP 组内），把一条样本的 seq 切开 → 每卡激活 ≈ 原来的 1/SP，等效内存降到 0.5bs 甚至更低，逻辑上仍按 bs=1 算 loss/grad（注意正确做 all-gather/reduce 和 loss 归一化）。
   - Global batch 不要小于有效 DP 能承载的最小值，否则部分 rank 空转；宁可减小 DP、增大 PP/TP 内聚合，或接受稍大的 global batch（预训练通常 global batch 都很大）。
   - 框架支持：Megatron-LM / Megatron-Core + DeepSpeed、Megatron-DeepSpeed、PyTorch FSDP + pipeline 自定义、Colossal-AI 等都能组 3D（DP+TP+PP）+SP。配置里明确 `tensor_model_parallel_size`（节点内）、`pipeline_model_parallel_size`（跨节点）、`sequence_parallel=True`、`zero_stage=3` 等。

### 调度与效率注意点
- Pipeline bubble ≈ (PP-1) / num_microbatches，所以 microbatch 数量要够（global_bs / (micro_bs × DP) 决定）。想“小 bs”时 bubble 会变差，需要 interleaved 或更多累积。
- 通信 overlap、通信计算流、拓扑感知放置（同一 PP stage 或 TP 组尽量高带宽域）很重要。
- 先 profile 内存（参数 vs 激活 vs 临时），再决定加 PP、加 SP 还是加 ZeRO 度。激活墙了优先 recompute + SP；参数/优化器墙了优先 PP 或 ZeRO-3。
- 长序列场景“0.5bs”诉求更强烈，SP/Context Parallel 几乎是标配。

### 简要配置逻辑示例（伪）
- 节点 8 卡 → TP=8，SP=True。
- 模型层数很多、跨多机 → PP = 节点数（或按内存调）。
- 剩余卡做 DP + ZeRO-3。
- micro_bs=1，gas 调到目标 global tokens/batch。
- 若 bs=1 激活仍爆 → 依赖 SP 把有效负载降到 ≈0.5，或再加 recompute / 切更短 micro-seq。

这样就能在“单节点塞不下 + 拒绝跨机 TP”的前提下，稳定跑起来，并把有效 batch 压到内存允许的最低（含等效 0.5）。具体数字（TP/PP/ZeRO stage、gas、seq_len）取决于模型大小、卡型、序列长度和集群网络，需要实测 memory 和 MFU。

常用参考实现：Megatron-LM 系列的 3D 并行 + sequence parallel、DeepSpeed 的 ZeRO + pipeline、PyTorch FSDP 官方示例。先把 TP 锁节点内、PP 扛跨机、SP/recompute 抠激活，再谈更激进的 offload 或自定义切分。
