# 数据工程是LLM预训练核心杠杆架构创新作用被高估

## 🧑‍💻 User

感觉llm预训练应该是数据工程很重要。对模型性能的提升很大。各种架构算法上的调整改动带来的提升占比没有想象中那么大

---
## 😀 默认助手 (7)

大体同意你的判断，但我觉得“占比”这个框架里藏着一个不对等的比较，值得拆开看。

## 结论先行

- **数据工程的收益是“对整条学习曲线起到倍增作用”**：它不改变模型形态，但改变“每个 token、每单位 FLOP 值多少分”。这类收益在几乎所有规模上都可复现，因此感觉“很值”。
- **多数架构改动的收益确实在噪声里**（归一化换位置、激活函数、注意力变体，单点改动常常 <1–2%，甚至小于同配置两次运行的方差）。
- **但少数架构/系统决定不是“提升几个百分点”，而是“这件事能不能做、成本能不能承受”**：Transformer 本身、MoE、GQA/MQA、FlashAttention、长上下文。它们不该和“调性之变”放在同一个百分比里比较。

## 你说对的部分

<details>
<summary><b>支撑“数据工程是高 ROI”的主要证据（点开）</b></summary>

- **去重**：Lee et al. 2021 显示去重既降记忆化，也提升训练效率；现在已是默认操作。
- **质量过滤/分类器**：FineWeb / FineWeb-Edu（教育质量打分过滤）在同 token 预算下对 MMLU、ARC 等明显优于不做过滤的公共语料；DCLM 那套基于模型打分的过滤，让 7B 级模型在 2.6T token 上追平甚至超过更强的公开基线，而算力还更省。
- **数据配方/合成与重写**：phi 系列的“教科书式数据”让 1B 级模型在小学数学类任务上逼近大得多的模型（当然里面有任务特化的成分，不能当通用结论）。
- **数据量与重复次数定律**：Chinchilla 把“数据该有多少”变成一等公民；data-constrained scaling（重复 epoch）给出去重后重复 4 轮≈等量新数据的经验规律。这些是**直接改写训练配方**的结论。
- **数据排序/课程**：相对弱，收益多在 1% 量级且不稳定——这也说明“数据工程”内部差异极大。

共同点：这些发现**在论文之外被大规模采纳了**，而架构消融论文多数没有被采纳。这本身就是市场对 ROI 的投票。
</details>

## 但“占比”这个说法有三个坑

<details>
<summary><b>可比性问题：为什么这类对比容易被高估</b></summary>

1. **预算不同 → 结论不迁移**。DCLM 自己就指出：小算力预算下胜出的过滤方法，放到大预算/大模型上不一定还赢。数据实验便宜，容易被做成“小模型上很惊艳”，然后被当成通用结论外推。
2. **“数据改进”常常悄悄改了算力**。过滤掉 70% 数据、训练同样步数，等于同时改了有效 token 数、每 token 信息量、以及实际消耗。这跟“换个激活函数”不是同一个实验设计，百分比不可加。
3. **评测污染是数据侧的问题，不是数据侧的功劳**。很多“数据配方带来大涨”在去污染后缩水。数据方向最容易产生**不可复现的漂亮数字**，因为改进方向和评测分布高度重合。
4. **噪声底**。小规模下 benchmark 的 run-to-run 波动可以到 1–2 个点，很多架构论文报告的差异就在这个量级——所以“架构没用”一部分其实是“我们测不出来”。
</details>

## 反过来：数据工程也有天花板和反噬

- **高质量 token 是有限资源**。过滤越狠，多样性越窄；靠合成数据补量，会引入模型自噬/分布坍缩的风险。所以数据工程的边际收益递减得很快，最终撞在“人类文本总量”上——这也正是现在进入 data-constrained 时代的根本原因。
- **数据不决定“能不能稳定训下去”**。大规模训练里，数值稳定性、通信拓扑、并行切分、显存与吞吐，这些“工程+架构”的改动不体现在 benchmark 上，但决定你能否跑完一次实验。在这个意义上，说架构占比小，是把“没跑挂”当成了默认值。
- **Tokenizer 是个被归错类的例子**。词表与压缩率直接改变每 token 的有效算力和序列长度，10–20% 量级的效率差，通常被记在“架构”账上，其实是数据/预处理决策。

## 一个更准确的表述

> 数据决定**上限与效率系数**；架构与优化决定**你能否接近上限、以及用什么成本接近**。

- 数据是**乘性效率项**：同样算力换更多能力，收益在整个规模区间分布，所以看起来“占比大”。
- 架构多数是**加法项且噪声大**，但少数是**可行性开关**（MoE/attention 变体/并行友好性）。
- 还有一个经常被忽略的第三条：**超参和优化器在“调好之后”差异会收敛**（有系统性的预训练优化器对比研究支持这一点），也就是说很多“算法改进”的收益其实是“超参没调到位”的补偿。这反过来支持你的直觉。

## 所以我的分歧点只有一个

不是“数据重不重要”，而是“**架构不重要的结论，大多是在架构已经收敛到 Transformer+RoPE+SwiGLU+RMSNorm+GQA 这个共识基座之上得出的**”。在基座内部做微调确实收益稀薄；但当年选对基座的那一步，是最大的单点收益。数据工程的高 ROI，某种程度上是**建立在架构已经标准化、不需要再探索的前提上**的。

顺带一个可能对你有用的判断：如果你的目标是“在小算力下拼出有竞争力的模型”，那数据配方的杠杆确实远大于架构；如果目标是“在固定硬件上把成本结构打下来”，架构/系统（MoE、稀疏化、KV cache）的杠杆会重新变大。

需要的话我可以去把 DCLM、FineWeb、data-constrained scaling、预训练优化器对比这几篇的具体数字和消融设置拉出来，看它们在“同算力、同 token 数、去污染”这三个约束下到底还剩多少——那是检验你这个判断最干净的方式。
