## 一、NV 这篇真正证明了什么（以及没证明什么）

| 它的做法 | 它的机制 |
|---|---|
| long-horizon：EoCC / SAC，窗口压到 16–48K，SAC 峰值 median 只有 7–9K、max 15–37K | 压进自然语言的 state，一轮一压 |
| long-input：把文档丢进**文件系统**，让 agent 用 `grep` / `sed` / `head` 自己读 | 无损存储 + agentic 选择，**不是**压缩 |
| 结果：Opus SWE-bench 70.2 vs 70.0；Terminal 51.8 vs 47.2；NIAH 60→100；RULER recall 62.5→95.7；BABILong +24.9 | 成本反而降 6.5–54.6× |

注意 long-input 那几张表里 **median compactions 几乎全是 0**。也就是说那部分的收益根本不由 compaction 提供，而是由 `grep` 提供；compaction 只是兜底。论文自己写了：LONGBench/LOONG 上“median 0 compactions”，RULER 上“median 0”。所以 **这篇论文的主要机制是无损存储 + 便宜的词法索引 + 有界读取，不是“小窗口也够”**。

更要命的是 §3.1 它自己承认了：给定固定 compaction budget，抛硬币那个构造**必然**丢信息、必然失败。它的解法不是“把窗口搞小”，而是“把完整历史存盘，再给你一个 selective reading 工具”。也就是说**它把 O(N) 的存储一分不少地保留了下来，只改变了访问模式**。

这和 sparse attention 的前提是**相反的**：

- sparse attention：KV 我丢掉一部分，靠 softmax 的峰性赌丢的不是关键。
- NV 这篇：一个字节都不丢，只是不再放进 attention 的视野里。

所以拿这篇论文去支持“sparse attn 很爽没问题”，是把它当成架构论文在读了。它其实是把 **memory 该放哪儿** 的论文：它给出的结论是“在模型上下文里，你只需要几 K”，前提是“模型上下文之外必须有一个**无损且可寻址**的 store”。你把 store 拿掉，它就是 §3.1 那个反例。

而且它替你说了一句更狠的话：**在长上下文上，打败 1M-token attention 的选择器是一个 1970 年代的 `grep`**。NIAH 60→100，RULER 62.5→95.7。这不是“长上下文不必要”，这是“attention 是个很差的索引器，正则是个很好的索引器”。你抱怨 selection 没有方法论——这就是最直接的证据，而且比你想的更难看。

## 二、你那条直觉是对的，但轴得换

“capacity 不是问题，selection 是问题”方向对，但不够锐。capacity 从来不是瓶颈：$d_{\text{state}} \times d_{\text{model}}$ 的 state 装下 1M token 的**相关信息**绰绰有余。真实约束是**信息论上的**：一个 query-blind 的定长 state 要精确回答对 N 个 token 的任意 point query，需要 $\Omega(N)$ bits。这是下界，不是工程差距。所以 Mamba 做不了精确 recall 不是因为 state 小，是因为**它必须在你提问之前就决定压什么**。

真正的轴是：**压缩决策发生在 query 之前还是之后**。

|  | read 依赖 query（读时决定） | read 与 query 无关（写时编码） |
|---|---|---|
| **store 无损** | full attn；sparse attn（截断） | — |
| **store 有损** | NV 的 SAC / compaction（自然语言 state） | Mamba / linear attn / Gated DeltaNet |

四格各有代表。sparse attention 落在左上：**store 无损、read 有损**。这个位置是它全部优点的来源，也是你说的“多抽几次还能抽到”的来源——它是**有偏但可重采样的估计**；右下角是**无偏但不可恢复**（信息压根没进去）。这两者的错误分布形状不同，见第五节。

索引那边有个漂亮的自指：任何 index 都是 query-blind 建立的，所以“用索引来减 selection 复杂度”这条路会**重新得一遍 Mamba 的病**，只是容量大了几个数量级。唯一逃法是多分辨率 + 无损叶子：上层是 query-blind 的粗粒度 sketch，叶子是原始字节，query 只做 $O(\log N)$ 次下降，且随时能回读原文。NSA 的 compression branch、hierarchical block-sparse、以及 NV 的 `grep`+`doc-read` 都是这个东西的不同实现。所以那句“sparse attention 在重新发明 retrieval”不是讽刺，是结构性的：**它是 attention 在重新发现“读记忆需要索引”，而没人愿意 jointly train 那个索引**。

## 三、CoT = query-aware write（这条你对了，而且论文替你证实了）

thought token 是在**问题已经在感受野里**的情况下生成的，所以它是一次 write，且这个 write 的条件包含 query——这正是 linear attention 结构上做不到的事。所以 CoT 相当于**把一个 query-blind 的有损写，变成了 query-aware 的有损写**，于是紧窗口就够用了。

更有意思的是 Appendix A 自己撞到了这件事，只是没用你的词：作者说“把 compaction 当成 summarization 的一个特例是 suboptimal”，因为 summarization 给所有事实同等权重、会被重复片段带偏；**最好的 compaction 不是忠实的叙事，而是“为尚未执行的工作挑选过的 brief”**。这就是 query-conditional selection。而且它的模板里第一条就是“verbatim 抄一遍任务”，第二条“当前意图与下一步”——活脱脱一个把 query 钉死在 state 里的做法。

所以你说“thinking 写的东西相当于 summary 里的某些东西”：对，但真正起作用的成分不是 summary，是 **conditioned on 你接下来还要什么**。而“还要什么”就是 selection。你绕了一圈回到了你自己抱怨的那个没有方法论的东西上。

## 四、“selection 还是 O(N²)”——要拆成三件事

1. 打分成本 $N^2 \cdot d_{\text{head}}$，确实是二次的，但它在一个低维便宜算子上；而且 decode 阶段瓶颈是 bandwidth 和 batch×N 的 KV 读，不是 FLOPs。所以这是真批评，但不是 sparse attn 胜负的原因。
2. 真正的隐患是**打分和混合共享同一个量**。$q^\top k$ 同时干两件事：决定相关性、决定加权平均。softmax 归一化会毁掉绝对尺度，而**截断决策恰恰需要标定过的相关性**。这就是 top-k 看起来丑的数学原因——你拿一个只有相对意义的量去做了绝对判断。所有“随便搞都能跑”的稀疏方案，都是在用不同的方式绕这个缺陷，而不是解决它。
3. 收益的大头其实不在稀疏，而在那个无损 store 上。你要做 sparse attn 却只给 4K window 训练——那你就造了一个常数更差的 Mamba，同时还保不住“多抽几次”这个唯一的优点。

## 五、你觉得“没有方法论”，因为它压根被建错了题

现在所有 sparse attn 论文都在解 kernel，没人在解 allocator。$k$ 是**逐层硬编码的超参**，但它本该是一个**输出**：给定算力/延迟预算 $B$，求读取策略

$$\min_{\pi} \ \mathbb{E}\big[\,\ell(\pi)\,\big] \quad \text{s.t.} \quad \mathbb{E}\big[|\pi|\big] \le B$$

这就是一个**预算下的 value-of-information 分配**问题。一旦这么写，方法论就存在了，而且你的几个抱怨全部变成可测的东西：

<details>
<summary><b>我会要求这个领域报的四个数（点开）</b></summary>

1. **输出误差**，不是 mass recall。$\varepsilon = \|A_s V - A_d V\| / \|A_d V\|$，逐 head / 逐 layer / 逐 query。mass recall 会骗人，因为**概率大 ≠ 贡献大**：低概率但 $\|V\|$ 巨大的 key（massive activations / outlier features）可以独扛答案。按 $p \cdot \|V\|$ 排序才等价于按贡献排序，而没人这么做。
2. **Oracle recall**：用梯度归因或消融，找出密集模型**实际用到**的那几个 key，看稀疏 pattern 覆没覆盖。这是唯一和答案相关的 recall。
3. **稀疏度-性能曲线 + CoT 预算作为协变量**。必须报拐点，且必须**条件在有没有 CoT/compaction 上**。你说的“疯狂 compact 跟 1M 才 compact 没本质区别”，本质是在声称这条曲线是平的；把它变成科学的方式就是报“拐点位置 vs 选择显著性”。
4. **等算力 best-of-$k$**。这条最重要，且全领域都在漏。

</details>

第 4 条展开一下，因为它同时解释了你最后两段。sparse attn 是**低偏、高方差**的随机估计（读错了但 store 还在，重采样能救）；Mamba 是**低方差、高偏**的确定性投影（信息压根不在）。所以拿 mean accuracy 比，是在比两个错误分布形状不同的东西；正确的统计量是

$$\mathbb{E}\Big[\max_{i\le k} \text{score}_i\Big]$$

在匹配 FLOPs 下比。**这大概率就是“随便搞都能跑”的真实原因**：稀疏的失败是尾部事件，尾部在聚合 benchmark 上被平均掉了，但在 any-of-$k$ 下暴露；而线性的失败是系统性偏差，怎么重采样都救不回来。你这一整段话，用一句话说就是：**大家在用错的统计量互相比较，所以谁都说服不了谁**。

## 六、温度那条：对，但三处会坏

1. **mass ≠ contribution**，如上。sharp 只保证概率集中，不保证贡献集中。
2. **head 是异质的**：induction/retrieval head 很 sharp，但大量 head 在做 aggregate（bag-of-words、位置、sink）。全局 top-$k$ 是范畴错误；正确的旋钮是**per-query 熵预算**。
3. **T 不是自由变量**：logit scale 训练中自然会涨，熵本来就会自己降；你手动 sharpen 等于改变了模型隐式的混合程度，并且**抬高 attention 输出的方差**——注意这和第五节第 4 条是同一件事的两面：你 sharpen + top-$k$，本质是在做低采样数的 Monte Carlo。这两条放一起看才有意思：你想让它 sharp 以便稀疏，但 sharp 同时把它变成一个高方差估计器，于是你**更**需要多抽几次。

## 七、所以“丑陋”到底在哪

我基本同意你，但换个说法：**丑的不是 sparse，丑的是 attention 让同一个 router 兼任 mixer。** 截断需要标定的绝对相关性，平均只需要相对权重，这两个需求被 softmax 焊死在一起。稀疏化只是把这个焊点暴露出去了，于是所有 workaround 看起来都像补丁：sink hack、top-$k$ 硬编码、per-layer 手工预算、块粒度妥协。

真正的解耦方案很朴素：**一个小而便宜的、单独训练的、以选择为目标标定的 router；一个只负责混合的 head。** 一旦分开，“预算”和“校准”就成了可训练对象，方法论才有地方长。目前没人做，是因为大家都在写 kernel——你感觉到的“过于工程”，说的就是这件事：**他们解决了实现，没有解决决策**。

## 八、你的直觉目前无法被证伪，而这是那个 benchmark 的锅

关于“疯狂 compact 和 1M compact 没本质区别”，论文自己给出了原因，而且就一句话：**“the actual amount of information required to solve those tasks remains low”**。如果任务所需的信息量远小于窗口，那压缩日程当然无所谓——$I_{\text{req}} \ll \log N$ 时，几乎所有机制都能过，拐点还没到。

于是你骂的那个点其实可以更精准地骂：**当前所有长上下文 benchmark 都是低 bit 内容 + 可词法寻址的**（NIAH 的针是句子、Counting-Stars 的数字带标记所以能 grep、RULER 有词面重叠——论文自己在 NIAH 那段承认了“straightforward lexical overlap”）。在这个分布上，稀疏注意力和 `grep` 的差别被完全抹平，谁都能跑，所以**没人能测出差别，所以“没有方法论”其实是“没有能分辨的度量”**。

要证伪你、或者证实你，只需要一个东西：**高信息密度 + 选择准则不可词法寻址**的长上下文任务。具体形态：答案依赖大量**低显著性**条目联合（不是找一根针，是要在 1M token 里对每个 token 做一次不显著但它参与了最终求和的运算），且 query 在读取时才知道要哪一条。在这种任务上，$I_{\text{req}} \sim N$，compaction 日程立刻变得决定性，per-round 和 1M 会分开，sparse 与 dense 也会分开。**这个 benchmark 不存在，才是这个领域目前最大的方法论缺口**——比“没有统一的 sparse attn 方案”更根本。

---

一句话收：**sparse attention 不丑，它只是把 attention 唯一没被工程化的那部分（决策）留在了原地。** 而 NV 这篇最有价值的其实不是“你不需要长上下文”，而是它顺手证明了：在这个决策问题上，一个正则表达式就能打赢 1M token 的 attention。这句话既是 sparse attention 的辩护，也是它最狠的指控——而且它说明真正的竞争不在 sparse 和 linear 之间，在于**你有没有一个能廉价寻址的无损 store**。linear recurrence 输了，不是因为常数，是因为它连 store 都没有。
