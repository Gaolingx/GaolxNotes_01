# 线性注意力内核在上下文并行（CP）路径下的数值精度缺陷：诊断与修复

## 核心结论（TL;DR）

CP 路径的精度缺陷 **99% 不是"算法"问题，而是三个具体机制**：

| 机制 | 典型症状 | 根因 |
|------|----------|------|
| **状态通信降精度** | 误差 ~ $10^{-3}$，随 CP 度缓慢增长 | 跨 rank 传递递归状态 $S$ 时用了 bf16/fp16 |
| **归约顺序改变** | 输出不可复现、误差 ~ $10^{-7}$ | prefix-scan 树形顺序 ≠ 单卡顺序 |
| **动态范围吸收（absorption）** | 误差随 token 位置单调爬升 | $S$ 随长度增长，小增量被大累加器吞掉 |

修复的主线只有一条：**递归状态 $S$ 及其所有部分和在通信、累加、归一化三处全程保持 fp32（或 bf16×2 拆分），绝不降精度。**

## 一、为什么 CP 会引入精度缺陷（根因分类）

线性注意力的递归形式：

$$
S_i = S_{i-1} + k_i v_i^\top,\qquad o_i = q_i^\top S_i
$$

CP 把序列切到多卡，需要一次 **prefix-scan**：

$$
S_{r} = \sum_{s \le r} \Delta_s, \qquad \Delta_s = \sum_{t \in \text{chunk}_s} k_t v_t^\top
$$

这引入单卡不具备的三个新"故障面"：

**1. 状态通信的精度面**
状态张量 $S \in \mathbb{R}^{d_k \times d_v}$ 要跨 rank all-gather。为了带宽常常 `to(bfloat16)`。bf16 只有 8 位尾数（$\epsilon \approx 2^{-8} \approx 3.9\times10^{-3}$），每次存储就注入 ~0.4% 相对误差。这是最常见、最致命的缺陷。

**2. 归约顺序面**
并行扫描用 Hillis–Steele / Blelloch 树形归约，加法顺序与单卡顺序不同。fp32 下差异只有 $\sim10^{-7}$，但它导致：
- **不可复现**：CP 度一变结果就变；
- **误差被放大**的温床（树形加法的舍入与求和次序耦合）。

**3. 数值动态范围面**
无门控时 $\|S_i\|_F \sim \sqrt{i}$（实验中 $i=127$ 时 $S$ 的范数是单块增量范数的 $11.3$ 倍）。于是"把小的 intra-chunk 输出加到巨大的累积状态上"就是经典的 **大数吃小数**：

$$
\text{fl}(S + \Delta) = S \quad\text{当}\quad |\Delta| < \epsilon_{\text{mach}} |S|
$$

**其他易被误判为"精度问题"的边界 bug**（务必先排除）：
- intra / inter chunk 的 mask、offset 差一，导致重复计数或漏计；
- 门控衰减因子 $\prod \lambda_i$ 在 bf16 下下溢为 0（应在 log 空间累加）；
- 分母 / normalizer 用了低精度；
- 反向传播的 reverse-scan 与 all-reduce 与正向不一致（梯度误差往往比正向更大）；
- TF32 matmul 累积、atomicAdd 非确定性。

## 二、诊断流程（Playbook）

### Stage 0 — 构造可复现的黄金对照

不要在生产配置上瞎试。建立最小可复现装置：

- **ground truth**：CPU 或 GPU 上的 `float64` 朴素实现（逐 token 递归，最原始公式）；
- 固定权重、固定输入（`torch.manual_seed`），关 dropout；
- 扫 CP 度 $\text{cp} \in \{1,2,4,8\}$，chunk size 作为超参；
- 用 `torch.testing.assert_close(rtol=..., atol=...)` 逐级比对。

### Stage 1 — 分层定位（关键一步）

把 CP 流水线拆成 4 个可 dump 的中间量，**逐级与 fp64 参考比**，第一个超差的阶段就是凶手：

```
[输入] → Δ_r (每 chunk 局部状态) → S_{r-1} (scan 后前缀状态)
      → O_intra (块内) → O = Q·S_{r-1} + O_intra → [输出]
```

常见判读：

- **只有 $\Delta_r$ 错** → 局部 chunk 内核本身的 dtype / mask 问题；
- **$\Delta_r$ 对但 $S_{r-1}$ 错** → scan 或状态通信的锅（最常见）；
- **$S$ 对但 $O$ 错** → inter-chunk matmul 的累积精度 / dtype 提升问题。

<details>
<summary><b>Stage 2 — 误差定性：位置曲线 + 消融矩阵</b></summary>

**误差-位置曲线**（相对误差 vs token index）：

- 单调爬升 → 累积型（absorption / scan 累积）；
- 平坦且量级较大（$\sim10^{-3}$）→ 单次 cast 型（通信降精度）；
- 在 chunk 边界出现尖峰 → 边界索引 / masking bug（不是精度）；
- 随 CP 度线性增长 → 归约累积。

**消融矩阵**（每行只改一个变量）：

| 消融 | 若误差消失说明 |
|------|----------------|
| 状态通信强制 fp32 | 通信降精度是主因 |
| 关闭 scan，改顺序递归 | scan 顺序是主因 |
| 关闭 intra/inter 融合 | 边界处理是主因 |
| 改 chunk size | 局部内核累积是主因 |
| 关闭 TF32 / 用 fp32 累积 | matmul 累积是主因 |

</details>

<details>
<summary><b>Stage 3 — 数值取证工具</b></summary>

- **条件数**：`torch.linalg.cond(S)`。条件数大 → 抵消/吸收严重；
- **ULP 直方图**：`(x - x_ref) / torch.spacing(x_ref)`，看舍入是否集中在边界；
- **量级监控**：记录每个 rank 的 `S.abs().max()`、norm、inf/nan/denormal 计数；
- **cast 定点**：grep kernel 里所有 `.to(torch.bfloat16)` / `.half()`，特别在 collective 前后；
- **反向单独测**：`torch.autograd.set_detect_anomaly(True)` + 有限差分（小模型）；梯度通过 CP 会做 all-reduce/reverse-scan，灵敏度更高；
- **通信层**：`NCCL_DEBUG=INFO`，nsys 抓 collective 的 dtype，确认 all-gather 的 buffer 类型。

</details>

## 三、修复策略（按层）

### Layer 1 — 通信精度策略（最高收益）

1. **递归状态 $S$ 及所有部分和全程 fp32**：在 `all_gather`/scan 前 `state = state.float()`，收到后再参与 fp32 累加，只把最终输出转回 bf16。
2. **带宽敏感时用 bf16×2（split-fp32）**：把 fp32 拆成两个 bf16

$$
x = \underbrace{\text{bf16}(x)}_{\text{hi}} + \underbrace{\text{bf16}(x-\text{hi})}_{\text{lo}}
$$

用两次 NCCL bf16（或一次 uint32）传输，可把状态误差从 $\sim5\times10^{-3}$ 拉到 $\sim10^{-5}$，且完全兼容只支持 bf16 的通信原语。
3. **normalizer / 分母永不降精度**。

### Layer 2 — 累加算法

- 局部 chunk 状态与 scan combine 用 **Kahan / Neumaier 补偿累加**；
- scan 用 **固定拓扑的确定性树**（按 rank 数确定），并保证正反向同一拓扑 → 可复现；
- 避免 `atomicAdd`，或接受并记录其非确定性。

### Layer 3 — 动态范围

- 门控 / 衰减：**累积 decay 在 log 空间算**，最后再 `exp`（fp32），避免连乘下溢；
- 当 $\|S\|$ 超过阈值时**周期性 rescale**（记录指数），防止 fp16 溢出 / bf16 吸收；
- fp16 状态要额外做 overflow 检测（bf16 动态范围大，主要死于尾数，不死于指数）。

### Layer 4 — 与参考语义对齐

- 保证 intra/inter 切割的 mask、offset 与单卡数学**逐位一致**（多数"精度 bug"其实是这类边界 bug）；
- intra 与 inter 路径用**同一 dtype 策略**；
- inter-chunk matmul 用 fp32 累积，或显式关闭 TF32。

### Layer 5 — DeltaNet / 矩阵型更新

$$
S_t = S_{t-1}(I - \beta k k^\top) + \beta v k^\top
$$

这是"近恒等矩阵连乘"，舍入误差比纯加法型更糟。用 **WY 表示 / UT transform** 并在 fp32 下做块内求逆。

## 四、验证与回归（放进 CI）

1. **黄金测试**：CP 度 vs 单卡，容差按策略定：

| 通信策略 | 状态相对误差 | 建议容差 |
|---|---|---|
| fp32 | $\sim10^{-7}$ | `rtol=1e-5` |
| bf16×2 | $\sim10^{-6}$ | `rtol=1e-4` |
| 纯 bf16（bug） | $\sim5\times10^{-3}$ | 不可接受 |

2. **CP 度不变性**：误差不应随 CP 度显著增长（不变量测试）；
3. **长上下文压力测试**：$L$ 拉到训练长度，监控 $\|S\|$ 与误差爬升；
4. **梯度测试**：小模型有限差分；
5. **可复现测试**：同 seed 同 CP 度 → 跨进程 bit 一致。

<details>
<summary><b>点击查看实验代码与结果（模拟 bf16 + prefix-scan）</b></summary>

实验设置：$d_k=d_v=64$，$N=128$ 个 chunk，增量 $\Delta \sim \mathcal{N}(0,0.5^2)$，fp64 为参考；bf16 用 round-to-nearest-even 软件模拟；扫描用 Hillis–Steele。

**通信策略 vs 最终状态误差**

```
state @ fp32   : 7.338e-08
state @ bf16   : 4.708e-03     <-- 默认 bug
state @ bf16x2 : 6.817e-06     <-- split-fp32 修复
```

**bf16 状态误差随 chunk 数（≈ CP 度）增长**

```
chunks=   4  state_rel_err=2.462e-03
chunks=  32  state_rel_err=4.065e-03
chunks= 128  state_rel_err=4.708e-03
```

**误差传播到输出** $O = Q S_{r-1}$：

```
fp32-state output rel_err: 1.633e-07
bf16-state output rel_err: 4.528e-03
```

**动态范围（吸收效应的来源）**

```
i=  0  ||S_i||/||delta_i|| =  1.0
i= 31  ||S_i||/||delta_i|| =  5.7
i=127  ||S_i||/||delta_i|| = 11.3   (≈ sqrt(128))
```

**确定性**：fp32 树形 scan 与顺序累加 **非 bit 一致**（rel diff $2.2\times10^{-7}$）→ CP 度改变必然改结果，需靠容差而非相等来判。

结论与上文的机制一一对应：主因是 **bf16 状态通信**（$10^{-7}\to5\times10^{-3}$，劣化 4 个数量级），bf16×2 或 fp32 可完全消除。
