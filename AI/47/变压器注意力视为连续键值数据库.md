## 结论先说

可以——而且这不是修辞上的类比，而是有严格数学对应的：**attention 就是一个"软寻址的内容可寻址存储器"（content-addressable memory / associative memory）**。你列的三条骨架（读操作无副作用、k-v 成对、相似度变成权重）基本都成立。但要让它真正"像数据库"，需要升级三处、并承认它缺三样东西。

---

## 一、你说对的部分（而且比你说的更硬）

**1. Query 之间互相独立 → 并行读，无副作用**

给定 $(K,V)$，每个 query 的输出只依赖 $q_i$ 自己和 $(K,V)$，token 之间没有交叉耦合：

$$\frac{\partial\, \mathrm{out}_i}{\partial q_j} = 0 \quad (i \neq j)$$

这正是 attention 能一次性并行算完、以及推理时 KV cache 能直接复用的原因。工程上"同一个 database 搜多少次都不变"是字面成立的——KV cache 本身就是这个 database 的物化形式。

**2. K-V 必须成对**

是构造性的：$K = XW_K$、$V = XW_V$ 按位置对齐，第 $i$ 行 key 只能读第 $i$ 行 value。没有 key 就没有"地址"，检索无从发生。

**3. "全找 + 相似度变权重" → 这就是核平滑（kernel smoothing）**

$$\mathrm{Attn}(q) = \sum_i \underbrace{\frac{\kappa(q,k_i)}{\sum_j \kappa(q,k_j)}}_{\text{权重}} v_i,\qquad \kappa(q,k)=\exp\!\left(\frac{q^\top k}{\sqrt d}\right)$$

这形式上是 **Nadaraya–Watson 核回归 / 核密度加权平均**。传统 DB 是 `WHERE k = q LIMIT 1`，attention 是 `ORDER BY sim(q,k) ALL, WEIGHT BY sim`——你把离散的"命中/未命中"换成了连续的"命中程度"。

---

## 二、需要升级的三处

### (a) 它不是"相似度"，而是**内积寻址**

$q^\top k$ 既不对称、又有尺度、也不满足度量的三角不等式。$\|k\|$ 变大 = 这个地址"更响"（更自信/更活跃），并不只是"更像"。

所以"相似度"应该升级为**可学习的双线性匹配分数**：$\text{score} = q^\top M k$ 的特例。你说的 Swin V2 用 cosine attention 恰恰是把 magnitude 除掉的特例——让寻址只依赖方向，再配一个可学习温度 $\tau$ 稳定 logits。这正是"纯相似度地址"的版本。同类变体还有 L2 距离 attention、无 softmax 的 attention、以及 $\phi(q)^\top\phi(k)$ 的核形式。

### (b) 归一化 → 它是**插值**，不是**取回**

softmax 权重和为 1，输出必然落在 $\{v_i\}$ 的凸包里。所以它是"模糊的平均"，不是"精确返回一条记录"。

- 温度 $\tau \to 0$：退化成 hard top-1（argmax，真正的 DB 查询）
- $\tau \to \infty$：退化成均值池化
- 现实是中间的软检索

这也解释了为什么它可以输出**从未被存储过的组合**——插值允许这样。（幻觉的一种机制就埋在这里。）

### (c) K 和 V 强耦合，所以"表"是低秩、有结构的

真实 DB 里 key 和 value 是独立字段，可以分别增删改。attention 里 $k_i$ 和 $v_i$ 是**同一个 $x_i$ 的两个线性投影**，不能任意配对。这个约束让它的表达能力受维度 $d$ 限制（叠加/superposition、容量问题）。它不是一张任意表，而是一张**被低秩结构绑死的表**。

补充两条结构性差异：

- **多头 = 多张表**：每个 head 有自己的 $W_Q, W_K, W_V$，即多套寻址空间，最后用 $W_O$ 混合。更像"多表 join 后 concat"。
- **多层 = 迭代检索**：第 $\ell$ 层的读结果写回残差流，第 $\ell+1$ 层重新生成 $K,V$——**数据库每层被重写一次**。它不是一次静态读，而是 read → write → read 的循环。

## 三、类比真正断掉的地方

<details>
<summary>点开看：真数据库有、而 attention 没有的六样东西</summary>

| 真 DB 能力 | attention |
|---|---|
| 返回空结果 / `NOT FOUND` | ❌ 永远返回某个值。这正是 **attention sink**（大量权重堆到一个无意义 token 上，充当 no-op / null key）存在的动机 |
| 唯一键、去重 | ❌ 重复 key 会被**平分权重后平均**，而不是去歧义 |
| 事务、原子写、不可变性 | ❌ 一次 forward 内是只读的；"写"发生在 MLP 与下一层的投影里 |
| 外部 client 发查询 | ❌ query 由同一个网络生成，是自组织内存，不是被外部调用 |
| schema / 索引可人工设计 | ❌ 度量 $W_Q,W_K$ 是梯度学出来的，没有人工 criteria |
| 容量保证、精确取回 | ❌ 软检索有干扰噪声，容量受 $d$ 限制 |

</details>

**一句话**：attention 更像 Kanerva 的 **Sparse Distributed Memory**（软寻址的内容可寻址内存）或核密度估计器，而不是 SQL 意义上的 KV store。

## 四、这个类比最有价值的三个推论

**1. 效率问题 = 缺索引问题。** 你说"全找"——对，attention 是 brute-force 扫描全部 $n$ 条记录，$O(n^2)$。于是所有高效 attention 都在做同一件事：**给这个 DB 建 ANN 索引**。Reformer 直接用了 LSH（经典 ANN 技术），Routing Transformer 用 k-means 聚类，还有各种稀疏/top-k attention（近似 top-k 检索，付出 recall 换速度）。这个映射非常干净。

**2. 工程上它已经字面是 KV 数据库。** KV cache = 物化表；量化/驱逐 = 压缩与剪枝；PagedAttention = 分页；RAG = 给这个软检索外挂一张真数据库。

**3. 可解释性上，有些 head 真的是查表。** induction head 就是字面的"匹配到之前出现过的 token → 复制它后面的内容"，是内容寻址 + 拷贝。而 FFN 层被证实用作**参数化的 key-value 记忆**（subject → attribute）。合起来一个很漂亮的图景：**attention = 上下文里的非参数 DB；FFN = 训练语料里的参数化 DB**。

## 五、更"对"的形式化版本

<details>
<summary>点开看：把类比写成公式的几个版本</summary>

**① 核回归（最直接的版本）**

$$\mathrm{Attn}(q)=\frac{\sum_i \kappa(q,k_i)v_i}{\sum_j \kappa(q,k_j)}$$

**② Linear attention = 一个矩阵式数据库**

用特征映射 $\phi$ 替掉 softmax，分子变成

$$\sum_i \phi(k_i)\,v_i^\top =: M$$

这是一张**用一个矩阵存下来的表**（Hebbian 外积记忆），查询 = 一次矩阵向量乘 $\phi(q)^\top M$。这才是最"KV-store"的形态：key 方向 → value 方向。代价是容量约 $O(d)$（经典线性联想记忆的界）。

**③ Modern Hopfield network = 一步检索**

softmax attention 的输出恰好等于现代 Hopfield 网络的一步更新 $\xi \leftarrow X\,\mathrm{softmax}(\beta X^\top \xi)$，即一次能量下降的检索；对应的存储容量随维度指数增长。所以"attention 是联想记忆的检索算子"有正式的收敛性证明支撑。

**④ Fast weight programmer**

把 attention 看成用外积动态改写权重矩阵——那"读"和"写"就统一了，DB 的边界也就模糊了。

</details>

## 一句话总结

你的直觉是对的：**attention 就是"用内积学出来的相似度做软寻址、把 top-1 换成全表加权、输出是 value 的凸组合"的内容寻址内存**。要补的三件事是：相似度其实是**带尺度、不对称、可学习的内积**；输出是**插值而非取回**；KV 之间**被同一个输入绑死、且每层重写**。它缺的那一样最关键的 DB 特性是——**永远不会告诉你"查不到"**。

## 😀 默认助手 (7)

# 先把"定义"和"设计选择"切开

你这条警告是整道题的钥匙。先把 attention 剥到不能再剥：

$$\text{out}(q) \;=\; \sum_i w_i\, v_i,\qquad w_i = g(q,k_i) \ge 0$$

**这就是 attention 全部的定义。** 一句话：*用学出来的、依赖内容的度量做软寻址，然后对载荷做非负加权聚合*。等价的说法是"一个由输入动态生成的线性算子"（data-dependent linear map / fast weights）。

剥掉所有 design choice 之后，剩下的**核心不可约**只有三条：

1. **地址空间与载荷空间分离**（要有 $k$ 和 $v$ 两组角色，不能是同一个东西）
2. **权重依赖 $(q,k)$ 的内容**，而不是位置/索引（这是"content-addressable"的全部含义）
3. **聚合是对 $v$ 的加权和**（而不是别的什么）

下面这些**全都不是定义**，每一条背后都是一个现实需求：

| 组件 | 地位 | 它真正解决什么 | 换成什么 |
|---|---|---|---|
| 点积 $q^\top k$ | design choice | 最便宜的两两交互、单个 GEMM 喂满硬件 | 加性 (Bahdanau)、L2、cosine |
| softmax | design choice | 数值尺度控制 + 凸组合 + 可核化 + 竞争性 | sigmoid/ReLU/gating、干脆不归一化 |
| $1/\sqrt{d_k}$ | design choice | 温度校准，防止 softmax 饱和 | 可学习温度 $\tau$、或先把 q,k 归一化 |
| multi-head | design choice | 解耦多个"选择预算" | 单头大维度、MQA/GQA |
| pos enc | design choice | 打破集合的无序性/重复 token 对称 | 输入进 score、或完全不加 |
| causal mask | design choice | 自回归因果性 + 顺带提供位置线索 | 双向、文档 mask、任意 $(n_q,n_{kv})$ 掩码 |
| $d_v = d_k$ | 习惯 | 顺手的对称 | 完全可以不等 |

**题眼**：把 $g$ 换成内积、把非负归一化换成 softmax、把 $k,v$ 从 $x$ 线性投影出来、再并行跑 $H$ 份——这四步是 **Transformer 的工程贡献**，不是 attention 的定义。所以下面每问我都分两层回答：**哪一层是本质，哪一层是现实需求**。

# Q1. QKV 从哪来，三个"参数"怎么理解

## 事实层

$$q_i = W_Q x_i,\quad k_i = W_K x_i,\quad v_i = W_V x_i,\qquad x_i \in \mathbb{R}^{d},\; W_\bullet \in \mathbb{R}^{d_{head}\times d}$$

**先纠正一个用词**：$W_Q,W_K,W_V,W_O$ 才是**参数**；$q,k,v$ 是**激活**，每个 token、每层、每个序列都不同。这个区分在 DB 视角下极其重要：

> **attention 的检索步里不存任何知识。** 所有"记录"都来自激活（上下文）。权重里存的只是"怎么寻址、怎么编码载荷、怎么读出"。知识在权重里则主要落在 MLP（即参数化的 k-v memory）。

## 为什么必须是三个（而不是一个）投影

因为**同一个 token 同时扮演三个不同角色**，而这三个角色的职责正交：

| 角色 | 语义 | DB 对应 |
|---|---|---|
| $W_Q$：我在找什么 | 探针（probe），用**地址空间**的语言提问 | 查询语句 |
| $W_K$：我能被谁找到 | **索引/标签**，不是内容本身 | 索引列 |
| $W_V$：找到我之后我给什么 | **载荷**，可以不等于"我是谁" | 数据列 |
| $W_O$：怎么把各头答案读回主干 | 读出/混合 | 结果投影 |

如果取 $W_Q=W_K=W_V=I$，你得到的就是"按原始 embedding 相似度做池化"——退化的，无法表达 **"出于理由 A 找到 X，提取信息 B"**。真实 DB 里 key ≠ value 是常识；attention 的三投影就是把这件事参数化。

关键洞察：$q^\top k = x_i^\top W_Q^\top W_K x_j = x_i^\top M x_j$，其中 $M = W_Q^\top W_K$。所以 $W_Q,W_K$ **合起来定义了一个学出来的度量**，$W_V$ 定义**载荷的编码方向**。三投影的"角色分离"接近核心，"三个"这个数字本身是工程习惯（可以两投影共享，也可以加更多）。

# Q2. Score 怎么算、为什么 $QK^\top$、为什么先 softmax 再乘 V、为什么除 $\sqrt{d_k}$

## (a) 为什么是 $QK^\top$

这是最容易被当成定义、其实最不本质的一步。

**本质只要**：score $= f(q,k)$ 依赖内容。**为什么偏偏点积**，现实原因：

- **最便宜**：$O(d)$ 一对，零额外参数，且整体就是一次 GEMM（$n\times d$ 乘 $d \times n$ 一次做完全部 $n^2$ 对）。加性 score 需要额外隐藏层和非线性，显存/带宽都要翻倍。
- **不损失表达力**：因为度量是学出来的，$M=W_Q^\top W_K$ 本身就是个一般的（低秩分解的）双线性型。点积的限制其实由 $W_Q,W_K$ 补回来了。
- **可核化**：$\exp$ 把点积变成可分离核 $\kappa(q,k)=\phi(q)^\top\phi(k)$，才解锁了 linear attention / 联想记忆等价这些理论结构。

替代品：加性 $\text{score}=v^\top\tanh(W_q q + W_k k)$（Bahdanau）、$-\|q-k\|^2$、cosine（Swin V2）。

**顺带一个反直觉推论**：$d_q = d_k$ 这个约束**不是 attention 的性质，是点积的性质**。换成加性 score，$d_q$ 和 $d_k$ 完全自由——这就直接接到 Q3。

## (b) 为什么要先 softmax 再乘 V

拆成两件被混在一起的事：

**"乘 V" = 聚合 = 检索本身。** 这是定义，不可换。

**"先 softmax" = 归一化，作用在 `k` 那个轴上。**

为什么顺序必须是这样？因为**归一化必须沿着候选轴（$n_k$，表的行数）做**，而不是沿载荷特征轴。先乘 V 再 softmax = 对 $d_v$ 做归一化，语义全错。

$$\underbrace{\mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)}_{\text{对每一行（=一条 query）在 } n_k \text{ 个候选上归一化}} V$$

DB 语言：**先把"检索权重"在整张表上分好，再按权重取数据。**

softmax 归一化买到什么（都是"方便"，不是必须）：

1. **尺度稳定**：输出是凸组合，$\|out\|$ 不随 $n$ 增长，能干净地接进残差流。若用无归一化的权重，输出尺度随 $n$ 漂移。
2. **竞争性**：softmax 是 **argmax 的软松弛**——固定的一份预算在表上分配。"哪条最匹配"才有意义。这是 sigmoid 做不到的（见 Q4）。
3. **平移不变**：logits 加常数不改变输出。logits 的绝对偏移本就无意义，softmax 自动扔掉它。
4. **锐化旋钮**：温度 $\to 0$ 退化成 hard top-1（真·DB 查询），$\to\infty$ 退化成均值池化。**硬查表和均值池化是同一个算子的两个端点**，这是非常漂亮的一点。

代价（诚实地说）：softmax 让**每条记录权重都非零**（稠密扫全表），而且**永远不能说"没找到"**——这就是 attention sink 的动机。

## (c) 为什么除 $\sqrt{d_k}$

**不是定律，是温度校准。**

若 $q,k$ 各分量 i.i.d. 均值 0 方差 1，则 $q^\top k$ 的方差是 $d_k$。于是 logits 标准差 $\propto\sqrt{d_k}$，维度一大 softmax 就饱和成 one-hot，Jacobian $\mathrm{diag}(p)-pp^\top \to 0$，梯度死掉。除以 $\sqrt{d_k}$ 把方差拉回 $O(1)$。

把它升格为 first principle，正确的表述是：

> **softmax 的有效温度必须和 logits 的量级匹配。** 选 $1/\sqrt{d_k}$ 只是"不想学这个温度"的一种偷懒方式。

两个佐证：
- **为什么是 $\sqrt{d_k}$ 而不是 $\sqrt{d_{model}}$**：logits 活在 head-dim 里。
- **Swin V2 的 cosine attention** 就是把 q,k 归一化 → 尺度问题消失 → 换成一个**可学习的 $\tau$**。同一件事的两种做法。

# Q3. 形状约束：哪些是本质，哪些是点积的连带产物

先把"长度"和"维度"分清（DB 语言：**行数 vs 列数**）：

$$Q\in\mathbb{R}^{n_q\times d_k},\; K\in\mathbb{R}^{n_{kv}\times d_k},\; V\in\mathbb{R}^{n_{kv}\times d_v}$$

两个约束来自**两个不同的运算**：

| 约束 | 来自哪一步 | 本质程度 |
|---|---|---|
| $d_q = d_k$ | 内积 $\langle q,k\rangle$ 要求同维 | **点积的产物**，不是 attention 的 |
| $n_k = n_v$ | $\mathrm{softmax}(S)V$ 要求权重向量的第 $i$ 项能索引到 $V$ 的第 $i$ 行 | **本质**：这是"k 与 v 必须成对"的矩阵表达 |

第二点正是你上一轮说的"不成对就读不了"的严格版本。**权重是按 k 的索引排的，V 也按同一个索引排**——索引对不上，地址就指不到行。

- $n_q \neq n_{kv}$ 完全没问题：cross-attention（$n_q$ 是 decoder 长，$n_{kv}$ 是 encoder 长）、prefix-LM、KV cache 推理时都是。score 矩阵和 mask 都是 $(n_q \times n_{kv})$ 形状，**q-k 的不对称性天然能表达**（causal mask 就是个三角矩阵，任意 mask 也是任意 $(n_q,n_{kv})$ 模式）。
- $d_v \neq d_k$ 也完全没问题：$W_O: \mathbb{R}^{d_v}\to\mathbb{R}^{d}$ 负责接回来。$d_v=d_k$ 纯粹是习惯。
- 现实中的"打破约束"：MQA/GQA 让多 head 共享 K/V（$n_k=n_v$ 仍成立，只是不同 head 复用同一张表）；DeepSeek 的 MLA 把 K/V 压成低维潜变量——**地址宽度 ≠ 载荷宽度**的极端版本。

# Q4. 为什么内积+softmax，不用 sigmoid

分两问：为什么"竞争式归一化"，为什么不是 sigmoid。

## 关键差异：**一份预算** vs **独立开关**

$$\text{softmax}: \sum_i w_i = 1 \quad\text{——argmax 的软松弛，权重互相竞争}$$
$$\text{sigmoid}: w_i=\sigma(s_i)\in(0,1)\ \text{各自独立}\quad\text{——没有相对比较}$$

DB 视角：softmax 表达的是"**整张表上分配一份注意力预算**"，能做到"这是最匹配的那条"。sigmoid 表达的是"每条记录各自说'我相关吗'"，**只能表达"有好的匹配"，表达不了"最好的匹配"**。而复制/检索类电路（比如 induction head 那种"匹配到之前出现过的那一个然后拷贝"）**本质就是相对竞争**——sigmoid 要靠额外机制去压制其他 key 才能模拟。

## 具体会坏在哪

| 用 sigmoid 的问题 | 后果 |
|---|---|
| $\sum_i w_i \approx n/2$，不归一化 | 输出范数随 $n$ 增长，跨长度/跨层尺度漂移，残差流统计被打乱 |
| 不平移不变 | logits 加常数会改变输出，而 logits 的绝对偏移本来无意义 |
| 两端饱和 $\sigma'\le 1/4$ | "明确无关"和"明确相关"两侧梯度都趋于 0，死区 |
| 不可核化 | 拿不到 $\phi(q)^\top\phi(k)$ 分解，失去 linear attention / 联想记忆等价 |

## 但你说得对：softmax 不是必须的

设计空间是一整个谱系，恰好说明 softmax 只是选项：

- **可换掉归一化**：ReLU/ReLU² attention（GAU）、Gaussian kernel 无 softmax（Softmax-Free ViT）、sigmoid/gated attention、线性 attention 用自己的分母。
- **可以直接取消"表"**：SSM/Mamba 干脆不留 $n$ 条记录，压成一个递归状态——这是比 linear attention 更激进的"DB 压缩"。
- **纯 attention 没有残差/MLP 会退化**（rank collapse），说明这些"便利件"其实承担了稳定性职责。

**一句话总结 Q4**：softmax 买到了 归一化 + 锐化 + 竞争性 + 可核化，代价是 稠密、且永远不能说"查无此条"。

# Q5. 为什么要 multi-head

## 先破一个常见但错的理由

"多头增加表达能力/秩"——不严谨。单头满宽 $M=W_Q^\top W_K$ 秩已经能到 $d$；拆成 $H$ 个 $d/H$ 维的 head 加起来秩还是 $d$。**秩不是理由。**

## 真正的理由：**解耦多个"选择预算"**

单头对每个 query 只能产生**一个 softmax 分布**——一次归一化，一次竞争，所有候选共享同一份预算、同一个度量。多头给每个 query **$H$ 个独立的权重向量**，最后用 $W_O$ 混合：

$$\text{out} = \sum_{h=1}^{H} W_{O,h}\,\underbrace{\mathrm{softmax}(Q_hK_h^\top)\,V_h}_{\text{第 } h \text{ 张表的检索结果}}$$

于是可以**同时**做多件事：一个 head "拷贝前一个 token"，另一个 head "取主语的属性"，互不争抢预算。**多头 = 把被单次归一化强行耦合在一起的多个检索掰开**，同时因为 $d_{head}=d/H$，FLOPs 和一个满宽单头一样——基本免费。

## DB 视角

多头 = **多张表 / 多套寻址空间的集成检索**：

- 每个 head 有自己的度量 $M_h$ 和自己的载荷编码 $W_{V,h}$（不同"关系"）。
- 单头机制上倾向 top-1（一个尖锐分布）；多头相当于从多张表各取若干行再混合，**等价于提高 recall**。
- 经验证据：确实存在分工明确的功能头（induction head、previous-token head、syntactic head、attention sink head）；也确实是冗余的（大量 head 可剪）。两个都真。

# Q6. 为什么要 pos enc，为什么 Q 也要，为什么 causal 可以不要（NoPE）

## 本质：attention 是一个**集合/多重集**算子

权重只依赖 $(q,k)$ 内容，所以整个算子是**置换等变**的——表本身没有顺序。但语言是序列。更隐蔽的问题是：**两个相同的 token 有相同的 $k$，权重会被平分，模型无法区分"第一个 the"和"第二个 the"**。这是必须注入位置的根本原因。

## 位置可以注入在四个地方（这才是 first-principle 的框架）

| 注入点 | 机制 | 代表 | 得到什么 |
|---|---|---|---|
| **内容**：加到 Q/K/V | 加性 | 原版 sinusoidal / learned APE | 绝对位置；改的是"被存进去的东西" |
| **度量**：旋转 Q **和** K | 乘性 | RoPE | $q_i^\top k_j \Rightarrow$ 只依赖 $i-j$，**相对位置**；V 不含位置 |
| **score**：直接加 bias | 加性 | ALiBi、T5 relative bias | 完全不动 Q/K/V，只在 logits 上加减 |
| **不注入**：靠 mask | — | NoPE | 位置从"可访问的集合大小"隐式涌现 |

这张表说明：**"给 Q/K 加位置"只是四种方案之一，位置必须进的是"寻址函数"，不是某个 tensor。**

## 为什么 Q 也要（RoPE 视角）

因为**相对位置是 $(q,k)$ 交互的属性，不是单个向量的属性**。

RoPE 对 Q 和 K 施加**同一个**角度为位置 $i$ 的旋转 $R_{\theta i}$，于是

$$(R_{\theta i}q_i)^\top (R_{\theta j}k_j) \;\Rightarrow\; \text{只依赖 } i-j$$

**只旋转 K、不旋转 Q**，$q$ 就完全不知道自己站在哪：模型能问"位置 $j$ 上是什么"（按绝对索引查表），但**问不出"我前面两个 token 是什么"**——做不了相对寻址。"我得在哪"这个信息必须由 query 自己携带。

（加性 APE 同时加在 Q 和 K 上时，$q^\top k$ 里会出现 $p_i^\top p_j$ 之类的交叉项，顺手带出一点相对信息，但很脏——所以 RoPE 这种"只改度量不改内容"的乘性方案更干净。）

另外注意：RoPE **不旋转 V**。因为位置只用于**寻址**，载荷本身不需要位置标签。这跟"位置必须进寻址函数"的原则完全吻合。

## 为什么 causal attention 可以不要 pos enc（NoPE）

关键在于：**causal mask 让等变性从"置换等变"降级为"前缀等变"，而前缀长度是位置的函数。**

- 位置 $i$ 能访问的集合是前 $i$ 个 token。**能看见多少 = 我在哪。** 顺序信息没有被消掉，它换了个地方存：不在向量里，而在"可见集合"里。
- 于是模型可以学出计数的电路：反复"attend to 第一个 token"或"sink token"，用相对距离做锚点；在层间累积中，位置被逐层恢复出来。这也顺带解决了重复 token 问题——两个相同的 token，**看到的前缀不同**，所以可区分。
- 一个更直白的机制在**未归一化**的注意力里：输出范数直接随可求和的行数增长。softmax 归一化后这个泄漏变弱，但结合多层复合、首 token 锚点、跨层计数，位置信息仍然可被线性探针恢复（Haviv 等 2022 的结论）。NoPE 也因此在**长度外推**上往往优于绝对 PE（Kazemnejad 等 2023）。

**反过来的对照组最能说明问题**：**双向（encoder）注意力什么都不加，就是真正的顺序盲。** 没有 mask，能访问的集合恒等于全体，前缀长度不再泄露任何东西；此时把句子打乱，输出完全不变。所以 BERT 必须加 PE，而 causal LM 可以不加——**位置信息需要"某种不对称"来承载，causal mask 已经提供了这种不对称。**

|---|---|---|
| QKV | 地址空间 ≠ 载荷空间；$W_Q,W_K$ 定义度量，$W_V$ 定义载荷 | 三投影、无 bias、fused QKV |

## 😀 默认助手 (7)

## 先立一个标准：什么才叫"attention 的本质"

在回答问题之前，先给出一个最小定义，后面所有判断都以它为尺子：

$$\mathrm{Attn}\big(q;\{(k_i,v_i)\}_{i=1}^n\big) \;=\; \bigoplus_{i} \Big[\, w(q,\,k_i)\;\cdot\; v_i \,\Big]$$

其中 $\bigoplus$ 是**排列不变（permutation-invariant）的聚合**（通常就是 $\sum$）。

**三件本质的事（拿掉任何一个，它就不再是 attention）：**

| # | 本质要素 | 为什么拿不掉 |
|---|---|---|
| ① | **角色分解**：一个"地址"部分、一个"载荷"部分、一个"请求"部分 | 没有分离，就没有"按什么找"和"找到什么"的区分 |
| ② | **权重由 q 与 k 的内容决定**（content-based addressing） | 否则就是固定的池化/卷积，不是内容寻址 |
| ③ | **对记忆做排列不变的聚合** | 这是"读一个集合"的语义；也是它并行化、可 cache 的根源 |

**不是本质的（全是实现选择）**：内积、softmax、$\sqrt{d_k}$、多头、线性投影、位置编码。下面逐题都用这个尺度来切。

## Q1. Q/K/V 从哪来，怎么理解这三个参数

**本质**：①② 说的角色分解。语义上是：

- $W_Q$：**"我在找什么"**（请求，request）
- $W_K$：**"我以什么身份被检索到"**（地址，address / index）
- $W_V$：**"我被找到之后，交出什么"**（载荷，payload）

一个 DB 的表有索引列和值列，SQL 有 query。三者角色不同，就不该共用一套表示——如果直接用 $x_i$ 自己同时当 key 和 value，那么"你凭什么是你"、"你交出什么"就绑死了，网络会失去"按一个方面匹配、返回另一个方面"的自由。

**为什么必须有 W_Q/W_K/W_V 而不是 x 本身？** 因为**输入只有 $x$，但角色的语义空间不需要等于模型宽度 $d$**。$W_Q, W_K$ 把 $x$ 映到"地址空间" $d_k$，$W_V$ 映到"载荷空间" $d_v$。这才是它们真正的作用：**定义 schema**——哪一维在当索引、哪一维在当内容。真实 DB 的 schema 是人写的，这里是学出来的。

**佐证它才是本质**：cross-attention 里 $Q$ 来自一个流、$K,V$ 来自另一个流。**"角色分离"在数据来源层面就已经独立存在了**——这正说明"q 和 k 不必同源"是 attention 的概念属性，而 $W_Q$ 等只是同一流内部实现这种分离的手段（NoPE/权重共享/QK-norm 这些都是这个环节的设计选择）。

**注意一个非本质但很关键的结构约束**：$K = XW_K$、$V = XW_V$ 是**同一个 $X$ 的两个投影**，所以 key 和 value 不是独立字段——真实 DB 里你可以在同一个 key 下改 value，这里做不到。这是"低秩、有类结构"的数据库，不是任意表。这点上一轮已经说过。

## Q2. Score 怎么来，为什么 $QK^\top$，为什么 softmax 后再乘 V，为什么除 $\sqrt{d_k}$

### (a) 为什么是 $QK^\top$ —— 本质的一半

**不要把它当 definition。** 本质要求只是"$w(q,k)$ 要能反映相关性、并且能端到端学成任何度量"。一般形式是**参数化双线性型**：

$$w(q,k) = q^\top M\, k,\qquad M = W_Q^\top W_K$$

也就是说，**$QK^\top$ 只不过是"任意可学习双线性型"的一个低秩分解**：参数量 $O(d\,d_k)$ 而不是 $O(d^2)$，而且天然给出 q/k 的不对称角色。

它来自两个现实需求：

1. **可分性 → 数据库才能被"物化"。** $q^\top k$ 对每个 pair 是分离的，所以 $K$ 可以预先算好、缓存、索引。如果 score 写成 $\mathrm{MLP}([q;k])$（更表达力），key 就不再是独立对象了——**没有 key 就没有索引，也就没有 DB 类比**。所以选双线性型，是在"表达力 vs 可物化/可缓存/可 GEMM"之间选了后者。
2. **计算形态**：一次 matmul 覆盖所有 $N^2$ 对，映射到稠密线性代数硬件。这是 $O(N^2 d)$ 而不是 $O(N^2 d^2)$。

### (b) 为什么先算权重再乘 V —— 这是本质，不是选择

因为语义是 **地址 → 权重 → 读取**。权重是"选择"的依据，必须先生成，再去挑 value。顺序由语义强制，不是实现细节。

至于 $w_i \propto \exp(s_i)$，它满足的性质里，哪些是需求、哪些是便利：

- **非负**（可组合成加权平均）、**随 score 单调递增**（越像越重）—— 这是需求，你说的对。
- **归一化为 1** —— 这是**最大的一个便利**：输出尺度与条目数 $n$ 无关（不会随 $n$ 爆炸）、输出是凸组合（有界稳定）、可解释为概率。
- **处处可导、处处非零** —— 这才是**软化的真正理由**：argmax 不可导，而 softmax 让**每一条记录都得到梯度**，没有"死检索"。温度 $\tau\to 0$ 就退回 hard top-1。

所以一句话：**内积负责"谁相关"，softmax 负责"把这 1 单位的读取预算怎么分"**。两者不在一个语义层级上。

### (c) 为什么除 $\sqrt{d_k}$ —— 纯工程，纯选择

假设 $q_j,k_j$ i.i.d. 均值 0 方差 $\sigma^2$：

$$\mathbb{E}[q^\top k]=0,\qquad \mathrm{Var}[q^\top k] = d_k\,\sigma^4 \;\Rightarrow\; \mathrm{std} \approx \sigma^2\sqrt{d_k}$$

logit 的标准差随 $\sqrt{d_k}$ 增长，会把 softmax 推进**饱和区**：分布近乎 one-hot，softmax 的 Jacobian $\partial w_i/\partial s_j = w_i(\delta_{ij}-w_j) \to 0$，梯度消失、训练卡死。除以 $\sqrt{d_k}$ 只是把 logit 方差拉回 $O(1)$，让 softmax 待在"响应区间"，并让初始化对 $d_k$ 尺度不变。

**它本质上是温度设定。** 缩放 $W_Q \to cW_Q$ 就把 logit 缩放 $c^2$，网络完全能自己学出温度——所以 $1/\sqrt{d_k}$ 只是个**初始化约定**。等价的替代方案：QK-norm（对 q、k 做 RMSNorm/LayerNorm，Gemma 2 / ViT-22B 一类做法）、cosine attention（Swin V2，把尺度除掉 + 学一个温度）、logit soft-cap（tanh 压 logit）。**同一件事的三四种写法，说明它是 condition number 问题，不是 attention 的语义。**

**而 "softmax 不是 definition" 你说得完全对**，替代品都是有理由的：

- **sparsemax / entmax**：能产生**精确的 0**，才是真正的 top-k（softmax 永远不会真的"不选"）
- **ReLU / ReLU²（Primer EZ）**：非负、有稀疏性
- **sigmoid**：见 Q4
- **完全不归一化 + 学一个 scale**：最诚实的"退掉偷懒"版本
- **Gumbel-softmax**：想采样出离散选择

而且注意代价：**softmax 的不可分性正是"没法线性时间精确计算"的根源**。linear attention 之所以要换成特征映射 $\phi(q)^\top\phi(k)$，就是在**主动放弃归一化**来换可分性。所以 softmax 不是免费午餐，它买的是"归一化 + 竞争"，付的是 $O(N^2)$ 和"必须分掉全部质量"。

## Q3. 为什么 $N_q \ne N_k$ 可以、$d_q = d_k$ 必须；$N_k = N_v$ 必须、$d_k \ne d_v$ 可以

先给结论，因为三件事的**强制性完全不同**：

| 约束 | 强制吗 | 原因 |
|---|---|---|
| $N_q \ne N_k$ 允许 | **概念上必然允许** | 读操作的次数与库的大小本来就是独立自由度 |
| $N_k = N_v$ 必须 | **结构上必然** | 一条记录一个地址；不成对就没法"按 key 读 value" |
| $d_q = d_k$ 必须 | **只是选择的结果** | 因为我们用了**无参数**内积 |
| $d_k \ne d_v$ 允许 | **概念上必然允许** | 索引空间与载荷空间是两个不同的东西 |

**长度（$N$）方向的自由度**：
输出长度 $= N_q$，因为**每个 query 产生一个结果**。$N_q \ne N_k$ 正是 cross-attention、encoder-decoder、prefix-LM、多模态（图文 token 当 $K,V$、文本当 $Q$）存在的理由。DB 视角下一句话：**库可以很大，而你可以只发一个问题。** 这也是"读操作无副作用"的直接体现。

**$N_k = N_v$ 是硬的**：权重 $w$ 是长度 $N_k$ 的向量，$V$ 是 $N_k \times d_v$ 的矩阵，对齐方式是**按位置**。让 $w$ 建立在 key 的索引上、却去读另一个索引空间的表——这个操作在语义上无法定义。这是"一条记录 = 一个 key + 一个 value"的必然结果。

**"$d_q = d_k$" 最值得拿来当"别把设计选择当公理"的例子。** 严格的 attention 不需要它。一般双线性型

$$w(q,k) = q^\top M\,k,\qquad M\in\mathbb{R}^{d_q\times d_k}$$

**允许两个维度不同**。你必须让 $d_q = d_k$ 的唯一原因是：你选了**没有参数的内积**当度量，那它自然要求两侧在同一个向量空间里。**"同一空间"约束的是"地址空间是共享的一个"，而不是"两个向量宽度相等"**——这是一个关于"索引必须是同一套坐标系"的要求（否则你没法把 key 单独存起来当索引去和查询比对），不是关于数字的。

同理，$d_v$ 只管**读出来多宽**，$W_O$ 再把它映回模型宽度。$d_v = d_k = d/H$ 只是参数配平和实现方便，不是必须。代价上：每个 head 的贡献秩被 $d_v$ 限制。

所以真正的规律是：**$q$ 和 $k$ 必须落在同一个地址空间；$v$ 和 $k$ 必须在长度上一一对齐。其余全是自由。**

## Q4. 为什么内积 + softmax，为什么不用 sigmoid

**内积**在回答"谁相关"（排名），**softmax** 在回答"预算怎么分"（分配）。而 sigmoid 是**逐元素的**，它把第二层语义整个换掉了：

$$\text{softmax: } \sum_i w_i = 1 \Rightarrow \text{输出是 } \{v_i\} \text{ 的凸组合}$$
$$\text{sigmoid: } \sum_i \sigma(s_i) \text{ 无约束} \Rightarrow \text{输出是 value 的"门控和"}$$

这不是谁对谁错，是**两个不同的功能**：

**softmax 强的地方**
- 竞争（winner-take-all）：$\tau\to 0$ 就能逼近精确 top-1。**"最近邻检索"这件事，softmax 天生可以实现，sigmoid 需要很多门同时饱和才能凑出来。**
- 归一化 ⇒ 尺度对 $n$ 不变、输出有界 ⇒ 训练稳。
- 一个统一的温度旋钮。

**sigmoid 强的地方（这些是真的优点，不是安慰）**
- **能表达"这里什么都没有"。** softmax 被迫把 1 单位的质量分完，即使全是垃圾——**attention sink 现象就是这条病的症状**。sigmoid 全部门接近 0 时，输出就是"空"。
- **天然可分 ⇒ 天然线性时间。** 这就是 AFTransformer 的 gating、也是 Mamba/SSM 里选择性门控的同一思想。
- 训练鲁棒性/量化友好（sigmoid 有上界，logit 不会失控）。

**为什么不选它作为默认**：默认配置下你要的是"带竞争的加权平均 + 可锐化为 top-1 + 尺度稳定"，softmax 一次全给你；sigmoid 给的是"选择性写入"，是另一个算子。近年（如 sigmoid self-attention 一类工作）证明 sigmoid 版能打平甚至在某些鲁棒性指标上更好——这**恰恰印证了 softmax 是选择而非定义**。

## Q5. 为什么要 multi-head

**本质**：一个 head 就是**一张表 + 一套度量**。单头意味着只有**一个**双线性型，也就是只有一种"相关性"概念。

问题在于：**一层里同时存在好几种彼此无关的关系**——句法依存、指代、位置邻接、induction（复制）、检索式查找。如果只有一套 softmax，这些关系必须**抢夺同一份归一化预算**：把质量给了指代，就给不了邻接。**归一化是零和的，这就是单头的干扰。**

多头 = **多个独立归一化的检索并行**。关键不等式：

$$\sum_{h=1}^{H}\mathrm{softmax}(Q_hK_h^\top)V_h \;\;\ne\;\; \mathrm{softmax}\Big(\sum_{h}Q_hK_h^\top\Big)V$$

不只是"几个 rank-$d/H$ 双线性型相加合成一个 rank-$d$ 的"——而是 $H$ 个**各自 softmax、各自 top-k** 的读取结果再合并。这是**表达力上的实质增益**，不只是参数切分。

**DB 类比**：多张不同 schema 的表（或同一张表上建多个索引/多种地址编码），各自返回结果再 merge。也像**多路 ANN / product quantization 多子索引**。

**经验支持**：可解释性工作显示 head 会功能专门化——induction head、previous-token head、position head、syntactic head；而且存在 **head superposition**（一个 head 同时承担多种功能，即多义性）。一侧是"很多 head 可剪掉"（冗余），另一侧是"少数专门化 head 是承重的"，两者并存。

**设计选择的部分**：$H$、$d/H$ 的切法，以及 MQA/GQA（把 $K,V$ 共享以省 KV cache 显存）都是**工程权衡**——MQA/GQA 的存在本身就说明「多头」里有一半是在买缓存效率，而不是纯粹的表达力。

## Q6. 为什么要 pos enc；为什么 q 也要；为什么 causal 可以 NoPE

### 根因：attention 对集合是排列不变的

$$\mathrm{Attn}(\pi\cdot X) = \pi\cdot \mathrm{Attn}(X)$$

**它对"顺序"这个词毫无概念，这是设计初衷（集合聚合），不是缺陷。** 语言需要顺序，就必须从外面注入。所以在 DB 视角下：**位置编码不是 attention 的一部分，它是"索引方案"的一部分**——把 position 加进地址里，就是给这个内容寻址库再建一个位置索引。

### 为什么 q 也要位置

以加法 PE 展开 score：

$$(q_i+p_i)^\top(k_j+p_j) = \underbrace{q_i^\top k_j}_{\text{纯内容}} + \underbrace{q_i^\top p_j + p_i^\top k_j}_{\text{内容×位置}} + \underbrace{p_i^\top p_j}_{\text{纯位置}}$$

最后一项才是"**与内容无关的相对寻址**"。它依赖 $i$ 和 $j$ 同时出现——也就是说，**"query 处在位置 $i$ 去找位置 $j$"这个能力，必须由 query 侧携带位置信息才能表达**。只给 $k$ 加 PE，顶层只能表达"我这条记录有位置 $j$"，却无法表达"我想找离我多远的东西"。ALiBi 本质上就是把 $p_i^\top p_j$ 这一项换成一个显式的相对距离 bias。

RoPE 更干净地说明同一点：$R_i q \cdot R_j k = q^\top R_{j-i} k$ ——**相对位置是从"两边都旋转"里掉出来的**，一边不转就没有相对量。

（顺带一个设计细节：encoder-decoder 的 cross-attention 里，q 和 k 来自两条不同长度的序列，"同一条绝对位置轴加给两者"是没意义的，需要 query 位置与 key 位置分开处理。这说明 PE 也是**索引方案**而不是算子性质。）

### 为什么 causal 可以 NoPE

**因为 causal mask 本身就是一个位置信号。** 关键观察：

$$\text{position } i \text{ 可见的集合} = \{0,1,\dots,i\}$$

可见集合的**大小**直接编码了 $i$。于是：

- 第 0 个位置**永远**只能看见 1 个元素；
- 一层可以做"看一眼开头 token / 数可见元素 / attend 到前一个 token"，**多层复合就能构造出计数器/位置特征**；
- 而且 causal 打破了排列不变性：score 里有一个结构性的 $-\infty$，让它成为**定义在有序前缀上的 DAG 算子**，函数类不再是"位置的对称群"。它带着一个很弱的**相对位置先验**（"我被遮罩了"这一信息本身就有方向）。

所以 NoPE 不是"不需要位置"，而是**位置可以从 mask + 深度里推出来，不必显式给**。（Kazemnejad 等 2023 的 NoPE 工作还发现，decoder-only 下它在外推长度上往往**更好**，因为显式学到的 PE 容易过拟合训练长度，而 NoPE 把位置推理留给了模型。）

**反过来，这也解释了为什么 encoder/bidirectional 不能省 PE**：没有 mask、没有 PE，attention 就是完全排列不变的，模型连 `abc` 和 `cba` 都分不出来——**信息在原理上就不可恢复**。所以"能不能省 PE"取决于"**还有没有别的通道泄露顺序**"，而不是取决于 attention 本身。

你这段话里其实藏着一个我觉得可以再往下切一刀的地方：**softmax 干了两件彼此独立的事，被强行绑在一个函数里了**。拆开之后，"总和=1 所以性质好"这个理由在今天的架构里已经**半过期**了，而真正留下来的那个理由，跟"总和=1"关系不大。

## 一、softmax = 归一化 + 指数锐化

$$\underbrace{\frac{s_i}{\sum_j s_j}}_{\text{归一化：sum=1}}\quad\text{vs}\quad\underbrace{\frac{e^{s_i}}{\sum_j e^{s_j}}}_{\text{归一化 + 平移不变 + 锐化旋钮}}$$

你说的"总和变 1，性质就好了"——如果只是这个，那 L1 归一化 $s_i/\sum_j s_j$ 就够了。但 L1 归一化：

| | L1 归一化 | softmax |
|---|---|---|
| sum = 1 | ✅ | ✅ |
| 平移不变 $\text{softmax}(s+c)=\text{softmax}(s)$ | ❌ | ✅ |
| 要求 $s_i \ge 0$ | ✅（强制） | ❌（自动） |
| 锐化旋钮（温度） | ❌ | ✅ |
| 光滑、可微、梯度好看 | 半 | ✅ |

**平移不变才是关键**：它意味着**只有相对差异有意义**，度量 $q^\top k$ 的绝对尺度被自动扔掉——这正是"排序/检索"该有的语义。而锐化旋钮意味着**hard top-1（argmax）和均匀池化是这个算子的两个端点**，中间连续可调。

### softmax 唯一真正 principled 的理由：最大熵软选择

$$\mathrm{softmax}(s/\tau) \;=\; \arg\max_{p \in \Delta^n}\ \big\langle p,\, s \big\rangle \;+\; \tau H(p),\qquad H(p)=-\sum_i p_i \log p_i$$

**softmax 是"在仍然偏好高分的前提下，最不 commitment 的那个选择"。** 这一条同时解释了：

- 为什么必须是 $\exp$（它是这个变分问题的唯一解，不是随便挑的正函数）；
- 为什么温度能当锐化旋钮（$\tau$ 就是熵的正则系数）；
- 为什么它是 argmax 的"正确"松弛（$\tau \to 0$ 就是 hard attention）。

所以"为什么 softmax"的答案可以升格为：**它是软检索在损失最少信息的意义下的最优解**——比"总和为 1 很方便"硬得多。

## 二、但你说的也对：尺度那件事，LayerNorm 已经接走了

现代架构多为 pre-LN。考虑注意力输出整体乘一个 per-row 正尺度 $c>0$：

$$\mathrm{LN}(c\,x) = \mathrm{LN}(x)$$

**逐 token 的正尺度被 LayerNorm 完全吃掉了。** 所以"防止输出范数随 $n$ 增长"这个经典理由，在今天的架构里基本是**过期理由**——归一化这一步是冗余的，真正剩下不可替代的只有：

1. **选择语义**：一份预算在整张表上竞争 = 软 argmax。（sigmoid 做不到，见上一轮 Q4。）
2. **平移不变**：让寻址只依赖相对相似度，度量尺度免校准。
3. **生态**：dot+softmax 才能被 FlashAttention 的 online softmax 融进一个 kernel。这是**锁定**，不是原理。

（一个诚实的 caveat：因为残差是 $x + \mathrm{Attn}(x)$，这个 per-row 尺度其实变成了"注意力分支的增益"，还会和残差量级耦合。LN 能吸收它，但增益本身仍有意义——这也是为什么后来大家干脆显式学一个 gate。所以严格说：**归一化影响的是"整体增益"，不影响"相对选择"**。）

代价也全从这两点来：

- 必须 sum=1 → **永远不能说"查无此条"** → 当没有匹配时，质量只能倾泻到某个任意 token 上 → **attention sink**。这几乎是"归一化"这个选择的直接病理产物。
- 精确 softmax 核 $\exp(q^\top k)$ 是**无限维特征映射**，写不成 $\phi(q)^\top\phi(k)$ → **归一化的依赖关系破坏了结合律** → 整个 $n\times n$ 矩阵无法先收缩掉。

第二条就是下一节的全部伏笔。

<summary>点开看：score 函数的演化线</summary>

| 时间 | 谁 | score | 为什么长这样 |
|---|---|---|---|
| 2013/14 | Graves（手写生成）、**NTM** | $e^{-\|k-k_t\|^2/2\sigma^2}$ 高斯核（+ 位置卷积） | 本来就是**可微内存寻址**，用显式距离核；NTM 就有**多读写头** |

| 2015 | Luong | dot / **general** $q^\top W k$ / concat 三种对比 | dot 零参数、最快；general 带对齐效果更好 |
| 2017 | Vaswani | $q^\top k/\sqrt{d_k}$ | 自注意力让 $q,k$ **同源同维**，dot 变自然；且原文明确说 dot 快且省显存，能用高度优化的矩阵乘 |
| 2021+ | Swin V2 等 | cosine | 归一化 $q,k$，让尺度问题消失，换可学 $\tau$ |

几个我想强调的推论：

**(1) KV-DB 视角不是类比，是词源。** attention 一开始就叫 "memory addressing"，Graves 的 NTM 有读写头、有 content-based addressing、有 location-based addressing、有 sharpening（$\gamma$ 幂次）。**DB 是最原始框架，"softmax + dot" 是后来的特化。**

**(2) softmax 从头就在，但理由换过。** Bahdanau 里 $\alpha = \mathrm{softmax}(e)$ 的出身是**"对齐 = 源端位置上的概率分布"**（软对齐、可解释性），不是数值稳定。"总和=1 性质好"是**事后 retrofit**。

**(3) 你上一轮问的 $d_q=d_k$，答案在这里补完。** 加性 score 不要求同维（各投影到公共空间即可）；**只有点积逼出同维**。所以"q/k 必须同维"是"q/k 同源（自注意力）+ 选了点积"联合的产物，不是 attention 的性质。最早用加性，恰恰因为 q、k 异构。

**(4) transformer 的内积其实是 Luong 的 general。** 因为

这就是 $x^\top M x$ 的**低秩因子化**。"点积"从来没限制表达力，它只是把双线性型拆成两个投影好算 GEMM。

**(5) multi-head 也不是 2017 首创。** NTM/DNC 就多读写头。Vaswani 的官方说法是"不同表示子空间"，但实质理由还是上一轮说的：**解耦多个选择预算**。

一句话：**加性 = 为异构；乘法 = 为同源 + 为硬件。** 而 **SDPA 是 2023 年 PyTorch 把这个硬件选择固化成 kernel**，不是 attention 的定义。

## 四、线性那族：关键不是"没 softmax"，是"把表压小了"

这是我觉得最值得说的一节，因为它能把你的 DB 框架直接延伸出去。

**softmax 恰恰是阻塞结合律的那一环**（精确核无限维）。一旦你放弃它、改用有限维 $\phi$ 或别的交互，就能

$$\sum_j \phi(k_j)v_j^\top =: M \quad\text{（先算成一个 } d\times d \text{ 的状态）}$$

于是 n×n 的"全表扫描"塌缩成定长 memory。所以**"去 softmax"和"O(n)"不是两个独立选择，是同一个选择的两个侧面。** 但真正区分这一族内部各家的，是**你怎么往这个数据库里写**：

| 架构 | 数据库语义 | 干扰特性 |
|---|---|---|
| **Full softmax attn** | **只读全表**，$O(n)$ 存储、$O(n^2)$ 读 | 零干扰、可精确 recall、容量不受 $d$ 限制 |
| Linear attn（Hebbian） | 只写不擦：$M \mathrel{+}= v k^\top$ | 键碰撞 → 干扰，容量 $\sim O(d)$ |
| **DeltaNet** | $M \mathrel{+}= (v - Mk)\,k^\top/\|k\|^2$ → **先擦旧值再写 = upsert** | 干扰大幅下降 |
| RetNet / GLA / RWKV | 加**遗忘门/TTL**，$M \leftarrow \alpha M + \dots$ | 用时间衰减换容量 |
| **Mamba** | 门控变成**输入相关**（selective） | 按内容决定遗忘 |
| **GDN / KDA** | delta 规则 + 细粒度 gate 的混合 | 当前最强的一档 |
| 多头 / 多状态 | 多张表 | — |
| **Hybrid**（几层全注意力 + 几层线性） | 少量精确查询 + 大量压缩索引 | 当下主流折中 |

Delta 规则那一步特别值得盯：**"先减去 $Mk$（擦掉这个 key 上现在存的值），再写入新的 $v$"——这是 upsert，不是 append。** Mamba 是"按内容决定遗忘"，是 TTL。这些全是数据库写策略，跟"用不用 softmax"关系不大。所以我会说：**这族不是"attention 去掉 softmax"，而是"把 attention 从全表扫描改成定长 sketch"，softmax 只是顺带被扔掉的那个不可分离件。**

---

## 五、那么今天为什么还要 softmax

倒过来说最清楚：

- Full attention 的**全部卖点**就是"表是完整的，能精确查，容量不受 $d$ 限制"。
- 只要你要这个，就必须保留**某种对全表、依赖每个 pair 的归一化竞争**。
- 在那一族里，softmax 是最 tractable 的那个：最大熵最优解、平移不变、可微、梯度形式干净（$p - p p^\top$）、有温度旋钮、并且**恰好能被 FlashAttention 融进一个 kernel**。

它换来的代价同样清楚：稠密、永远说不"查不到"（→ sink）、以及把结合律堵死（→ 才有了后面那一整族）。所以今天还在用 softmax，不是因为它是 attention 的定义，而是因为**它和它锁定的 kernel 生态，是"精确全表检索"这一档需求下性价比最高的快照**。而 Mamba/RWKV7/GDN/KDA 那条线，本质是在回答一个完全不同的问题：**表能不能不用完整留着。**

（顺带说一句：如果没有那套 kernel 生态，如果 2017 年就有人把 DeltaNet 这类 upsert 记忆做到同样的工程成熟度，今天的默认解很可能不是 softmax。这就是"设计选择"最赤裸的样子。）
