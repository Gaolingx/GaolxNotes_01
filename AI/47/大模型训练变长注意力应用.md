### 🤖 Assistant

The FlashAttention “varlen” (variable-length) interface – typically `flash_attn_varlen_func` – is designed to compute attention efficiently over multiple sequences of **different lengths** that have been **packed into a single batch**. Instead of requiring every sequence to be padded to the same length (which wastes compute and memory), you concatenate all samples along the sequence dimension and pass cumulative sequence lengths (`cu_seqlens`) that define where each sequence starts and ends. Inside the kernel, attention is then restricted to each sequence independently – tokens only attend to tokens within the same sequence.

In LLM training, you would use the varlen interface whenever you *pack several variable-length examples into a single training sample* and want to **maximise hardware utilisation while enforcing strict segment‑wise attention masking**. The main scenarios are:

---

### 1. Pre‑training with document packing (most common)
- **Why pack?** Web‑scale documents vary widely in length (tens to thousands of tokens). Padding every document to the fixed context length wastes huge amounts of FLOPs and memory. Packing multiple documents into one sequence of length \(L\) (up to the model’s maximum context) recovers this waste and can **increase effective throughput by 2‑5×**.
- **How varlen is used:** The model’s input is a concatenation of documents separated by an `<EOS>` or boundary token. `cu_seqlens` marks each document’s span. FlashAttention’s varlen kernel then performs attention block‑diagonally – tokens from document \(i\) never attend to tokens from document \(j\).
- **Examples in practice:** Megatron‑LM, Meta’s LLaMA pre‑training, and many other frameworks adopt sequence packing backed by FlashAttention varlen.

---

### 2. Supervised fine‑tuning / instruction tuning with packed examples
- When you have a dataset of prompts and completions (e.g., “User: … Assistant: …”) of varying lengths, you can pack several complete conversations into one training sequence. Each conversation is a separate segment; masking should prevent cross‑conversation leaks.
- **Varlen advantage:** No need to create a complex 2D attention mask; you just provide the segment boundaries and let the kernel handle the per‑segment attention. This simplifies the data pipeline and improves speed compared to padding or hand‑crafted masks.

---

### 3. Any training loop with dynamic, intrinsically variable‑length batches
- If your data loader naturally produces sequences of different lengths (e.g., after truncation to each sample’s own maximum), you can avoid padding entirely by concatenating them and invoking varlen attention. This eliminates the “maximum length bias” in batching and often yields a denser compute schedule.

---

### 4. When you need block‑diagonal (non‑causal) masks for efficiency
- Some training schemes (like certain multi‑document QA or prefix‑language models) require that attention be restricted to user‑defined segments. Instead of building a massive `(batch, seq, seq)` boolean mask, varlen accepts a list of segment boundaries and computes only the allowed interactions. This is both memory‑friendly and fast.

---

### When **not** to use the varlen interface
- **All sequences are already equal length** (e.g., after chunking a single long document into fixed‑size blocks) – the standard `flash_attn_func` with `is_causal=True` is simpler and sufficient.
- **The attention mask cannot be expressed as independent segments** – e.g., if you need an arbitrary pattern (mixture of causal + bidirectional within a single sequence) that doesn’t decompose into clean sequence boundaries, you’ll likely need a custom mask.

---

### Practical note for implementation
```python
from flash_attn import flash_attn_varlen_func

# q, k, v shape: (total_tokens, num_heads, head_dim)
# cu_seqlens_q is a int32 tensor of shape (batch_size + 1), e.g. [0, 512, 1024, ...]
# max_seqlen_q = max sequence length in the batch

out = flash_attn_varlen_func(
    q, k, v,
    cu_seqlens_q, cu_seqlens_k,
    max_seqlen_q, max_seqlen_k,
    causal=True,       # can still apply causal masking *within* each segment
    softmax_scale=scale,
)
```

In pre‑training and fine‑tuning pipelines that use packing (arguably the standard today for frontier LLMs), switching to the varlen API is essential for both performance and simplicity.
