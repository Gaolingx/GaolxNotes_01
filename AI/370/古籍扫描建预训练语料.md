# 古籍扫描建预训练语料

### 🧑‍💻 User

早于1840s的书籍要如何扫描作为llm预训练数据集？

---

### 🤖 Assistant

对于将1840年代之前（19世纪初期及更早）的实体古籍转化为LLM预训练数据集，整个流程可分为**“物理扫描 → 图像预处理 → OCR文本提取 → 后处理与校对 → 数据集格式化”** 五大环节。由于这类书籍属于公版（版权过期），在法律层面完全允许使用，你的主要挑战在于**古籍的物理脆弱性、古旧字体与拼写、版面复杂**导致的OCR困难。下面是一套可行的工作流程与工具推荐。

---

### 1. 物理扫描：设备与参数
- **首选非接触式扫描仪**（如书本翻拍仪、V型扫描仪、 overhead scanner），避免压平书脊造成损伤。
- 若无专用设备，可用**高像素相机+固定支架**拍照扫描，两侧用LED冷光源均匀补光。
- **关键参数**：
  - 分辨率≥ **300 DPI**（推荐 400-600 DPI 捕捉旧字体细节）。
  - 保存为**TIFF**或**PNG**无损格式（JPEG会引入伪影影响OCR）。
  - 每页单独命名，含页码或顺序编号，方便后续校正。

---

### 2. 图像预处理（去噪与版面分析）
古籍常见问题：透背、霉斑、泛黄、印刷墨色不均。
- **去背透/降噪**：使用 `ScanTailor` 或 Python 的 `scikit-image` 进行背景清理、自适应二值化。
- **版面切割**：
  - 分离正文、页眉、页码、旁注。
  - 工具：`OCRopus`、`Kraken` 内置版面分析模型；也可手工标注后用 `Transkribus` 的 Layout Analysis。
- **纠偏/去边框**：`unpaper` 命令行工具非常适合批量处理扫描页。

---

### 3. OCR核心引擎选择 —— 这是最难的一环
现代标准OCR（如Tesseract默认英文）对19世纪早期印刷体、长s（ſ）、连体字（ct, st, fi等）、古体拼写（如“ye”代表the）识别率很低，必须**使用专门的历史文本模型**或工具：

| 工具/引擎 | 优势与适用场景 |
|-----------|----------------|
| **Tesseract 5 + 历史语言包** | 有 `eng_old` 或 `Latin` 古字体训练包，适合15-19世纪英文印刷品。需自行训练或下载社区模型。 |
| **Kraken / OCRopus** | 为历史文献设计，基于LSTM，可针对具体字体进行微调（仅需少量标注页）。命令行友好，适合大批量处理。 |
| **Transkribus** | 欧洲顶尖的历史文档OCR/HTR平台，内置大量公共古英语、法语、德语模型；可上传图片直接识别手工或印刷体。免费额度较多。 |
| **ABBYY FineReader** | 商业软件，对旧印刷体有一定支持，可手动训练字符集，但对16-18世纪字体仍需人工校正。 |

**关键技巧**：
- 先尝试**Transkribus**的公共模型（如“English Printed M1”），识别长s等字符效果好。
- 如有大量同字体书籍，用 **Kraken** 微调一个专用模型性价比最高。
- OCR时务必输出**置信度低的字符位置**，方便后续校正。

---

### 4. 文本后处理与自动校正
OCR产出的原始文本充满错误，需要用语言模型和词典进行纠错，但又要**保留原始拼写特征**（如“musick”“publique”），否则会丢失历史语言信息（LLM从原始拼写中也能学到演化规律）。

- **构建自定义词典**：
  - 收录该时期高频词、常见古拼写（可参考《牛津英语词典》历史变体）。
  - 使用 `Hunspell` 或 `SymSpell` 结合基于上下文的大模型进行校对。
- **基于语言模型的纠正**：
  - 使用**BERT/RoBERTa**等MLM模型对OCR输出做“错词检测 + 候选替换”，但需要限制替换候选词为同历史时期词汇。
  - 更保守的方法是仅修正高频OCR错误（如“m”识别成“rn”，“e”识别成“c”）用规则替换。
- **字符归一化**：
  - 长s (ſ) → 是否保留？若要保留，可在训练数据中直接使用 `ſ`，LLM能学到其规律；若不保留，统一转为 `s`。
  - 连字（æ, œ）→ 通常保留。
  - 断行连字符 → 务必按语言规则重新连接单词。

**实操流程**：
1. OCR输出 → 对齐原始图像，人工精校少量样本（如每100页抽1页），统计常见错误模式。
2. 编写Python脚本进行高频错误批量修正。
3. 用 `textdistance` 或模糊匹配跨校验不同OCR引擎结果（若同时用Tesseract和Kraken），合并高置信度部分。
4. 最终通过阅读质量抽检。

---

### 5. 数据集格式化与清洗
LLM预训练一般要求**连续、干净、去重的文本流**，可保留部分元数据。

- **去除噪音**：删除页码、页眉页脚、注释号（若仅需正文）、library stamps等。
- **段落重组**：古籍段落标记可能缺失或仅用缩进表示，需利用空行或缩进规则重新分段。
- **元数据保留**：可生成JSONL格式，每条包含 `{"text": "...", "title": "...", "year": 1720, "author": "..."}`，便于调试和主题分析。
- **去重**：对整个文档集做段落级模糊去重（`MinHash` 或 `SimHash`）。
- **分词与分割**：将长文本切成不超过模型最大上下文的块（如2048 tokens），并使用完整的句子边界。

**最终产出格式示例**（一行一个文档）：
```json
{"text": "It is a truth universally acknowledged...", "title": "Pride and Prejudice", "year": 1813}
```

---

### 6. 绕过扫描与OCR的替代方案（强烈建议先查询）
许多1840s之前的英语书籍已被数字化校对过：
- **Project Gutenberg**：有超过60,000本公版书籍，文本经过人工校对，可直接下载作为预训练数据。
- **Internet Archive**：提供多种格式的扫描本，部分已OCR处理。
- **HathiTrust Digital Library**：适合批量获取学术级元数据的古籍文本。

如果这些平台已收录你的目标书籍，直接使用其纯文本版本能节省数周时间。只有冷门、无数字版的孤本才需要自己扫描与OCR。

---

### 7. 协作式高质量数据集构建
若项目对质量要求极高：
- 使用**Distributed Proofreaders**模式（分布式校对）：将OCR文本与图像切分为短片段，经由志愿者多人交叉校对。
- 后续可用校对干净的数据重新训练OCR模型，提升后续同类型书籍的识别准确率。

---

**总结一条高效路径**：
```
实体书 → 高分辨率拍摄 → ScanTailor去背/裁边 → Kraken提取区域 → Kraken/Transkribus古体OCR
→ Python基于历史词典纠错 → 文本去噪/分段/去重 → JSONL格式LLM预训练数据集
```

如果目标语言是英文且印刷字体规范，Transkribus + 其公共英模型能让整个流程在几周内产出可接受纯文本。祝你挖掘出高质量的历史文本语料！
