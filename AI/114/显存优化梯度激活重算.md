## 😀 默认助手 (7)

# 显存的两本账：梯度与激活

先建立一个可核算的模型。混合精度 + Adam 训练一个大模型 $P$ 参数量、激活显存 $M_{act}$：

$$
M_{\text{total}} = \underbrace{2P}_{\text{bf16 权重}} + \underbrace{2P}_{\text{bf16 梯度}} + \underbrace{(4P+8P)}_{\text{fp32 master + Adam }m,v} + \underbrace{M_{act}}_{\text{激活}}
$$

对 7B 模型，光是前四项就是 $16 \times 7\times10^9 \approx 112\ \text{GB}$，而激活在大 batch/长序列下可以轻松再翻一倍。两条战线的本质不同：

- **梯度/优化器态是"静态账"**：与 $P$ 成正比，形状固定，可以提前预算、精确切分。
- **激活是"动态账"**：与 batch × seq × 层数成正比，随配置爆炸，是最容易 OOM 的地方。

---

## 一、梯度方向：核心是"不冗余 + 少而精"

梯度和优化器状态的问题是**每张卡都存了一份完整副本**，而它们只服务于参数更新。推进思路有四条。

### 1. 切分冗余（最主流，几乎零精度损失）

| 方案 | 分片内容 | 单卡显存（$N$ 卡） | 代价 |
|---|---|---|---|
| DDP + ZeRO-1 | 优化器状态 | $4P + 2P + \frac{8P}{N}$ | 通信量小 |
| ZeRO-2 | + 梯度 | $4P + \frac{10P}{N}$ | 反向期通信 |
| ZeRO-3 / FSDP | + 参数 | $\frac{16P}{N}$ | 前后向都要 all-gather |
| ZeRO-Offload | 优化器/梯度下沉 CPU | 再加 CPU 内存换显存 | PCIe 带宽成瓶颈 |

FSDP/ZeRO-3 让梯度显存近似 $O(1/N)$，代价是计算时反复 all-gather 参数。**梯度分片的关键细节**：ReduceScatter 而非 AllReduce，把规约和分片合成一步，否则先 AllReduce 再丢弃等于白存一份峰值梯度。

### 2. 减少"需要梯度"的参数（最省，且省的是全部四项）

只要参数被冻结，它既不产生梯度、也不需要优化器状态：

- **LoRA / Adapter / 只训分类头**：可训练参数降到 0.1%–1%，梯度账几乎归零，还能全精度训练不损失精度。
- **QLoRA**：基座 4-bit 量化冻结 + 少量 LoRA，7B 单卡 24GB 可训。
- 本质权衡：**表达能力 vs 显存**。全参微调仍是高上限场景的刚需。

### 3. 压缩梯度本身（$\partial M/\partial \text{bits}$）

- 梯度用 bf16（与权重同精度），master weight 保持 fp32 防止小更新被吞。
- **8-bit 优化器**（bitsandbytes）：$m,v$ 从 $8P$ 压到 $2P$，占优化器态的大头。
- **低秩梯度投影**（GaLore）：把梯度投影到低秩子空间再更新，Adam 状态按投影维度存，可训练全参但优化器显存降一个量级——代价是每次要 SVD、且是近似更新。

### 4. 复用与融合（消除"隐式"峰值）

- **Fused Adam / 融合 optimizer step**：避免 `grad → grad_fp32 → update` 过程中的临时张量。
- **梯度累积直接写进累积缓冲区**，不保留每个 micro-batch 的独立 grad。
- **扁平化参数/梯度缓冲**（flat buffer）本身省的是碎片与多次 kernel launch 的临时分配，减少显存碎片导致的"假 OOM"。
- 融合反向的 `grad += ` 就地写回，避免中间张量。⚠️ 注意 autograd 对 in-place 的限制。

> **一句话**：梯度方向的推进顺序是 —— 先 FSDP/ZeRO 切冗余 → 再 LoRA/冻结砍规模 → 再 8-bit/低秩压精度 → 最后靠融合消峰值。

## 二、激活方向：核心是"存得少 + 算得起"

激活显存对 Transformer 单层约（Megatron 论文的经典估算）：

$$
M_{\text{layer}} \approx s\,b\,h\left(34 + 5\cdot\frac{a\,s}{h}\right)
$$

其中 $s$ 序列长、$b$ 微批、$h$ 隐维、$a$ 注意力头数。$L$ 层累积。注意第二项 $\propto s^2$，**长序列时注意力激活会压过 MLP**。四条推进路径：

### 1. 重计算（Checkpointing）：用时间换空间

- **朴素 checkpointing**：每层只存输入，反向时重算该层前向。激活从 $O(L)$ 降到 $O(L)$ 份"层输入"，常数大幅下降，代价约 +33% 计算。
- **sqrt 策略**：每 $\sqrt{L}$ 层存一个 checkpoint，峰值降到 $O(\sqrt{L})$，这是理论最优的重算粒度。
- **选择性重算**（Megatron 推荐）：只重算便宜的 attention 部分，保留 MLP 激活，几乎不增加计算量就能省一大块——因为 attention 重算成本低。
- **CPU/NVMe offload**：激活推到 host，代价是 PCIe 往返，长序列下带宽可能打满。

### 2. 结构性消除（不存而不是重算）

- **FlashAttention**：分块计算，永不物化 $s\times s$ 注意力矩阵，注意力激活从 $O(s^2)$ 降到 $O(s)$。这是长序列的第一功臣。
- **融合 kernel**：LayerNorm/RoPE/激活函数融合，消掉大量中间张量。
- **序列并行**（Ulysses / Ring Attention）：沿 seq 维切分，激活按卡数分摊；**张量并行**同理切隐维。
- **序列 packing**：去掉 padding，变长 attention，避免为无效 token 分配激活。

### 3. 降低激活精度

- 激活统一 bf16/fp16，避免隐式 fp32 上转（LayerNorm、softmax 是重灾区，写成 fp32 会凭空多一倍）。
- 8-bit 激活、量化 checkpoint（激活也走低精度存储）。

### 4. 缩小工作集

- **micro-batch / 梯度累积**：显存峰值只看 micro-batch，全局 batch 靠累积拼——这是最直接、最无痛的旋钮。
- 序列长度是最敏感维度（平方项），能减就减（截断、分块处理长文）。

> **一句话**：激活方向的推进顺序是 —— 先开 FlashAttention + 选择性重算 → 再序列/张量并行分摊 → 再降 micro-batch/序列长 → 最后才 offload。

## 三、两条战线的交汇与实战组合

现代大模型训练基本是这套"全家桶"叠加：

$$
\text{FSDP/ZeRO-3} \;+\; \text{FlashAttention} \;+\; \text{选择性激活重算} \;+\; \text{梯度累积} \;+\;\text{fp32 master}
$$

几条容易踩的坑：

1. **FSDP 与激活重算叠加**：重算会重新 all-gather 参数，通信量上升，需调 `reshard_after_forward` 粒度。
2. **ZeRO-3 下梯度分片的 all-gather 时机**会与 checkpointing 相互放大，优先用 ZeRO-2 + AC。
3. **动态显存池**：`PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` 往往能救回几个 GB 的碎片。
4. **精度账要算全**：报 OOM 时先看是不是某个 fp32 中间张量在偷偷翻倍。

<details>
<summary><b>排查 OOM 的决策顺序（点开）</b></summary>

1. 打印显存账本：参数/梯度/优化器态/激活各占多少（PyTorch Memory Profiler）。
2. 如果**梯度+优化器态**是大头 → 上 FSDP/ZeRO、8-bit optimizer、LoRA。
3. 如果**激活**是大头 → FlashAttention、选择性重算、降 micro-batch/序列长、序列并行。
4. 如果两者都不大却 OOM → 查碎片与临时张量，开 expandable_segments、检查 fp32 上转。
5. 若单卡无论如何放不下 → 张量并行/流水并行 + FSDP 组合。

</details>

**总结成一句**：梯度方向靠"分片 + 砍可训练规模 + 压精度"把静态账做小；激活方向靠"重算 + 不物化（FlashAttention）+ 并行分摊 + 缩小工作集"把动态账做小。二者独立可叠加，实践中几乎总是组合使用。
