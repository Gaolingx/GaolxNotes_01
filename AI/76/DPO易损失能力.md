# 为什么 DPO 容易破坏模型原有能力

## 一句话结论

DPO 的优化目标是**在一个固定的偏好数据集上，把「好答案相对参考模型的对数概率」抬得比「坏答案」更高**。它没有显式奖励模型做泛化，KL 约束又只在数据支撑集上「隐性」生效，所以一旦偏好信号里有捷径、或数据分布与当前策略漂移，梯度就会**大幅重分配概率质量**，把通用能力（推理、代码、多语言、事实性）一起牺牲掉。这就是经典的 **alignment tax（对齐税）**。

---

## 1. DPO 到底在优化什么

给定参考模型 $\pi_{\text{ref}}$、偏好对 $(x, y_w, y_l)$，DPO 的损失是：

$$
\mathcal{L}_{\text{DPO}}(\pi_\theta)
= -\mathbb{E}_{(x,y_w,y_l)\sim\mathcal{D}}
\log \sigma\!\left(
\beta \log\frac{\pi_\theta(y_w\mid x)}{\pi_{\text{ref}}(y_w\mid x)}
- \beta \log\frac{\pi_\theta(y_l\mid x)}{\pi_{\text{ref}}(y_l\mid x)}
\right)
$$

它等价于把隐式奖励定义为

$$
r_\theta(x,y) = \beta \log\frac{\pi_\theta(y\mid x)}{\pi_{\text{ref}}(y\mid x)}
$$

也就是说，DPO 用「**策略相对参考模型的对数概率比**」来充当奖励。这个奖励是**推导出来的、只在数据分布附近成立**，不是训练出来的、可泛化的奖励函数——这是所有问题的源头。

---

## 2. 破坏能力的七个机制

### ① 隐式奖励只能外推，出分布就失真（最核心）

RLHF/PPO 里有一个独立的奖励模型 $r_\phi(x,y)$，它对**任意新输出**都能打分，因此天然做泛化。

DPO 的隐式奖励 $r_\theta$ 只有在 $y$ 落在偏好数据覆盖的分布里时才可靠。当策略开始生成数据集中没见过的输出时，$\log\frac{\pi_\theta}{\pi_{\text{ref}}}$ 是**外推**，数值不可信，而此时**没有任何惩罚把模型拉回来**（KL 正则项在数据支撑集外梯度为零）。结果就是：模型被优化推向一个数据外的方向，通用能力随之崩掉。

> 关键点：DPO 推导时 $Z(x)$ 的消去依赖于「同一 $x$ 下 chosen/rejected 共享归一化」，这一步在有限数据、有限模型容量下只是近似。

### ② KL 约束是「隐性且局部」的，很容易过冲

PPO 里 KL 惩罚是**显式**加在 loss 里的，且对**当前策略采样出的所有输出**生效：

$$
\mathbb{E}\big[r_\phi(x,y)\big] - \beta\,\mathrm{KL}\!\left(\pi_\theta \,\|\, \pi_{\text{ref}}\right)
$$

DPO 的 KL 只是**隐式**藏在参考模型项里，而且**只在偏好对的分布上被约束**。这导致：

- $\beta$ 太小 → 约束近乎失效 → 策略跑飞、模式坍塌；
- $\beta$ 太大 → 几乎学不动；
- 无论怎么调，它都**无法全局**约束「所有 token 的分布」不偏离参考模型。

### ③ 偏好数据里的「伪相关」被忠实地学走

人类标注偏好带有强烈捷径：

- **长度偏置**：更长的答案更讨喜；
- **格式偏置**：带标题/列表/emoji 的更讨喜；
- **谄媚（sycophancy）**：附和用户观点的更讨喜。

DPO 会**精确拟合这些捷径**。于是模型学会「写得更长、更客气、更结构化」，但推理、代码正确性、事实准确性下降——因为这些东西在偏好对里信号更弱，被顺带的概率重分配所淹没。

### ④ 只看差值 → 概率质量重分配 → 熵坍塌

损失只关心 $y_w$ 与 $y_l$ 的**相对**对数概率差。降低损失有两条路：

- 抬高 $y_w$ 的概率；
- **压低 $y_l$ 的概率**（哪怕是把它压到接近 0）。

第二条路代价很低，但会**大量消耗模型的概率质量/熵**。被 rejected 的样本里往往包含正确的推理链、代码片段、常识表述。压低它们会：

- 降低输出多样性、导致 mode collapse，损害 pass@k / 探索能力；
- 让模型「不敢说」某些本来正确的表述，表现为能力退化。

### ⑤ 偏好信号缺少「奖励模型」这一层泛化瓶颈

| 维度 | RLHF (PPO) | DPO |
|---|---|---|
| 奖励来源 | 独立学习的 $r_\phi$，可打任意样本 | 隐式 $r_\theta$，只在数据附近可靠 |
| 泛化 | 强（标量函数） | 弱（直接改 token 概率） |
| KL 约束 | 显式、全局 | 隐式、局部 |
| 采样 | 在线采样新鲜输出 | 离线固定偏好集 |
| 过优化迹象 | 有独立 RM 验证集可早停 | 无此信号，易悄悄过优化 |

缺了奖励模型这层「平滑瓶颈」，偏好里的噪声和偏差会**直接**写进策略参数，而不是先被奖励模型平均/过滤掉。

### ⑥ Goodhart 定律 / 过优化曲线

DPO 的隐式奖励 $r_\theta$ 可以被**无限**推高（把 $\pi_\theta$ 对 $y_w$ 的概率推大即可），但**真实质量会在某个点之后下降**——这就是典型的过优化（over-optimization）曲线。DPO 因为缺少独立奖励模型的验证，很难判断「什么时候该停」，常常在 chat win-rate 还在涨的时候，下游 benchmark 已经开始掉。

### ⑦ 超参与数据敏感性

- $\beta$、学习率、训练轮数都极敏感；
- 偏好对质量差（标注噪声、模糊对、两极分化不足）；
- 用**不同模型**生成的偏好数据（off-policy 程度大）→ 分布漂移更严重。

这些都会放大①②的效应。

## 3. 为什么「chat 变好」但「能力变差」会同时发生

偏好数据衡量的是**人类主观偏好**，而不是客观正确性。模型可以：

- 在偏好分布上得分极高（更啰嗦、更礼貌、更"像助手"），
- 同时把用于推理/代码校准的分布改坏。

两者不矛盾——**这正是 DPO 容易出现的退化模式**。

<summary><b>缓解手段（点击展开）</b></summary>

1. **加正则 / 混合目标**：在 DPO loss 上叠加 SFT loss（如 $-\lambda\log\pi_\theta(y_w|x)$），或用 **IPO / KTO / ORPO / SimPO** 等对过优化更稳健的变体。
2. **加强 KL**：显式加 $\mathrm{KL}(\pi_\theta\|\pi_{\text{ref}})$，或调大 $\beta$、做 KL 早停。
3. **数据去偏**：长度控制、格式中性化、去掉谄媚样本；保证 chosen/rejected 质量差明显。
4. **数据质量 > 数量**：少而精的偏好对通常优于海量噪声对。
5. **在线 / on-policy 迭代**：多轮用当前策略生成新偏好对迭代 DPO（更接近 RL 的在线性）。
6. **能力回放**：混入通用能力数据（指令、数学、代码）做 regularization，防止灾难性遗忘。
7. **监控下游指标**：别只看 win-rate，盯住 math/code/multilingual/长上下文等 benchmark。
8. **参考模型刷新 / 周期性重置 $\pi_{\text{ref}}$**：避免策略漂移太远。

</details>

## 4. 小结

> DPO 破坏能力，本质是因为它把「偏好比较」压缩成一个**只在数据分布附近成立的隐式奖励**，又缺乏**全局显式的 KL 约束**和**可泛化的奖励模型**。于是：分布外奖励失真 → 概率质量被重分配 → 捷径与噪声被直接学走 → 熵坍塌与过优化。表现为 **chat 更讨喜、通用能力下降**。

这是方法本身的**结构性特征**，不是单纯调参能完全消除的；实践中通常要用混合目标、去偏数据和下游监控来压制。
