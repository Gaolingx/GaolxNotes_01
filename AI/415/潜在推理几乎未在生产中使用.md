# 潜在推理几乎未在生产中使用

## 🧑‍💻 User

为什么latent reasoning在实际生产中用的几乎不存在

---
## 😀 默认助手 (7)

## 结论先行

不是因为"理论上不行"，而是因为它同时输了三种东西：**可验证性、可优化的工程管线、以及接口经济**。生产系统的瓶颈从来不是"能不能算出答案"，而是"能不能把这条链路接进已有的 RL、缓存、工具调用、评测和审计体系里"。离散 token 的 CoT 恰好是这条链路上唯一的通用货币。

---

## 1. 最根本的原因：整条工业化管线是"离散 token"的接口经济

现在的推理模型产线，几乎每一环都要求中间产物能被**当字符串处理**：

| 环节 | 对中间步骤的要求 | 潜在推理的后果 |
|---|---|---|
| 可验证奖励 RL（RLVR / GRPO） | 需要可切分的片段做信用分配 | 潜在步的 advantage 怎么定义？无从下手 |
| 拒绝采样 / 蒸馏（R1 那套） | 要按文本过滤好坏 trace，再做 SFT | 连续向量无法过滤、无法入训练集 |
| 过程奖励模型（PRM） | 需要对每一步打分 | 没有"步"这个单位 |
| 工具调用 / 函数调用 | 必须在中间吐出离散 token | 必须回到离散域，那还不如全程离散 |
| 前缀缓存 / prefix caching | 缓存的是可序列化的文本前缀 | 潜在向量不能跨 API 边界传输 |
| 投机解码 | 草稿模型按 token 分布做验证 | 连续步无法验证 |
| 约束解码 / 结构化输出 | 需要 token 级约束 | 完全不适用 |
| 评测与榜单 | trace 是可审计的 artifact | 无 artifact → 无榜单 → 无激励 |
| 护栏与内容审查 | 审查模型读 CoT 文本 | 审查一个向量流？ |

一句话：**离散 token 是一个标准化接口**，像软件里的 JSON/IP。它牺牲了带宽（信息密度低），换来的是整个生态可以对它做分工。潜在推理像"直接传内存指针"——更高效，但没人能接。

这也解释了为什么**把推理蒸馏进权重**反而先落地了：同样是"省掉显式 CoT"，业界选了"离线思考、烘焙进参数"（Qwen3 的非思考模式、R1 蒸馏系列、thinking budget），而不是"在线在潜空间里想"。前者不破坏任何管线，后者要重写全部管线。

---

## 2. 训练侧：可扩展性的证据还停留在小模型 + 合成任务

潜在推理的代表工作（Coconut 的连续思维、recurrent-depth / looped transformer 那类）结果通常是：

- 在**受控合成任务**上（图可达性、逻辑演绎、BFS 式搜索）能超过同规模 token-CoT；
- 需要**课程学习**（逐步把语言思维替换成连续思维），稍有不慎语言能力就崩；
- 目前主要在小模型、窄任务上验证，**没有 frontier 规模的 scaling law 证据**。

更技术性的困难是信用分配：对潜在步做反向传播近似于在思维步上做 BPTT，梯度要穿过 $S$ 个连续步骤：

$$\frac{\partial \mathcal{L}}{\partial z_t} = \sum_{s \ge t} \frac{\partial \mathcal{L}}{\partial z_S}\prod_{k=t+1}^{S}\frac{\partial z_k}{\partial z_{k-1}}$$

长链上梯度消失/爆炸、且没有离散瓶颈提供的"强制抽象"。而离散 token 自带一个天然的正则化：必须落成一个词，就难以走捷径。连续思维更容易塌缩到退化解，或学会"看起来在算其实在抄"。

**历史上所有"窄任务上漂亮、规模上不 work"的方法，工业界都会先等。** 潜在推理目前就是 2024 年才起步的方法，处于这个位置。

---

## 3. 可观测性、信任与合规：这是产品问题，不只是研究问题

- 用户和客服要"看你为什么这么答"；潜在推理**什么都给不出来**，连摘要都做不了（摘要本身就是一次显式 CoT）。
- 出故障时无法定位到某一步、无法编辑某一步重试（"reasoning editing" 这类生产技巧全部失效）。
- 监管（如 EU AI Act 的可解释性与审计要求）倾向于"可记录的推理痕迹"，隐藏状态是负债。
- 安全侧：安全团队对"模型在人类读不到的空间里思考"有天然抵触。

## 4. 服务侧经济学：是真实约束，但不是主因

<details>
<summary>展开：算力与调度的细节（可跳过）</summary>

要公平地说，潜在推理在**内存**上可能有真实优势：

- decode 阶段是内存带宽受限，单 token 吞吐大致 $R \approx \dfrac{\text{带宽}}{\text{每 token 读字节数}}$，与 FLOPs 关系不大。recurrent-depth 方案每步复用固定 KV，所以 $S$ 个潜在步的显存是 $\mathcal{O}(d \cdot L \cdot b)$，**不随推理深度增长**，而 CoT 的 KV 随 token 数线性涨。
- 单条请求的延迟量级也可以打平：CoT 是 $T \approx N_{\text{tok}}\cdot t_{\text{decode}}$，潜在是 $T \approx S \cdot t_{\text{layer-pass}}$，两者都是串行的。

真正的劣势在**批处理与利用率**：CoT 的每个 token 步可以被跨序列大 batch 填满，走的是高度优化的 matmul / fused kernel 路径；循环深度推理的串行结构对融合、CUDA graph、TP 切分、投机解码都更不友好，同等总 FLOPs 下 GPU 利用率更低——而每 token 的 FLOPs 大约是 $2P + \text{attention}$ 这种量级，多出来的算力要是不能被 batch 摊掉，就变成纯成本。

结论：**如果潜在推理能在同质量下省掉一半成本，工业界一定会用。它现在还没证明这一点**（缺乏公开的 cost–quality–latency Pareto 优势），所以谈不上"被经济性挡住"，而是"还没到谈经济性的阶段"。

## 5. 它其实已经以变形的方式在生产里了

这是最容易被忽略的平衡点。生产里真正跑的"潜在/隐式推理"是：

1. **推理蒸馏进权重**：把长 CoT 的能力离线压缩进参数，推理由"在线潜空间"变成"权重里的先验"。这是目前最主流的"去 CoT"路线。
2. **Pause token / 思考预算**：在固定位置塞无内容 token 换算力，是潜在推理最弱的一种形式，曾有小范围使用。
3. **混合方案**：显式 CoT 为主 + 摘要压缩 + 提前退出，把长思维压成短思维（业界普遍做法）。
4. **通用隐式计算**：残差流的逐层计算、MoE 路由、状态空间模型（Mamba 类）的隐状态，本质上都是"潜在推理"——只是没人把它当 reasoning 卖。
5. **研究前沿**：looped / recurrent-depth transformer 在 2025 年重新升温，但仍是论文级别。

所以准确的说法是：**"在潜空间里显式地、可扩展地做多步推理"在生产中几乎不存在**；而"把推理从显式 token 挪到参数或压缩过的隐式计算里"正在大量发生。

---

## 6. 什么条件下它会进生产

- 出现一个**公开的、规模化的** Pareto 优势：同质量下成本或延迟显著更低（比方说 2× 便宜）；
- 或者它解锁了 token-CoT **结构上做不到**的能力（例如超长链搜索、恒定显存超长推理），以致于愿意为它重写工具链；
- 或者 API 协议进化到能承载"隐藏 KV / 潜在前缀"（现在 chat completions 这类接口是字符串契约，这是硬门槛）；
- 或者监管与产品反向要求"不要展示推理过程"（目前趋势相反，即使 OpenAI 也展示摘要）。

在那之前，**离散 token 作为推理的公共接口，地位非常稳固**。它是用效率换互操作性的选择，而生产系统永远先买互操作性。
