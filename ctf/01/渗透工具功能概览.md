# Meterpreter 能执行的操作

Meterpreter（Meta-Interpreter）是 Metasploit 框架中的高级内存驻留 payload。它运行在目标内存中，不写入磁盘（无文件），通过 **staged** 方式加载，通信全程加密。以下是它主要能执行的操作分类。

---

## 1. 信息收集与侦察

| 命令 | 作用 |
|------|------|
| `sysinfo` | 系统信息（OS、架构、主机名、域） |
| `getuid` | 当前会话权限（用户身份） |
| `getpid` / `ps` | 当前进程 / 列出所有进程 |
| `getsystem` | 尝试提权到 SYSTEM |
| `route` / `arp` | 查看路由表 / ARP 缓存 |
| `ipconfig` / `ifconfig` | 网络接口信息 |
| `getproxy` | 当前代理配置 |
| `env` | 目标环境变量 |
| `idletime` / `last` | 空闲时间 / 最近登录用户 |

## Meterpreter 的核心特性

| 特性 | 说明 |
|------|------|
| **内存驻留** | 不落地磁盘，减少痕迹 |
| **无文件操作** | 避免传统文件检测 |
| **加密通信** | 支持 TLS 加密，规避 IDS/IPS |
| **跨平台** | Windows / Linux / macOS / Android / PHP / Java |
| **模块化** | 按需加载扩展，灵活扩展功能 |
| **多通道** | 支持多种传输方式（TCP/HTTP/HTTPS） |

## ⚠️ 使用须知

Meterpreter 是**渗透测试与红队评估**的合法工具，但**未经授权使用属于违法行为**。上述能力应在以下前提使用：

- ✅ 获得书面授权的渗透测试
- ✅ 自建的实验/靶场环境（如 HTB、VulnHub、自建 LAB）
- ✅ 安全教学与研究
- ❌ 任何未授权的真实系统

> 从**防御角度**，理解这些能力有助于部署 EDR、行为监控、日志审计和网络分段等防护措施来检测和阻断此类攻击。

# 为什么预设 Payload 会被快速检测？

先理解检测原理，才能理解对抗思路。杀软不是"认识 Meterpreter"，而是识别**特征与行为**：

| 检测层面 | 具体机制 |
|---------|---------|
| **静态特征 (Signature)** | 默认 `windows/meterpreter/reverse_tcp` 的 shellcode stub、PE 模板、固定字符串已被写入海量特征库 |
| **启发式 (Heuristic)** | 检测可疑 API 调用序列、自解密 stub、异常节区熵值 |
| **行为监控 (Behavior)** | 进程注入、`CreateRemoteThread`、反射式 DLL 加载、进程空洞化 |
| **内存扫描** | 现代 EDR 直接扫描进程内存中的已知 payload 特征 |
| **网络特征** | 默认 SSL 证书、"Meterpreter" 明文握手、固定流量模式 |
| **AMSI / ETW** | Windows 脚本与 .NET 层面直接拦截 |

> 关键认知：**默认 payload = 官方模板 = 全世界都有的特征**。只要用了"原厂未改"的东西，就等于举着身份证做测试。

## 核心对抗思路（概念层面）

从**红队工程**角度，evasion 分为几大方向。以下为**原理性说明**，用于理解攻防，而非照抄步骤。

<details>
<summary><b>1. 静态层对抗 —— 让文件"不像"已知恶意</b></summary>

- **自定义编码/加密 stub**：不用 msfvenom 默认编码器，改用多层编码 + 自定义密钥
- **Payload 分离 (Staged / Split)**：把 loader 与 payload 分开，文件本体不含 shellcode
- **合法证书签名**：借用或伪造代码签名证书，降低信誉告警
- **打包器 / Packer**：对最终 PE 再打包，改变节区熵与结构
- **源码级重编译**：使用 `msfvenom` 之外的加载器（如 Cobalt Strike、Sliver、自研），或在源码层修改特征字符串

</details>

<details>
<summary><b>2. 内存/执行层对抗 —— 避免落地与注入特征</b></summary>

- **反射式 DLL 注入 (Reflective DLL Injection)**：不通过 `LoadLibrary`，绕过文件系统与部分 API 监控
- **进程注入 / 迁移**：注入到合法进程（如 `explorer.exe`、`svchost.exe`）降低可疑度
- **进程空洞化 (Process Hollowing)**：创建挂起进程后替换其内存
- **无文件执行**：通过 PowerShell、WMI、MSHTA 等在内存中执行
- **API Unhooking / Direct Syscall**：绕过用户态 EDR Hook
- **ETW Patching / AMSI Bypass**：针对 Windows 遥测与脚本扫描

</details>

<details>
<summary><b>3. 网络层对抗 —— 让流量"正常化"</b></summary>

- **更换 C2 框架**：Meterpreter 默认流量特征明显；改用 **Cobalt Strike、Sliver、Havoc、Mythic** 等，其 beacon 可自定义
- **合法域名 + 真实 TLS 证书**：把 C2 伪装成正常服务
- **域前置 (Domain Fronting)、CDN 代理**：隐藏真实 C2 地址
- **Malleable C2 Profile**：把流量伪装成 jQuery、Office 更新等正常请求
- **加密与协议混用**：HTTPS / DNS / SMB / WebSocket 隧道

</details>

<details>
<summary><b>4. 操作安全 (OPSEC) —— 比技术更重要</b></summary>

- **减少行为噪声**：不自作聪明跑一堆扫描命令
- **控制 payload 存活时间**：用完即走，避免长时间驻留被沙箱/EDR 溯源
- **针对性定制**：每个目标环境不同，通用 payload 必然暴露
- **测试节奏**：了解蓝队的检测阈值与响应时间

</details>

## 现代红队的现实做法

单纯"改 msfvenom payload"已经很难对抗**内存扫描 + 行为 EDR + 沙箱**。业内主流趋势：

1. **换用更现代的 C2**（Sliver / Mythic / Havoc / Cobalt Strike），它们从设计上就内置了 OPSEC 与 malleable profile
2. **自研加载器**：用 C/C++、Rust、Nim、Go 编写，避开公开特征
3. **Living-off-the-Land (LotL)**：滥用系统自带工具（`certutil`、`bitsadmin`、`rundll32`），不引入新二进制
4. **初期就配合免杀工程**，而非事后打补丁

> ⚠️ 这些都是**双刃剑**技术。在授权测试中用于**验证防御能力**是正当的；未授权使用则是犯罪。业内合规做法是：红队评估前签订授权书（RoE），明确范围、时间窗与禁止事项。

## 从防御方看：如何检测这些"高级"行为

理解攻击才能更好防守。对抗 evasion 的检测重点：

| 攻击手法 | 防御检测点 |
|---------|-----------|
| 反射式注入 / 进程注入 | 监控 `VirtualAllocEx`+`WriteProcessMemory`+`CreateRemoteThread` 链；EDR 内存扫描 |
| 无文件执行 | PowerShell 日志 (ScriptBlock 4104)、AMSI、WMI 事件、`mshta` 父子进程异常 |
| LotL 滥用 | 命令行审计、Sysmon 事件 ID 1/3/8/10，检测异常父进程 |
| C2 流量 | NDR、JA3/JA3S 指纹、TLS 证书异常、beacon 周期性检测 |
| 进程空洞化 | 检测进程映像与磁盘文件不一致 |
| 凭据窃取 | 监控 LSASS 访问（Sysmon Event ID 10） |

**关键防御措施**：
- 部署 **EDR + 内存扫描**（不只看文件）
- 启用 **Sysmon + 集中化日志 (SIEM)** 做行为关联
- 开启 **AMSI、PowerShell 深度日志、ETW**
- **应用白名单 (WDAC/AppLocker)** 阻止未授权二进制
- **网络分段 + 出口流量监控**，限制横向移动
- 定期做 **紫队演练 (Purple Team)**，把红队 TTP 转化为检测规则

## 总结

```
默认 Meterpreter → 特征明显 → 秒被查
       ↓
现代对抗 = 自定义加载器 + 现代 C2 + OPSEC + 初始即免杀
       ↓
防御方 = 内存扫描 + 行为 EDR + 日志关联 + 白名单 + 网络监控
```

**核心结论**：免杀不是"改几行代码"就完事，而是一整套 **OPSEC 工程**；而防御也不是靠单一杀软，而是 **纵深检测体系**。
